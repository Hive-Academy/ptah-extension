# PtahCode replay demo: protocol, recorder, and CI research

Scope: read-only repository research. No checks or renders ran.

## 1. Message protocol inventory

### Wire format

- `ClaudeRpcService.call()` creates a `correlationId` and posts `{ type: 'rpc:call', payload: { method, params, correlationId } }` (`libs/frontend/core/src/lib/services/claude-rpc.service.ts:144-154`, `:219-222`). The registry types the method, params, and result (`:144-148`).
- The response is top-level `{ type: 'rpc:response', correlationId, success, data?, error?, errorCode? }`, not a payload envelope. `error` accepts a string or `{ message }` (`libs/frontend/core/src/lib/services/claude-rpc.service.ts:85-92`, `:229-238`). Responses correlate through `pendingCalls` (`:259-263`).
- Electron maps `window.vscode.postMessage` to IPC `rpc`, `getState` to synchronous `get-state`, and `setState` to `set-state` (`apps/ptah-electron/src/preload.ts:24-34`). Main-process `to-renderer` becomes a synthetic `MessageEvent` (`:71-73`).
- `IpcBridge` unwraps the RPC payload, calls `RpcHandler`, and returns the response (`apps/ptah-electron/src/ipc/ipc-bridge.ts:412-478`). Unexpected failures return `success: false` and `error: 'Internal error: ...'` (`:479-503`).
- `MessageRouterService` consumes `window` messages and expands `batch.payload.events` (`libs/frontend/core/src/lib/services/message-router.service.ts:110-121`, `:284-317`). RPC responses must remain unbatched (`:161-180`). The listener does not check `event.origin` (`:110-115`); keep the demo same-origin and use curated input only.

## 2. Boot handshake and gating

- VS Code injects `window.vscode` and `window.ptahConfig`, then sends `webview-ready` after 100 ms (`apps/ptah-extension-vscode/src/services/webview-html-generator.ts:446-505`). Electron preload defines the same API but has no ready message (`apps/ptah-electron/src/preload.ts:18-51`). The replay bridge therefore needs no ready handshake when it emulates Electron.
- Load `replay-bridge.js` before the inline theme script. Define `window.vscode` directly, plus `getState` and `setState`. Set `ptahConfig` with `isVSCode: false`, `isElectron: true`, `theme: 'dark'`, a synthetic workspace, relative icon URIs, `panelId`, `platform`, and `initialView`. These are the Electron fields (`apps/ptah-electron/src/preload.ts:35-51`). Also stub `ptahClipboard` if the scenario uses copy or voice.
- Seed state with `theme-v2` and optional `ptahRoute`. The route key is `WEBVIEW_ROUTE_STATE_KEY = 'ptahRoute'` (`libs/shared/src/lib/types/webview-route-state.ts:23`). Keep `setState` functional in memory; a pure no-op can break route and theme restoration.
- `initialView` takes precedence according to `resolveBootNavigation`; disabled initial navigation then performs one explicit navigation (`apps/ptah-extension-webview/src/app/initial-navigation.ts:34-47`, `:92-126`). Use `chat` or `command-center`. Command Center is Electron-only (`apps/ptah-extension-webview/src/app/app.routes.ts:203-217`).
- Routing is path-shaped but memory-backed, not hash-based. `MemoryPlatformLocation` avoids `file:` History API errors (`apps/ptah-extension-webview/src/app/app.config.ts:198-227`). The source base is `/`; Electron rewrites it to `./` (`apps/ptah-extension-webview/src/index.html:6`; `apps/ptah-electron/scripts/copy-renderer.js:174-183`). Use `<base href="/demo/">` for the hosted copy.
- Theme selection reads `window.vscode.getState()` before `localStorage`, then applies the Ptah glass default or a deferred theme sheet (`apps/ptah-extension-webview/src/index.html:37-59`, `:96-180`). Preserve this order in the bridge.
- Fonts use a Google CSS import for Inter, Cinzel, and JetBrains Mono (`apps/ptah-extension-webview/src/styles.css:7`). Icons are relative files under `images/`; the public source contains only three images (`apps/ptah-extension-webview/public/images/`). Worker assets are copied to `assets/pierre` and `assets/command-center` (`apps/ptah-extension-webview/project.json:18-32`).
- Electron CSP allows self scripts, inline styles, Google fonts, HTTPS/data/blob images, blob media, and self/blob workers (`apps/ptah-electron/scripts/copy-renderer.js:159-173`). VS Code CSP is similar but nonce-based (`apps/ptah-extension-vscode/src/services/webview-html-generator.ts:282-303`). Reuse the Electron source list for `/demo/`, with `frame-src 'self'` as needed.
- License state does not gate features. It populates the membership card only, and the old gating UI was removed (`libs/frontend/chat/src/lib/services/chat-store/chat-lifecycle.service.ts:80-90`). Production `isPremium` and `isCommunity` reads occur only in that card. No free-tier feature hiding needs reproduction.

## 3. Recorder design

### Tap and output

1. Tap in the Electron main process, not preload. `IpcBridge` sees both directions and preserves actual delivery order (`apps/ptah-electron/src/ipc/ipc-bridge.ts:185-220`, `:412-478`). Preload would add a second instrumentation path and would not explain batching decisions.
2. Record an accepted RPC request after sender validation. Capture `method`, `params`, and `correlationId` (`:413-463`). On reply, store `response.data` under `rpc[method]` for the scenario. Record failures separately as `{ success: false, error, errorCode? }`. The existing harness uses exactly direct response data and reconstructs the envelope (`libs/frontend/webview-e2e-harness/src/lib/scenarios/marketplace/marketplace.fixtures.ts:180-188`, `:238-243`).
3. Record host pushes at each actual `webContents.send('to-renderer', ...)`: ordinary pushes at `apps/ptah-electron/src/ipc/ipc-bridge.ts:219`, single and batched stream pushes at `:329-339`, and RPC responses at `:471-478`. Exclude `rpc:response` from the timeline because the bridge answers those on demand.
4. Use `performance.now()` relative to recorder start. Emit `{ rpc: { [method]: responseData }, timeline: [{ t, message }] }`. Keep actual `batch` envelopes and their order. `IpcBridge` flushes queued stream events before an RPC response (`:459-478`); the tap must preserve that boundary.
5. Record writes and params only in a local raw capture for debugging. Do not copy them into the publishable scenario unless a curated interaction requires them. Use one synthetic workspace and one session per scenario where possible. A method-only response map cannot distinguish different session IDs or pagination params.

### Sanitize and privacy gate

- Prefer a dedicated synthetic workspace, synthetic accounts, and public sample code. Automated redaction is not a substitute for this boundary.
- Allow-list RPC methods and push types. Drop credentials, auth fallback scripts, API-key status hints, account sign-in data, raw file reads, image/audio base64, and arbitrary terminal output.
- Replace home/workspace paths with `/workspace`. Keep only reviewed relative paths such as `src/example.ts`. Cover `cwd`, `workingDirectory`, `taskFolder`, `outputFilePath`, file links, and paths inside text.
- Replace emails, real names, usernames, account labels, hostnames, IP addresses, and URL credentials with fixed fixtures. Allow only required public hosts such as `ptah.live` and reviewed provider documentation URLs.
- Recursively redact secret-shaped fields with `isSecretFieldName()` and text with `redactSecrets()` (`apps/ptah-electron/src/services/diagnostics/log-redaction.ts:14-54`). Add JWT, GitHub, AWS, Slack, Anthropic, OpenAI, PEM, cookie, and connection-string patterns. The existing helper alone is insufficient for PII.
- Treat assistant text, tool results, diffs, compact summaries, and CLI output as file-content carriers. Replace them with curated text. Permit code only from an explicit public-file allow-list and review the final rendered scenario.
- Add a Jest privacy test that scans every published JSON string and key. Fail on emails, home paths, non-allow-listed hosts/IPs, credential field names, bearer/JWT/API-key shapes, PEM blocks, large base64 strings, and canary secrets inserted by sanitizer unit tests. Fail closed on unknown RPC methods, push types, or payload fields that the sanitizer does not understand.

### Ship gate

- Require all of: `!app.isPackaged`, `NODE_ENV === 'development'`, and `PTAH_REPLAY_RECORD=1`. Require an explicit local output path outside the served assets.
- Add `__PTAH_REPLAY_RECORDER__` to `apps/ptah-electron/esbuild.config.cjs`. Its existing `isProd` and `define` pattern is at `:52-71`. Define it as `false` for production and `true` only for development. Guard the recorder import and all tap calls with this constant so production minification removes them.
- Keep raw output outside `dist` and `public`. Run sanitization as a separate offline step. Add a production bundle assertion for the recorder marker if the implementation lane wants a final guard.

## 4. CI guard against protocol drift

Put scenario contracts and their Jest guard in **`libs/web/landing` (Nx project `web-landing`)**. It has `scope:web` and `type:feature` (`libs/web/landing/project.json:1-18`). `scope:web` may depend on `scope:shared` but not `scope:webview` or `scope:e2e` (`eslint.config.mjs:318-329`). Do not import the existing e2e harness into production code; copy its direct-data semantics instead.

Use two complementary checks:

1. **Runtime Jest validation:** parse every scenario JSON. Assert each `rpc` key is in `RPC_METHOD_NAMES` (`libs/shared/src/lib/types/rpc.types.ts:3686-3688`). Assert each timeline type is in `Object.values(MESSAGE_TYPES)` (`libs/shared/src/lib/types/messages/message-constants.ts:374-377`). Validate available Zod payloads and require nonnegative, monotonically ordered `t` values. `StrictMessageType` is not a validator because it ends in `| string` (`libs/shared/src/lib/types/messages/message-type.ts:9-109`).
2. **Generated TypeScript validation:** generate a `scenario.generated.ts` with the JSON as a const value and `satisfies ReplayScenario`. Define `ReplayScenario.rpc` as `{ [M in RpcMethodName]?: RpcMethodResult<M> }`. Define timeline messages from `MessagePayloadMap` (`libs/shared/src/lib/types/messages/payload-map.ts:337-513`). First add the missing streaming, stats, ID-resolution, and batch entries to that shared map; otherwise full payload validation has gaps. Run the normal `web-landing` typecheck over the generated file.

Keep the privacy test beside the same scenarios so one project check validates protocol and publication safety. The recorder's own sanitizer unit tests belong in `ptah-electron`.

## 6. Nx boundaries and deployment

- `ptah-landing-page`: `scope:landing`, `type:app` (`apps/ptah-landing-page/project.json:7`). Every `libs/web/*`: `scope:web`; `web-landing` is `type:feature`. `ptah-extension-webview`: `scope:webview`, `type:app` (`apps/ptah-extension-webview/project.json:7`). `libs/shared`: `scope:shared`, `type:util`.
- Landing may import shared, web, and API contracts, not webview (`eslint.config.mjs:306-329`). Keep the bridge and scenario runtime free of `@ptah-extension/*` webview imports. Ship the compiled webview as opaque static assets.
- A build-time copy does not violate the source-import rule. Add `ptah-extension-webview:build` to the landing build's `dependsOn`, then copy `dist/apps/ptah-extension-webview/browser` into an asset output such as `/demo`. Angular assets currently copy only `apps/ptah-landing-page/public` (`apps/ptah-landing-page/project.json:13-27`). Electron and VS Code already use explicit cross-app build dependencies and copy steps (`apps/ptah-electron/project.json:327-344`; `apps/ptah-extension-vscode/project.json:99-115`).
- Patch the copied HTML to `<base href="/demo/">` and inject the bridge before the theme script. Do not serve the raw source index with `<base href="/">`. Keep webview lazy chunks and worker assets in the same tree.
- Production landing deployment is DigitalOcean App Platform static hosting, not the Caddy service. The workflow builds and deploys through `.do/app.yaml` (`.github/workflows/deploy-landing.yml:54-55`, `:82-90`). The spec publishes `dist/ptah-landing-page/browser` and uses `index.csr.html` only as the SPA catchall (`.do/app.yaml:48-64`). Caddy serves only `api.ptah.live` (`caddy/Caddyfile:11-28`; `docker-compose.prod.yml:93-121`).
- `/demo/` can therefore ship as static files. Same-origin iframe loading needs no CORS headers. Do not send `X-Frame-Options: DENY`; use no XFO or `SAMEORIGIN`. If required, set `Content-Security-Policy: frame-ancestors 'self'` as a response header. It does not work in a meta tag (`apps/ptah-electron/scripts/copy-renderer.js:137-139`, `:157-158`). The current App Platform spec shows no custom-header mechanism, so verify platform support before relying on per-path headers.
- Webview production uses `outputHashing: "none"` (`apps/ptah-extension-webview/project.json:61-77`). Use revalidation/no-cache for its HTML, JS, CSS, and scenario JSON. Do not apply landing-style immutable caching to those files.

## 7. Risks

- **Scenario identity:** one method-only response cannot answer different sessions, workspaces, or pages. Curate one identity per scenario or add params-aware rules before recording complex histories.
- **Ordering:** stream batches, RPC responses, `session:id-resolved`, turn-state events, and agent-child opens must share consistent tab/session IDs. RPC responses must not enter `batch`.
- **Boot redirect:** a missing or unauthenticated `auth:getAuthStatus` answer sends the demo to settings instead of chat.
- **Tribunal drift:** the old standalone Tribunal view no longer exists. A scenario that navigates to it silently lands on chat.
- **Incomplete payload authority:** `MessagePayloadMap` omits several active streaming messages, and `StrictMessageType` accepts any string. A names-only test would give false confidence.
- **Privacy:** transcripts, diffs, paths, CLI output, account metadata, and license identity can all leak PII or secrets. Use synthetic source data plus fail-closed sanitization and human review.
- **Electron emulation:** `isElectron: true` enables boot RPCs, display-window state, updates, Command Center, and synchronous state behavior. An incomplete bridge produces timeouts or a blank shell.
- **Document order:** the bridge must exist before the pre-paint theme script reads `window.vscode.getState()`. The wrong base href also breaks every lazy chunk and worker URL.
- **Browser policy:** external fonts, blob workers/media, frame headers, and cache policy need browser validation. Do not add COOP/COEP without testing Google fonts and workers.
- **Bundle cost:** the production initial budget allows 4 MB, before lazy surfaces (`apps/ptah-extension-webview/project.json:63-73`). Mobile should use the recorded fallback rather than download and execute the full app.
- **Video determinism:** the existing showcase launcher intentionally runs real providers and no mocks. It needs a replay adapter before it can render identical scenario videos.
- **Deployment headers:** App Platform static hosting is proven, but per-path security and cache headers are not configured in the repository. Confirm this capability before the design depends on it.
