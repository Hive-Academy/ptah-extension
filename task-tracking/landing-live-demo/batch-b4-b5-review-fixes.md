## Finding → Change → Test Mapping

| Finding | Change | Test Coverage |
| --- | --- | --- |
| **M1** (`__PTAH_REPLAY_RECORDER__` fails open on non-`production` `NODE_ENV`; production bundle unverified) | Updated `apps/ptah-electron/esbuild.config.cjs` so `__PTAH_REPLAY_RECORDER__` defaults to `'false'` and is `'true'` only when `!isProd && process.env.NODE_ENV === 'development' && process.env.PTAH_REPLAY_RECORDER_BUILD === '1'`. Added Step 2b in `apps/ptah-electron/scripts/validate-deps.js` asserting that `dist/apps/ptah-electron/main.mjs` contains none of `PTAH_REPLAY_RECORD`, `__PTAH_REPLAY_RECORDER__`, `createReplayRecorderIfEnabled`, or `ReplayRecorder`. | `replay-recorder.spec.ts` (`M1: build-time define gate and production bundle tree-shaking assertion`): tests all env combinations for `esbuild.config.cjs`, runs `esbuild.build` with the production define over `ipc-bridge.ts` verifying zero recorder strings/symbols survive, and verifies `validate-deps.js` includes the gate. |
| **B1** (Recorder failures in `IpcBridge` can send a duplicate `rpc:response` or abort `dispose()` before `ipcMain.removeAllListeners`) | Added non-throwing `tapReplayRecorder(recorder, fn)` in `replay-recorder.ts` and wrapped every tap call in `ipc-bridge.ts` (including `flush()` in `dispose()`). Made `ReplayRecorder` methods (`recordRpcCall`, `recordRpcResult`, `recordPush`, `flush`) catch internal/serialization/write errors, log once via `console.warn`, and permanently disable the recorder instance. Added cycle detection to `stableSerialize`, fail-fast JSON cloning on circular structures, and capped `pendingCalls` at `1000`. | `replay-recorder.spec.ts` (`B1: failure isolation — recorder errors never change bridge behavior`): verifies cyclic RPC responses send only one `rpc:response`, log once, and disable the recorder; verifies `writeFile` throwing inside `bridge.dispose()` does not throw and removes all `ipcMain` listeners/handlers. |
| **R1** (Non-atomic `writeFileSync` and O(n²) deep-clone + full timeline re-serialization every 250 ms) | Added `atomicWriteFileSync` (`${filePath}.tmp` + `renameSync`), raised `DEFAULT_FLUSH_DEBOUNCE_MS` to `2000` ms, added a soft cap (`DEFAULT_MAX_TIMELINE_ENTRIES = 10_000`) with a one-time warning, and stored pre-serialized JSON strings per timeline entry on `recordPush` so `flush()` assembles the output incrementally without deep-cloning or re-serializing timeline entries. | `replay-recorder.spec.ts` (`R1: atomic writes and incremental pre-serialized flush`): verifies `.tmp` + rename atomic writes, 2000 ms default debounce, and `toJSON` call-count proof that timeline entries are serialized once on `recordPush` and reused across flushes. |
| **S1** (`scanScenarioPrivacy` in `scenario-sanitizer.ts` was weaker than B2 `libs/web/landing/src/lib/live-demo/scenario/privacy-scan.ts`) | Aligned `scanScenarioPrivacy` and `sanitizeScenario` in `scenario-sanitizer.ts` with all B2 rules: plain-text credential assignments (`password=`, `token:`, `api_key=`, `client_secret=`, `private_key=`, `auth=`) with placeholder exemptions, all token prefixes (`github_pat_`, `ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`, `glpat-`, `xox*`, `sk-ant-`, `sk-proj-`, `AIza`, `npm_`, `hf_`, `AKIA`, `ASIA`), home paths (`~/`, `/root`, `/var/folders/`, `C:/Users/`, `C:\Users\`), Windows & bracket/comma/brace-delimited paths, generic hostnames in URL/`@`/`//` contexts plus `.internal`/`.local`/`.corp`/`.sh`/`.cloud`/`.me`/`.tech`, and private IPv4 vs version context. | `scenario-sanitizer.spec.ts` (`S1: privacy scan parity with B2 contract scanner over shared canary list`): runs 39 shared canary cases through both `scanScenarioPrivacy` and `sanitizeScenario`, plus placeholder and version-string exemptions. |
| **S2** (Encoded/escaped values bypass privacy scan and sanitization) | Added bounded decode-before-scan and decode-before-sanitize passes in `scenario-sanitizer.ts` (`MAX_DECODE_DEPTH = 4`) for: (1) nested JSON strings (`JSON.parse` + recursive visit/sanitize), (2) URL-encoded strings (`safeDecodeURIComponent`), (3) escaped backslashes (`C:\\Users\\...`), and (4) base64/base64url segments ≥ 40 chars that decode to printable UTF-8 ASCII text (`tryDecodePrintableBase64`). | `scenario-sanitizer.spec.ts` (`S2: decode-before-scan and sanitization for nested JSON, URL encoding, escaped backslashes, and base64 >= 40 chars`): tests both `scanScenarioPrivacy` detection and `sanitizeScenario` scrubbing across all 4 encoding vectors. |
| **S3** (`tool_result` and CLI output array/object content bypassed placeholder replacement) | Updated `tool_result` (`output`, `result`, `content`, `stdout`, `stderr`), CLI output (`agent-monitor:output`, `session:cli-output-page`), `tool_start` input content, diff, and file content rules to replace non-allow-listed arrays (e.g. `[{type:'text', text}]`) and objects with their respective placeholders (`PLACEHOLDER_TOOL_OUTPUT`, `PLACEHOLDER_CLI_OUTPUT`, etc.), while recursing and sanitizing when allow-listed. | `scenario-sanitizer.spec.ts` (`S3: array and object tool_result / CLI output replacement`): tests array and object `tool_result` and CLI output replacement for both blocked and allow-listed files. |
| **Minor (CLI & key paths)** (CLI allowed `--in` equal to `--out`, wrote non-atomically, and `redactedFields` recorded unsanitized key paths) | Updated `sanitize-replay-scenario.mjs` to refuse resolved `--in === --out`, write atomically via `${resolvedOut}.tmp` + `renameSync`, catch top-level errors without echoing raw content, and emit only sanitized key paths in `redactedFields`. | `scenario-sanitizer.spec.ts` (`CLI script (sanitize-replay-scenario.mjs)`): verifies `--in === --out` rejection, atomic write without leftover `.tmp`, and secret redaction inside object keys in `report.redactedFields`. |
