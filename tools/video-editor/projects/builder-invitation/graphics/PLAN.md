## The argument, in English

1. **0:00–0:44** — Ask any developer: shipping an MVP with AI coding tools is
   not the same as following the software development life cycle. If you do not
   understand the life cycle end to end, you do not get quality, and you do not
   get long-term maintainability.
2. **0:44–1:21** — A real company does design, requirements and planning first.
   MVP, then proof of concept, then an architecture that is scalable and
   maintainable. Design is not only UI and UX. Many decisions need someone who
   understands software development. An AI-generated MVP is not a scalable app.
3. **1:22–2:14** — This is not a claim that AI output is low quality. With the
   right workflow and the right agentic harness it is good. The invitation: two
   weeks, build a SaaS application together, share the experience.
4. **2:14–3:14** — Someone who understands the life cycle applies it, and AI
   gets them to the output faster while they stay aware of the technical depth.
   Join from installation, providers, subscriptions, design, planning.
5. **3:14–4:13** — Architecture that stays consistent, versus vibe-coded apps
   that reach a point where quality degrades and technical debt goes out of
   hand. Totally free. Start with the Electron app. VS Code extension and CLI
   also exist. All open source. Builders community.
6. **4:38–5:33** — Free for 25 days. Workshops plus the code. The real-estate
   SaaS: authentication, multi-tenancy, domain-driven design, payment, billing.
   Vibe-coding tools hide the life cycle; the bill arrives a year later as
   scaling problems and developer turnover. Focus: the TypeScript stack.
7. **5:34–6:04** — .NET and Python developers can contribute their communities'
   principles and best practices to the open-source application.
8. **6:04–6:30** — Live: download and install the desktop app. The publisher is
   registered, the code is signed, so the warning stops appearing.
9. **6:30–8:34** — Providers and settings. Claude Code as the main provider,
   plus Codex and Antigravity. One harness shared across every provider.
   Workspace analysis. Scaffold a new project. The tribunal.
10. **8:34–9:27** — Workspace analysis does a deep read of the project: stack,
    frameworks, design patterns. It then generates coding agents per provider,
    plus connectors and MCP servers.
11. **9:28–10:08** — Memory, indexed memory, AST and tree-sitter, graph memory,
    RAG, so the agent can reach into a large codebase. The workspace: CLI,
    React app, Astro docs, Electron app, VS Code extension, landing page,
    license server, Remotion pipeline.
12. **10:09–10:43** — One workspace, shared across all of it. Memories per
    domain. A task management system the agents can read.
13. **10:44–11:36** — The canvas: several sessions at once, session history, and
    a clear view of agent execution. Build your own harness and sub-agents.
14. **11:35–12:17** — The main agent runs on Claude. Hit a limit, move the same
    session to Codex or Antigravity. Same orchestration. That is one layer.
15. **12:17–12:37** — The other layer is context: the agent understands the
    business and knows where to look. Then orchestration is a given.
16. **12:38–13:07** — Join, share the experience, show how software developers
    ship something different from vibe-coded tools, cut through the hype.
17. **13:08–13:38** — No application ever reaches perfection. There is always
    technical debt. Our duty is to teach people what debt is, so they invest in
    something that lasts — so that after the MVP and its validation they can
    hand it to a good developer who builds on it instead of starting over.

## Render contract for every overlay

- `data-fps="60"` on the composition root in `index.html`. HyperFrames
  **silently defaults to 30** and a 30 fps overlay on this 60 fps timeline
  throws away half the smoothness the rebuild bought. `scripts/render-overlay.sh`
  now asserts the rendered rate and the alpha channel, and fails loudly.
- Pass `render-overlay.sh` an ABSOLUTE output path, or let it default. The
  script resolves both paths before the render changes directory; a relative
  path used to resolve twice and land in a nested `projects/...` tree.
- ProRes 4444 at 1080p60 costs about **43 MB per second**. G07 is 1.2 GB for
  28 s. Budget roughly 12-15 GB for all 19. `renders/` is gitignored.

## Design constraints

1. **Amber must not sit on the orange wall.** The A-roll background is orange
   and `amber #f5a524` sinks into it. Over A-roll: place right of frame, lead
   with `emerald #34d399`, or sit the graphic on a near-black card with real
   elevation. Over B-roll there is no conflict.
2. **English text over Arabic speech.** Card text must be short enough to read
   without competing with a language the viewer is already listening to.
   Maximum two lines, maximum six words per line.
3. **No `[innerHTML]` equivalent shortcuts.** Every composition is authored, not
   templated from the transcript.
4. **Renders are MOV with alpha**, imported to video track 2. One composition
   per beat, under `graphics/<beat-id>/`. Never one long composition.

## Captions — Arabic (decided)

- Source: `transcript/words.json`, WhisperX word-level, Arabic, forced-aligned.
- Font: **IBM Plex Sans Arabic**, paired with Inter for the English graphics.
  Inter carries no Arabic glyphs, so the brand font cannot set captions.
- Direction: right-to-left, with bidirectional runs for embedded Latin terms
  (`Claude Code`, `MCP`, `TypeScript`). Latin runs render left-to-right inside
  the RTL line. Getting this wrong reverses words — verify every mixed line.
- Position: bottom band. Reserve the lower 15% of frame across the whole video.
  Graphics may not enter it.
- Collision: the webcam picture-in-picture occupies roughly the left 22% and
  bottom 35% of every B-roll frame. Centered captions clear it, but the margin
  is tight. Check each B-roll caption against the PiP.

### Transliteration cleanup (required before captions ship)

WhisperX wrote English technical terms in Arabic script, phonetically. Arabic
technical writing keeps those terms in Latin. Uncleaned captions will read as
broken to the target audience.

Known cases so far: `الاركتكتشر` → architecture, `بايب كودد` → vibe-coded,
`التكنيكال ديبت` → technical debt, `work of law` → workflow, `Long Term
Inability` → long-term maintainability, `توتالي فريه` → totally free,
`سيل اي تول` → CLI tool, `الكوميونيتي` → community, `اوركستريشن` →
orchestration, `ديجريديشن` → degradation.

Approach: build a term dictionary from the repository's own vocabulary, apply
it over the word list while preserving each word's timing, then review the
remainder by hand. 1832 words total.

## Sound — decided

- **No music bed.**
- Sound effects are attached to the graphics, one per animated beat.
- Preferred: bake the audio into each graphic's MOV render, so sound cannot
  drift from the animation it belongs to. Confirm HyperFrames writes audio into
  an alpha MOV. Fallback: a matching WAV per graphic placed on audio track 2 at
  the same frame.
