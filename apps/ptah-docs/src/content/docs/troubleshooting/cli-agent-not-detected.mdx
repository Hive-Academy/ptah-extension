Ptah can run several agent CLIs as lanes: Codex, Copilot, Cursor, Antigravity, OpenCode, Pi, Grok, and Claude. A CLI must be installed and on the `PATH` before Ptah can use it.

## Quick check

Open **Settings → Providers** and find the **CLI agents** matrix. The **Status** column shows if Ptah found each CLI. For a CLI that is not found, the row has an install guide.

After you install a CLI, click the retry action in its row. If Ptah shows **Still not found. Check the step above, then try again.**, quit Ptah fully and start it again.

## Common problems

**Symptom:** The CLI works in a terminal, but Ptah does not find it (macOS or Linux).
**Likely cause:** An app that starts from the dock or the desktop gets a short `PATH`. Ptah runs your login shell to read the full `PATH`, and it adds common npm global folders.
**Fix:** Put the install folder of the CLI on the `PATH` in your login shell profile, for example `~/.zprofile` or `~/.profile`. Then start Ptah again.

---

**Symptom:** The CLI works in a terminal, but Ptah does not find it (Windows).
**Likely cause:** The install folder is not on the `PATH` of your user account.
**Fix:** Add the folder in **System Properties → Environment Variables → Path**. Then start Ptah again. Run `where <cli>` in PowerShell to find the folder.

<Aside type="tip">
If you use a Node version manager (nvm-windows, fnm), install global CLIs again after you change the Node version. Each Node version has its own global packages.
</Aside>

---

**Symptom:** Ptah finds the CLI, but the first request fails with "authentication required".
**Likely cause:** The CLI has not done its own sign-in.
**Fix:** Run the sign-in command of the CLI once in a terminal, for example `codex login`. Then try again in Ptah.

---

**Symptom:** Ptah finds the CLI, but it uses the wrong account.
**Likely cause:** Another tool changed the credential file of the CLI.
**Fix:** Run the sign-in command of the CLI again. Each CLI keeps its credentials apart from Ptah.

---

**Symptom:** Ptah finds the CLI, but never uses it.
**Likely cause:** The CLI type is in `agentOrchestration.disabledClis`.
**Fix:** Remove it from that list in `~/.ptah/settings.json`. See [Ptah CLI](/providers/ptah-cli/#turn-off-a-cli).
