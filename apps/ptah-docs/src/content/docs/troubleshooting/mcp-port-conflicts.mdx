The built-in MCP server of Ptah listens on `localhost`, TCP port **51820** by default. If Ptah cannot bind that port, it tries the next two ports (51821 and 51822). Agents that Ptah starts get the port that Ptah actually uses.

## Symptoms

**Symptom:** The startup log shows that port 51820 was not available and that Ptah uses another port.
**Likely cause:** Another program uses the port. With `EADDRINUSE`, this is often a second Ptah instance. With `EACCES` on Windows, the OS reserved the port (a Hyper-V or WinNAT excluded port range).
**Fix:** No action is necessary. The fallback port works. If you need a stable port for an external client, set a different port.

---

**Symptom:** The log shows `No fallback port left - the MCP server did not start.`
**Likely cause:** All three ports are in use or reserved.
**Fix:** Set a different port, then restart Ptah.

---

**Symptom:** An external MCP client cannot connect.
**Likely cause:** The client uses `51820`, but Ptah uses a fallback port.
**Fix:** Set a free, stable port in Ptah and in the client.

## Set the port

1. Open **Settings → Advanced**.
2. Find the MCP port setting and type a free port.
3. Save. Restart Ptah to use the new port.

To find out which program uses a port:

```bash
# Windows
netstat -ano | findstr :51820

# macOS / Linux
lsof -iTCP:51820 -sTCP:LISTEN
```

On Windows, show the reserved port ranges with:

```bash
netsh interface ipv4 show excludedportrange protocol=tcp
```

<Aside type="tip">
External MCP callers (Claude Code, Cursor, Codex, Antigravity) have read-only access by default. Change this with the external caller access setting in **Settings → Advanced** (`mcp.externalCallerAccess`).
</Aside>
