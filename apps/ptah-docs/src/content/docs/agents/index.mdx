# Agents in PtahCode

Agents are specialized AI workers that PtahCode coordinates for you. Each agent has a focused role, such as backend code, UI review, or research, and a system prompt for that role.

![Agents overview](/screenshots/agents-overview.png)

## The 14 built-in agents

PtahCode has 14 agent templates. The [setup wizard](/setup/setup-wizard/) analyzes your project and writes the agents that apply to it into `.claude/agents/`.

## How agents fit together

PtahCode uses a three-tier orchestration model:

1. **Orchestrator** — the top-level agent that plans, decomposes, and delegates.
2. **Senior leads** — specialists (architect, backend-dev, reviewer, etc.) spawned as sub-agents.
3. **CLI lanes** — installed CLIs or configured Ptah CLI providers assigned focused sub-tasks or whole phases. Running every phase on a lane is [Relay](/tribunal/relay/), requested through the `tribunal` skill in main chat.

The orchestrator spawns sub-agents and phase or batch executors. The team-leader recommends executors and records batch state, but spawns nothing. `visual-reviewer` and `ui-ux-designer` also do not delegate to CLI lanes. Specialists report evidence without editing `task.md` or `batches.md`.

:::tip[When to use what]

- **One-off question** → chat directly with the default agent.
- **Multi-step feature** → let the orchestrator delegate to senior leads.
- **Wide, parallel exploration** → use CLI lanes (three concurrent by default in the workflow; the runtime limit is configured separately).
  :::

Enable the `agent-lanes` skill for CLI work through `orchestration` or `tribunal`. A dependent skill names what to enable when a requirement is missing. Read more in [Agent orchestration](/agents/agent-orchestration/).

## Where agents are stored

Agents are stored for each workspace in:

```
<workspace-root>/.claude/agents/
```

Each agent is a Markdown file with YAML frontmatter and a system prompt. Edit these files directly. Refer to [Custom agents](/agents/custom-agents/).
