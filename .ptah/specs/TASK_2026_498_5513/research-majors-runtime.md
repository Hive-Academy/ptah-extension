# Research Report — TASK_2026_498 — Runtime-package major/minor upgrade audit

Audit only. No files edited outside this report.

## Method note

- **Report date**: 2026-09-21 (Pre-migration baseline snapshot)
- **Baseline commit / lockfile state**: measured against `d5d1a6bd73bd40742a209c677f0e348176acda83` / `9ced6498e` (pre-migration branch state prior to dependency upgrades landing). Package versions and audit findings recorded herein represent this pre-migration baseline.

For every package: (1) diffed `npm view <pkg>@<current>` vs `@<target>` for
`type`, `exports`, `engines`; (2) grepped `libs/` and `apps/` for every import
site and read the call signatures used; (3) cross-referenced the breaking-change
source against those exact symbols; (4) checked Node 24.15.0 (installed) against
`engines`; (5) checked ESM-only vs CJS-consumer risk the way the sanitize-html /
htmlparser2 precedent (TASK_2026_498 context) requires.

Repo-wide facts used below: root `package.json` has no `"type"` field (default
CommonJS at the repo root); `apps/ptah-cli` and `apps/ptah-electron` bundle with
esbuild to **ESM** output (`main.mjs`) with a `createRequire` banner, so a
`require('x')` call inside those bundles is Node's real `require` at runtime —
which, on Node ≥22.12 (we are on 24.15.0), CAN synchronously load an ESM-only
package. **Jest is the exception**: every `jest.config.*` in this repo uses
`ts-jest` with no `transformIgnorePatterns`/ESM opt-in, so Jest's own
CommonJS module loader (not Node's native loader) handles `node_modules`
requires, and it does **not** support loading an ESM-only package the way Node
24 does. This is the exact class of defect the task names for sanitize-html.

## NEEDS-CHANGE summary (exact edits required)

- **commander 14→15**: Reclassified to SAFE. `apps/ptah-cli/src/cli/commands/harness.spec.ts:62` uses a type-only import (`import type { GlobalOptions } from '../router.js'`), so `ts-jest` strips it and does not load `router.ts` or its runtime `commander` dependency during tests. - **uuid 11→14**: Reclassified to DROP-IN on Node ≥24.9. `libs/backend/agent-sdk`, `libs/backend/cli-agent-runtime`, and `libs/shared` build targets emit CJS (`format: ['cjs']`), while `libs/frontend/chat-state` has no library build target and runs tests with `jest-preset-angular` (not `ts-jest`). Test or build failure risk is scoped to runtimes prior to Node 24.9 lacking synchronous `require(esm)`.

- **gridstack 12→13**: `libs/frontend/canvas/src/lib/canvas-workspace-grid.component.ts` and `libs/frontend/tribunal-panel/src/lib/tribunal-page.component.ts` use direct static `<gridstack>` and `<gridstack-item [options]="...">` template elements rather than dynamic `selector`/`input` registration APIs. Concrete migration work is limited to type-only import changes (e.g., `nodesCB` / `elementCB`) and updating Jest test stubs (`test-gridstack-stub.ts`, `canvas-workspace-grid.component.spec.ts`).
