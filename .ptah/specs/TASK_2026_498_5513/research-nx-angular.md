# Research Report - TASK_2026_498

## Question

- Decision this supports: the exact command sequence and ordering for migrating this workspace from Nx 22.6.5 / Angular 21.2.6 to Nx 23.2.1 / Angular 22.1.7.
- Question: what is the correct, verified migration path and order, and what breaks along the way in this specific repo.
- Bounds: does not cover `libs/api/**` (NestJS/Prisma, unaffected by this migration), does not re-verify every one of the 90 projects' `project.json` files (3 representative ones read), does not execute the migration — this is a pre-flight report only. No source file or `package.json` was changed.

## Answer

Run `nx migrate` for both hops (22.6.5 → latest-22.x → 23.2.1); it drives the Angular 21→22 upgrade too via `@nx/angular`'s bundled migrations, so a separate `ng update` is not required and should not be run. The hard blocker found by direct inspection, not by any blog post, is TypeScript: `@angular/compiler-cli@22.1.7` and `ng-packagr@22.1.1` both peer-pin `typescript: ">=6.0 <6.1"`, so this repo's current `typescript@5.9.3` must go up to `6.0.x` (not the installed-latest `7.0.2`, which both Angular 22 and Nx 23 explicitly do not support) before or during the Angular hop. `jest@^30` and `eslint@9.39.4` + `typescript-eslint@8.59.4`, already in this repo, already satisfy jest-preset-angular 17's and angular-eslint 22's peer ranges, so those two are not blockers.

## Options

Not a multi-option comparison — this is a single prescribed upgrade path. The only real "option" is ordering/batching, covered under Answer and the command sequence below.

## Disagreements

- Whether `nx migrate` alone is sufficient vs. needing `ng update`: the Nx docs page for `@nx/angular` migrations states Nx migrations update Angular packages directly and does not instruct running `ng update` afterward; general Angular-ecosystem blog posts (not Nx-specific, e.g. devm.io/bacancytechnology summaries found in search) describe `ng update` as _the_ Angular upgrade tool without mentioning Nx at all. In an Nx workspace the two are not run side-by-side for the framework bump — `nx migrate` is authoritative here because `@nx/angular` ships and runs the same generators `ng update` would invoke, scoped to Nx's workspace shape. Running `ng update` afterward risks re-touching files `nx migrate` already normalized and is explicitly _not_ the recommended path for Nx workspaces.
- TypeScript ceiling: the prompt's framing ("does Angular 22/Nx 23 support TypeScript 7.0.2, or cap at 5.9.x") turned out to be neither exactly — the verified peer range is `>=6.0 <6.1`, a narrower band than 5.9.x and one version short of the installed `latest` (7.0.2). Generic upgrade-guide blog posts found in search paraphrase this as "Angular 22 requires TypeScript 6.0" without stating the `<6.1` upper bound; the upper bound only surfaced from the registry `peerDependencies` read directly, which is what gates the later TS-7 migration wave this task is presumably sequencing against.

## Local consequences

- `package.json`: `nx` and all nine `@nx/*` packages (`angular`, `esbuild`, `eslint`, `eslint-plugin`, `jest`, `js`, `node`, `web`, `workspace`) move together to `23.2.1` — `nx migrate` keeps these in lockstep; do not hand-bump a subset.
- `package.json` `optionalDependencies`: the five `@nx/nx-{darwin-arm64,darwin-x64,linux-arm64-gnu,linux-x64-gnu,linux-x64-musl}` entries are generated by `nx migrate`'s own package.json rewrite alongside the main `nx` version bump (same mechanism used for the current `22.6.5` pins) — no separate hand-edit is expected, but the `--include=optional` npm install flag matters in CI/Docker if that pipeline uses `npm ci` with default optional-dependency skipping (this repo's own `npm run docker:db:start` / CI config was not inspected for that flag — see Unknowns).
- `package.json`: `@angular/build`, `@angular/cdk`, `@angular/cdk-experimental`, `@angular/ssr`, `@angular/youtube-player`, `@angular/compiler-cli`, `@angular-devkit/core`, `@angular-devkit/schematics`, `@schematics/angular`, `ng-packagr`, `angular-eslint`, `jest-preset-angular`, `ngx-markdown`, `ngx-monaco-editor-v2` all need coordinated version bumps to their Angular-22-compatible releases (22.1.8 / 21.2.4-or-22-equiv / ~22.x / 22.5.0 / 17.0.0 / 22.0.2 / 22.0.5 respectively) — `nx migrate --run-migrations` for the Angular hop is expected to propose these; verify each one landed rather than assuming full coverage, since third-party libs (`ngx-markdown`, `ngx-monaco-editor-v2`) are not part of Nx's own migration generator set and may need manual `npm install <pkg>@latest` after the Nx-driven core bump.

No forced zoneless migration for this app.
- Zoneless libs (the rest of `libs/frontend/*`): Angular 22 declares the zoneless path "stable" but does not force it; this repo's mixed Zone/zoneless setup needs no immediate change for this specific version bump — re-verify signal/OnPush-only libraries build clean under the new compiler, since Angular 22's default-`OnPush`-when-unset behavior change could alter previously-implicit change detection in any component that omitted `changeDetection` (search below).

- `nx.json` `plugins` array (currently only `@nx/eslint/plugin`) is a likely target for the Nx-23 `convert-to-inferred` codemod to _add_ entries for `@nx/jest`, `@nx/esbuild`, and `@nx/angular` build/test inference if this repo opts into fuller Crystal adoption — but per the executors already declared in `project.json` files (`@angular/build:application`, `@nx/esbuild:esbuild`, `@nx/jest:jest`), Nx 23 does not force this conversion; it deprecates the executors on a slower timeline, so `nx migrate --run-migrations` alone should not silently rewrite every `project.json`'s executor to an inferred target unless a specific migration script for one of these plugins does so — treat this as a per-migration-step review item, not an assumption.

## Copy-pasteable command sequence

Run from `D:\projects\ptah-extension`, one step at a time, committing after each successful step so a bad step is easy to isolate/revert. Do this in a disposable branch off `chore/task-498-dependency-migration`, not directly on `main`.

```bash
# 0. Baseline safety
git status
git checkout -b chore/task-498-nx23-angular22-migration

# 1. First hop: land on the newest Nx 22.x release before crossing the major.
#    (Confirm the exact newest 22.x patch/minor at execution time — do not hardcode 22.6.5 twice.)
npx nx migrate latest --to=nx@22   # or the explicit newest 22.x, e.g. nx@22.<latest>
npx nx migrate --run-migrations
npm install
npx nx run-many -t typecheck
git add -A && git commit -m "chore(nx): land on latest Nx 22.x before crossing to Nx 23"

# 2. Second hop: Nx 22.x -> Nx 23.2.1. This migration set is expected to also
#    bump the Angular 21 -> 22 packages via @nx/angular's own migrations —
#    do NOT run `ng update` separately.
npx nx migrate 23.2.1
# Review migrations.json before running — check it proposes @angular/* bumps,
# ng-packagr, angular-eslint, and the TypeScript floor.
npx nx migrate --run-migrations
npm install
git add -A && git commit -m "chore(nx): migrate to Nx 23.2.1 (incl. Angular 21->22 via @nx/angular migrations)"

# 3. TypeScript: verify/force the peer-required 6.0.x band (>=6.0 <6.1) —
#    do NOT let this drift to the registry "latest" (7.0.2), which neither
#    Angular 22 nor Nx 23 support yet.
npm view typescript@6 version   # confirm current 6.0.x patch
npm install --save-dev typescript@6.0.3
npx tsc --version

# 4. Third-party Angular-ecosystem libs not covered by Nx's own migration
#    generators — bump explicitly and verify peer ranges resolve cleanly.
npm install ngx-markdown@22.0.2 ngx-monaco-editor-v2@22.0.5 jest-preset-angular@17.0.0
npm ls marked   # confirm it satisfies ngx-markdown@22's "^17.0.0 || ^18.0.0"

# 5. Confirm the 5 @nx/nx-<platform> optionalDependencies were rewritten to
#    23.2.1 by step 2's package.json update; if any environment (CI/Docker)
#    uses `npm ci` with default optional-dep skipping, use:
npm install --include=optional

# 6. Full verification sweep.
npx nx reset   # after project.json-touching migrations, before trusting targets
npx nx run-many -t lint
npx nx run-many -t typecheck
npx nx run-many -t build
npx nx run-many -t test
```

- `migrations.json` — created by `nx migrate`, transient, safe to delete after `--run-migrations` completes and is committed.
- Individual `apps/*/project.json` and `libs/**/project.json` — only if a specific 22→23 migration script targets an executor this repo still declares explicitly (e.g., an Angular build target option rename); the three files read here (`ptah-extension-webview`, `platform-core`, `chat`) show no obviously-deprecated executor keys, but every `project.json` using `@angular/build:application`, `@nx/esbuild:esbuild`, `@nx/jest:jest`, or `@nx/angular:ng-packagr-lite` should be diffed after the run.
