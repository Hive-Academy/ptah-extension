# Codex runtime unpin research

Decision served: select installed `codex` on every OS when its version meets a minimum, otherwise use the bundled binary. Options are retain exact pin/gates, replace with minimum-version selection (task objective), or accept any executable. This maps current code; it does not set the threshold. Citations are repository-relative `file:line`. **Verified** means direct source inspection; **inferred** marks a consequence. No external sources were needed.

## 5. Installed CLI discovery and version probing

- **Verified:** `libs/backend/agent-sdk/src/lib/detector/codex-native-binary-path.ts:18-25,85-189` knows six platform packages and probes packaged `app.asar.unpacked`, `require.resolve` platform/CLI packages, Windows `%APPDATA%/npm`, Unix `/usr/local/lib`, `/usr/lib`, `~/.npm-global`, NVM for the running Node version, and paths relative to an optional detected CLI path. - **Verified:** `libs/backend/cli-agent-runtime/src/lib/cli-agents/cli-adapters/cli-adapter.utils.ts:81-90` offers `resolveCliPath` using `which`, `:369-405` offers `probeCliVersion` (best-effort, 5-second default), and `:681-740` resolves npm `.cmd` wrappers to target/Node for spawn. `fix-path.ts:9-95` repairs GUI PATH including common macOS paths. `libs/backend/cli-agent-runtime/src/lib/cli-agents/cli-adapters/codex/codex-native-binary.ts:34-64` can map a detected CLI path to native platform binary/version. **Inferred:** these are building blocks, not an existing installed-first Codex selector. - **Verified:** Electron uses real `execFile(path,['--version'])` at `apps/ptah-electron/src/di/codex-runtime-composition.ts:210-216`; default lane probe uses real `probeCliVersion` at `libs/backend/cli-agent-runtime/src/lib/cli-agents/cli-adapters/codex/codex-app-server-lane-binary.ts:59-66`. `libs/backend/codex-runtime/src/lib/codex-executable-inspection.ts:119-124` *synthesizes* `codex-cli ${pin.pinnedVersion}` if no reader is passed; CLI engine passes none (`libs/backend/cli-engine/src/lib/codex-lane-runtime-composition.ts:166,205`). **Inferred:** synthetic version cannot prove a minimum-version check.

## Decisions

- **Research classification:** TS pin is the runtime source; JSON is offline evidence. Alternatives: JSON drives runtime vs TS drives runtime. Evidence: `libs/backend/codex-runtime/src/lib/codex-executable-pin.ts:2,23` imports TS data. Reversible: yes if future code loads JSON.
- **Research classification:** keep session admission and protocol validation distinct from parity admission. Alternatives: remove all admission/validation vs remove only pin/parity. Evidence: `apps/ptah-electron/src/di/codex-runtime-composition.ts:889-958` binds session routing; `libs/backend/codex-runtime/src/lib/codex-app-server-process.ts:227-252` validates protocol/home. Reversible: yes; architect decides replacement contracts.

## Open questions

- What minimum Codex CLI version and required app-server methods/fields define compatibility? Current manifest records `0.165.0` (`libs/backend/codex-runtime/src/lib/protocol/codex-app-server-protocol.manifest.json:2-17`); no minimum constant or manifest-driven method probe was found.
- Should the same selection result feed Electron chat, Electron lanes, CLI/TUI lanes and the separate usage probe? Their current call sites differ (`apps/ptah-electron/src/di/codex-runtime-composition.ts:133-154`; `codex-lane-composition.ts:159-169`; `libs/backend/cli-engine/src/lib/codex-lane-runtime-composition.ts:159-172`; `libs/backend/auth-providers/src/lib/providers/codex/codex-account-usage.service.ts:570-575`).
- Where is the VS Code host implementation for the product-wide requirement? It is absent from this worktree, so its executable resolution cannot be mapped here.
