## Contracts

Add `libs/backend/codex-runtime/src/lib/select-codex-executable.ts`, exported from the lib index. It owns the sole minimum-version constant and selection policy. Candidate discovery and process probing are injected so unit tests have no real Codex dependency:

```ts
export const CODEX_MIN_SUPPORTED_VERSION = '0.165.0'; // proposed floor
export type CodexExecutableOrigin = 'installed' | 'bundled';
export interface CodexExecutableSelection {
  readonly path: string;       // canonical native executable, never .cmd/.js
  readonly version: string;    // normalized X.Y.Z
  readonly source: CodexExecutableOrigin;
  readonly reason: string;     // safe for status UI, no home path or secret
}
export interface CodexExecutableProbes {
  installedCandidates(): Promise<readonly string[]>;
  bundledCandidate(): Promise<string | undefined>;
  canonicalNativePath(path: string): Promise<string | undefined>;
  readVersion(path: string, timeoutMs: number): Promise<string>;
}
export interface CodexSelection {
  readonly selected: CodexExecutableSelection;
  readonly bundledFallback?: CodexExecutableSelection;
}
export function parseCodexVersion(output: string): string | undefined;
export function isCodexVersionSupported(
  version: string,
  minimum?: string,
): boolean;
export function selectCodexExecutable(
  probes: CodexExecutableProbes,
  minimum?: string,
): Promise<CodexSelection>;
export interface CodexSelectionSnapshotPort {
  /** Fresh candidate and version probes for every new runtime open. */
  selectForOpen(): Promise<CodexSelection>;
  current(): CodexExecutableSelection | undefined;
  /** One safe bundled switch for this open; never replay a received turn. */
  activateFallback(failed: CodexExecutableSelection): Promise<CodexExecutableSelection>;
}
```

Parsing accepts `codex-cli 0.165.0`, prefixes, whitespace, prerelease/build suffixes and `v` prefixes. Compare numeric major/minor/patch: a prerelease at exactly 0.165.0 is below the stable minimum and is rejected; a prerelease with a higher numeric tuple (for example 0.166.0-beta.1) is accepted. Malformed versions are rejected. Do not parse a fabricated version from a package manifest. Probe each candidate with a 5–10 second timeout, dedupe canonical paths, prefer the first supported installed candidate in PATH order, then standard install locations, then the bundle. Resolve Windows `codex.cmd`/`codex.ps1` to its platform `codex.exe` without invoking a shell or parsing arbitrary script text; reject unresolved shims. Standard locations include npm global, Homebrew and common `~/.codex/bin`/Unix bin paths. The existing `resolveCodexNativeBinaryPath` can supply bundled packages to the injected probe, but `codex-runtime` must not import `agent-sdk` or `cli-agent-runtime`.

Replace `CodexExecutableManifestRow` with a selected executable source carrying `path/version/source/reason`; no platform, SHA or exact pin enters runtime DI. Keep `IProcessSpawner` from `platform-core`. Define `CodexSelectionSnapshotPort` in `codex-runtime` with `selectForOpen(): Promise<CodexSelection>`, `current(): CodexExecutableSelection | undefined`, and `activateFallback(failed: CodexExecutableSelection): Promise<CodexExecutableSelection>`; bind it as `CODEX_RUNTIME_TOKENS.SelectionSnapshot` in each host scope. The Electron chat/lane compositions and CLI lane factory inject that same host-scoped port. The lane adapter's `detect()` uses `selectForOpen()` and returns its `version/source/reason`; `agent:detectClis` forwards that result without independently guessing the binary. The renderer only reads the RPC result. Re-select and read `--version` on **each new runtime open**, including a new lane or detection refresh; cache only within that open/turn for agreement and the one-shot fallback. No long-lived version cache survives an in-place upgrade. Retain a canonical path/executable check at spawn; the SHA `launchGuard` entry is removed.

At startup, spawn selected `path app-server` with the existing allowlisted child environment and `CODEX_HOME=profile.normalizedHome`; retain returned-home verification. `initialize` remains required. Probe `model/list` read-only before exposing a dynamic catalog. No app-server capability enumeration exists in the current code, so method support is determined by JSON-RPC `-32601` on a real call. Introduce a typed `CodexUnsupportedMethodError { method, version, source }` at the process boundary; do not set it to generic retryable. The `-32601` mapping is a protocol assumption pending an authorized live Codex check: if Codex uses a different code, show the normal method failure and do not auto-fallback until that code is classified. Required core methods are `initialize`, `model/list`, `thread/start` or `thread/resume` for the chosen route, and `turn/start`. `turn/started`/`turn/completed` and token usage notifications are processed when present; absence of optional notification types is not a missing-method error. History, interrupt, steering, compaction and rate limits remain feature-local: a missing method disables or errors that operation without making basic chat unavailable.

Fallback orchestration lives at the runtime/open boundary for initialize, catalog and thread open, and at chat/lane first-turn orchestration for `turn/start`. If the installed executable returns `-32601` for a required method before a turn receipt exists, close that process, switch the cached selection to the already-probed bundled candidate, reopen with the **same** home/profile and retry once. A second failure is terminal. Never replay a turn after a receipt or uncertain write; never fallback on auth rejection, malformed required data, timeout, cancellation or home mismatch. For an optional method, retain the current context and report that operation unavailable. Preserve session-level `RuntimeAdmissionPort` and session identity persistence.

Inbound parsing policy: Zod `z.object` strips extra server fields; retain strict outbound `z.strictObject` request validation and strict JSON-RPC envelope/core IDs. A server request with additive envelope fields must still receive `-32601` when its method is unknown. Replace the closed optional item/status enums with tolerant parsing that maps unknown variants to unsupported evidence, not a fabricated known event. For `model/list`, require `id` and `model` nonempty per entry; optional display/default/effort/modalities fields are read when understood, unknown optional enum values are ignored, and one malformed entry is skipped with bounded redacted diagnostics. Keep the public `CodexModelInfo` shape normalized: `displayName = entry.displayName ?? entry.model`, `isDefault = entry.isDefault ?? false`, `supportedEfforts = understood reasoning efforts or []`; optional description stays undefined. `codex-context.ts` performs this mapping, and the lane's private schema must accept the same optional fields and default them identically. Preserve server order and paging limit. An empty valid catalog or failed discovery is an explicit unavailable/empty state, not a seven-ID fallback.

## User-facing failure behavior

| Condition | Action and message |
| --- | --- |
| Installed version below minimum | Choose bundle; status: “Installed Codex 0.164.0 is below the supported minimum 0.165.0; using bundled Codex 0.165.0.” |
| Installed missing/unreadable, bundle valid | Choose bundle; status: “Installed Codex was not found or could not be started; using bundled Codex 0.165.0.” No raw path or stderr. |
| Installed missing required method before turn | Close and retry bundle once; status: “Installed Codex X lacks required method model/list; using bundled Codex Y.” |
| Bundle below minimum or neither candidate works | Block new Codex use; “No supported Codex is available. Install Codex 0.165.0 or newer, or update Ptah’s bundled Codex.” Include only safe versions and method name. |
| Bundled required method also missing | “Codex Y does not support required method turn/start. Update Codex or Ptah.” No retry loop. |
| Unknown notification/field/optional enum | Continue; bounded redacted debug evidence, no user error. |
| Malformed required frame/home mismatch/auth error | Preserve existing failure semantics; do not claim unsupported version or silently switch home. |
| Future model absent from rate card | Run and show token usage; cost `null`, label “Not priced”; other null-cost reasons remain “Cost unavailable.” |

Do not use raw Codex error text in UI. Error mapping should use typed method/code/source/version. For an unknown requested model, send the requested ID to Codex; if Codex rejects it, preserve source-aware advice from `codex-model-rejection.ts`.

## Status and model flow

`selectCodexExecutable` → host-scoped `CodexSelectionSnapshotPort` → Electron chat/lane or CLI/TUI lane process → `initialize` → `model/list` → chat/lane/provider catalog. Add optional `codexSource` and `codexReason` to `CliDetectionResult` in batch 1, before the lane adapter populates them in batch 7. The adapter calls `selectForOpen()` and returns the port's active source/version/reason; `agent:detectClis` forwards those fields in batch 10, including an actual fallback, and the existing CLI matrix shows one status line. **That CLI matrix line is the only status UI surface in this task.** The `llm:getProviderStatus` projection is deferred; no provider-status handler, state service or settings component is assigned to change. The matrix must report the active snapshot from the shared selector, including chat/lane fallback, rather than infer chat choice from auth state. Existing Codex auth service continues to resolve override → `CODEX_HOME` → `~/.codex`; never derive auth home from binary source.

For omitted lane model, return `{ model: undefined, source: 'cli-default' }` from spawn policy and pass no model to Codex. Explicit request/settings/restored model retain precedence and are passed unchanged. Map dynamic `model/list` IDs (`model.model` runnable value) and `isDefault` labeling without a Ptah-chosen ID. Remove static provider filtering and fallback; provider discovery should use the selected app-server catalog when available, with account API discovery as a separate dynamic source. It must not use a model-name regex to discard future IDs. Keep user-configured tier mappings, but do not use seven static entries to decide visibility or execution.

For pricing, preserve exact rate-card lookup and token accounting. Add a narrow unavailability reason (e.g. `rateMissing` versus `usageIncomplete`/`billingUnknown`) to `ExactCostResult` and the existing session stats RPC shape only where needed to label an absent rate. This prevents “Not priced” from mislabeling an unknown billing mode or ambiguous cache usage. Do not invent a substitute rate or return zero. Keep coverage/provenance fields and backward-compatible optionality for existing snapshots.

## Decisions

- **One selector in `codex-runtime`:** alternatives were Electron-only detection and separate per-host checks. Existing Electron, CLI and lane probes all have different exact pin checks (runtime research §1–2), so the common library is the only stable dependency direction. Reversible: yes.
- **Use 0.165.0 as the sole proposed support floor:** alternatives were no floor or a newer unproven floor. The current bundled SDK/CLI and protocol evidence are 0.165.0 (`package.json:95`, manifest `:2-17`), so this is the lowest repository-evidenced baseline. Align the account `/models` client-version request floor with the exported constant; a newer local cache version may still raise that request version. User confirmation is requested below. Reversible: yes by one constant and tests.
- **Keep home and session admission:** alternatives were removing all admission or preserving only identity/auth admission. Current `CODEX_HOME`/home check and `RuntimeAdmissionPort` protect session routing independently of parity (runtime research §4; `EL/codex-runtime-composition.ts:889-958`). Reversible: no reason to remove in this task.
- **Omit an unspecified lane model:** alternatives were stale Ptah default or choosing `isDefault` from catalog. Passing no model delegates the default to the selected Codex version and works when the catalog is temporarily unavailable (`CAR/lane-spawn-policy.ts:53-64`; lane adapter `:228-235`). Reversible: yes.
- **Empty catalog on discovery failure:** alternatives were seven stale IDs or last-known-good cache. A stale catalog can conceal future IDs; the current lane fallback is hardcoded (`codex-app-server-lane.adapter.ts:183-207`). Explicit model requests still run. Reversible: yes.
- **Separate missing-rate reason:** alternatives were blanket “Not priced” for every null cost or a narrow reason. Current `calculateExactMessageCost` returns null for unknown billing and incomplete usage as well as absent rate (`pricing.utils.ts:517-588`). A narrow reason prevents a false claim. Reversible: yes.
- **Delete the offline manifest/generator, pending user approval:** alternatives were sanitize and retain them. Runtime imports the TypeScript pin row, while the JSON contains one machine-specific win32/x64 SHA and has no admission role (runtime research §2–3). The schema JSON remains a labeled frozen fixture because validator/evidence-harness specs read it; it must not act as a compatibility gate. Required-method tests are more useful for compatibility. Reversible: can regenerate evidence later, but removal is user-reserved.
