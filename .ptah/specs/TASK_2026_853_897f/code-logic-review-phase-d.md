## Numbered findings

1. **Blocking — rollback deletes an existing global skills.sh root.** At libs/backend/rpc-handlers/src/lib/skills-sh/skills-sh-source-root.service.ts:529, a matching global root sets resumed=true. Failures in clearing the retired mark, propagation, or validation call rollbackGlobal (lines 577, 603, 620), which deletes any matching owned global root at line 797, regardless of whether this invocation staged it. Install the same root globally and in a workspace, then let Make global propagation fail: the earlier global install is removed. Pass a createdThisAttempt flag to rollback and delete only roots staged by this call; test resumed-root failure.

2. **Major — a failed MCP intent write still looks like a completed install or conversion.** libs/backend/harness-sync/src/lib/sources/mcp-intent-store.ts:476 catches failed atomic writes and only logs them. record at line 344 and makeGlobal at line 438 then return; libs/backend/cli-agent-runtime/src/lib/mcp-directory/mcp-install.service.ts:218 proceeds to reconcile as if desired state were saved. With a full disk or sharing violation, intent is absent, target results can look successful, and a later reconcile loses the request. Propagate a typed persistence failure. The same store's read at line 446 treats EACCES/EIO as an empty file; distinguish ENOENT before a later write can replace existing intent.

3. **Major — one workspace's MCP configuration overwrites another's.** libs/backend/harness-sync/src/lib/sources/mcp-intent-store.ts:319 stores config once per serverKey and replaces it on every record. listFor at lines 224–234 reads the selected workspace target bucket with that shared config. Install key github with config A in workspace A, then B in workspace B; reconciling A writes B's arguments or credentials. Store config per scoped bucket, or reject conflicting configs with a clear result; add a two-workspace test.

4. **Major — a transient stat error can permanently complete migration without visiting a workspace.** libs/backend/rpc-handlers/src/lib/install-scope/install-scope-migration.service.ts:907 skips a candidate when isDirectory returns false; that helper at line 1102 catches every stat error, including EACCES/EIO. knownWorkspaceRoots still returns complete=true at line 912, allowing finish to persist completedAt at line 1018. A temporarily unreadable recent workspace is never reconciled and migration never retries it. Treat only ENOENT/ENOTDIR as absent; other errors must keep the ledger incomplete.

5. **Major — explicit global MCP install with no folder reports failure after saving intent.** libs/backend/rpc-handlers/src/lib/handlers/mcp-directory-rpc.handlers.ts:482 permits global scope without a folder, and McpInstallService.install records it at libs/backend/cli-agent-runtime/src/lib/mcp-directory/mcp-install.service.ts:218. reconcileTargets at line 659 then fails every target with No workspace folder open. The design enables All workspaces with no folder (design-spec.md:95), so the user sees failure although global intent was saved; home targets are not applied yet. Apply valid home targets directly and return a distinct accepted/deferred outcome for project targets.

6. **Major — raw host errors reach the MCP install alert.** libs/backend/cli-agent-runtime/src/lib/mcp-directory/mcp-install.service.ts:676 copies a caught exception message into results; libs/backend/rpc-handlers/src/lib/handlers/mcp-directory-rpc.handlers.ts:554 does likewise. libs/frontend/chat-ui/src/lib/molecules/setup-plugins/mcp-directory-browser.component.ts:645 interpolates it into the visible alert at line 127. A host error can disclose paths, config values, or provider text. Log raw causes in the host and return fixed coded copy to the UI; test an exception containing a secret sentinel.

## Five logic questions

1. **How does this fail silently?** Intent writes only warn (mcp-intent-store.ts:476–484); stat errors can become a completed migration (install-scope-migration.service.ts:1102–1109).
2. **What user action produces unexpected behavior?** A Make global retry against a matching global root can remove it after propagation fails (skills-sh-source-root.service.ts:529–545, 783–799). Selecting global MCP install with no folder reports failure after saving intent (mcp-install.service.ts:218–231, 659–665).
3. **What input data produces a wrong answer?** Two workspaces with the same serverKey and different configs share one top-level config (mcp-intent-store.ts:319–343, 216–237).
4. **What happens when a dependency fails?** Atomic intent writes are swallowed (mcp-intent-store.ts:476–484), migration stat errors look like missing workspaces (install-scope-migration.service.ts:1102–1109), and reconcile exceptions reach the UI (mcp-install.service.ts:676–683).
5. **What is missing from requirements?** The v2 schema never defines independent config for the same key in different workspaces (implementation-plan.md D-1; mcp-intent-store.ts:80–87). The no-folder global flow needs an accepted/deferred result (design-spec.md:95; mcp-install.service.ts:659–665).

## Decisions

- **Shared per-key config is a finding even though planned.** The v2 shape in implementation-plan.md D-1 prescribes one config per key; mcp-intent-store.ts:319–343 and 216–237 prove cross-workspace overwrite. Options: keep that limitation or store config per scope. Recommend scoped config; a v3 migration can reverse the schema choice.
- **No-folder global needs a deferred state.** Options: fail after saving, apply home targets and defer project targets, or accept all as deferred. design-spec.md:95 enables global while mcp-install.service.ts:659–665 reports failure. Recommend applying home targets and exposing deferred project targets; reversible contract change.
- **Verification limit.** I reviewed the changed production paths most directly implicated by scope, migration, conversion, and UI result handling, plus the specs and batch reports 17–41. This was not a line-by-line audit of all 98 changed files or their tests. Batch 41 reports 62/62 scoped VS Code DI/RPC smoke checks. I ran no build or tests under this read-only assignment. Scoped ptah_get_diagnostics timed out, so it supplies no evidence. Findings are source-level failure traces, not claimed reproductions.
