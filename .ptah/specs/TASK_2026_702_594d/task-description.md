# Elevate the Chat start screen

## Context

The zero-tile board currently has a board action (`libs/frontend/canvas/src/lib/canvas-rail/canvas-rail-board.component.ts:127-164`), a dock action (`libs/frontend/canvas/src/lib/orchestra-canvas.component.ts:149-193`), and a rail footer action (`libs/frontend/canvas/src/lib/canvas-rail/canvas-rail.component.ts:232-246`). They converge on the dock-anchored name popover (`orchestra-canvas.component.ts:144-235,584-628`). User decision #9 removes the entire dock (`orchestra-canvas.component.ts:85-240`) on empty and populated boards. `parity-inventory.md` records each dock capability and its approved destination or removal. The two setup presentations come from `libs/frontend/chat/src/lib/components/molecules/setup-plugins/project-setup-card.component.ts:35-110`; the same card appears in the single-chat empty state at `chat-empty-state.component.ts:82-85`.

## Classification and outcome

**Type:** FEATURE, matching the task carrier. **Estimate:** L on the carrier's XS/S/M/L/XL scale: this changes a shared Angular screen in Electron and VS Code, preserves session creation and setup flows, introduces a locally ported CSS Aurora background, and needs visual/accessibility review in two themes and hosts. No repository priority scale or user priority was supplied.

When a user opens an empty Chat board, they should see a clear primary New session action, a restrained Aurora gradient hero, one Get ready checklist, and up to three genuine recent sessions when available. The established session, setup, and history behaviors in `parity-inventory.md` are the baseline.

## Scope

### In scope

- Chat canvas in Electron and the VS Code webview: remove the entire dock row on empty and populated boards so the session viewport receives its height. Anchor the shared New Session popover to the centre hero button on an empty board and to the sidebar footer button when tiles exist; preserve the optional name, keyboard behavior, focus return, accessibility text, and both capacity guards.
- Move the layout-write, newer-version read-only, and `headerMessage` warnings to an **inline dismissable board notice**, not a snackbar. Dismissing a notice hides that instance; it shall reappear when its underlying condition is still true on the next relevant board entry or condition refresh.
- Remove the dock back-office ticker and its Thoth click target with user approval; Thoth remains reachable from its own page. In this task's last phase, after TASK_2026_593_7c2e merges, unmount the dock needs-you chip and delete the unused `libs/frontend/canvas/src/lib/canvas-needs-you-queue*.ts` implementation and spec files. The bell then supplies the one attention entry point. The other dock-removal work may proceed before that merge.
- Aurora visual behind or adjacent to the empty-board content, ported locally as CSS gradients and animation tinted with theme tokens for dark and light; static under reduced motion and paused while the board is hidden.
- One `surface-3` Get ready card with Skills and Agents status rows and a Project scan action row. Count only the two status rows; when both are ready, collapse the card to a compact one-line Ready strip with its actions still reachable.
- The same shared checklist replaces the shared setup card on the single-chat `showProjectSetup` empty state. Its existing logo, tagline, suggestions, and condition for showing setup remain.
- Up to three most recently active persisted sessions on the zero-tile board, using existing session-list data and existing open/resume behavior.
- Focus, keyboard, screen reader, reduced motion, hidden-board animation, and layout checks at 800px minimum window width and wide widths in both hosts and both themes.

### Out of scope, with reason

- Session list/modal search, filters, organization, and persistence changes: the new cards are a compact entry point into existing history, not a history redesign.
- Nonempty canvas tiles, rail keyboard model, and compact sheet: dock removal shall leave existing session surfaces functioning.
- Notification-center code and the replacement bell: TASK_2026_593_7c2e owns them in `.claude-worktrees/attention-notifications` and does not edit `orchestra-canvas.component.ts`; this task owns removal of the chip's mount and the entire dock, with chip unmount and queue-file deletion gated on that task merging first.
- Agent setup wizard, Marketplace, plugin catalog, or RPC contract changes: the checklist invokes existing actions and reads existing status.
- An Aurora effect across the whole app or on populated sessions: the request targets the initial empty board.
- The full Aurora hero and recent-session cards on the VS Code single-chat start screen: that compact surface receives the shared checklist and a low-opacity Aurora behind its logo (decision #15); its logo, tagline, suggestions, and footer remain.
- Invented analytics, readiness fields, or recent-session fixtures in production: no backing data would make them trustworthy.

## Requirements and acceptance criteria

1. **Session entry and viewport.** When the Chat canvas renders with zero or more tiles, the system shall render no canvas dock row and shall give the released dock height to the session viewport. When the board is empty, it shall show the centre hero New session button as the primary action; when tiles exist, the sidebar footer New session button shall remain the entry point. No dock New Session control shall return on a populated board.
2. **Shared create flow.** When the empty-board hero or populated-board sidebar footer button is activated by pointer, Enter, or Space, the system shall open the existing optional-name popover anchored to that invoking button. The input shall have its name label and accept an optional name; Enter/Create shall use the supplied name or existing default name, add a tile, and focus it; Escape/Cancel or backdrop close shall dismiss without creating and return focus to the invoking button.
3. **Creation limits.** When the running-session cap or tile limit blocks creation, the system shall prevent the hero and footer actions from creating a session, keep the applicable disabled/running-cap states, `aria` description, title, and screen-reader reason, and expose the reason to sighted users. The final create shall recheck both limits and show an inline dismissable board notice for a blocked attempt.
4. **Hero.** When an empty board is visible and motion is allowed, the system shall render a locally ported ngxui Aurora effect using CSS gradients and animation behind the content, tinted with existing theme tokens in `anubis` and `anubis-light`. When either theme is displayed, text over the Aurora shall meet at least 4.5:1 contrast and control boundaries and focus rings shall meet 3:1, measured on Gate 1.7 screenshots and during Electron visual review.
5. **Motion and visibility.** When `prefers-reduced-motion: reduce` is active, the system shall show a static theme-tinted Aurora gradient with all content and actions usable. When the motion preference changes while the board is open, the hero shall switch between static and animated CSS states without a reload. When the board is hidden, the Aurora animation shall be paused with `animation-play-state`; when it becomes visible and motion is allowed, the animation shall resume.
6. **Checklist content.** When the Get ready surface is shown, the system shall show Skills and Agents as status rows and Project scan as an action row, with a truthful text count of "N of 2 ready" based only on confirmed Skills and Agents status. When either status is loading, unknown, or failed, the system shall not count it as ready, shall keep the card expanded, and shall expose the applicable loading, error, or retry state. Project scan shall offer Run setup without a done state and shall never affect the count. When both counted rows are confirmed ready, the system shall collapse the card to a compact one-line "Ready" strip rather than hide it; Run setup, Generate agents, and Project guidance shall remain reachable from the strip.
7. **Checklist actions.** When Skills needs configuration, Open Library shall open Marketplace Skills through the existing route. When Agents needs configuration, Configure shall invoke the existing `setup-wizard:launch` path; the row shall retain the existing Update/retry/workspace-not-open affordance where relevant. When Project scan offers Run setup, it shall use the existing `setup-wizard:launch` path; if it is the same operation as Agents Configure, the two rows shall share one actionable control rather than duplicate triggers. When agent status has loaded, Generate agents and Project guidance shall remain reachable as secondary checklist actions, including from the collapsed Ready strip, launch their existing `setup-agent-generation` and `setup-project-prompt` workflows, and show the existing "Could not open generation" failure feedback when launch fails. Launching and failures shall have readable feedback, and an action shall not silently count as completion before its backing status confirms it.
8. **Shared single-chat surface.** When the single-chat empty state sets `showProjectSetup`, the system shall show the same Get ready checklist and state/action behavior as the empty board. When it does not, the system shall preserve the existing prompt suggestions and hero content without a checklist.
9. **Recent sessions.** When the existing session-list store returns persisted sessions for the active workspace, the system shall display at most the three entries with greatest `lastActivityAt`, with accessible names, and allow each to open through the existing `SessionRowActionsService.openSession` path, including its canvas branch. When opening fails, the system shall announce the failure and retain the card. When the Previous sessions dialog's search or filter changes and the dialog closes, the cards shall still show the active workspace's three most recently active sessions. When there are none or loading has not confirmed any, it shall not show fabricated cards or an incorrect empty-history claim. The existing Previous sessions dialog remains available.
10. **Responsive and accessible presentation.** When tested at an 800px-wide application window and at a wide window in Electron and VS Code webview, the system shall keep the primary action, checklist actions, and recent cards visible or reachable by scrolling without clipping or horizontal overflow. When the single-chat empty state is shown in a 280px VS Code sidebar, checklist rows, actions, and count shall be readable and reachable with no horizontal overflow. The keyboard focus sequence shall run from the board primary action through checklist actions in row order, recent-session cards, then rail controls; visible focus indicators shall remain clear. The checklist count shall be exposed as text, the decorative Aurora background shall be ignored by assistive technology, and control names, statuses, and disabled reasons shall be announced.
11. **Third-party attribution and rendering dependency.** When the hero ships, it shall use a local port of ngxui Aurora's CSS gradients and animation with no WebGL, Three.js, canvas, or new npm dependency for the hero. The ported source shall name the upstream Aurora files and MIT licence in a header comment. `libs/frontend/ui/src/lib/native/brand-mark/aurora-notices.txt` shall contain Omnedia's MIT copyright line and full permission notice. The implementation shall add this plain-text file to the asset lists in `apps/ptah-electron/project.json` and `apps/ptah-extension-vscode/project.json`, and to `apps/ptah-electron/electron-builder.yml` `extraResources`, following the existing `brand-icons-notices.txt` entries. During implementation, reviewers shall statically confirm that the notice file exists with the full MIT text, that the three packaging declarations include it, and that neither Electron's `files` exclusions nor `apps/ptah-extension-vscode/.vscodeignore` excludes it; reviewers shall also check that no new package dependency or forbidden rendering API was introduced for the hero. At release time, the packaging owner shall inspect the VSIX listing and an unpacked Electron installer to confirm that each distributed artifact contains the notice. The packaged-build check is a release gate, not a build in this task.

12. **Dock removal and warning parity.** When the final dock removal is complete, the system shall no longer mount its back-office ticker, Thoth click target, or needs-you chip; Thoth shall remain available from its own page, and TASK_2026_593_7c2e's merged bell shall cover attention. When layout writing fails, when the active board path is read-only because it was saved by a newer version, or when `headerMessage` has content, the system shall show each applicable existing warning text in an inline dismissable board notice with status semantics, without adding a snackbar system. When a notice is dismissed while its condition remains true, the system shall show it again on the next relevant board entry or condition refresh. A component test shall fail if any of these three warning paths is removed or stops rendering its text.
13. **Gated chip removal.** When TASK_2026_593_7c2e has merged and its bell covers the chip's attention, lane-permission, Allow/Deny, and open-session capabilities, this task's last phase shall unmount the needs-you chip from `orchestra-canvas.component.ts` and delete the four `libs/frontend/canvas/src/lib/canvas-needs-you-queue*.ts` implementation/spec files. When that merge has not happened, the system shall retain the chip capability and its source files while the independent dock-removal work proceeds. Completion review shall confirm the merged bell's replacement coverage, the absent chip mount, and the absence of those four files.

## Non-functional constraints

- Angular UI follows the repository’s standalone, `OnPush`, `inject()`, signal-based state pattern; cross-library imports use public indexes only. These are checkable in changed component imports and metadata.
- Changed templates shall introduce no `text-base-content/NN` alpha class, as enforced by `apps/ptah-extension-webview/src/app/no-alpha-base-content.spec.ts`. Theme colors use existing tokens; `surface-3` is the card style in `apps/ptah-extension-webview/src/styles.css:385-403`.
- Only existing `ClaudeRpcService`/store actions may reach the host. Recent sessions are obtained from `ChatStore.sessions`/`loadSessions` (`libs/frontend/chat/src/lib/services/chat.store.ts:108-112,210-220`), backed by the existing `session:list` flow; opening follows the existing previous-sessions action rather than a new transport. Avoid changing the dialog’s filter/query to populate the cards.
- The decorative Aurora layers shall not capture pointer or keyboard interaction needed by the board; CSS animation shall be paused while the board is hidden.

## Stakeholders

- New and returning users need one obvious start action and a quick route back to real sessions.
- Users with incomplete setup need accurate, actionable status without false completion or a misleading warning during loading.
- Keyboard and screen-reader users need a single clear primary path, preserved disabled reasons, and focus recovery.
- Canvas users need layout-save and create-limit warnings that remain available after the dock is removed, including when a persistent condition recurs after dismissal.
- Electron and VS Code host maintainers need matching CSS-only behavior, reduced-motion support, and no new RPC contract.

## Aurora research and recommendation

The [ngxui Aurora repository](https://github.com/omnedia/ngx-aurora) describes an animated gradient background. Its [component source](https://github.com/omnedia/ngx-aurora/blob/master/src/lib/ngx-aurora.component.ts) exposes `invert`, `versionTwo`, and `styleClass`; it uses an `IntersectionObserver` to track visibility. Its [template](https://github.com/omnedia/ngx-aurora/blob/master/src/lib/ngx-aurora.component.html) and [SCSS](https://github.com/omnedia/ngx-aurora/blob/master/src/lib/ngx-aurora.component.scss) implement the visual with CSS gradients and animation; no canvas, WebGL, shader, or Three.js renderer is involved. The [licence](https://github.com/omnedia/ngx-aurora/blob/master/LICENSE) is MIT and requires its copyright and permission notice in copies or substantial portions.

**Resolved direction (decision #12, superseding #6):** port Aurora locally as CSS gradients and animation, tinted with existing dark and light theme tokens. Keep the background static for reduced motion and pause CSS animation while the board is hidden. Add no npm dependency. Preserve Omnedia's MIT copyright and full permission notice in `libs/frontend/ui/src/lib/native/brand-mark/aurora-notices.txt`, a plain-text sibling of the existing generated `brand-icons-notices.txt`. Copy it through both hosts' build assets and ship it through Electron `extraResources`.
