# Canvas zoom, pan and stable node cards — TASK_2026_678_9083

## Summary

- **Recommendation:** add one small scene-camera transform owned by `CommandSceneComponent`, and use the already installed Floating UI positioning service for one shared node card.
- The prototype has no zoom or translation pan: its drag changes orbit tilt; its tooltip opens and closes instantly on label hover.
- At 24 nodes, collision and density rules move, compact or hide labels, so the pointer can leave its current trigger without the user moving away.
- Keep the Canvas 2D renderer and DOM labels in the same logical world coordinates; project both through the camera, then inverse-project pointer hit tests.
- Add zoom controls, fit view, zoom to selection, keyboard pan, wheel and pinch with no animated motion when reduced motion is requested.
- A stable card needs delayed hover, a short exit grace path, click pinning, and a stable node ID. Positioning alone will not stop flicker.
- Preserve the 24-node scene cap and the complete keyboard work list; a minimap is not justified at this scene size.

## Flicker root cause

**Verified:** `prototype/command-center.html:81` wires every label's `mouseenter` directly to `showTip` and `mouseleave` directly to `display='none'`; there is no intent delay, grace region, or pinned state. `:82` positions the tooltip relative to the label. The tooltip itself has `pointer-events:none` (`:12`), so a popover covering its trigger is **not** the supported cause in this prototype. `:95` repositions visible labels with `translate3d` and sets `display='none'` if collision placement fails; at `nodes.length>12` it shows only five ordinary labels alongside priority labels. `:89` runs pair separation and edge clamps, and `:90` calls `positionLabels` during drawing. `:96` keeps drawing while work is active. `:98` changes orbit tilt on drag and does not translate the scene. `design-spec.md:42-44` makes the dense placement and hiding rules intentional.

**Inference:** with many nodes, a label may move, shrink or disappear beneath a stationary pointer, generating leave/enter transitions; immediate handlers turn those transitions into visible toggling. A second unproven contributor is tiny/overlapping canvas hit areas; the prototype uses only click hit testing (`:98`), so it cannot explain this prototype's hover tooltip. Reproduce at the 24-node preview with a stationary pointer and log label rect/hovered ID per frame to distinguish layout churn from hand motion.

**Recommendation:** hand-write the bounded camera because the existing renderer already owns projection, the scene is limited to 24 nodes, and all libraries still need the same camera/DOM synchronization and keyboard policy. This is a modest addition to pending Batches 11–14, not a renderer replacement. If trackpad gesture testing exposes platform-specific input complexity, `d3-zoom` is the strongest fallback: it explicitly supports Canvas and supplies a usable transform model. Use zoom around the pointer or selected node, clamp scale (proposed `0.65–2.5`, tune in Electron), suppress click selection after a real pan, and keep the existing orbit tilt on a separate gesture/control so it does not compete with drag-to-pan. Reduced motion disables camera easing, not navigation.

Full graph packages are poor fits for Decision 13's owned renderer: [Cytoscape.js](https://js.cytoscape.org/) and [AntV G6](https://github.com/antvis/g6) can render graphs, but would take over scene layout/drawing or require custom-node integration that duplicates the Canvas 2D sphere path. [Sigma.js](https://www.sigmajs.org/) uses WebGL, against the chosen Canvas 2D renderer. [`@xyflow/system`](https://github.com/xyflow/xyflow) offers viewport helpers but belongs to React/Svelte Flow's node editor model, not this Angular Canvas sphere scene. None is needed for camera input; no full graph library was measured or version-audited for adoption.

**Recommendation:** create one `CommandOverlayComponent` card keyed by stable node ID. For hover, propose 120–180 ms open intent and 180–250 ms close delay; cancel close when pointer enters the card or the trigger again. Treat trigger-to-card corridor as safe (pointer trajectory or an invisible bridge), and do not close merely because the label is repositioned/hidden while its node remains hovered by canvas hit test. For click, pin the selected card until explicit close, Escape, selection change or scene teardown; keep keyboard focus in a sensible place and expose the same content in the work list. Place with Floating UI `offset`/`flip`/`shift`, avoid a backdrop for passive hover, and anchor to the sphere when its label is hidden. This is a proposed interaction policy; verify delays and collision cases in Electron. `libs/frontend/tribunal-panel` yielded no reusable tooltip/popover implementation in the targeted search; no zoom/pan implementation was found in `libs/frontend/ui` or `libs/frontend/tribunal-panel`.

## Level of detail at high node counts

- **Project rule:** preserve `design-spec.md:42-45`'s 24-node draw cap, completed-node count chip, priority for active/awaiting/failed nodes, labels on Ptah/selected/awaiting/failed plus up to five others when `N>12`, and the full accessible work list. Never make scene culling remove a work-list item.
- **Lane proposed:** compute visibility in world space plus camera scale. At fit/low zoom, show only priority labels and small dots/spheres for low-priority delegates; hide metadata before hiding names. At higher zoom, reveal labels only if the collision test passes, with hysteresis around the threshold so a small wheel movement cannot toggle a label repeatedly. Keep selected/keyboard-focused node marked even when its label is hidden.
- **Lane proposed:** retain the current completed-item count chip for `N>24`; do not introduce automatic semantic clustering for 24 nodes. If a parent has many children, an explicit collapse/expand subtree is a later design change, since the current work tree and status semantics must remain inspectable.
- **Lane proposed:** Fit to view computes bounds of visible spheres plus halo padding, clamps to camera range and excludes the fixed header/foot. Zoom to node centers the selected sphere in the usable stage region while leaving room for the card. Both should be button and keyboard actions; instant under reduced motion.
- **Minimap: no for this scope.** A 24-node maximum, fit view, zoom to selection and full work list provide orientation without another render layer. Reassess only if navigation testing shows users getting lost at maximum zoom.
