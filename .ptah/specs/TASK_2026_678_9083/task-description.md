# Voice Command Center — requirements

## Outcome and classification

Provide an Electron Command Center page where a user speaks with “Ptah, head of engineering,” delegates engineering work through an ordinary Ptah chat session, and hears concise progress while an HTML `<canvas>` shows only work descended from that session. This is a different view of the existing chat runtime for voice command and status, not a session detail view. **Type: FEATURE; estimate: Complex.** The task carrier and `context.md` classify it as a feature and Complex; the hands-free speech loop, persistent session, multiple agent sources, and canvas projection drive that size. No repository priority scale was supplied.

## Evidence and boundaries

Ptah already selects local Whisper/Kokoro or ElevenLabs STT/TTS through its main voice configuration and keeps the ElevenLabs key in an encrypted store (`libs/backend/voice-providers/src/lib/voice-provider-selector.ts:47`; `libs/backend/voice-providers/src/lib/voice-secret-store.ts:22,75`; `libs/backend/rpc-handlers/src/lib/handlers/voice-rpc.handlers.ts:170-183,244-274`). Current `VoiceInputService` records then transcribes after stop (`libs/frontend/chat/src/lib/services/voice-input.service.ts:73-80,144-180`), so hands-free turn detection and playback are new. The existing chat canvas is a DOM session board (`libs/frontend/canvas/src/lib/canvas-rail/canvas-rail-board.component.ts:77,161,182`), not an HTML canvas agent graph. Chat RPC already supports start, continue, resume, abort, streaming and permissions (`libs/backend/rpc-handlers/src/lib/handlers/chat-rpc.handlers.ts:107-112,388-396`); child sessions require a live parent (`libs/backend/cli-agent-runtime/src/lib/session-children/session-spawner.service.ts:273`). Agent Monitor exposes lane and SDK agent state (`libs/frontend/chat-streaming/src/lib/agent-monitor.store.ts:758,816,1160,1456,2008-2175`); Tribunal phase progress is derived from lane and task state (`libs/frontend/tribunal-panel/src/lib/services/tribunal-progress.service.ts:113-127,322-361`). The property-hub reference offers reusable VAD, sentence chunking and playback queue patterns (`research-property-hub-elevenlabs.md`, “Portability to Ptah”).

### In scope

- A dedicated Electron page, entry in Electron navigation, and a real HTML `<canvas>` showing Ptah and descendants of this page's orchestrator only. [user-requested: `context.md`, user decisions 2–4]
- A dedicated ordinary Ptah chat session using the existing chat runtime, with head-of-engineering persona/instructions, existing MCP tools, streaming, permissions and a persistent session identity across page navigation. [user-requested: user correction, decision 1]
- Hands-free voice turns using the configured main voice providers and existing `voice:transcribe`/`voice:synthesize` RPC, with VAD, playback, barge-in and spoken status updates. [user-requested: user correction, decision 1]
- Voice delegation to Ptah CLI lanes, child sessions, and Council/Forge/Race/Crucible Tribunal workflows, with visible lifecycle and spoken status. [user-requested: `context.md`]
- Reuse of Ptah's existing voice provider selection, ElevenLabs key vault and voice settings. [user-requested: user correction, decision 1]
- Host-neutral model and event contracts even though the page ships only in Electron. [user-requested: `context.md`, user decision 2]

### Out of scope

- Session transcript detail, chat editing, and replacement of the existing chat canvas or Tribunal page: the requested page is for command and status, and those surfaces already serve their own purposes. [user-requested: `context.md`; evidence: `research-ptah-reuse.md` §§1–2]
- VS Code page, CLI/TUI page, and their live microphone support in release 1: Electron is the chosen first host. [user-requested: `context.md`, user decision 2]
- Agents belonging to unrelated chat sessions or other Tribunal runs: canvas ownership is limited to this orchestrator tree. [user-requested: `context.md`, user decision 3]
- A second LLM, ElevenLabs Conversational AI agent, ConvAI client tools or signed URL flow, and per-minute ConvAI billing: the existing Ptah chat runtime is the brain. [user-requested: user correction, decision 1]
- A general ElevenLabs agent management dashboard or port of property-hub's Nest voice API and CRM persona: the main Ptah voice settings and RPC already provide the configured speech path. [user-requested: user correction; evidence: `research-property-hub-elevenlabs.md` §§7–8]

## Stakeholders and functional requirements

- **Command Center user:** can start a live conversation, give a task, hear progress, and inspect a legible status graph without opening session details. [user-requested: `context.md`]
- **Delegated agent operator:** sees which lane, child session, or Tribunal phase is active, done, or failed, so they can ask Ptah for a useful update. [user-requested: `context.md`]
- **Electron host/security maintainer:** can keep microphone permission, provider credentials and voice RPC within existing host and settings boundaries. [pm-proposed; evidence: `research-ptah-reuse.md` §§3, 6]
- **Architect/implementer:** can choose the VAD, speech playback, status narration and projection design while preserving the observable behavior below. [pm-proposed]

## Acceptance criteria

1. **Page access** — When Electron navigation opens Command Center, the system shall show a dedicated page with Ptah as the root of a real HTML `<canvas>` graph and usable voice controls; outside Electron, the navigation entry shall be hidden and the route shall not expose an active Command Center page. [user-requested: `context.md`, decisions 2, 4; evidence: `apps/ptah-extension-webview/src/app/electron-only-surface.guard.ts:19-20`]
2. **Session identity** — When the page starts a new Command Center conversation, the system shall create an ordinary Ptah chat session with head-of-engineering persona/instructions; subsequent voice and text turns shall use that session's existing `chat:start`/`chat:continue`/`chat:abort`, streaming, permission and MCP tool behavior. [user-requested: user correction, decision 1; evidence: `research-ptah-reuse.md` §4]
3. **Voice readiness** — When a configured user starts voice mode and grants microphone access, the system shall use the selected main STT and TTS providers, show listening/thinking/speaking state, and begin a hands-free turn loop without requiring a press to stop recording after each utterance. [user-requested: user correction, decision 1]
4. **Start/stop/mute** — When the user starts, stops, or mutes voice mode, the system shall show the resulting state; stop shall release mic and playback resources, while mute shall stop capture without ending the underlying chat session. [pm-proposed]
5. **Utterance detection** — When the user speaks and then pauses, VAD shall close the utterance and send it through existing `voice:transcribe` to the current chat session; silence and background noise shall not create empty chat turns. [user-requested: user correction, decision 1; pm-proposed: empty-turn behavior]
6. **Playback and interruption** — When Ptah produces a spoken response through existing `voice:synthesize`, the system shall play ordered chunks. When the user speaks over playback, it shall stop stale audio and queue the new utterance until the in-flight chat turn finishes, including any tool call; an explicit Stop response control shall call `chat:abort` before a new turn is sent. Superseded audio shall not play later. [user-requested: user correction, decision 1; pm-proposed: in-flight turn policy]
7. **Permission denied** — When microphone permission is denied or unavailable, the system shall show an actionable permission state and keep the page, text controls and graph usable. [pm-proposed; project-rule: `apps/ptah-electron/src/windows/permission-policy.ts:12,174`]
8. **Provider readiness** — When the selected STT/TTS provider is unavailable or its existing ElevenLabs key is missing/invalid, the system shall explain the issue, link to the existing voice settings, preserve text interaction, and never display the key. [user-requested: user correction, decision 1; pm-proposed: recovery]
9. **Speech failure recovery** — When transcription, synthesis or playback fails, the system shall stop the affected voice turn, present a safe text error and allow another voice or text turn in the same chat session without replaying a previous command. [pm-proposed]
10. **Voice delegation** — When VAD closes a transcribed task utterance, the system shall send it to the Command Center chat session. When that session invokes an existing delegation tool to start a CLI lane, child session or Tribunal workflow, the system shall create one stable owned work item and show its state. Head-of-engineering instructions shall ask Ptah to acknowledge accepted delegation; a manual voice scenario shall check the acknowledgement. [user-requested: user correction, decision 1; pm-proposed: deterministic projection and persona check]
11. **Status integrity** — When agent events arrive or the user asks for status, the system shall correlate them to the Command Center chat session and its descendants, show and report the latest owned work state, and exclude unrelated session work. [user-requested: `context.md`, decision 3; pm-proposed: correlation]
12. **Spoken updates** — When an owned lane or child session starts, completes or fails, or a Tribunal run reaches a meaningful phase or outcome, the system shall queue one concise spoken update through the configured TTS provider at a suitable turn boundary; unrelated events and duplicate notifications shall not be narrated. [user-requested: user correction, decision 1; pm-proposed: turn boundary and deduplication]
13. **Status on demand** — When the user requests status by voice or text, the system shall provide the latest projected state of owned work to the Command Center session and show it on the page. Head-of-engineering instructions shall ask Ptah to distinguish running, completed and failed items in its reply; a manual voice scenario shall check that summary. [user-requested: `context.md`; pm-proposed: deterministic projection and persona check]
14. **Canvas lifecycle** — When owned agents are queued, starting, running, awaiting input, completed, failed or cancelled, the canvas and its text alternative shall render their identity, parent relationship, type and state; terminal states shall remain inspectable for the current Command Center session. [user-requested: `context.md`; pm-proposed: state vocabulary]
15. **Tribunal grouping** — When Ptah starts a Council, Forge, Race or Crucible run, the canvas shall show the run as a group under Ptah with its participating lanes and current workflow stage, including completion or failure, rather than flattening it into unrelated nodes. [user-requested: `context.md`; evidence: `research-ptah-reuse.md` §2]
16. **Navigation persistence** — When the user leaves and returns to the page within the same workspace, the ordinary Ptah chat session and its owned work shall retain their identity and status; voice capture/playback shall stop on exit and may resume on return without resending prior delegation. After an app restart, reopening the page shall offer resume of the latest persisted Command Center session in that workspace or a new session if none exists. [user-requested: user correction, decision 1; pm-proposed: page and restart lifecycle]
17. **Text fallback** — When microphone or audio playback is unavailable, the user shall be able to type commands and read Ptah's replies and status in a compact view; the canvas shall have an equivalent text list of nodes and states without becoming a transcript detail page. [user-requested: user correction, decision 1; pm-proposed: accessibility]
18. **Keyboard use** — When navigating without a pointer, the user shall be able to reach the page, start/stop/mute/interrupt voice, send text and inspect node status; state changes shall be announced through accessible text rather than color alone. [pm-proposed]
19. **Secret boundary** — When using ElevenLabs as the configured speech provider, the system shall continue using Ptah's existing key store and host voice RPC, and shall not send the long-lived API key or raw secret-bearing errors to the renderer. [user-requested: user correction, decision 1; evidence: `research-ptah-reuse.md` §6]
20. **Responsive voice and canvas** — During a normal configured-provider session, Ptah shall begin responding before delegated work completes and shall expose measured end-of-utterance to first-audible-response latency. The **pm-proposed latency target** is the measured baseline of the selected STT + chat + TTS providers on a representative Electron workload, with a documented acceptable upper bound set before implementation; no fixed number is supported by the inputs. At the representative maximum simultaneous node count **N** established by an architecture spike, canvas draw work shall stay within one display refresh interval per frame and controls shall remain responsive. The architect shall record the latency bound, N and display refresh baseline before implementation. [user-requested: near real-time; pm-proposed: measurable budget]
21. **Error recovery** — When a chat turn, tool call or delegated agent fails, the system shall surface a safe error and current task state in voice or text and on canvas, while allowing the user to continue the session or retry an explicitly identified action. [pm-proposed]
22. **Pending permission or question** — When the Command Center session or a delegated child waits for tool permission or an AskUserQuestion-style answer, the system shall speak a short prompt summary, show the full prompt and available choices on the page, and mark the relevant canvas node and text alternative as awaiting input until resolved. An ordinary question may be answered by voice or an on-page/keyboard control; the answer shall resolve the pending question rather than become a new chat turn. Tool approval or denial shall require an explicit on-page/keyboard action in release 1; speech recognition alone shall never approve a tool. If the user cannot hear the prompt, its visible state shall remain actionable so the hands-free loop cannot stall silently. [pm-proposed; evidence: `chat:pending-questions` in `chat-rpc.handlers.ts:113`]
23. **Playback echo protection** — When Ptah speaks through ordinary laptop speakers or a headset, its own synthesized audio shall not create a user chat turn or trigger a false barge-in; real user speech during playback shall still be accepted. The capture path shall request echo cancellation and noise suppression where supported, and the VAD/playback coordination shall be checked in both speaker and headset scenarios. [pm-proposed; evidence: `research-property-hub-elevenlabs.md` §6]
24. **Spoken content boundary** — When synthesizing a reply or status update, the system shall speak only bounded conversational assistant text: tool calls, tool results, code blocks, diffs and long markdown shall not be read aloud. The full assistant text shall remain available in the compact text view; the architect shall set a maximum spoken length before implementation. [pm-proposed]
25. **Session cardinality and ownership** — When the page opens in a workspace, it shall use one active Command Center session for that workspace; an explicit New Command Center action shall create another ordinary chat session while retaining prior sessions for later resume. While voice mode is active, Command Center shall be the only surface sending turns to its active session; if the same session is open in regular chat, that surface shall show its state but block competing sends with a clear route back to Command Center. [pm-proposed]

## Dependencies and risks

| Dependency or risk | Required action |
| --- | --- |
| Existing `VoiceInputService` records until stopped, while hands-free VAD and speech overlap are new. | Prototype VAD with the selected local and ElevenLabs providers, including noise, silence and interruption; adapt property-hub's VAD, chunker and playback queue patterns where useful. |
| A tool permission or question can block the orchestrator or child while a voice user sees no transcript. | Surface and speak pending prompts, mark the affected node, keep on-page controls available, and require explicit UI or keyboard action for tool approval. Test an unanswered prompt and a misrecognized spoken "yes." |
| Synthesized speech can re-enter the microphone as a false user utterance or barge-in. | Request echo cancellation/noise suppression where supported and verify VAD gating with laptop speakers and headset playback while preserving real user interruption. |
| Assistant output can contain code, diffs and long tool results unsuitable for speech. | Filter speech to bounded conversational text; retain full text in the compact view and test a code-heavy reply. |
| Speech providers differ in transcription and synthesis latency. | Measure end-of-utterance to first-audio latency for configured provider combinations and set an acceptable baseline-derived target before implementation. |
| Voice status narration can compete with a user's live command. | Queue and deduplicate updates, interrupt stale playback, and deliver narration only at appropriate turn boundaries. |
| ElevenLabs STT and TTS usage can rise with each voice turn and narrated status update. | Deduplicate narration, cap spoken reply length, and present local providers as an available lower-cost setting; record usage and cost assumptions for release 1. No separate cost-guard requirement is added. |
| Monitor events and Tribunal phases come from different projections; foreground completion may lack one expected event. | Use stable ownership IDs and reconcile from authoritative session/lane state, including completion fallbacks (`agent-monitor.store.ts:2396-2410`). |
| Existing chat session lifecycle and page lifecycle differ. | Preserve the chat session identity and descendant ownership across page navigation while releasing mic and playback resources on exit. |
| Concurrent sends from regular chat and Command Center could reorder turns or duplicate delegation. | Gate sends to the active Command Center session while voice mode is active and verify resume and explicit new-session flows. |
| Canvas can hide information from keyboard and screen reader users. | Ship the text node/status list and keyboard controls alongside the canvas. |

## Pre-implementation measurement gate

Before implementation, the architect shall record a representative Electron workload, the selected-provider end-of-utterance to first-audio upper bound, maximum simultaneous canvas node count N, and display refresh baseline. AC20 is testable against those recorded values; the task inputs supply no numeric thresholds. [pm-proposed]

## Architect questions

1. Where should the head-of-engineering persona/instructions attach to an ordinary Ptah chat session without changing other sessions' prompts or permissions?
2. How should VAD end an utterance, chunk chat output for synthesis, distinguish real speech from playback echo, and cancel pending audio on barge-in across local and ElevenLabs providers?
3. How will spoken status be queued and deduplicated from Agent Monitor and Tribunal state without turning status narration into a new chat command?
4. How will ownership and stable node IDs join CLI lanes, child sessions, SDK subagents and Tribunal phases across navigation and session resume?
5. What measured first-response latency bound, maximum simultaneous node count N, display refresh baseline, and spoken-output length limit fit a representative Electron workload?
