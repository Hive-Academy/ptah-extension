## Root cause

**High confidence from source, corroborated by the Phase E visual observation; no runtime trace was captured in this lane.** Command Center creates a normal chat tab only with an active workspace (`libs/frontend/command-center/src/lib/model/session-coordinator.ts:55-60,115-123,164-175`; `libs/frontend/chat-state/src/lib/tab-manager.service.ts:1004-1021`). Its send uses `MessageSenderService` with that tab ID (`session-coordinator.ts:224-242`). The lookup returns that active workspace path, or the owning background partition path, for this tab (`tab-workspace-partition.service.ts:325-349`). Thus the `lookup.workspacePath !== null` pulse guard is not the blocker for a valid Command Center tab.

The page is outside the chat surface, and no Command Center code registers its tab with `registerVisibleTab`. `StreamViewportController.deriveViewport` includes the active tab only when `currentSurface() === 'chat'`, plus `visibleTabIds` (`libs/frontend/chat/src/lib/services/stream-viewport-controller.service.ts:75-87`). Once v2 viewport negotiation succeeds (`:107-120`), the Command Center tab is hidden. The host then retains its stream events instead of sending `CHAT_CHUNK` (`libs/backend/rpc-handlers/src/lib/chat/streaming/chat-stream-delivery-coordinator.service.ts:164-184,186-217`), and defers terminal messages (`:227-239`). On reveal it sends the retained snapshot (`:301-341`). The visual review reports `lastTurnStateRevision` still undefined after the backend completes (`.ptah/specs/TASK_2026_678_9083/visual-review-phase-e.md:71`), consistent with neither generating nor terminal `turn_state` being delivered to the tab. Session stats use a separate handler (`libs/frontend/chat/src/lib/services/chat-message-handler.service.ts:168-172`), so seeing stats does not prove chunk delivery.

When a chunk is delivered, `ChatMessageHandler` routes `CHAT_CHUNK` through `StreamFlushScheduler` to `ChatStore` (`libs/frontend/chat/src/lib/services/chat-message-handler.service.ts:149-152,498-535,537-561`), `StreamingHandlerService` intercepts `turn_state` (`libs/frontend/chat-streaming/src/lib/streaming-handler.service.ts:208-237`), and `TurnStateApplier` resolves the tab, checks ownership/revision, finalizes, then calls `applyTurnState` (`libs/frontend/chat-streaming/src/lib/turn-state-applier.service.ts:87-139,194-221`). A hidden tab's frontend queue also has no flush schedule (`libs/frontend/chat/src/lib/services/stream-flush-scheduler.service.ts:29-45`), so simply forwarding hidden chunks would still strand them. `applyTurnState` is therefore never reached on this path. If reached for the current session with a first revision, `acceptsTurnState` accepts it (`libs/frontend/chat-state/src/lib/tab-manager.service.ts:1895-1923`), updates status, and emits the pulse after a streaming to idle/failed transition (`:1704-1802`). Command Center reads that pulse for reply and status (`command-center-page.controller.ts:73-81,310-320`). Command Center's `attachSession` only rekeys its send lock and records the session (`tab-manager.service.ts:1990-2008`); it does not change turn-state ownership.

Other loaded-status paths do not explain the observed undefined revision: `CHAT_COMPLETE` resets only the `clear` command (`chat-message-handler.service.ts:375-397`); `markTabIdle` is spinner-only (`tab-manager.service.ts:3064-3083`); `applyFinalizedTurn` is called by the accepted terminal applier and flips loaded in a microtask after synchronous `applyTurnState` (`turn-state-applier.service.ts:115-139`; `tab-manager.service.ts:2218-2252`). Error and local abort paths can set loaded (`libs/frontend/chat/src/lib/services/chat-store/completion-handler.service.ts:77-99`; `libs/frontend/chat/src/lib/services/chat-store/conversation.service.ts:434-456`), but neither accounts for a normally completed run with no turn-state revision. Send failures also set loaded (`libs/frontend/chat/src/lib/services/message-sender.service.ts:490-518,755-779`), whereas the reported send succeeded and model ran.

## Fix

No source file changed: the root cause is outside the allowed `libs/frontend/chat-state/src/lib` scope. The exact fix belongs in the page-scoped `CommandCenterPageController` (`libs/frontend/command-center/src/lib/components/command-center-page.controller.ts:35-48`): while the page is active, track `store.markedTabId()` in an Angular effect, call `tabs.registerVisibleTab(tabId)` for the current tab, and unregister it on ID change or page destruction. `CommandCenterPageComponent` provides the controller per page lifetime (`command-center-page.component.ts:24-44`). The existing viewport derivation then declares the tab visible (`stream-viewport-controller.service.ts:75-87`), the host reveals retained events (`chat-stream-delivery-coordinator.service.ts:214-217,301-341`), and the frontend schedules the visible queue (`stream-flush-scheduler.service.ts:35-45,80-90`). Add a Command Center page spec proving the tab is registered and released, and an integration spec that a terminal snapshot reaches `lastTerminalPulseByTab`. No regression spec was added here because the required fix is outside lane ownership.

## Consumers checked

`CommandCenterPageController` reads `lastTerminalPulseByTab` for reply and status (`command-center-page.controller.ts:73-81,310-320`); `CommandCenterTribunalTransport` also reads the per-tab pulse (`command-center-tribunal.transport.ts:39,84,119`). The notification ledger consumes the queued pulse and uses its non-null `workspacePath` for completion cards (`libs/frontend/notification-center/src/lib/notification-ledger.service.ts:166-174,222-248`). The proposed visibility registration does not alter pulse shape or workspace-keyed card behavior. Relaxing `workspacePath` in chat-state would not fix missing turn-state delivery and would conflict with the ledger's workspace target (`tab-manager.service.ts:140-151,1773-1801`).

## Decisions

- Report the cause as a visibility/delivery issue outside lane scope. Options: loosen the pulse guard or make the Command Center tab visible to the existing stream protocol. Evidence: active workspace is required and the visual review saw no `lastTurnStateRevision`; host and frontend both suppress hidden traffic. The visibility registration is reversible.
- Keep `TerminalTurnPulse.workspacePath` required. The notification ledger builds workspace-keyed targets from it. Reversible if the consumer contract changes later.

## Not done

- No changes outside `libs/frontend/chat-state/src/lib` were made, and no chat-state change or spec is warranted for this cause.
- Nx, Jest, build, serve, e2e and package were not run, as required. Runtime confirmation of the proposed outside-scope fix remains for the owning lane.
