# Implementation plan — Ptah voice Command Center (revision 3)

## Contract and scope

Add an Electron-only Command Center page over an **ordinary chat tab**. The head-of-engineering persona belongs to that tab/session, including every SDK resume. The Canvas 2D scene shows only work descended from that root. Existing chat, Tribunal, voice settings, key vault, and session board retain their capabilities. AC25 changes regular chat only for that root while voice is active: it displays the session but holds competing sends and links back to Command Center. Explicit **New Command Center** creates another resumable ordinary session and switches the workspace's active marker.

Authority: `context.md` and `decisions.md` #7 choose the existing chat runtime plus main voice settings; #2 Electron only; #3 root-owned tree; #13 Canvas 2D and CSS transforms; #14 provider marks. `task-description.md` rev 3 AC1–25 and `design-spec.md` rev 3 govern behavior and UI. `prototype/command-center.html` is a renderer reference. This adds a surface and removes no capability.

## Session and work model

1. **Tab and persona.** `CommandCenterStore` holds the marked tab, SDK ID, workspace, voice state and projection. `CommandCenterSessionCoordinator` creates an ordinary tab, marks it, then calls `chat:start` with the fixed head-of-engineering persona. Put the persona resolver in `chat-state`, keyed by validated `commandCenterOrigin`, so both Command Center and regular-chat sends into that tab attach the same prompt on every `chat:continue`. Extend `rpc-chat.types.ts`, `chat-rpc.schema.ts` and `chat-session.service.ts` to pass that optional prompt to inactive SDK resume. Also thread it through `chat:resume {activate:true}` and `ensureSessionActiveForRewind` (`chat-session.service.ts:1183-1192,1418-1427`); history-only resume remains unchanged. Test start, process restart, regular-chat send after restart, activate/rewind and ordinary unmarked tabs. Never restore a voice-active lock.
2. **Stream and prompts.** The page selects the marked tab's `ChatStore` transcript, streaming/turn state, pending questions and session identity. The existing `ChatMessageHandlerService` handles all messages, including SDK rekey and question routing. The page may use selectors in `chat-state`/`chat-streaming` for a specific tab but creates no root handler or duplicate transcript reducer. Test interleaved events from two tabs: only the marked root updates its text/voice; regular chat sees the same tab and can answer pending prompts.
3. **Send lock.** `CommandCenterSendLockService` is transient, keyed by both tab and SDK ID; update atomically on `session:id-resolved`. Engage only while voice mode is active; release on mute, stop, page teardown and renderer reload. Regular-chat queued content already present when it engages is held in `TabState`, never cleared or flushed by `sendQueuedMessage`; it can be sent after unlock with user intent. Gate keyboard, text, slash, queued and direct sender routes. Stop response, permission decisions and question answers stay enabled. The Command Center owner token permits its turn; other roots and ordinary tabs stay writable. Test lock engaged during a pending queued flush and tab→SDK rekey.
4. **Owned projection.** Stable IDs: `root:<sdkId>`, `cli:<agentId>`, `sdk:<parentId>:<agentId>`, `child:<sessionIdOrTabId>`, `tribunal:<runId>`, `phase:<runId>:<phase>`. Reconcile monitor snapshots, live child descriptors and persisted `session:list` organization rows on return; replace provisional child tab ID with SDK ID without duplicating the node. Keep terminal nodes for the current root. Ignore unknown/unattributed work and all sibling roots. Existing session-child live-parent rule (`session-spawner.service.ts:269-275`) means root chat stays alive during delegation. The accessible list keeps every owned item even when the scene caps draw at 24.
5. **Tribunal proposal, confirmation and registration.** On an explicit Council/Forge/Race/Crucible request, the coordinator sends a discovery-only turn to the root chat. Ptah calls `ptah_agent_list`, skips AT LIMIT lanes (the host spawn refusal remains the final backstop) and honors the saved `agent:getConfig.preferredAgentOrder` and `disabledClis` (`agent-orchestration-config.component.ts:601-629`; `providers-settings-state.service.ts:765-780`; `agent-rpc.handlers.ts:360-375`). The Tribunal wizard roster is only an in-memory signal (`tribunal-wizard.component.ts:180,251-252`), so it is not a saved preference. Ptah proposes a `VendorLane[]` from live rows, one per family where possible, and calls the existing tab-scoped `AskUserQuestion` tool with a bounded delimited payload containing nonce, root ID, mode, lane IDs/roles/names, objective and rounds. The page parses it as untrusted input, requires at least one lane, checks lane ID/role syntax, `rosterIsLaunchable` (`tribunal-roster-rules.ts:42-47`), move-specific round bounds (`tribunal-run.service.ts:109,230-232`) and current root, then shows a confirm card with lanes, mode and rounds. The voice loop speaks one short summary. `AskUserQuestion` choices are **Decline** first and **Confirm** second. Only an explicit click or focused key activation on the card sends Confirm; speech never does. `ChatStore.handleQuestionResponse` posts `{id,answers:{[questionText]:"Confirm"}}` through `PermissionHandlerService` to `ASK_USER_QUESTION_RESPONSE` (`chat.store.ts:499-509`; `permission-handler.service.ts:567-578`), which resumes the blocked root turn. Its backend auto-selects the first option after five minutes or failed delivery (`ask-user-question.service.ts:177-205,233-258`), so Decline must be first. The discovery turn must terminate after the answer without spawning; the coordinator validates the matching nonce and exact Confirm before preparing a separate launch turn. Neither the discovery prompt nor its answer grants the model permission to spawn. Deny, timeout, exit, stale/malformed proposal or no launchable roster create no task or manifest and return to ordinary chat with a concise explanation. After explicit confirmation and completion of the discovery turn, the coordinator revalidates the immutable roster, calls `tasks:create` where required (`tribunal-run.service.ts:248-267`), persists `{runId,rootTabId,rootSdkId,move,specTaskId,laneIds/roles,rounds,startedAt}`, then sends the framed root `chat:continue`. The framing helper (`tribunal-run.service.ts:150-180,315-363`) tells the head-of-engineering Ptah to conduct this approved run and return to its normal role afterward; it does not replace the session persona. Tagged `[tribunal:<laneId>] (<role>)` tasks (`tribunal-run.service.ts:397-409`) bind lanes to the UUID run ID. The pure extracted `tribunal-phase-derivation.ts`, exported from narrow `src/phase.ts`, accepts `{move,specTaskId,laneBindings,agents,artifacts}` for both surfaces. Read `tasks:get`/`tasks:getRoundJudge` only for the registered folder (`tribunal-progress.service.ts:480-505,532`); missing artifacts show phase unavailable with reason. Unregistered tagged work shows provisional lane state keyed by `{rootSdkId,turnId}`. During a long conductor turn, queue one barge-in utterance; status-on-demand reads the latest projection without another turn, and Stop remains actionable via `chat:abort`. Test no spawn during discovery or before Confirm, ordered answer-to-turn-completion-to-registration-to-framed-launch, timeout/deny/stale nonce, AT LIMIT/preferences, two runs, restart and missing folder.
6. **Status and narration.** For an on-demand status turn, prepend a bounded, clearly delimited `COMMAND_CENTER_STATUS_CONTEXT` block (≤2 KB) to that root's outgoing prompt with node IDs, states and ages; exclude secrets and raw tool output. It becomes transcript input by design, so format it as ephemeral context and test that ordinary chat sends receive no block and history replays safely. The persona instructs Ptah to distinguish running, completed and failed. Automatic status narration uses no synthetic user turn. Queue/dedupe by `{root,workId,stateOrPhase}` at turn boundaries; stale states are revoked. A visible pending card remains actionable if speech fails.

## Voice loop and failure seams

`CommandVoiceLoop` owns one microphone stream, Web Audio VAD, transcription, chat turn, bounded sentence chunking, TTS and ordered playback. Adapt property-hub `vad.ts`, `sentence-chunker.ts`, `tts-playback-queue.ts` and `voice-session.service.ts` behavior only after the cross-repository licence decision; otherwise implement equivalent small logic locally. Request `echoCancellation`, `noiseSuppression`, `autoGainControl`. Use one AudioWorklet PCM ring buffer with a short pre-roll and encode each utterance to `audio/wav` before `voice:transcribe`; a recorder started on onset cannot preserve pre-roll. Reject empty/noise clips, cap payload below 25 MB, and set explicit RPC timeouts. A nonempty transcript answers a pending ordinary question or starts one serialized `chat:continue` turn.

Only assistant conversational text goes to speech: strip code fences, diffs, tool calls/results, raw links and secret-shaped strings. Limit a reply to 600 characters or four sentences, and automatic status to 180 characters, with a short “See text for the rest” cue. Full text remains in the compact view. Bound TTS requests to two in flight; generation IDs revoke stale clips on barge-in, stop, mute and navigation. Host synth has no cancel, so report cold-worker and post-barge-in latency separately. During playback, require sustained user onset plus echo correlation; stop audio immediately on real barge-in, queue one utterance until the current tool/turn completes, and reserve `chat:abort` for explicit Stop response. Release tracks, context, worker, URLs, timers and listeners on exit.

Mic denied → text/graph/settings remain usable. Missing provider/key → voice settings and text fallback. Transcription failure → no chat turn. TTS/playback failure → full text and retry. Chat/tool failure → safe error and current node state, without raw exception or replay. Canvas 2D unavailable → accessible list only. Retry only idempotent reads with bounded backoff. Existing Electron mic permission policy remains audio-only unless evidence shows failure.

Repeating CSS motion changes only transform/opacity. `CommandOverlayComponent`, `CommandVoiceHudComponent`, `CommandPendingInputComponent`, `CommandWorkListComponent`, `CommandSessionControlsComponent` are standalone OnPush/input/output presentational units. The keyboard list names node, provider, parent and state, and supports selection. Scene cap 24 visual nodes; overflow completed nodes collapse to a count chip while the list/status retain all nodes.

Resolve provider art by provider ID through the narrow secondary entry and `PROVIDER_BRAND_SLUGS`; DOM uses `ProviderMarkComponent`, unknown IDs use monograms. No `glm→ollama` alias. Use cached shield art for Tribunal, ≥32 px satellites, ≥12 px chip marks and theme-aware chips. Follow rev-3 72 px header, 336 px rail, responsive stack, focus rings, 44 px targets and reduced-motion behavior. Route guard and nav changes are Electron-only; no VS Code active page.
