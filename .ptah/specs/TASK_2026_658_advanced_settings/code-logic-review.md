## Findings

1. **Serious — raw host exception displayed under a field.** `libs/backend/rpc-handlers/src/lib/handlers/settings-rpc.handlers.ts:181-189` returns `error.message` from any failed `setConfiguration`, and `libs/frontend/chat/src/lib/settings/advanced/advanced-settings-group.component.ts:419-420,432-434` renders it verbatim. A write failure containing a file path, provider detail, or sensitive text becomes visible in the webview. The shared validator's safe range message does not make arbitrary host exceptions safe. Return a fixed public write error from the host, or show only a recognized validator error under the field; keep exception detail in host logs. Add a test with an exception containing a sentinel secret and assert it is absent from the UI.

2. **Serious — the five-second read timeout never starts if the host bridge is not ready.** `libs/frontend/chat/src/lib/settings/advanced/advanced-settings-group.component.ts:284-303` waits for each `rpcCall` before it can show Retry. But `rpcCall` awaits the unresolved readiness promise *before* installing its timeout (`libs/frontend/core/src/lib/services/rpc-call.util.ts:60-67,115-133`). If the host fails before sending `WEBVIEW_READY`, the group stays in Loading indefinitely and the promised Retry control never appears. Bound readiness plus the response wait with one deadline, or wrap this group’s read in an independent five-second deadline; test a `rpcCall` promise that never settles.

3. **Moderate — a malformed successful read looks ready.** `libs/frontend/chat/src/lib/settings/advanced/advanced-settings-group.component.ts:284-308` checks the envelope's two `success` flags but not that `data.value` is present. A host or bridge response `{success:true,data:{success:true}}` therefore enters `ready`, then `numberText` shows an empty number or `booleanValue` shows the descriptor default (`advanced-settings-group.component.ts:313-329`) while the saved value is unknown. Reject a missing `value` as a read failure with Retry; retain the separate stored-invalid notice for a present but invalid value. Add the malformed-success case to the read tests (`advanced-settings-group.component.spec.ts:111-211`).

## Five logic questions and verification

1. **Silent failure:** a malformed successful read becomes a ready state with a fabricated default/blank (finding 3); `file:line` evidence above.
2. **Unexpected user action:** opening the settings group while the host bridge never becomes ready leaves Loading forever (finding 2); saving during a host write failure may reveal the exception under the control (finding 1).
3. **Wrong answer from input data:** an invalid stored boolean is displayed as its default with a visible stored-invalid notice (`advanced-settings-group.component.ts:313-319,355-359`), so it is flagged; a missing value in a malformed success envelope lacks that notice (finding 3).
4. **Dependency failure, timeout, wrong shape:** response timeouts lead to Retry (`advanced-settings-group.component.ts:284-303`), but the readiness wait has no deadline (finding 2); write timeout leaves the prior display and says unconfirmed (`:415-436`); malformed successful reads have the gap in finding 3.
5. **Unstated requirement:** public error copy needs a boundary between validator advice and internal host exceptions (finding 1); the plan approved numeric maxima but did not define this exception boundary (`batch-frontend-report.md`, “Host error text” decision).
