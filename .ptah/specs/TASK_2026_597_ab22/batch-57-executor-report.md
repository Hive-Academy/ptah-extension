## Deviations

- Task 57.3 says to follow "the existing `settings:*` entries in the same specs", but none of the four specs names individual methods. The host surfaces are derived from manifest × profile. A method that every host serves therefore changes no frozen excluded list. To record the method on every surface anyway, each spec gets an explicit "registered" assertion, and the allowlist spec gets an ownership block modelled on the existing `wizard:get-resumable-run` block.
- Invalid params return a structured `{success:false, error}` (the `settings:*` pattern) rather than throwing `RpcUserError` (the `sessionOrganization` pattern). The batch named `SettingsRpcHandlers` as the pattern, and the shared result type already has `error?: string`. The invalid-params text is deliberately different from `'unavailable'`, so the banner can tell a host without the budget service from a bad request.
- The sibling schema file was created because both reference handlers (`settings`, `sessionOrganization`) keep their zod schemas in a `*-rpc.schema.ts` sibling.
