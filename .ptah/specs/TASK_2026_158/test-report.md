## 4. New specs added (Batch 7 gap-closing only)

Both close a genuine coverage gap; neither duplicates existing assertions. No production code was touched.

1. **`libs/backend/skill-synthesis/src/lib/spec-harvester.concurrent-attribution.spec.ts`**
   Closes the gap between the store-level R4.3 regression (real SQLite, hand-constructed calls simulating two tasks) and the harvester-level provenance tests (real fixture folders + real store, but only ever one spec per `harvest()` call). This file drives the **real `SpecHarvesterService`** over **two real `.ptah/specs/TASK_*` fixture folders** with the same executor slug and overlapping file-mtime windows, processed in a **single `harvest()` pass**, against a real (in-memory) `better-sqlite3` connection with no store mocking. Two tests: (a) no-cross-attribution with a legacy row present in the overlap zone untouched by either exact pass, (b) idempotency across two concurrent specs. Both pass.

2. **`libs/frontend/skill-synthesis-ui/src/lib/services/skill-clones-state.perf.spec.ts`**
   Closes the gap between the existing "ONE getScorecards call" correctness test (asserted with a 3-clone/1-agent-slug fixture, which cannot distinguish a batched call from a lucky single-clone case) and the NFR's explicit 200-clone scale claim. Builds 200 synthetic clones (150 agent-kind), asserts `getScorecards` is called **exactly once** with all 150 agent slugs. Passes — confirms the implementation has no chunking/per-card fallback path that would only surface at scale.
