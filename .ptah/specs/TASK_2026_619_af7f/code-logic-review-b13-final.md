## New findings

1. **MODERATE — a directory delete discards supported source edits from the same batch during the delete cooldown.** `onBatch` collects eligible source changes in `kept`, but once any extension-less delete is found it calls `requestDeleteFullRun()` and returns before scheduling `kept` (`libs/backend/thoth-runtime/src/lib/workspace-index-lifecycle.ts:263-295`). If the delete is inside the cooldown, the only work is the trailing full run at the window end (`libs/backend/thoth-runtime/src/lib/workspace-index-lifecycle.ts:304-318`), so an unrelated saved `.ts` file that would normally be reindexed after `debounceMs` can remain stale for up to 30 seconds. The trailing census eventually makes the answer correct, but this is not merely the documented dotted-directory trade-off: it drops a supported, non-deleted source update on a common mixed watcher batch. No test exercises a directory delete plus a source update in the cooldown window (`libs/backend/thoth-runtime/src/lib/workspace-index-lifecycle.spec.ts:251-277`, `339-357`).

The trailing callback does not start concurrent full runs: it delegates to `requestFullRun`, which records one follow-up when a run is in flight (`libs/backend/thoth-runtime/src/lib/workspace-index-lifecycle.ts:313-318`, `364-399`); disposal clears the queued timer and makes an already-entered callback a no-op (`libs/backend/thoth-runtime/src/lib/workspace-index-lifecycle.ts:244-258`, `313-317`). Jest's modern fake timers advance `Date.now()` with `advanceTimersByTime`, so the supplied cooldown tests are valid for this clock/timer pairing (`libs/backend/thoth-runtime/src/lib/workspace-index-lifecycle.ts:306-318`, `libs/backend/thoth-runtime/src/lib/workspace-index-lifecycle.spec.ts:75-82`, `339-355`). On the Windows host, `node:path` parses backslash paths before `extname`, and the existing Windows-path tests exercise source event normalization (`libs/backend/thoth-runtime/src/lib/workspace-index-lifecycle.ts:1`, `274`, `libs/backend/thoth-runtime/src/lib/workspace-index-lifecycle.spec.ts:157-168`, `305-311`); no Windows-specific defect was found.
