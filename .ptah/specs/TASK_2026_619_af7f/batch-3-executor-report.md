## How each listed risk and assumption was handled

- **Risk row 1 (transport; `mcp-serve` exposes only agent tools, and the CLI never starts the HTTP MCP).** The bench owns a host process that makes the same `withEngine` full boot as `mcp-serve` and then calls `startCodeExecutionMcp`. Calls therefore go through the real HTTP server, `handleMCPRequest` and the CLI adapters. `startCodeExecutionMcp` swallows errors, so the host checks `getPort() !== null` itself and fails loudly. Scorecard host label: `cli-headless`.
- **Assumption: CODE_EXECUTION_MCP resolves in the CLI container.** Verified at runtime (smoke: server started, 58 tools listed). No blocker. The host still carries an explicit `BLOCKER:` fatal for a future container that drops it.
- **Risk row 2 (real `~/.ptah` DB).** Five layers. (1) HOME/USERPROFILE/APPDATA/LOCALAPPDATA/XDG point at a temp dir. (2) Explicit `PTAH_CONFIG_PATH` (userDataPath) and `PTAH_DB_PATH`. (3) The host refuses to boot unless all three paths are inside the isolated home and `os.homedir()` equals it. (4) The launcher rejects a host whose reported home is not the temp home. (5) A read-only SHA-256 + mtime + size guard on the real `ptah.sqlite` and `-wal`, before and after every run, including failed boots. The smoke shows the guard unchanged and the bench pid absent from the real DB's holders.
- **Assumption: HOME/USERPROFILE isolation covers every path.** It covers what the smoke exercised: `cli-token-vault.ts:30` and `register-thoth-libraries.ts:66` use `os.homedir()` and resolve into the temp home. No real-home write was observed. Code paths not exercised by a `tools/list` and two calls (memory seeding, the lifecycle scenarios) are covered by the guard on every later run, not by inspection.
- **Edge case: building / unavailable / unknown coverage.** Classified and scored as errors. `building` is retried after `retryAfterMs`, with the wait capped and every attempt counted (spec: "retries building after the hint", "outlasts the budget").
- **Edge case: truncation and spool.** Any output-budget trailer counts as truncated. An absolute spool path is checked for containment in the workspace root, case-folded on win32. A relative "under the workspace root" locator counts as ours only when the file exists under our root. "system temp directory" and save failures count as not in the workspace (spec covers inside, outside, temp-label and save-failure cases).
- **better-sqlite3 ABI.** The root module loads under Node 24 (ABI 137). The bundle keeps it external and resolves it from the main checkout's `node_modules`.

## Plan deviations

1. **Module-boundary assumption was false.** `tags: ["type:tool"]` matches no depConstraint, so `@nx/enforce-module-boundaries` failed with "A project without tags matching at least one constraint cannot depend on any libraries". Batch 1 imported no lib, so it never hit this. Fix inside the owned `project.json`, without touching `eslint.config.mjs`: added the `scope:cli` tag, whose constraint allows `scope:shared | scope:cli | scope:extension` (platform-core, cli-engine, vscode-core). Batch 4 (Electron) will need its own decision; `scope:cli` does not allow `scope:electron` libs.
2. **Imports beyond "cli-engine and vscode-core only".** The host also imports `PLATFORM_TOKENS` from `@ptah-extension/platform-core`, to set `mcpPort = 0` through the product's own `setConfiguration`. The launcher imports `killProcessTree` from platform-core instead of duplicating a tree kill.
3. **`build-host` is a composite.** The CLI container forks `integrity-worker.mjs`, `embedder-worker.mjs` and `workspace-watch-host.mjs` from its bundle's `__dirname`, and needs `wasm/` for tree-sitter. The first smoke died with `Cannot find module …\dist\tools\mcp-bench\integrity-worker.mjs`. So `build-host` builds the entry plus those three bundles and copies the wasm, mirroring `apps/ptah-cli` targets. The banner renames `createRequire` to `__esm_createRequire`, because an unminified bundle already declares `createRequire` (`SyntaxError: Identifier 'createRequire' has already been declared`).
4. **`thoth: 'oneshot'`.** This opens and migrates the isolated SQLite file so the symbol and memory layers resolve, without starting cron, the gateway or the memory triggers.
5. The batch lists no spec for Task 3.1. Its classifier and recorder are tested inside `host-launcher.spec.ts` over the real transport, which keeps the batch at 6 files.
