# External research: free-form agent HTML in an app

Research checked 2026-10-20. **Decision supported:** whether Ptah should add an isolated HTML artifact surface alongside its existing dashboard catalog. This is a recommendation for the architect, not an implementation decision. “UNVERIFIED” means the cited public material did not establish the detail.

## Summary

- **Closest precedent:** t3code lets an agent publish a self-contained HTML page into a conversation, with scripts and theme updates. Its current web source renders the page from an asset URL in an iframe with `sandbox="allow-scripts allow-forms"`, deliberately omitting `allow-same-origin`; the server also returns a CSP `sandbox` directive. [User guide](https://github.com/pingdotgg/t3code/blob/main/docs/user/html-renders.md), [frame source](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/files/BrowserDocumentFrame.tsx), [server source](https://github.com/pingdotgg/t3code/blob/main/apps/server/src/http.ts).
- **Claude Code mods are a different model:** a mod returns a host-rendered tree of `Box`, `Text`, `Button`, etc. for panes and other render sites; its JavaScript runs with the user's permissions and is explicitly unsandboxed. A mod pane is not evidence for rendering arbitrary agent HTML safely. [Interface guide](https://code.claude.com/docs/en/plugins/mods/interface), [mods overview](https://code.claude.com/docs/en/plugins/mods/overview).
- **MCP Apps supplies a portable bridge:** an MCP server advertises an HTML `ui://` resource; the host loads it in a sandboxed iframe and exchanges JSON-RPC messages over `postMessage`, with declarative network allowlists and host-provided theme/context. [Overview](https://apps.extensions.modelcontextprotocol.io/api/documents/overview.html), [CSP guide](https://apps.extensions.modelcontextprotocol.io/api/documents/csp-and-cors.html).
- **Claude Artifacts and ChatGPT Canvas prove demand for a separate creative surface, but do not publish enough iframe internals to copy wholesale.** Claude documents a sandboxed `*.claudeusercontent.com` viewer origin for Claude Code artifacts; OpenAI documents HTML/React preview in Canvas, while the public Canvas help does not specify its sandbox attributes or bridge. [Claude artifact docs](https://code.claude.com/docs/en/artifacts), [OpenAI Canvas announcement](https://openai.com/index/introducing-canvas/), [OpenAI Canvas help](https://help.openai.com/en/articles/9930697-what-is-the-canvas-feature-in-chatgpt-and-how-do-i-use-it).
- **Recommendation sketch:** preserve Ptah's schema blocks for small, data-backed summaries and add a versioned HTML artifact for large visual answers, rendered in an opaque-origin iframe with a minimal validated bridge and default-deny network policy. This follows t3code's artifact precedent and MCP Apps' isolation/bridge pattern. [Ptah surface catalog](../../../../.claude/skills/ptah-surface-authoring/references/catalog.md), [t3code frame source](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/files/BrowserDocumentFrame.tsx), [MCP Apps security](https://apps.extensions.modelcontextprotocol.io/api/documents/overview.html#security).

## Per-product findings

### Claude Code mods

The mod author writes a plugin manifest, `hooks.json` and JavaScript/TypeScript handlers. Claude Code calls handlers for `session.start`, `command.run` and `ui.render`; `$.ui.open()` creates a pane and `ui.render` returns an element tree from `$.ui.resolve(e)`. The pane appears beside the transcript in a wide terminal or above the prompt in a narrow one; the same tree is rendered by terminal, Desktop Code tab or VS Code. This is a host component API, not raw HTML, `srcdoc`, an iframe or a webview in the documented example. [Overview](https://code.claude.com/docs/en/plugins/mods/overview), [worked pane example](https://code.claude.com/docs/en/plugins/mods/interface#build-a-pane-with-tabs), [element tree](https://code.claude.com/docs/en/plugins/mods/interface#build-a-tree-from-elements).

Data enters through hook event arguments and shared module variables; callbacks such as `Button.onPress` modify state and call `$.ui.invalidate('ui.render')` to redraw. `$.state` survives module reloads within a session, while `$.store` persists JSON in the plugin's store across sessions until deleted/cleaned up. No `postMessage` bridge is involved in this documented UI path. [Mod interface and state guide](https://code.claude.com/docs/en/plugins/mods/interface#keep-state).

Security is materially different from an artifact: Anthropic says mods run with the user's permissions, can read files/secrets and make network requests, and are **not sandboxed**; even Claude Code's Bash sandbox does not confine a process a mod starts. Treat a mod as installed trusted code, not as a viewer for untrusted agent output. [Trust section](https://code.claude.com/docs/en/plugins/mods/overview#decide-whether-to-trust-a-mod).

### t3code

The [official user guide](https://github.com/pingdotgg/t3code/blob/main/docs/user/html-renders.md) calls these “visual replies”: an agent builds a self-contained HTML page that appears above its written reply on web, desktop and mobile. Scripts run in the page; the page follows the app's theme, supports fullscreen, embeds local images at publication, and is deleted with its thread. The guide says agents check work with screenshots from a separate headless browser before publishing; that is a preview/verification step, not the live frame. [Guide source](https://github.com/pingdotgg/t3code/blob/main/docs/user/html-renders.md).

The current [BrowserDocumentFrame.tsx](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/files/BrowserDocumentFrame.tsx) has an `HtmlRenderDocument` iframe with `src` set to an asset URL, **not `srcdoc`**, and `sandbox="allow-scripts allow-forms"`. Its comment says omitting `allow-same-origin` gives an opaque origin and keeps the page out of the app session. The host posts theme and shortcut data to `contentWindow`; incoming messages are checked against the frame's `contentWindow`, parsed by named readers, and used for height, keyboard/link and image interactions. Thus this is a narrow bridge, not DOM access. [Frame source around iframe and messages](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/files/BrowserDocumentFrame.tsx#L1058-L1406).

The [server asset response](https://github.com/pingdotgg/t3code/blob/main/apps/server/src/http.ts#L1729-L1740) uses `Content-Security-Policy: sandbox allow-scripts allow-forms allow-popups allow-downloads` for HTML documents. That header grants more capabilities than the embedded iframe (`allow-popups`, `allow-downloads`), apparently for standalone asset viewing; the iframe attribute remains narrower. **Important limit:** this CSP line is a sandbox directive, not a `default-src 'none'` or network allowlist, so it does not prove a default-deny outbound network policy. [Server source](https://github.com/pingdotgg/t3code/blob/main/apps/server/src/http.ts#L1729-L1740).

The [issue proposing web file preview](https://github.com/pingdotgg/t3code/issues/5100) mentions `srcdoc` as a *possible first implementation* for ordinary workspace HTML files. It should not be confused with the current published visual-reply frame, which uses an asset `src`. t3code also documents MCP Apps from tool results as a separate path; those can call server tools and send chat messages with host approval, whereas a visual reply is a published HTML page. [Visual reply and MCP App guide](https://github.com/pingdotgg/t3code/blob/main/docs/user/html-renders.md).

### Claude.ai Artifacts

Claude's current [help page](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them) says artifacts can be single-page websites, dashboards and interactive tools, open beside a conversation, and are saved in the Artifacts tab for later editing and sharing. The current template system and older “legacy artifacts” differ, so HTML export should not be assumed to describe every artifact type. [Help page](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them).

For **Claude Code-published artifacts**, Anthropic documents a live page at a private claude.ai URL that updates as the session continues. The viewer loads the artifact from a sandboxed `*.claudeusercontent.com` origin; Anthropic enumerates permitted external font and JavaScript CDN hosts. The page can be private, organization-shared or public. The public page does **not** state the precise iframe `sandbox` attributes, CSP header or host/iframe messaging protocol; these remain **UNVERIFIED** for Claude.ai. [Claude Code artifact guide](https://code.claude.com/docs/en/artifacts), [viewer domain/network section](https://code.claude.com/docs/en/artifacts#allowlist-the-viewer-domain).

### ChatGPT Canvas and OpenAI Apps SDK

OpenAI says Canvas can render HTML and React code and is a side workspace for writing and coding. Its help page discusses web preview, user confirmation for communication with unfamiliar third parties, and configurable Canvas code-execution/network controls for Enterprise. The public material checked does **not** identify Canvas' exact frame origin, iframe attributes, CSP or messaging bridge: **UNVERIFIED**. Canvas should be counted as a product example, not an implementation blueprint. [OpenAI Canvas announcement](https://openai.com/index/introducing-canvas/), [Canvas help](https://help.openai.com/en/articles/9930697-what-is-the-canvas-feature-in-chatgpt-and-how-do-i-use-it).

OpenAI's **plugin UI / Apps SDK** is better specified. Its MCP server returns HTML UI resources linked to selected tools with `_meta.ui.resourceUri`; ChatGPT renders components in an iframe and uses MCP Apps JSON-RPC over `postMessage` for initialization, tool input/results, tool calls, follow-up messages and model-visible context. `window.openai` is an optional ChatGPT-specific extension, with widget state APIs for persistence. OpenAI directs authors to declare `connectDomains`, `resourceDomains` and, when needed, `frameDomains`; nested frames are blocked by default. This is server-authored UI tied to tools, not proof that ChatGPT Canvas uses the same implementation. [OpenAI UI guide](https://developers.openai.com/plugins/build/chatgpt-ui).

### MCP-UI and MCP Apps (SEP-1865)

The legacy [MCP-UI protocol](https://mcpui.dev/guide/protocol-details) describes `ui://` HTML resources rendered in a sandboxed iframe and `window.parent.postMessage` actions. The newer [MCP Apps overview](https://apps.extensions.modelcontextprotocol.io/api/documents/overview.html) standardizes UI resource discovery and a JSON-RPC bridge: a tool advertises `_meta.ui.resourceUri`; the host reads HTML, renders an iframe, sends tool input/results and host context, and may broker `tools/call` or `ui/message`. The specification originated in [SEP-1865](https://github.com/modelcontextprotocol/modelcontextprotocol/pull/1865). A UI resource can be arbitrary HTML/CSS/JS even though the *protocol envelope* is structured; a fixed visual component catalog is not required. [MCP Apps overview](https://apps.extensions.modelcontextprotocol.io/api/documents/overview.html), [SEP-1865](https://github.com/modelcontextprotocol/modelcontextprotocol/pull/1865).

MCP Apps specifies sandboxed iframes without host DOM/cookie/storage access, declarative CSP domains (`connectDomains`, `resourceDomains`, optional `frameDomains`), and no external connections when domains are not declared. The host supplies light/dark theme, locale, dimensions and platform during initialization, later notifying changes; CSS custom properties support visual blending. An app can be inline or request fullscreen, but the host decides. MCP Apps' resource URI is a delivery/discovery mechanism; **it is not required for a Ptah-local HTML artifact unless Ptah wants MCP server interoperability**. [Overview and security](https://apps.extensions.modelcontextprotocol.io/api/documents/overview.html), [CSP/CORS guide](https://apps.extensions.modelcontextprotocol.io/api/documents/csp-and-cors.html).

## Safe free-HTML pattern for Ptah

The following is an **inference/recommendation**, derived from [t3code's frame/server source](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/files/BrowserDocumentFrame.tsx), [MCP Apps security](https://apps.extensions.modelcontextprotocol.io/api/documents/overview.html#security), [MCP Apps CSP guidance](https://apps.extensions.modelcontextprotocol.io/api/documents/csp-and-cors.html), [MDN iframe sandbox guidance](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe), and [Electron security guidance](https://www.electronjs.org/docs/latest/tutorial/security). No Ptah implementation was built or tested.

1. Store each generated document as an immutable, versioned artifact with metadata (title, source turn, creation time, byte count, optional attached assets). Make replacement a new version and render only a completed document; show streamed generation as escaped source/progress until it is complete. This avoids executing half-written scripts and preserves reproducible history. **Inference**; t3code's thread-owned published pages and Claude's versioned artifacts support the lifecycle model. [t3code guide](https://github.com/pingdotgg/t3code/blob/main/docs/user/html-renders.md), [Claude artifact guide](https://code.claude.com/docs/en/artifacts).
2. Render the document only in a nested `<iframe sandbox="allow-scripts">` (add `allow-forms` only if required), without `allow-same-origin`, `allow-popups`, `allow-top-navigation` or `allow-downloads` by default. Give it an explicit title and user-controlled open/close/fullscreen. Do not bind raw HTML to Angular `[innerHTML]` in the host. MDN warns that `allow-scripts` plus `allow-same-origin` on same-origin content can defeat sandboxing; t3code omits the latter. [MDN iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe), [t3code frame](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/files/BrowserDocumentFrame.tsx).
3. Choose delivery deliberately: `srcdoc` is simple for a small, truly self-contained page, but it is an HTML injection sink and inherits URL-resolution behavior that needs review; a dedicated custom/asset protocol or URL is better for persisted documents and attached images, with a separate origin and response CSP. A custom protocol's exact Electron/VS Code behavior needs a prototype. **Inference**, grounded in [MDN `srcdoc`](https://developer.mozilla.org/en-US/docs/Web/API/HTMLIFrameElement/srcdoc), [t3code's asset-URL frame](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/files/BrowserDocumentFrame.tsx), and [MCP Apps CSP/CORS](https://apps.extensions.modelcontextprotocol.io/api/documents/csp-and-cors.html).
4. Enforce artifact-specific CSP with `default-src 'none'`; permit inline style/script only as required to support authored single-file HTML, use a nonce/hash or controlled wrapper where feasible, allow `data:` images if needed, and default `connect-src`, `form-action`, `frame-src`, navigation and external assets to none. Any external domain should be reviewed/allowed explicitly; note that t3code's visible CSP sandbox directive alone does **not** enforce this network default. **Inference**, based on [MCP Apps declarative deny-by-default domains](https://apps.extensions.modelcontextprotocol.io/api/documents/csp-and-cors.html), [t3code server CSP](https://github.com/pingdotgg/t3code/blob/main/apps/server/src/http.ts), and [MDN CSP sandbox](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/sandbox). A CSP `<meta>` cannot express every header directive; verify the final response policy in each host. [MDN CSP sandbox](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/sandbox).
5. Keep Electron renderer `nodeIntegration` off, `contextIsolation` on, and its sandbox on for untrusted content. Deny unexpected navigation, window opening, downloads and permissions at host level. The iframe must never receive a preload/Node API. [Electron security checklist](https://www.electronjs.org/docs/latest/tutorial/security). Apply the analogous webview CSP/navigation controls in VS Code. **UNVERIFIED:** the exact current Ptah host settings were outside this read-only research scope.
6. Use a versioned `postMessage` protocol with a fresh frame/session token and strict `event.source === iframe.contentWindow` checks, message type/size validation, no privileged generic RPC, and explicit capabilities such as `theme`, `resize`, `requestOpenLink` and `artifactAction`. `event.origin` can be `"null"` for opaque origins and is not sufficient alone; source/token checks matter. Host owns all tool invocation and link opening. This is an **inference** from [t3code's source checks](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/files/BrowserDocumentFrame.tsx) and [MCP Apps' brokered JSON-RPC channel](https://apps.extensions.modelcontextprotocol.io/api/documents/overview.html). Start with a one-way theme/data message and optional bounded resize; add actions only for a demonstrated use case.
7. Put byte limits on HTML, image attachments and messages, plus a maximum frame height and cleanup on close. Treat scripts as potentially infinite loops: isolate and allow the user to close/reload the frame. Exact budgets need profiling on Ptah's Electron and VS Code surfaces. **Inference**; [MCP-UI's resource limits](https://mcpui.dev/guide/protocol-details) and [MCP Apps' host-controlled dimensions](https://apps.extensions.modelcontextprotocol.io/api/documents/overview.html) show the relevant controls.

## Recommendation sketch

Recommend a **hybrid** for the architect to assess: keep `ptah-ui`/surface catalog blocks for concise verified summaries and add a separate “HTML artifact” output type for prompts asking for a dashboard, prototype, report or interactive explanation. The agent emits a self-contained HTML document or writes one to a file, while the host stores it as a versioned artifact and renders it in an isolated frame in the conversation or display panel. This is justified by the catalog's plain-text limits and t3code's demonstrated visual-reply path. [Ptah catalog](../../../../.claude/skills/ptah-surface-authoring/references/catalog.md), [t3code guide](https://github.com/pingdotgg/t3code/blob/main/docs/user/html-renders.md).

For a first slice, accept only local/self-contained HTML and embedded or approved attached images; send theme and bounded sizing data, with no network or tool bridge by default. Provide a source tab and a visible “open larger” action. A later slice could adopt MCP Apps `ui://` discovery/bridge for third-party server-authored UI; that is a distinct interoperability decision. [MCP Apps overview](https://apps.extensions.modelcontextprotocol.io/api/documents/overview.html), [CSP guide](https://apps.extensions.modelcontextprotocol.io/api/documents/csp-and-cors.html). **Recommendation, not a committed architecture.**

## Decisions

- **Research classification:** Treat Claude Code mods as a host component precedent, not a free-HTML precedent. Alternatives were to count a pane as arbitrary HTML or to separate them. The documented `$.ui.resolve` element tree and unsandboxed mod security settle the classification; reversible as docs evolve. [Mod interface](https://code.claude.com/docs/en/plugins/mods/interface), [mod trust](https://code.claude.com/docs/en/plugins/mods/overview#decide-whether-to-trust-a-mod).
- **Precedent to prioritize:** Use t3code's visual reply as the closest product comparison; MCP Apps as the bridge/security reference. Alternatives were Claude artifacts/Canvas, whose exact frame settings are not public in checked sources. Evidence: t3code source exposes `iframe`/CSP code; MCP Apps publishes protocol and CSP; reversible if other vendors release implementation details. [t3code frame](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/files/BrowserDocumentFrame.tsx), [MCP Apps](https://apps.extensions.modelcontextprotocol.io/api/documents/overview.html).
- **Scope boundary:** v0's full-project VM preview is a different tier; Bolt/Cursor were not researched beyond relevance triage. This keeps the report focused on single-document agent output and is reversible if Ptah later targets live app preview. [v0 FAQ](https://vercel.com/docs/v0/faqs).
