# Editor-Surface Purge: Impact Report

## 1. Executive verdict

**Yes — the explorer, Monaco tabs/split panes, terminal, search, quick-open, vim, branch popover, status bar and sidebar can be purged.** Only one component consumer of the full surface exists: `electron-shell.component.ts:307` lazily mounting `EditorPanelComponent`. Everything else reaches the lib for three narrow things — git state services (`app.config.ts:54-58,183-185`; `workspace-coordinator.service.ts:104-110`), `DiffViewComponent` (`lazy-diff-view.component.ts:166`), and `EditorService.openFile` (`file-path-link.component.ts:91`). The VS Code host already serves none of it (`apps/ptah-extension-vscode/src/di/rpc-surface.spec.ts:57-68,170-171`).

**The catch:** the entire frontend git surface — every `git:*` caller and the only diff renderer — lives inside the purge target. A git lib must be carved out _before_ deletion, not after.

## 3. Git-first direction: exists vs missing

**Already exists, untouched by purge**

- 18 host-agnostic `git:*` handlers (`git-rpc.handlers.ts:98-115`) over `GitInfoService` (`git-info.service.ts:244`): `diffFile` (860), `applyHunks` with index-tree rollback (1131, 1517-1537), worktree CRUD (394-490), stage/commit/push. Consumed by agent-sdk (`worktree-hook-handler.ts:93`), task-specs (`task-sweep.service.ts:65`), cli-engine (`container.ts:404`), and the CLI (`apps/ptah-cli/src/cli/commands/git.ts:137-340`).
- SDK hook that _creates_ per-task worktrees under `.claude-worktrees/` (`worktree-hook-handler.ts:152-161,209-215`) and the `HostProfile.worktree` seam (`host-profile.ts:20-27`).
- `session:rewindFiles` per-message file/insertion/deletion set, path-validated (`session-rpc.handlers.ts:1062-1114`).
- `file:open` reference implementation on VS Code (`file-rpc.handlers.ts:43-71`); `IProcessSpawner` port (`process-spawner.interface.ts`).
- `DiffViewComponent` designed EditorService-free (4 inputs + `retryRequested`, `diff-view.component.ts:696-730`); a Monaco-free seed in `diff-display.component.ts:13,52-55`.
- Sanitised git error table (`git-read-error-messages.ts`, not barrel-exported).

**Missing**

- **Change-set view**: `GitDiffComparison = 'staged' | 'worktree'` (`rpc-git.types.ts:276`, doc at `git-info.service.ts:856`) — no ref-vs-ref diff, no changed-files-between-refs RPC. Per-turn touched paths are computed then discarded (`message-summary.utils.ts:62-108`).
- **Task ↔ worktree binding**: agent-managed via prompt only (`task-card.component.ts:45-46,435`).
- **Merge / PR**: zero backend surface; `git:push` (`git-info.service.ts:680`) is the only outbound op.
- **Open-in-external-editor**: no port. `IUserInteraction.openExternal` (`user-interaction.interface.ts:77`) is http-only on CLI (`cli-user-interaction.spec.ts:163-166`). Electron `file:open` reads content and does nothing visible (`editor-rpc.handlers.ts:262-283`) — tasks-ui `openArtifact` (`tasks-store.service.ts:1362`) is already a silent no-op there.
- **A listener host**: `GitStatusService.handleMessage` drops pushes until `startListening()` (`git-status.service.ts:269,286-290`), called only by `editor-panel.component.ts:845`. `GitBranchesService` uses a raw `window` listener (`git-branches.service.ts:179-192`), against lib rule 1.

## 5. Risks and open questions

1. **Monaco decision.** Keeping `DiffViewComponent` keeps 16 MB of assets, `MonacoLoaderService`'s 20 s poll (`monaco-loader.service.ts:70-73,150-161`), the 30-pair model cache (`diff-view.component.ts:687-692`), `provideMonacoEditor`. A non-Monaco unified-diff renderer (seed: `diff-display.component.ts`) loses glyph-margin hunk staging — the feature `hunk-apply-real-rpc.spec.ts` proves. Owner must choose.
2. **Watcher cannot narrow to `.git/`.** The `'workspace'` cause (`git-status.ts:14`) is how agent working-tree edits surface; the recursive `fs.watch` (`git-watcher.service.ts:478-499`) stays, only its tree/reread jobs go. Its churn issue (`perf-m3-watcher-churn.md:1-30`: `.nx/cache`, `.angular/cache` not excluded) is a keep-side fix.
3. **`IEditorProvider` goes dark on Electron** without the launcher calling `notifyFileOpened` — `ptah_ide` MCP editor tools and context auto-include silently return empty.
4. **CLI is a `git:*` consumer** (`git.ts:137-340`). Verify before pruning `git:checkout`/`stashList`/`tags`.
5. **Launcher transport**: `openExternal` rejects `file://` on CLI; deep links (`vscode://`, `cursor://`) vs binaries (`code -r`, `cursor`) and Antigravity detection are unspecified.
6. **Returning users** carry `editorWidth`/`editorVisible` in persisted layout blobs; restore path (`electron-layout.service.ts:580-593`) must tolerate them.
7. **Showcase pipeline**: `editor-tour` is the documented exemplar (`FOLLOW-UP.md:35`) and `prewarm.ts` targets the editor for every scene — promote another scene first.
8. **Three `git:worktreeChanged` broadcasters, one raw `window` listener** (`worktree.service.ts:251`), also cited as precedent by `tasks-store.service.ts:50` — the relocation must preserve the contract.
9. **Multi-worktree change sets** will hit the one-workspace-at-a-time watcher constraint (`git-status.service.ts:73-90`) and `GitInfoService.getWorktrees` has no cache (`:394-406`).
10. **No lazy-chunk budget** (`project.json:62-73`); after purge nothing ratchets the new git lib's size. Add one, and re-baseline `startup-tti.spec.ts` to prove the win.
11. `manifest` partition invariant (`register-rpc-surface.ts:141`, `rpc-allowlist.spec.ts`) means every phase's contract edits — `rpc.types.ts` interface + `true` map, manifest, capabilities, host profiles, three expected-absent lists — land in one commit or boot throws.
