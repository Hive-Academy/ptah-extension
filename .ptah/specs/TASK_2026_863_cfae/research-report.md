# Bug 1 root causes, ranked

1. **Shown-tab gate (certain).** The automatic effect reads only this view's `activeTab`, `tabId`, and `bannerVisible`; every one must qualify [libs/frontend/chat/src/lib/services/session-budget-actions.service.ts:140-166,199-225]. The chat component supplies its resolved active tab and budget-banner visibility [libs/frontend/chat/src/lib/components/templates/chat-view.component.ts:1020-1027,1200-1208,1343-1346]. A background tab is not evaluated. Live estimated stage counts only while the shown tab streams [session-budget-actions.service.ts:145-166].
2. **Skill probe (high).** The effect also requires `budget.autoHandoff`, `limit`, no prior wrap-up/claim or missing-skill marker, no start guard, and no permission prompt [session-budget-actions.service.ts:199-219]. Discovery queries `autocomplete:commands` in the configured workspace and matches exact `session-handoff`; errors become false [session-budget-actions.service.ts:339-361]. A false result adds the session to `autoSkillMissing`, blocking future attempts from that view [session-budget-actions.service.ts:131-135,369-379]. The repository skill is named correctly [`.claude/skills/session-handoff/SKILL.md:1-9`]; installation in the user's *runtime workspace* remains unverified. The CLI hand-off service is downstream of this command [libs/backend/cli-agent-runtime/src/lib/session-children/session-handoff.service.ts:269-270].
3. **Post-probe and queue gates (medium).** After the asynchronous probe, a tab switch, hidden banner, changed stage/setting, or start guard aborts the send [session-budget-actions.service.ts:276-296,382-403]. Permission is rechecked [session-budget-actions.service.ts:378-379]. The claim is retained after send/held-queue failure, so that session cannot retry [session-budget-actions.service.ts:299-335; libs/frontend/chat/src/lib/services/session-auto-handoff.service.ts:37-74]. Explicit cancellation also permanently marks the in-memory session [session-auto-handoff.service.ts:63-70]. Streaming alone is not a veto: the normal send path queues behind the turn [session-budget-actions.service.ts:91-108,293-318].
4. **Stage and settings (lower).** `limit` means usage reaches 100% of the configured limit; reducing `handoffPercent` alone does not reach it [libs/backend/agent-sdk/src/lib/helpers/session-budget/session-budget-stage.ts:124-136]. Provisional in-turn stages are display-only [libs/backend/agent-sdk/src/lib/helpers/session-budget/session-budget.service.ts:192-203]. The backend publishes `autoHandoff` from validated config [session-budget.service.ts:528-539]; invalid or unreadable boolean settings use the off default [libs/backend/agent-sdk/src/lib/helpers/session-budget/session-budget-config.provider.ts:87-99,122-127,148-156; libs/shared/src/lib/types/session-budget.types.ts:228-232]. Budget tokens default to 50 million and cannot be set below 1 million [session-budget.types.ts:153-172].

`git show 5e7b108d4` confirms the opt-in was added across shared settings, backend state and frontend actions. `git show 4a009eb21` confirms a later command-identity queue fix; it did not relocate the view-bound trigger.

# Bug 2 root causes, ranked

1. **Narrow arm conditions (certain).** The reducer needs both compaction settings enabled, no in-flight compaction, a matching ended turn, no later activity/prefix change, an actual `1h` cached request, a context reading, and a future fire time [libs/backend/agent-sdk/src/lib/helpers/compaction/idle/idle-session.reducer.ts:48-73,137-209]. The request tracker classifies TTL from usage and may have no request snapshot [libs/backend/agent-sdk/src/lib/helpers/compaction/idle/idle-request-tracker.ts:99-122]. TTL is 3,600,000 ms and fire fraction 0.9 [libs/backend/agent-sdk/src/lib/helpers/compaction/idle/idle-compaction.types.ts:7-9]. Minimum tokens default to 200,000, with 100,000 as the setting floor [libs/shared/src/lib/types/advanced-settings.types.ts:183-203].
2. **Session release (plausible background cause, not proven).** A per-session RxJS timer is created from reducer state [libs/backend/agent-sdk/src/lib/helpers/compaction/idle/idle-compaction.service.ts:140-204]. `session-released` clears its attempt and timer [libs/backend/agent-sdk/src/lib/helpers/compaction/idle/idle-session.reducer.ts:403-412]. Query-executor release emits that signal [libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-query-executor.service.ts:424-449], and stream end releases its compaction tap [session-query-executor.service.ts:1882-1893]. Inspect actual signal order before treating this as the observed cause. There is no explicit shown-tab gate in the idle service or fire gate.
3. **Fire-time vetoes (certain).** The gate rejects disabled settings, wrong TTL, lateness over 60 seconds/expiry, missing or small reading, activity, changed prefix, coordinator busy/claimed, rate limiting, background-subagent phase, or phase other than idle [libs/backend/agent-sdk/src/lib/helpers/compaction/idle/idle-fire-gate.ts:25-58; libs/backend/agent-sdk/src/lib/helpers/compaction/idle/idle-compaction.types.ts:9]. The sender submits `/compact` with `require-idle` [libs/backend/agent-sdk/src/lib/helpers/session-lifecycle-manager.ts:866-873], and a pre-enqueue callback vetoes changed/released sessions [libs/backend/agent-sdk/src/lib/helpers/compaction/idle/idle-compaction.service.ts:398-425]. Turn-end reading comes from the live query [session-query-executor.service.ts:507-533]. No attached webview is directly required.

# Close old session design

Default **off** because `closeTab` can interrupt dirty, streaming, resuming or background-work tabs [libs/frontend/chat-state/src/lib/tab-manager.service.ts:1483-1505]. The hand-off event carries source tab/session IDs [libs/backend/cli-agent-runtime/src/lib/session-children/session-handoff.service.ts:269-270; libs/shared/src/lib/types/messages/session-handoff.ts:7-17]. `ChatMessageHandlerService` passes it to adoption [libs/frontend/chat/src/lib/services/chat-message-handler.service.ts:249-275], and adoption returns `adopted` only when the source is found [libs/frontend/chat/src/lib/services/agent-session-adoption.service.ts:309-324; libs/frontend/chat-state/src/lib/tab-manager.service.ts:1255-1285]. Close after that event, not when the command merely queues: a newly announced session can fail to start [tab-manager.service.ts:1288-1305].

For Electron, close removes the source tab and, if orphaned across all tabs/surfaces, stops its SDK process through existing `ClosedTabSessionEnderService` → `chat:abort` [libs/frontend/chat/src/lib/services/closed-tab-session-ender.service.ts:12-29,49-85]. VS Code uses the same webview/host RPC route. Preserve persisted transcript and task files; do not delete history. Add a programmatic close path that bypasses UI confirmation only after creation and only for a clean, idle source; otherwise retain the tab and show why. Current `closeTab` searches the active partition [tab-manager.service.ts:1490-1493], so hidden workspace partitions need a safe cross-partition operation with session-id recheck.

- Short development TTL tests scheduling, not real cache-expiry economics.
- Programmatic closure must not interrupt pending subagents, permissions, streaming or dirty state; retain source on uncertainty.
- The idle background correlation is an inference until live signal/skip logs identify release, missing reading or admission as the cause.
