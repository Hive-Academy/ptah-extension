## Verdict

**Do not adopt `@copilotkit/angular` in Ptah now.** The current package is genuinely MIT-licensed and first-party, but `0.5.2` requires Angular 22 while Ptah is on Angular 21; its built-in assistant renderer writes unsanitized `marked` output to `innerHTML`; and the supported production escape hatch for a non-HTTP/custom `AbstractAgent` is documented as an Enterprise Intelligence feature. Use this research as evidence for evaluating AG-UI directly instead. [S1][S8][S14][S22]

## Paid or hosted-only features

- **Production `selfManagedAgents`**, the configuration Ptah would need for a custom postMessage/IPC `AbstractAgent`, is documented as part of the **Enterprise Intelligence tier**. The same shape is available as `agents` only for local development/prototyping. The MIT source does not contain a client-side enforcement branch at this registration point, but adopting a documented Enterprise-only production path would create a commercial-policy risk. [S8][S14]
- **Rich/durable threads and the Angular threads drawer** require CopilotKit Intelligence. The drawer explicitly stays locked unless runtime license status is `valid`/`expiring` and `checkFeature("threads")` succeeds. Hosted plans limit retention, thread count, and storage; the free Developer tier currently provides 3-day retention, 200 threads, and 1 GB. [S15][S16][S17]
- **Durable memory/recall, analytics, automatic learning/skill delivery, Channels (Slack/Teams), hosted projects/API keys, conversation history, hosted thread inspection, and plan management** are Intelligence capabilities. Cloud hosting has a free Developer tier with limits and paid Pro/Team/Enterprise tiers; self-hosting requires Team or custom Enterprise access and a license key. [S15][S16]
- **The legacy React `useCopilotChatHeadless_c` surface** is documented as Intelligence-gated. This is not the same as Angular's low-level `injectAgentStore` headless composition, which is present in the MIT package; do not infer that Angular headless signals themselves are paid. [S11][S18]
- **Public browser license key/watermark:** Angular `0.5.2` still accepts `licenseKey` and can merge it into `X-CopilotCloud-Public-Api-Key`, but its watermark implementation is compiled with `LICENSE_WATERMARK_ENABLED = false`; the current package neither renders the watermark nor logs a missing-key warning. A public key is therefore not required for ordinary MIT package use in this release. [S8][S19]

## Angular fit

**Version fit fails.** `@copilotkit/angular@0.5.2` peers are exactly `@angular/core`, `@angular/common`, and `@angular/cdk` `^22.0.0`, plus RxJS `^7.8.0`; its package declares an Angular 22 compiler/support baseline. It will not install cleanly in Ptah's Angular 21 workspace. The previous current-scope releases did support earlier majors, but adopting an old release would freeze Ptah on a pre-0.5 line and is not the “latest package” decision under review. [S1][S5]

**Framework style fits otherwise.** The first-party package is in `CopilotKit/CopilotKit/packages/angular`, uses standalone components, Angular DI, signals/computed state, `ChangeDetectionStrategy.OnPush`, and documents tests with `provideZonelessChangeDetection()` and no Zone.js dependency. Prebuilt chat, popup, sidebar, tool renderers, A2UI, Open Generative UI, and optional MCP Apps are shipped; `styles.css` is a separate explicit import. Headless use is possible through `CopilotKit`, `injectAgentStore`, `AgentStore` signals, tool/HITL registration functions, and direct agent methods without importing the stylesheet or chat components. [S5][S6][S7][S9][S11]

**Maturity:** this is first-party but young: the current-scope package was first published on 2026-06-18 and has reached `0.5.2`, last released 2026-09-08. A repository path-filtered count at 2026-09-20 found 48 commits touching `packages/angular` in the prior 30 days and 108 in 90 days, showing active development and high churn. The repository has no open issues carrying an `angular` label; GitHub search found 18 open issues mentioning Angular, including open gaps for stop/serialized send parity, a `sendMessage` convenience API, explicit effect dependencies, and automated visual regression. [S3][S20][S21]

**Parity with React:** CopilotKit does not publish a contractual “full React parity” statement. All five capabilities named in this task are implemented in Angular `0.5.2`: generative UI (typed renderers, A2UI, Open Generative UI, MCP Apps), frontend tools/actions, human-in-the-loop/interrupts, shared state through `AgentStore.state` and `agent.setState`, and headless composition. Official Angular examples list 41 supported features, 40 with runnable examples. Remaining observable gaps include the open stop/serialized-send and `sendMessage` issues and absence of Angular from automated visual-regression coverage; therefore describe it as **broad feature coverage, not proven React parity**. [S10][S11][S20][S21]

OpenBot does not strengthen the Angular case: its UI uses React 19 and `@copilotkit/react-core`, while its server registers remote AG-UI agents. It is useful as an AG-UI/runtime architecture reference, not evidence that the Angular package works for Ptah. [S23][S24]

## Transport and runtime

Default `runtimeUrl` mode expects CopilotKit Runtime over HTTP: discovery uses `GET {runtimeUrl}/info`; runs use `POST` either to `{runtimeUrl}/agent/{id}/run` (REST/multi-route) or to the single runtime endpoint; streamed AG-UI events use SSE. Intelligence mode additionally uses a websocket URL advertised by `/info`. There is no GraphQL requirement in the current Angular path. [S12][S13]

The CopilotKit Runtime is **not technically mandatory**. The public extension point is:

- `packages/angular/src/lib/config.ts:37-45`: both `agents` and `selfManagedAgents` accept `Record<string, AbstractAgent>`. [source](https://github.com/CopilotKit/CopilotKit/blob/6e888d7d88038e03a29218bbf1f4c0f270733bbc/packages/angular/src/lib/config.ts#L37-L45)
- `packages/angular/src/lib/copilotkit.ts:160-167`: those instances are merged into `CopilotKitCore` as `agents__unsafe_dev_only`. [source](https://github.com/CopilotKit/CopilotKit/blob/6e888d7d88038e03a29218bbf1f4c0f270733bbc/packages/angular/src/lib/copilotkit.ts#L160-L167)
- `packages/angular/src/lib/agent.ts:46-81`: `AgentStore` is transport-agnostic and projects any `AbstractAgent` into Angular signals. [source](https://github.com/CopilotKit/CopilotKit/blob/6e888d7d88038e03a29218bbf1f4c0f270733bbc/packages/angular/src/lib/agent.ts#L46-L81)

For a normal AG-UI server, CopilotKit documents `selfManagedAgents: { default: new HttpAgent({ url }) }`, which uses fetch/HTTP POST and SSE. For Ptah, a custom `AbstractAgent` subclass could instead implement `run`/`connect` by turning VS Code postMessage RPC or Electron IPC events into the required RxJS `Observable<BaseEvent>`; no HTTP listener is technically necessary. However, CopilotKit documents direct production `selfManagedAgents` as Enterprise Intelligence, and runtime-dependent features such as threads/memory/middleware would still be absent. This means the extension point exists but is not a clean free-production fit for Ptah. [S8][S12][S14]

## Security and CSP

**Blocking markdown issue:** the built-in assistant renderer runs agent text through `marked`, performs no DOMPurify or Angular sanitizer call, and assigns the resulting string directly to `container.innerHTML`. Marked's own documentation warns that it does not sanitize output HTML and recommends DOMPurify for unsafe strings; therefore agent-provided HTML reaches the DOM here without the required filter. No `bypassSecurityTrust*` call is used, but direct DOM assignment bypasses Angular's template sanitization just as effectively. This violates Ptah's mandatory single `libs/frontend/markdown` sanitization chokepoint, so Ptah must not use CopilotKit's prebuilt assistant/chat renderer. [S22][S29]

Typed Angular generative UI uses application-supplied component classes and is structurally safer than raw HTML. Open Generative UI deliberately executes agent-generated HTML/JavaScript inside `@jetbrains/websandbox` iframes, and MCP Apps builds an iframe `srcdoc` CSP that explicitly allows `'unsafe-inline'`, `'unsafe-eval'`, `blob:`, broad `connect-src *`, and broad frames. This is sandboxed rather than injected into the host DOM, but it is incompatible with Ptah's “no unsafe-eval/no remote scripts” security policy without a dedicated review and likely CSP exceptions. Whether VS Code's outer webview CSP blocks every nested sandbox execution path was not run end-to-end and remains **UNVERIFIED**. [S25][S26]

The basic headless state/tool APIs can avoid both renderers and keep all user/AI markdown in Ptah's existing sanitizer. That would remove the direct XSS conflict, but not the Angular-22 or Enterprise custom-transport problems. [S8][S22]

**Telemetry/phone-home:** the Angular service mounts `@copilotkit/web-inspector` by default only in development browser builds; `enableInspector: false` disables it, and production builds disable it. When mounted, the inspector fetches CopilotKit-hosted announcements and sends anonymous interaction telemetry to `https://telemetry.copilotkit.ai/ingest`, which fans out to PostHog/Reo/Scarf. Inspector telemetry can be opted out with localStorage, and a runtime `telemetryDisabled` flag also suppresses it. Ptah should set `enableInspector: false`; CSP should also keep CopilotKit domains out of `connect-src`. Server/runtime telemetry can additionally be disabled with `COPILOTKIT_TELEMETRY_DISABLED=1` or `DO_NOT_TRACK=1`, but Ptah would not be running that runtime under the recommended verdict. [S7][S27][S28]

## Bundle

Registry `dist.unpackedSize` for `@copilotkit/angular@0.5.2` is **5,093,773 bytes (4.86 MiB)**. The package's seven pinned CopilotKit/AG-UI direct dependencies total **14,689,257 bytes (14.01 MiB) unpacked** before their dependencies; package plus those seven distributions is **19,783,030 bytes (18.87 MiB)**. A clean `npm install --omit=peer --ignore-scripts @copilotkit/angular@0.5.2` measured locally on 2026-09-20 produced **72 unique packages, 25,409 files, and 111,589,212 bytes (106.42 MiB)** under `node_modules`; this is install footprint, not shipped browser JavaScript. [S3][S4]

Dependencies of note are `marked`, `highlight.js`, `katex`, `@jetbrains/websandbox`, `@copilotkit/a2ui-renderer`, `@copilotkit/web-components`, `@copilotkit/web-inspector`, RxJS, Zod 3, and `zod-to-json-schema`; Ptah itself pins Zod 4.3.6. CopilotKit's Angular quickstart warns that markdown and syntax-highlighting dependencies can push a fresh Angular production build past the default 1 MB budget. [S1][S5]

An optimized Ptah production delta was **not measured** because the current package cannot be resolved against Angular 21 without overriding peer safety. Tree shaking may remove UI, inspector, sandbox, and styling code from a carefully headless-only import graph, so unpacked/install sizes are an upper-bound signal rather than a browser-bundle claim. Exact minified/gzipped headless and prebuilt-UI deltas remain **UNVERIFIED** until CopilotKit publishes Angular 21-compatible peers or Ptah upgrades to Angular 22.
