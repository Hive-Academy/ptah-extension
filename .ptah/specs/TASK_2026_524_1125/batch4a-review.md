**Verdict: REVISE**

1. **High — Route validation does not enforce the full route contract.** `libs/shared/src/lib/types/webview-route-state.ts:29-30,84-93`: `SCHEME_SEGMENT` checks only the start of a slash-delimited path segment, so `/settings?next=javascript:alert(1)` and `/chat;next=http:evil` are accepted even though the contract forbids a scheme anywhere. The raw-string checks also accept `/chat/%2F%2Fevil`, `/chat/%5Cevil`, and `/chat/%00x`; Angular decodes escaped URL components when parsing them. These values can enter boot as restored routes while containing decoded authority-like separators, a backslash, or a control character. The synthetic `MemoryPlatformLocation` (`libs/frontend/core/src/lib/routing/memory-platform-location.ts:37-54,120-127`) prevents the Router from navigating the browser to an external origin, so this is a contract and downstream-consumer boundary failure, not a demonstrated external navigation. **Required change:** validate the route's decoded URL components as well as its raw spelling, reject malformed encodings, and apply a scheme check across the whole route. Add rejection cases to `libs/shared/src/lib/types/webview-route-state.spec.ts:121-140` for schemes in query/matrix/hash positions and percent-encoded `//`, backslash, controls, and schemes. Unicode slash/backslash lookalikes are ordinary characters to Angular's URL parser; they do not by themselves create an authority or external navigation.

2. **Medium — A malformed escaped route can break boot navigation.** `libs/shared/src/lib/types/webview-route-state.ts:84-93`: `/%` and `/%GG` pass the parser, although they are not URLs the Angular Router can serialize and `decodeURIComponent` fails on them during Router parsing. A corrupted persisted record can therefore be returned as a valid route by the security boundary and fail when boot navigates to it. **Required change:** reject malformed percent escapes before returning the route and cover those inputs in `libs/shared/src/lib/types/webview-route-state.spec.ts:114-141`.

3. **Low — The parser's never-throws guarantee does not hold for arbitrary `unknown`.** `libs/shared/src/lib/types/webview-route-state.ts:67-71,80-82`: `isPlainRecord` accepts objects with throwing property getters or proxies, and reading `ptahRoute` or destructuring its fields can throw. Normal VS Code JSON state cannot contain getters, but the exported parser promises that every invalid input returns `null`. **Required change:** constrain accepted records to safe own data properties or catch property-access failures and return `null`; add a throwing-getter case in `libs/shared/src/lib/types/webview-route-state.spec.ts:78-106`.
