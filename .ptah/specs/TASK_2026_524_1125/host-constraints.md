6. **Electron loads the Angular renderer as a file, with a directory base.** `apps\ptah-electron\src\activation\post-window.ts:84` sets `rendererPath = path.join(__dirname, 'renderer', 'index.html')`; line 85 calls `mainWindow.loadFile(rendererPath)`. This boot path does not use an HTTP server or custom app protocol. `apps\ptah-electron\src\windows\main-window.ts:123` sets `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, and `webSecurity: true`. `apps\ptah-electron\scripts\copy-renderer.js:175` replaces the source base with `'<base href="./">'`; that exact base is present in `dist\apps\ptah-electron\renderer\index.html:7`. The exact policy, defined at copy-renderer lines 156–169 and present at built index line 4, is:

   ```text
   default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; img-src 'self' https: data: blob:; font-src 'self' https://fonts.gstatic.com data:; connect-src 'self'; media-src 'self' blob:; worker-src 'self' blob:; object-src 'none'; base-uri 'self'; frame-src 'none'; form-action 'none'
   ```

   `file:` is not an HTTP origin with arbitrary same-origin path rewriting. More precisely, the [HTML history URL rewrite algorithm](https://html.spec.whatwg.org/multipage/nav-history-apis.html#can-have-its-url-rewritten) (updated 2026-09-21, retrieved 2026-09-22) permits file query/fragment changes but rejects a changed file pathname. Origin opacity alone is not the deciding test. With normal path routing, `/route` or `<renderer-directory>/route` differs from `<renderer-directory>/index.html`, so **PathLocationStrategy fails this host constraint**. The navigation guard also only allows the same file pathname (`apps\ptah-electron\src\windows\navigation-policy.ts:54`–56); it is not a mechanism for relaxing History API security.

7. **Installed Angular forwards directly to native history, with no catch or fragment fallback.** `node_modules\@angular\common\fesm2022\_platform_location-chunk.mjs:60`–61 assigns `window.location` and `window.history`. Exact methods at lines 100–105:

   ```javascript
   pushState(state, title, url) {
     this._history.pushState(state, title, url);
   }
   replaceState(state, title, url) {
     this._history.replaceState(state, title, url);
   }
   ```

   `node_modules\@angular\common\fesm2022\_location-chunk.mjs:70` resolves the path base using `href ?? this._platformLocation.getBaseHrefFromDOM() ?? inject(DOCUMENT).location?.origin ?? ''`; thus in this installed version a missing base is not an unconditional constructor error. Lines 83–97 join the base and route and call the platform's push/replace methods. The normal host HTML in this repository supplies a base in either case. `node_modules\@angular\platform-browser\fesm2022\_browser-chunk.mjs:77` normalizes a DOM base with `new URL(url, document.baseURI).pathname`.

8. **`withHashLocation()` still calls history, and Electron's existing base prevents an unconditional “works” verdict.** `node_modules\@angular\router\fesm2022\_router_module-chunk.mjs:1800`–1805 provides `LocationStrategy` using `HashLocationStrategy`. `node_modules\@angular\common\fesm2022\_common_module-chunk.mjs:14` defaults its own base to `''`; lines 19–20 only apply the optional injected base. Lines 38–44 construct `'#' + url` and call `this._platformLocation.pushState(state, title, url)`; lines 46–48 do the same for replace. It does **not** assign `location.hash` and does **not** bypass the HTML document base during native URL resolution.

   Chromium's inspected upstream `third_party/blink/renderer/core/frame/history.cc:273`–277 resolves a nonempty history argument against `DomWindow()->BaseURL()`. Given the shipped `<base href="./">`, `#/route` resolves to `file:///.../renderer/#/route`, not `file:///.../renderer/index.html#/route`. Combined with its file-path rejection, this predicts a **SecurityError with the current base**, not an assured hash-routing success. Hash routing is conditionally viable when native resolution preserves the loaded file's pathname; changing only `APP_BASE_HREF` does not repair the browser's document base. This exact combination was not executed in the installed Electron binary, so the table marks it **unverified**. Source: [Chromium history argument resolution](https://raw.githubusercontent.com/chromium/chromium/main/third_party/blink/renderer/core/frame/history.cc) (undated upstream source retrieved 2026-09-22; not pinned to Electron 44.4.3).

9. **A genuine in-memory PlatformLocation removes these host URL constraints.** `node_modules\@angular\common\fesm2022\_location-chunk.mjs:69` stores the injected platform location and lines 93/97 forward state changes to it. Angular Router itself calls `this.location.replaceState(...)` or `this.location.go(...)` in `node_modules\@angular\router\fesm2022\_router-chunk.mjs:4405` and 4411. A concrete installed demonstration of the seam is `MockPlatformLocation` in `node_modules\@angular\common\fesm2022\testing.mjs:55`: it stores `urlChanges` (line 60), returns its own base (lines 99–100), replaces an array entry (lines 125–138), and pushes an array entry (lines 140–157), rather than using native history. **Verified source-level feasibility in both hosts:** a complete equivalent production implementation, provided for `PlatformLocation`, can supply logical paths, base, state, and pop/hash subscriptions without changing the browser URL. This is not a recommendation to import Angular testing utilities into production. A custom implementation's correctness and integration are **unverified** because none was implemented here; it must not inherit unoverridden native-history behavior.

10. **Hiding retains Ptah's webview DOM; explicit HTML reload replaces it.** `apps\ptah-extension-vscode\src\providers\angular-webview.provider.ts:126` sets `retainContextWhenHidden: true` for editor panels; `apps\ptah-extension-vscode\src\core\ptah-extension.ts:101` does the same for the sidebar. The wizard also sets it at `libs\backend\agent-generation\src\lib\services\wizard\webview-lifecycle.service.ts:129`. `node_modules\@types\vscode\index.d.ts:10070` describes retaining the content iframe when hidden; lines 10073–10079 distinguish default destruction from retention. Consequently a simple hide/show does not require restoring a router URL from persisted state. In contrast, `apps\ptah-extension-vscode\src\providers\angular-webview.provider.ts:324` and 334 assign new `webview.html` during reload; the installed host creates a new iframe at the runtime file cited in finding 5, line 1019. This is not the same lifecycle as hiding.

11. **VS Code state persistence does not automatically persist a Router URL.** `apps\ptah-extension-vscode\src\services\webview-html-generator.ts:417` injects `initialView` into `window.ptahConfig`; lines 432–434 call `vscode.getState()` and assign the result to `window.ptahPreviousState`. Neither writes a browser URL. `libs\frontend\core\src\lib\services\vscode.service.ts:219` reads the API state; lines 244–247 merge a supplied key and call `this.vscode.setState(newState)`. In the installed runtime `...\out\vs\workbench\contrib\webview\browser\pre\index.html:228`–235, `setState` sends `'do-update-state', JSON.stringify(newState)` and `getState` returns the separate stored object; line 870 reinjects that state into a new content document. **This is independent of `window.history.state`, the fragment, and Angular's navigation IDs.** The searched shell/core code only declares/documents `ptahPreviousState` and does not consume it to restore a Router URL. Therefore a route can be restored after a content reload only if application code explicitly persists the logical URL and seeds/navigates the Router from it; neither URL-based nor memory routing gets that restoration from the current injection alone. Panel restoration across a complete VS Code restart also requires lifecycle handling beyond hide/show: the API describes serializers at `node_modules\@types\vscode\index.d.ts:10206`, and no `registerWebviewPanelSerializer` call was found in the searched VS Code app/backend sources.

## Unknowns

- No live `Router.navigateByUrl`, push/replace/back/forward, content reload, or hide/show experiment was run. All verdicts are bounded to source evidence. In particular, the installed VS Code iframe's final `location.href`, `document.baseURI`, effective CSP, and origin were not captured.
- Upstream Chromium sources establish relevant rules and a standard-custom-scheme exception, but were not matched to the Chromium revision inside either installed host. The next smallest probe is to inspect those four document properties and test both push and replace with a path and `#/route` in an isolated host fixture using the same HTML/base/CSP. For Electron, compare the existing `./` base against a document-preserving base. No such fixture was created under this read-only scope.
- The existing extension artifact definitively misses the generator's charset string match. Whether a running installed extension uses that artifact is unverified. Its nonce and concrete `webview.cspSource` are runtime values, so the report gives the exact template, not fabricated substitutions.
- A correctly implemented memory provider is feasible by the installed injection contract; a production provider's navigation-event semantics, initialization and reload persistence are unverified. Memory routing does not preserve anything through DOM destruction unless explicitly persisted.
- The historical origin and current firing frequency of `WebviewErrorHandler` are unverified. Its presence cannot settle either host's routing feasibility.
- VS Code for the web, remote-host combinations, older VS Code/Angular/Electron releases, and an already packaged Ptah binary were not verified. The desktop runtime-source findings must not be generalized to them.
