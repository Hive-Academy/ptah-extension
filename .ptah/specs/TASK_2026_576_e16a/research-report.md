## Answer

Build **`@pierre/diffs`** for the review renderer: in the real Nx/Angular
production build, with the JavaScript regex engine (`preferredHighlighter:
'shiki-js'`, Pierre's default) and five fine-grained lazy grammars plus two
themes (the exact Req 3.2 configuration), the measured cost is **130.7 KB gz**
for the core `FileDiff` chunk and **58.3 KB gz** more once the grammars/themes
for a realistic first diff load — **~189 KB gz total**, not the ~377 KB gz
figure from the earlier WASM-oniguruma esbuild bench, which measured a
configuration (the `shiki-wasm` engine, plus Shiki's statically-imported
`bundledLanguages` list that produces 397 lazy chunks / 1.8 MB gz in the build
output) that Ptah is not adopting — only the grammars actually used are ever
fetched. `@codemirror/merge` measured **145.0 KB gz** in the same real build
for one language, matching its prior esbuild estimate almost exactly. The
eager `main.js`/main closure did not grow from adding either bench component
(383.9 KB gz / 802.8 KB gz closure, unchanged before and after). Pierre's own hunk parser
(`parsePatchFiles`) preserves `@@`-block order and exposes native `<slot>`
projection points keyed by hunk index, so Angular can host real, ARIA-capable
hunk controls outside Pierre's shadow root — Req 3.3's harder half is
satisfiable. All four VS Code commands Req 5 needs exist verbatim at the
1.100.0 tag. Ptah's `WorktreeRemove` hook will **never fire** for its own
`.claude-worktrees` git worktrees — the SDK removes them directly and only
dispatches the hook for non-git (`WorktreeCreate`-hook-owned) worktrees; RC10
needs a different detection path. For commit-message generation, reuse
`SdkQueryRunner.runOneShot` plus the curator's "fall back to the active
provider" pattern already proven in `sdk-internal-query.curator-llm.ts`.

## Disagreements

- Two earlier `@pierre/diffs` bundle-size estimates disagreed (~130 KB gz vs
  ~377 KB gz) because they measured two different configurations, not because
  either was wrong: 130 KB gz was the vanilla `FileDiff` class alone (no
  highlighter wired), and ~377 KB gz was a fuller Shiki runtime that inlined
  the WASM oniguruma regex engine. Req 3.2 specifies the JS regex engine, not
  WASM oniguruma — the real Angular build under that exact configuration
  measured ~131-158 KB gz, which sides with the lower figure once the correct
  configuration is used. The ~377 KB figure is not wrong, it answers a
  question Ptah is not asking.
- The task brief's own open question ("does the SDK skip its own worktree
  removal when Ptah registers a `WorktreeRemove` hook?") presupposes the hook
  fires at all for git worktrees. The maintainer's own closed-issue comment
  says it does not: `WorktreeRemove` is scoped to non-git,
  `WorktreeCreate`-hook-owned worktrees only, and "not a bug in the current
  behavior." This is a maintainer statement on a public issue tracker, not an
  SDK changelog entry — it is the most authoritative source available, but it
  is a comment, not documentation, and issue #94212 shows the docs text itself
  was revised afterward without a version-pinned changelog note.

  rename and CRLF cases — this should be the first thing that spec checks.

  `git.openMergeEditor` was not pinned down (only confirmed present at
  1.100.0, which is at or above Ptah's floor — sufficient for this decision,
  but not a precise "introduced in X" citation).
