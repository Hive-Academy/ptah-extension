## Findings

### Finding 1: Cross-platform inode comparison on Windows during commit lock recovery

- **Location**: `implementation-plan.md:350-352` (Component 5)
- **Severity**: Minor (Advisory / Implementation Detail)
- **Description**: The plan specifies that `commit` records the `stat` (`ino` and `mtimeMs`) of `<gitdir>/index.lock` prior to killing a hanging hook, and removes the lock only if `ino` and `mtimeMs` match after the child process tree exits. On Windows, Node.js derives `stat.ino` from the NTFS File ID. When standard numbers are used, 64-bit NTFS file IDs can suffer truncation or return `0` on certain filesystems (such as FAT32, exFAT, or network-mounted development shares).
- **Recommendation**: During implementation, the lock comparison helper should check `stat.mtimeMs` and `stat.size` as primary invariants, and compare `stat.ino` only when `stat.ino !== 0` (or invoke `fs.statSync(path, { bigint: true })` to prevent 64-bit integer truncation).

### Finding 2: Exact VS Code command registration call site

- **Location**: `implementation-plan.md:943` (Component 21)
- **Severity**: Minor (Documentation / Note)
- **Description**: The file list for Component 21 states: `MODIFY D:/projects/ptah-extension/apps/ptah-extension-vscode/src/core/ptah-extension.ts (or activation/post-init.ts, whichever calls registerCommands)`. In the actual codebase, command registration is split: `licenseCommands.registerCommands(this.context)` is invoked directly in `apps/ptah-extension-vscode/src/core/ptah-extension.ts:78`, while other commands are wired via `apps/ptah-extension-vscode/src/activation/wire-runtime.ts:183`.
- **Recommendation**: Wire `ReviewCommands.registerCommands(this.context)` in `apps/ptah-extension-vscode/src/core/ptah-extension.ts:78` alongside `licenseCommands`, or through `wire-runtime.ts`.

## Correctness and risk assessment

1. **Write-Mutex Scope & Deadlock Prevention**:
   - `GitRepoWriteLock` serializes mutations per normalized repository path using a FIFO promise chain.
   - Synchronous reentrance detection via `AsyncLocalStorage` throws `GitReentrantLockError` if a locked method attempts to acquire the lock again, completely eliminating nested deadlocks.
   - The complete ladder of `applyHunks` (snapshot diff, write-tree, check, apply, verify, rollback) runs inside a single lock invocation. Because `diffFile` is a read operation and is explicitly unlocked, `applyHunks` calling `diffFile` will not attempt to acquire the lock and will not deadlock.
   - Network operations (`push`, `fetch`) and admin tasks (`worktree add/remove/prune`) are kept outside the lock, preventing long network operations from blocking interactive staging.
2. **Watcher Redesign (Windows, macOS, Linux, Linked Worktrees)**:
   - Replacing fragmented per-file `fs.watch` calls with a single recursive `IWorkspaceWatcher` (`@parcel/watcher`) on `<gitdir>/commondir` solves all three operating systems uniformly.
   - Because linked worktrees store their `HEAD` and `index` under `<commonDir>/worktrees/<name>/`, watching the common directory captures both the main repository and all linked agent worktrees in one subscription.
   - Pure function `classifyGitDirChange` accurately separates own-worktree events from foreign worktree administrative changes.
3. **Timeouts, Hook Execution & `index.lock` Recovery**:
   - `GIT_HOOK_TIMEOUT_MS = 600_000` (10 min) accommodates heavy pre-commit or pre-push checks while providing a deterministic ceiling against stuck hooks.
   - Client RPC timeout is calculated via `gitRpcTimeoutFor(backendMs) = backendMs + 15_000` ms (615s client timeout for 600s backend hook). This guarantees the backend always terminates, performs cleanup, and returns an RPC error response before the frontend drops the call.
   - Stranded `index.lock` prevention: when git is killed during hook execution, it leaves `.git/index.lock` behind. Component 5 stats `<gitdir>/index.lock` immediately prior to terminating the process, and if the file still exists with matching stat properties after the process tree exits, cleans it up and logs the recovery.
4. **Index.lock Retry Profile**:
   - Backoff intervals `[100, 200, 400, 800, 1600]` ms (3.1s total) provide sufficient runway to absorb transient git collisions without hanging the UI or causing indefinite spin loops.
5. **Diff Cap (2 MiB)**:
   - Applying `GIT_DIFF_MAX_SIDE_BYTES = 2 * 1024 * 1024` uniformly across blob reading, diff generation, and spot editing matches the existing `FILE_VIEW_MAX_BYTES` contract, preventing renderer out-of-memory crashes on massive files.
6. **RC10 Worktree Hook Evaluation**:
   - The plan correctly resolves the discrepancy between research report Q4 and codebase reality: Ptah registers a `WorktreeCreate` hook that creates worktrees via `gitInfo.addWorktree`.
   - The architect adopts a defense-in-depth architecture: handling `WorktreeRemove` if dispatched by the SDK, while concurrently detecting worktree pruning/removal via the watcher and status refresh, with both mechanisms designed to be fully idempotent.
7. **`@pierre/diffs` CSP / Eval & Fallback**:
   - The plan records a dedicated verification seam (Assumption A2) ensuring `@pierre/diffs` and Shiki JS engine do not execute `eval()` or `new Function()` under Electron's `'script-src self'` CSP.
   - If CSP or lazy chunk size gates fail, `@codemirror/merge` serves as an immediate, pre-evaluated drop-in fallback.
8. **Security of `ptah.review.*`**:
   - All newly registered review commands carry the `ptah.` prefix (`ptah.review.openChanges`, `ptah.review.openDiff`, `ptah.review.openMerge`, `ptah.review.openScm`). Because the RPC allowlist accepts `ptah.*` by prefix, no security allowlist modifications are required.
   - Commands validate path containment against `vscode.workspace.workspaceFolders` via `isPathWithinRoots` and strip absolute paths from user-facing error text.
9. **RC14 Option / Flag Injection**:
   - Ref sanitization via `assertSafeRef` and `assertSafeRevision` rejects leading hyphens, control characters, and injection metacharacters. All git invocations pass `--end-of-options` before revisions and `--` before file paths.
