## New findings

1. **MOD — A delayed preference read can undo an explicit Split press.** `libs/frontend/git-ui/src/lib/review-canvas/comparison-bar.component.ts:340` returns before setting `layoutChangedByUser`; `:363` consequently still permits the pending read to replace the model. Scenario: stored preference is Unified, `settings:get` is pending, the initial model is true, and a narrow canvas visibly shows Unified through `autoUnified`. Clicking Split emits the new session override and visibly switches to split, but hits the equality return. When the stored false value arrives, `:367` switches back to unified despite that deliberate click. The new narrow default makes this previously same-value click a real layout change. Fix: record every explicit choice before the equality return and reconcile a pre-load choice with the eventual stored value, so it wins and is persisted if different; retain no redundant write when the loaded preference already agrees. Add a deferred-read case for this sequence when tests are permitted.

2. **MOD — Nonshrinking metadata can push file-header actions out of the narrow viewport.** `libs/frontend/git-ui/src/lib/review-canvas/file-section-header.component.ts:85` removes wrapping, while `:160`, `:168` and `:173` make the comparison badge, every chip and the action group nonshrinking. Scenario: at the allowed 300–319 px dock width, open a comment on a new working-tree file and collapse the section. `libs/frontend/git-ui/src/lib/review-canvas/file-diff-section.component.ts:620` adds the hunk count, `:621` adds `new`, and `:627` adds `comment in progress`. These chips plus the Working tree badge, toggle, actions and gaps exceed the row even after the path shrinks to zero. The container queries only hide action labels and totals, so the result is horizontal overflow and loss of the intended always-visible path/actions. Fix: give secondary chips a bounded overflow strategy at narrow widths (for example, a compact named summary with full metadata available), preserving space for the path and action controls. Verify the populated/collapsed-comment combination, not only an empty chips input.

3. **MOD — Long author names now take unlimited width above 400 px.** `libs/frontend/git-ui/src/lib/history/history-timeline.component.ts:293` adds both `flex-shrink-0` and `whitespace-nowrap` to arbitrary author text (also `:237` for root commits). Scenario: a timeline just above the 400 px container breakpoint contains a long multiword person or automation author name. The author cannot wrap or shrink, while the subject at `:287` has zero minimum width, so the subject disappears first; sufficiently long names overflow the row together with the fixed SHA/time. This contradicts the subject-priority fix and introduces the same failure at wider sizes. Fix: cap and truncate the visible author width while retaining its full accessible text/title, or hide it whenever the remaining subject space is insufficient. Keep the existing below-400 px behavior.
