## Findings

### Serious

1. **A status failure can break every orchestration setting read.** At `d2de2093f:libs/backend/rpc-handlers/src/lib/handlers/agent-rpc.handlers.ts:462-476`, `getStatus()` is awaited inside the single `agent:getConfig` result construction and any rejection is rethrown. `DecisionModelConfig.getStatus()` calls the workspace read and Ollama probe before returning (`d2de2093f:libs/backend/lane-routing/src/lib/decision-model/decision-model.config.ts:251-264`); its per-provider catches do not cover every operation. For example, a workspace provider read that throws during startup rejects `getStatus`, so the caller receives none of the otherwise available CLI and orchestration fields. The decision row's failed read does permit a save (`4a3b758c9:libs/frontend/chat/src/lib/settings/providers/decision-model-row.component.ts:461-476`), but it cannot preserve the rest of `agent:getConfig`. Isolate status failure and return a five-state DTO, or otherwise keep the rest of the config result available.

2. **A combined Jev selection and key write is not atomic, while the UI says the choice was unchanged on failure.** The UI sends both fields together (`4a3b758c9:libs/frontend/chat/src/lib/settings/providers/decision-model-row.component.ts:535-545`). The handler stores the selection before calling secret storage (`d2de2093f:libs/backend/rpc-handlers/src/lib/handlers/agent-rpc.handlers.ts:564-574`). If `setJevApiKey` fails, `applySetConfig` returns `success: false` (`:693-705`) after the selection has changed. The UI then shows the fixed `SAVE_FAILED` sentence that the saved choice is unchanged (`4a3b758c9:libs/frontend/chat/src/lib/settings/providers/decision-model-row.component.ts:42-46,574-585`). After restart, Jev is selected but may have no usable key. Reconcile partial writes, or report/read back the actual persisted state on failure.

3. **Raw provider and RPC error text reaches logs and can reach the row.** The System One client copies a provider body's `error` field, or its whole body, into `detail` (`53dc2bb99:libs/backend/lane-routing/src/lib/decision-model/system-one.client.ts:225-245`) and logs that detail (`:255-260`). The status DTO explicitly carries live error detail (`d2de2093f:libs/shared/src/lib/types/rpc/rpc-agents.types.ts:145-153`), and the row prints it verbatim as `Detail: ...` (`4a3b758c9:libs/frontend/chat/src/lib/settings/providers/decision-model-row.component.ts:318-324`). Separately, the row passes caught RPC/model-list errors directly to `LoggingService.warn` (`:472-475,580-582,610-613`). A remote endpoint that echoes a submitted request, header, or credential in an error body can disclose that text in logs or Settings; 200-character truncation does not remove sensitive content. Map external failures to fixed, safe detail before logging or displaying them.

### Moderate

4. **The structured-model suggestions use the wrong capability.** The only filter is `supportsToolUse` (`4a3b758c9:libs/frontend/chat/src/lib/settings/providers/decision-model-row.component.ts:598-608`), and the help text claims tool use is what structured output needs (`:442-453`). Requirement 1.2 asks for configured models supporting structured output, while the adapter requests JSON schema output (`53dc2bb99:libs/backend/agent-sdk/src/lib/lane-routing/structured-decision.adapter.ts:128-139`). A provider model that supports JSON schema output without tool use disappears from suggestions; a tool-use model without JSON schema support appears usable. Free-text entry limits the harm, but the offered list gives a wrong answer. Use explicit structured-output capability where available, or leave suggestions unfiltered and avoid the unsupported capability claim.

5. **Abort does not bound all stages of the structured adapter.** `complete()` awaits authentication before installing its abort listener (`53dc2bb99:libs/backend/agent-sdk/src/lib/lane-routing/structured-decision.adapter.ts:119-126`), then awaits `query.execute` and iterates the stream without a local race against the signal (`:127-140,199-219`). If the resolver, query startup, or iterator stalls and ignores cancellation, a deadline abort does not settle `complete()`; the router cannot rely on this adapter alone for a timely fallback. Race those awaits with cancellation or establish and verify a caller-owned deadline that settles independently of this promise.

6. **A hung shared discovery can poison later model listings.** Batch 14 retains one promise per provider until that promise settles (`66f724fed:libs/backend/rpc-handlers/src/lib/services/lane-model-listing.adapter.ts:254-270`). A row abort returns its configured/tier entries (`:188-207`), but the underlying `fetchModels` receives no abort signal (`:273-288`); if it never settles, the map keeps that pending promise. Every later row for that provider reuses it and likewise times out to the saved entries, even after connectivity recovers. Release or expire abandoned in-flight discovery without cancelling another active row's work.

## Five logic questions

1. **Silent failure:** a timed-out provider discovery returns only configured/tier entries (`66f724fed:libs/backend/rpc-handlers/src/lib/services/lane-model-listing.adapter.ts:188-207`), which looks like a valid list; the indefinite shared promise can repeat this on later reads (Finding 6).
2. **Unexpected user action:** entering a new Jev key while switching to Jev can change the selection even when the save reports failure (Finding 2).
3. **Wrong answer from input data:** a model with JSON schema output but no tool-use flag is omitted from suggestions, while a tool-use-only model is offered (Finding 4).
4. **Dependency failure/timeout/shape:** a rejected status read breaks the entire config RPC (Finding 1); a stalled resolver or query does not settle from abort alone (Finding 5). The UI does reject unknown DTO states at `4a3b758c9:libs/frontend/chat/src/lib/settings/providers/provider-consumer-rows.ts:618-650`.
5. **Requirement gap:** the contract does not define partial success for a selection plus write-only key in one `agent:setConfig`; the current UI assumes all-or-nothing (`4a3b758c9:libs/frontend/chat/src/lib/settings/providers/decision-model-row.component.ts:535-545,574-585`).

## Decisions

- **Separate decision deep link:** leave it out of this verdict. Options were a dedicated `decision` focus target or the existing `background-models` target. Requirement 1 requires a setup-provider link, which exists; no criterion requires a row-specific focus target. Evidence: `4a3b758c9:libs/frontend/chat/src/lib/settings/ptah-ai/orchestration-settings.component.ts:31-36` and `libs/frontend/chat/src/lib/settings/providers/decision-model-row.component.ts:342-351`. Reversible: yes.
- **Capability suggestions:** treat the `supportsToolUse` filter as a logic gap rather than a blocked scope decision. Options are explicit structured-output metadata or unfiltered suggestions. The current flag does not establish the requested capability (`4a3b758c9:libs/frontend/chat/src/lib/settings/providers/decision-model-row.component.ts:598-608`); either correction is reversible.

The 5/10 score reflects several independent failure paths in settings reliability and data exposure. It is above the 3–4 band because the core DTO, Zod persistence boundary, secret-storage path, existing roles, and ordinary row rendering are present; it is below the 7–8 band because a failed read can break the whole settings RPC and a failed combined write can leave a different selection persisted.
