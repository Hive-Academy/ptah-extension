# Angular date and timer lifecycle audit — TASK_2026_856_d668

## Summary

Read-only source audit of the supplied candidates and targeted `libs/frontend` component/service searches. **Verified** means the cited code implements a behavior; user-visible effects marked **inferred** were not run. The strongest lifecycle risk is a component-held guard for system-prompt regeneration (T1). Provider probe elapsed (T2), analysis start bookkeeping (T3), and slow-loading hints (T4–T5) also originate in components. Several relative labels hold stable timestamps but lack a reactive clock (T6–T12).

The scan found **13 distinct `setInterval` sites in Angular component files**: 11 date/elapsed/countdown/age loops and two cosmetic typing loops. `TranscriptLiveClock` adds one component-lifetime interval outside a `*.component.ts` file. These are sites, not a measured simultaneous count: each visible compact-session card and ambient-account row can create its own interval. Root services run separate clocks. No build, test, lint command, or runtime trace was run. A Ptah diagnostics request on the Markdown deliverable returned unavailable without diagnostics after 45 seconds.

## Recommended design

1. Put operation identity and absolute start/deadline in a durable owner **before** work starts: host status if the operation outlives the renderer, otherwise a root store keyed by workspace/session/turn/agent/probe ID. T1 needs host-visible regeneration state or a persisted operation record because root Angular state also disappears on window reload. T2 needs a probe ID; T3 needs an analysis run ID, rather than a component “first event” latch.
2. Generalize or extract `CacheCountdownClockService` into a root wall-clock service with reference counting and visibility resume. Use its epoch-now signal for second-resolution labels, and derive coarse minute/day updates for relative dates. `PlanLimitsStore.now` updates only every 30 s, so it is not sufficient for live timers. Keep the store-owned handoff deadline/action and host timeout decisions independent of display ticks.
3. Compute `max(0, now-startedAt)` only for running work; completed values use host end timestamps or reported durations. Refresh immediately after remount/visibility return. Host deadlines remain authoritative for permission/question expiry.
4. Verify with route/tab/drawer unmount/remount, hidden Electron window, midnight rollover, and renderer reload during active host work. Smallest T1 experiment: let regeneration RPC time out, close/reopen drawer, then compare host status with Regenerate availability.
