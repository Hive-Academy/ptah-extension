# Session Metrics Audit — TASK_2026_856_d668

## Summary

Static audit of the named Angular surfaces found **no component incrementally accumulating session cost or tokens from streaming events**. Lifetime totals normally arrive as a backend `SessionStatsEntry` and persist through root `SessionStatsAggregatorService` and `TabManagerService`. The risks are competing token definitions, fallback sums over retained or partial data, a turn count from the loaded message window, and Command Center lookups limited to active-workspace tabs. Component destruction usually reruns a projection rather than erasing its source. No runtime symptom was reproduced. Paths below are workspace-relative; “likely” means inferred from code.

## Duplicated computations

- **Token meaning:** host `tokenCount` is four classes (`libs/shared/src/lib/types/rpc/rpc-session.types.ts:376–384`); badge sums two (M1), turn activity reports two with coverage (M5), inspector adds cache into input (M6), and inspector root store recomputes four when authoritative total is missing (M7). Scopes and labels need to match.
- **CLI lanes:** output header folds segments (M2), lane summary conditionally folds segments (M3), and agent-card/inspector adapters choose structured, roster, tray, or retained values (M4). `stats-bar.utils.ts:55–66` calls segment totals partial; output header lacks that cue.
- **Subagent tools:** tile prefers execution tree then `record.toolUses`; inline bubble uses `record.toolUses` only when its store tree is empty, otherwise displayed children (M12).
- **Command Center:** page uses active `tabs.tabs()` (M9), whereas inspector store calls `findTabByIdAcrossWorkspaces` (`session-inspector.store.ts:198–204`). Session list has a separate host `tokenUsage`/`messageCount` feed (M10).

## Host data available

- `SessionStatsEntry` contains lifetime input/output/cache classes, `tokenCount`, `totalCost`/`knownCost`, `messageCount`, `agentSessionCount`, `cliAgents`, `modelUsageList`, optional `durationMs`, and `contextSnapshot` (`libs/shared/src/lib/types/rpc/rpc-session.types.ts:359–462`). Missing `tokenCount` means unavailable (355–357).
- In-turn `session:stats-live` carries a provisional snapshot, optional model/context tokens, and revision (`libs/shared/src/lib/types/messages/session-stats-live.ts:15–37,117–153`). Root `SessionStatsAggregatorService` routes it to `TabManagerService.installSessionStats` (`session-stats-aggregator.service.ts:102,207–235`; `tab-manager.service.ts:2682–2701`); loaded sessions install host stats via `applyLoadedSessionStats` (`tab-manager.service.ts:2752`). Angular need not reconstruct lifetime totals from stream events.
- Root `AgentMonitorStore` (`libs/frontend/chat-streaming/src/lib/agent-monitor.store.ts:731`) retains structured CLI `usageTotals`; adapters use partial retained segments only when absent (`lane-stats.adapters.ts:78–107`). `session:list` supplies `ChatSessionSummary.tokenUsage` and `messageCount` (`command-center-start.component.ts:249–275`). No lifetime turn-count field was found in inspected `SessionStatsEntry`.

## Recommended owners

1. Keep lifetime cost, token classes/total, context, per-model rows, message and subagent counts in backend `SessionStatsEntry` and root `TabManagerService`; preserve unavailable semantics (M7).
2. Put one CLI/subagent usage projection near root `AgentMonitorStore`/`SessionAgentRosterService`, retaining partial/cache availability; use it in output header, lane bar, and inspector (M2–M4).
3. Use a shared four-class message token helper and distinct uncached-input versus prompt-input labels (M1,M6). Keep per-turn figures explicitly scoped/coverage-marked, or place them in root chat state if turns can trim (M5).
4. Resolve Command Center tabs across workspaces; prefer open-tab snapshot over stale list entry (M9–M10). Add host lifetime turn count only if desired; otherwise name inspector figure visible turns (M8).

- **Decision:** Treat pure component projections of root/host data as lower-risk display logic. **Options:** move every formatter; move only divergent/partial/lifecycle-sensitive calculations. **Evidence:** `session-stats-summary.component.ts:95–107,203–240`, `compact-session-card.component.ts:440–457`, `tab-manager.service.ts:2682–2701`. **Reversible:** yes. Recommendation is the latter; architect retains the design choice.
- **Decision:** Mark failure modes inferred, not reproduced. **Options:** static audit; UI reproduction. **Evidence:** read-only scope forbids build/test, and no runtime run was requested. **Reversible:** yes via focused reproduction.
