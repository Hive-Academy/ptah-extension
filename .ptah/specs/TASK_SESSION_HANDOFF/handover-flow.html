Session hand-over flow — branch fix/session-handoff-workflow

Batches A and B, plus the fix round in progress. The frontend part (batch C) is not built yet.

1. How the system knows the agent finished its turn

The only end-of-turn signal is the SDK result message. A successful interrupt is the second release path. armAtTerminal runs before markTurnEnded, so the gate is closed before the queue is released.

flowchart TD
    SDK["Claude Agent SDK stream"] -->|"result message (success or error subtype)"| ST["stream-transformer onTurnEnd"]
    INT["Successful interrupt (session-control.service.ts:124)"] --> TT
    ST --> TT["SessionLifecycleManager.onTurnTerminal (session-lifecycle-manager.ts:500)"]
    TT --> CHK{"At blocking limit? canSend() = false"}
    CHK -->|yes| ARM["coordinator.armAtTerminal: queued inputs move to hand-over FIFO"]
    CHK -->|"no, no operation"| REL
    ARM --> REL["registry.markTurnEnded: releases the pump"]
    REL --> PUMP["SessionStreamPump: next input"]
    PUMP --> GATE{"Hand-over active? admitOrHold"}
    GATE -->|no| TURN["New source turn starts"]
    GATE -->|yes| HOLD["Input held in FIFO (no new turn)"]

2. All inputs go through one gate

flowchart LR
    U["User composer (chat:continue)"] --> A
    L["Lane completion"] --> A
    R["Agent report"] --> A
    P["Peer message (ptah_session_send)"] --> A
    S["Steer / stop-intent (interrupt refused)"] --> A
    C["Ptah CLI continue"] --> A
    A["Coordinator admission (before budget refusal)"] -->|idle| Q["Source queue: new turn"]
    A -->|hand-over active| F["Transfer FIFO: SESSION_HANDOVER_HELD"]
    F -->|success| SUC["Successor: in order, once"]
    F -->|"failure / cancel"| SRC["Back to source: in order"]

3. States of one hand-over

stateDiagram-v2
    [*] --> idle
    idle --> waiting_for_turn_end: request while turn runs
    idle --> armed: request while idle
    waiting_for_turn_end --> armed: SDK result
    armed --> awaiting_confirmation: budget limit (user confirms)
    armed --> compacting: successor mode (auto)
    awaiting_confirmation --> compacting: user clicks Continue
    awaiting_confirmation --> cancelled: Keep working
    compacting --> writing_handoff: new compact_boundary saved
    writing_handoff --> starting_successor
    starting_successor --> successor_confirmed: tab bound and focused (ack)
    successor_confirmed --> closing
    closing --> closed: token matches
    compacting --> failed
    writing_handoff --> failed
    starting_successor --> failed: ack timeout 15 s
    failed --> idle: FIFO restored, source stays open
    cancelled --> idle: FIFO released in order

4. Full transition between sessions

sequenceDiagram
    participant SDK as Source agent (SDK)
    participant LM as Lifecycle manager
    participant CO as Coordinator
    participant UI as Webview
    participant H as Successor host
    participant N as New session
    SDK->>LM: result (turn ended)
    LM->>CO: armAtTerminal (limit reached)
    LM->>LM: markTurnEnded (gate already closed)
    Note over CO: Lane completions, reports and peer messages now go to the FIFO
    CO-->>UI: state via session:stats (revisioned)
    UI->>CO: Continue in new session (beginHandover)
    CO->>SDK: owned /compact turn
    SDK-->>CO: new compact_boundary saved
    CO->>CO: build handoff (summary + agent text)
    CO->>H: startSuccessorSession(seed, FIFO, config)
    H->>N: start and register live
    H-->>UI: session:successorReplacement
    UI->>UI: bind successor into source tab, focus it
    UI->>H: session:successorBound (ack)
    H-->>CO: started: true
    CO->>N: deliver FIFO in order, once
    CO->>SDK: close source (token must match)

Gaps still open

  1. Fix lane in progress: the coordinator holds its own /compact, and two services use the wrong DI token. Until fixed, every real hand-over fails.
  2. UI timing depends on batch C: hand-over state travels on session:stats, which arrives before turn_state. The banner must wait for turn_state.
  3. No result = no hand-over: if the SDK process stops without a result, the end of the turn is never detected.
  4. Turn is not run: background lanes can finish after the turn. After arming, their completions go to the FIFO and then to the successor.
