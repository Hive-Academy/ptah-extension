3. **[Serious] `SessionHandoffChainStore` synchronous `IStateStorage.get`/`update` calls can throw `StateStorageNotReadyError` on Electron worker-backed workspace storage and ignore workspace scoping** (`implementation-plan.md:106-118`, `implementation-plan.md:133-136`, `libs/backend/platform-electron/src/implementations/electron-state-storage.ts:73-141`, `libs/backend/platform-core/src/interfaces/async-state-storage.interface.ts:56-92`, `libs/backend/platform-core/src/interfaces/workspace-scoped-state-storage.interface.ts:30-68`, `libs/backend/agent-sdk/src/lib/session-metadata-store.ts:568-580,1730-1737`).
   - On Electron, `PLATFORM_TOKENS.WORKSPACE_STATE_STORAGE` is backed by `ElectronStateStorage` in worker mode (`readinessState = { status: 'not-ready' }` until the worker handshake completes). Both `get()` (`electron-state-storage.ts:117`) and `update()` (`electron-state-storage.ts:140`) call `this.assertReady()`, throwing `StateStorageNotReadyError` if invoked before `whenReady()` / `getAsync()`.
   - Additionally, `WORKSPACE_STATE_STORAGE` implements `IWorkspaceScopedStateStorage` (`WorkspaceAwareStateStorage`); un-scoped reads/writes hit whichever workspace happens to be active rather than the handoff session's `record.workspacePath` (`session-handoff.service.ts:100`).
   - **Required revision**: Have `SessionHandoffChainStore` use `isAsyncStateStorage` (`getAsync` / `whenReady`, falling back to `get` for synchronous doubles, matching `SessionMetadataStore` at `session-metadata-store.ts:1730-1737`), and either make `get(sessionId)` return `Promise<SessionHandoffChain>` (since `session:get-handoff-chain` in `session-rpc.handlers.ts` is already `async`) or hydrate via `getAsync` before reading/updating. Scope storage via `isWorkspaceScopedStateStorage` when `workspacePath` is known.

4. **[Serious] Calling `sessionLifecycle.endSession(SessionId.fromTrusted(entry.sdkSessionId))` omits `tabId` from the `session:ended` payload when `realSessionId` is already resolved** (`implementation-plan.md:45-50`, `libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-control.service.ts:220-232,313-325`, `libs/frontend/chat/src/lib/services/chat-message-handler.service.ts:750-758`).
   - In `SessionControlService.endRecord(rec, sessionId)` (`session-control.service.ts:313-325`), the `SESSION_ENDED` broadcast sets `sessionId: sessionId as string` and only includes `realSessionId: rec.realSessionId` when `rec.realSessionId !== (sessionId as string)`.
   - If `SessionHandoffService.onCallerTurnFlushed(tabId)` passes `entry.sdkSessionId` (which equals `rec.realSessionId` once resolved), `rec.realSessionId !== (sessionId as string)` is `false`, so `SESSION_ENDED` is broadcast with `{ sessionId: realSessionId }` only and no `tabId`. If any frontend listener or un-rekeyed tab state still keys by `tabId`, it misses the transition.
   - Conversely, if `onCallerTurnFlushed(tabId)` passes `SessionId.fromTrusted(tabId)` (or tries `tabId` first and falls back to `entry.sdkSessionId`), `this.registry.find(tabId)` still locates `rec` (`session-control.service.ts:221`), and `endRecord` broadcasts `{ sessionId: tabId, realSessionId: rec.realSessionId }`, causing `ChatMessageHandler.handleSessionEnded` (`chat-message-handler.service.ts:750-758`) to mark **both** `tabId` and `realSessionId` as `'ended'` in `SessionLivenessRegistry`.
   - **Required revision**: In `SessionHandoffService.onCallerTurnFlushed(tabId)`, call `this.sessionLifecycle.endSession(SessionId.fromTrusted(tabId))` (or pass `tabId` when registered) so `SESSION_ENDED` carries both `sessionId: tabId` and `realSessionId`.

5. **[Moderate] Misidentified wiring file for `onLinkWritten` and invalid parallel batching between Runtime and RPC batches** (`implementation-plan.md:137`, `implementation-plan.md:206-215`, `libs/backend/cli-agent-runtime/src/lib/wiring/agent-events.ts:58-102`).

   - Finally, `implementation-plan.md:207-215` groups the **Runtime** batch (`libs/backend/cli-agent-runtime`) and the **RPC and replay** batch (`libs/backend/rpc-handlers`) under "Parallel-safe work", contradicting line 206: `libs/backend/rpc-handlers` imports `CLI_AGENT_RUNTIME_TOKENS.HANDOFF_TURN_FLUSH`, `CLI_AGENT_RUNTIME_TOKENS.SESSION_HANDOFF_CHAIN`, `IHandoffTurnFlush`, and `ISessionHandoffChain` from `@ptah-extension/cli-agent-runtime`.
   - **Required revision**: Subscribe to `onLinkWritten` inside `libs/backend/cli-agent-runtime/src/lib/wiring/agent-events.ts` (preferably via `CLI_AGENT_RUNTIME_TOKENS.SESSION_HANDOFF_CHAIN`), and either move the new `@ptah-extension/cli-agent-runtime` port/token exports into Batch 1 (Shared/Contracts) or sequence the Runtime batch before the RPC batch.
