## New findings

1. **Serious — the text-only timestamp fallback can merge two different messages.** Plan 555–565 matches a synthesized, tool-free live message to the newest *unmatched* JSONL message within ±2 seconds, then suppresses its stream deltas for snapshot block indices. Suppose message A is in the snapshot and message B starts within two seconds but has not yet been written to JSONL. B has a synthesized live ID, one text block, and no tool ID. The fallback aliases B to A and drops B's text while the user watches; it may also create an incorrect prefix until B's complete-source event arrives. The SDK explicitly retains synthesized IDs (`libs/backend/agent-sdk/src/lib/message-transform/stream-event.transformer.ts:204-216`), stamps live events with `Date.now()` (`:181-190`), and the accumulator appends stream text at `libs/frontend/chat-streaming/src/lib/accumulator-core.service.ts:311-319`. Risks 3 (plan 1007–1012) names only *duplicate output outside* the window, not this false match *inside* it; merge spec 3 (629–633) does not exercise two nearby text-only messages. **Fix:** use a provable identity for suppression (propagate the real SDK message ID when reconciling a synthesized start, or defer aliasing until a complete event establishes it). If identity remains uncertain, retain both messages temporarily; test two distinct text-only messages within the window and a snapshot taken before B is saved. The acknowledged outside-window duplicate is an acceptable bounded display limitation on its own; the inside-window data loss is not.

2. **Serious — the 256 KB page cap is not guaranteed for escaped text.** Plan 435–450 clips `text_delta`/`thinking_delta` above 96 KB and says every resulting event is below 100 KB, yet it does not require checking the serialized UTF-8 byte length after escaping. A text block of 96,000 control characters can expand to roughly 576 KB as JSON `\u0001` escapes; it is below the proposed pre-serialization threshold. The at-least-one-event rule would then emit that event despite `maxBytes`. The existing converter passes the text block directly (`libs/backend/agent-sdk/src/lib/helpers/history/session-replay.service.ts:531-542`), and the JSONL reader accepts files far above one page (`libs/backend/agent-sdk/src/lib/helpers/history/jsonl-reader.service.ts:113-118`). **Fix:** measure the actual serialized event/response bytes, clip until the hard cap is met, and advance the cursor even for one event. Add a control-character or escape-heavy text fixture alongside the 300 KB plain-text and 1 MB tool-result cases in plan 465–474.

3. **Moderate — the batch description overstates file isolation.** Plan 860–861 and 877–889 allow several batches to revisit the same files in serial order; the file lists at 918–950 confirm that. This is operationally sound when the stated dependencies are enforced, but it does not satisfy a literal claim that *every* batch is file-disjoint. **Fix:** state the invariant precisely: parallel-capable batches are file-disjoint, and recurring-file batches run serially with rebasing/handoff. No additional architecture change is needed.
