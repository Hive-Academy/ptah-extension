# Research Report - TASK_2026_367 (spawn runtime: C1, C2, C7)

## Question

- Decision this supports: how to fix C1 (ptah-cli stderr mislevelled + model-rejection question), C2 (wrong tier in the spawn log line), and C7 (event-loop lag after `ptah_agent_spawn` + the `SubagentRegistryService.setTaskId` race), for the BUGFIX plan the architect will write next.
- Question: for each cluster — what does the code do today, what is the root cause, what are the fix options and their cost in this repo, and which one is recommended.
- Bounds: does not cover C3, C4, C5, C6 (harness/session/memory clusters — separate report `research-report-harness.md` per context.md) or the mojibake em-dash cluster. Does not design the fix, only recommends.

## Answer

**C1**: the three ERROR lines are benign CLI diagnostics, not evidence of a leaked key or a rejected request. `ptah-cli-registry.ts` sets `ANTHROPIC_AUTH_TOKEN` (never `ANTHROPIC_API_KEY`) for `ollama-cloud`, and `buildSafeEnv` never forwards the host's own `ANTHROPIC_API_KEY`. The claude.exe binary's own strings confirm both stderr messages are non-fatal: the connectors notice fires for _any_ non-Anthropic auth route, and `unrecognized_model` is declared in the CLI's own changelog as a stderr-only diagnostic — "a request goes out" regardless. Fix: stop blanket-logging every stderr line at ERROR; reuse the regex-based info/error classifier already duplicated in four other adapters. **C2**: the "Spawned headless agent … with model X" line recomputes `effectiveTiers?.sonnet` instead of reusing the already-resolved `tier`/`model` locals from lines 613-621 — a copy-paste bug, one-line fix. **C7 (lag)**: every `child_process.spawn()` in the CLI-agent path (`probeCliVersion`, and each adapter's actual long-running spawn in `cli-adapter.utils.ts`'s `spawnCli`) pays a synchronous `CreateProcessW` cost proportional to the target binary's size on Windows — the exact mechanism `agent-sdk`'s `OffThreadProcessSpawner` was built to defeat for the SDK's own `query()` call (TASK_2026_341), but that fix was never extended to `cli-agent-runtime`. **C7 (race)**: `task_started` (stream message) reliably arrives before `SubagentStart` (hook) by construction — the code's own comment says so — so `setTaskId` always misses; the fix is a pending-map buffer identical in shape to the `pendingTeammateNames` pattern already in `SubagentStateStore`.

### C1 — stderr level

| Option                                                                                                                                                                                                                                                                                    | Fit here                                                                                    | Cost to adopt                                                                                                                         | Known failure mode                                                                                                                                                               |

| Leave at ERROR but suppress two specific known-benign patterns by string match                                                                                                                                                                                                            | Lowest effort                                                                               | Very small                                                                                                                            | Reintroduces a bespoke allowlist that silently swallows a REAL third error sharing a substring; also does nothing for the 4-adapter duplication already present                  |

Recommendation: extract the shared regex classifier and reuse it in `ptah-cli-registry.ts`; it is the smallest change that also removes duplication rather than adding a fifth copy.

### C1 — env var (ANTHROPIC_API_KEY question)

No fix needed — this is a "is it a bug" question, not a design decision. `authEnv` for `ollama-cloud` carries `ANTHROPIC_AUTH_TOKEN` (per its `authEnvVar` field) and `ANTHROPIC_BASE_URL`; `buildSafeEnv` never forwards the host process's own `ANTHROPIC_API_KEY`. The stderr line's literal mention of `ANTHROPIC_API_KEY` is the CLI's own generic wording for "any third-party auth route is active" (confirmed from the binary's own strings), not a report of that specific variable. Nothing to strip.

Recommendation: promote `OffThreadProcessSpawner` (or an equivalent structural port, mirroring the `HARNESS_PREFLIGHT_TOKEN` structural-port pattern `agent-sdk` already uses to avoid a `harness-sync` dependency) into `cli-agent-runtime`'s spawn path, since it is the one component with a measured, repo-native fix for the exact underlying mechanism. ## Disagreements

None found — no two sources disagreed. The one thing worth flagging as a correction to the task prompt's framing: C7's `SubagentHookHandler` "agentId fallback" lines are not necessarily downstream consequences of the exact same `setTaskId` miss (they resolve a _different_ identifier — `toolUseId` at `SubagentStop` time vs. `toolCallId` at registration time) — the 7-and-7 count matching in this log is consistent with the framing in `context.md`, but this report did not trace each pair's `toolCallId`/`agentId` end-to-end to prove one-to-one causation, only that both symptoms co-occur 7 times in the same session and share the same underlying "hook fires late relative to a stream message" shape.
