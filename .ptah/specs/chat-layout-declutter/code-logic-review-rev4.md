## Acceptance criteria verification

### 1. B1 + S1 — overlay and compact sheet `absolute` inside the board box: VERIFIED (structural)

- The dock host is `display: contents` (`canvas-inspector-dock.component.ts:109`), so both `[data-inspector-dock]` and `[data-compact-sheet]` flatten directly into `.canvas-rail-board-layout relative flex h-full min-h-0 min-w-0` (`canvas-rail-board.component.ts:131`, the dock mounts at `canvas-rail-board.component.ts:346-354`). Control-flow blocks create no DOM boxes, so no element sits between the two.
- Ancestor walk (overlay → window), all three layouts (single, split, compact share this chain): board layout (`relative`, no z/transform) → `.canvas-interactive` (`flex-1 min-h-0`, no position, `orchestra-canvas.component.ts:88`) → `.session-viewport` (`relative overflow-hidden`, `orchestra-canvas.component.ts:85`) → `.canvas-grid` (`relative`, `orchestra-canvas.component.ts:80`) → content area `flex-1 overflow-hidden` (`app-shell.component.html:343`) → app-shell navbar row, **hidden in Electron** (`app-shell.component.html:116-119`) → retained row → `ptah-app-shell` → `configuration-surface-host` (`overflow-hidden`) → `.electron-shell-body flex flex-1 min-h-0 overflow-hidden` (`electron-shell.component.ts:379`). No `transform`, `filter`, `contain`, `will-change` or z-index anywhere on the chain; `absolute` uses only the board layout as containing block, and because `inset-0`/`inset-y-0 right-0` keep the overlays inside the board layout box, none of the `overflow-hidden` ancestors can clip them.
- Starts below the app top bar: the board layout lives inside the chat column, which is a `flex-1` row child below the shell navbar (`electron-shell.component.ts:369-408`); in Electron the app-shell's own navbar is hidden. The old B1 defect was `fixed` + `inset-y-0` measuring from the **window**; now the same inset measures from the board top, below the bar.
- Ends left of the GIT rail: the Git dock (`min-w-[300px]`, `electron-shell.component.ts:420-424`) and the Git tab (`electron-shell.component.ts:451-457`) are flex siblings **after** the chat column, so the board box's right edge is the chat column's right edge — the overlay can no longer reach them. This is the structural fix for S1 (at 900px the old sheet ran x512..900 under the Git tab; the new right edge is the board's, ~64px short of the window).
- Still covers the chat panes: the overlay is `z-50` (`canvas-inspector-dock.component.ts:193`); the pane floating control group is `absolute right-2 top-2 z-20` (`canvas-focus-area.component.ts:47`); the split grip renders only when `!overlay()` (`canvas-inspector-dock.component.ts:168-169`, and an open drag that flips overlay drops its draft via the `cancel()` effect at `canvas-inspector-dock.component.ts:337-339`); lane tabs carry no z-index. No ancestor creates a stacking context that traps the z-50, and the dock is the last child of the board layout, so it paints above everything inside the board at equal z. (The split pane's `rail-pane-enter` animation leaves `transform: translateX(0)` with fill `both`, creating a stacking context on the pane section — it traps the z-20 group, which makes the z-50 overlay win by a wider margin, not narrower.)
- Width cannot escape: `max-w-full` replaces `max-width: 100vw` — for the absolutely positioned aside, 100% resolves against the board layout, so a stale `dock.width()` larger than the board is capped there instead of at the window (`canvas-inspector-dock.component.ts:189,191`).
- Scrolling: the compact sheet keeps `absolute inset-0 z-50 overflow-y-auto` (`canvas-inspector-dock.component.ts:241-248`); it fills the board box, so its own scroll works unchanged. The expanded aside's inner `min-h-0 flex-1` inspector scrolls itself.
- Focus trap / Escape / restore: all DOM-query based on `this.root()` (`canvas-inspector-dock.component.ts:360-422, 434-453`) — position-independent, untouched by the diff.
- e2e `compaction-duplicate-session.spec.ts:309-315`: the click on `Compact session details` inside `[role="dialog"][aria-label="Session details"]` failed while the dialog was `fixed` at window y=0 with its title row (y≈8..36) under the top bar — the visual review's `elementFromPoint` evidence shows those coordinates hit Marketplace/Settings/Change theme instead (`visual-review-rev2.md` B1). With `absolute` the dialog top is the board top, below the bar, so the button is visible, stable and unobstructed. **Judged: plausibly fixed** — CI must re-run it to confirm (I ran no e2e).

### 2. B2 — chat column floor: VERIFIED, with a constant mismatch (minor defect 1)

- The floor `min-w-[min(400px,calc(100vw-6rem))]` (`electron-shell.component.ts:405`). At a 400px window the floor is 304px; the two side tabs plus the floor total 64+304 = 368 ≤ 400, so with both toggleable panels closed the row fits and the board's session rail sits fully inside the window (S2's ~19px sliver is gone — the rail's right edge becomes the window edge instead of 32px past it).
- **The 6rem does not equal the tab widths**: `ptah-sidebar-tab` renders `w-8` (32px, box-sizing border-box) for its default size and the shell passes no `size` for either tab (`sidebar-tab.component.ts:63-64`, `electron-shell.component.ts:390-396, 451-457`), so the tabs are 4rem, not 6rem. Over-reserving is the safe direction (with both panels closed the column is `flex-1` and fills the leftover 336px regardless, so nothing visible changes), and when the workspace sidebar or Git dock is open at <496px the extra reserve actually reduces the overflow — but the changed comment ("leaving room for both sidebar tabs") describes 4rem, and in the band where the floor binds with a panel open the chat column is 32px narrower than it could be.
- Git dock / Apps split interaction: the 50% cap (`electron-layout.service.ts:54-55`, applied at `:146-152` and `:180-184`) is unchanged by this diff and no longer matches its comment at <496px windows — the floor it claims to protect is no longer 400px there. With the Git dock open below ~796px the row still overflows (64 + floor + 300 min dock) and the Git tab still clips — pre-existing, unchanged, and strictly improved by 32px.
- Composer toolbar (`chat-input.component.ts:369-370, 435, 601-617`): the wrap rules live inside the existing native `@container ptah-composer (max-width: 400px)` query — the container is the composer root (`chat-input.component.ts:166, 585-588`), so wider layouts are untouched. At ~300px panes the container is ≤400px: labels are already icon-only (the 400px rule above), the start group takes `flex-basis: auto` so it keeps content width, and the end group wraps to its own right-aligned row (`margin-left: auto`) instead of overlapping — the "Opu… over the YOLO icon" collision cannot occur because flex wrapping guarantees the two groups never share an over-constrained row. Between 400 and ~450px panes the pre-existing squeeze/truncate behavior remains, which is by design (no overlap is possible there: every group carries `min-w-0`).

### 4. M2 — rail `⋯` menu offset: VERIFIED

`offset = round(trigger.left − rail.left) + 6` (`canvas-focus-header.component.ts:229-238`). With `left-start`, FloatingUI's offset middleware puts the menu's right edge at `trigger.left − offset` (`floating-ui.service.ts:163-181`, main-axis offset away from the reference), so the menu's right edge lands at `rail.left − 6` — exactly the requested 6px clearance left of the rail edge, replacing the old `offset: 4` measured from the trigger, which overlapped the rail by ~10px. Edge cases: null rail → `Math.max(0, …)` guards and the offset falls back to 6 (production rail mode always has the `data-inspector-rail` ancestor — the rail host carries it at `canvas-inspector-dock.component.ts:141`; the fallback is only reachable in tests); the spec's mocked rects (trigger 1510, rail 1496 → offset 20) pin the arithmetic (`canvas-focus-header.component.spec.ts:164-186`). Resize/scroll while open: `position()` installs `autoUpdate` (`floating-ui.service.ts:210`), which recomputes on resize and ancestor scroll; the captured inset stays valid because the rail's width is fixed and trigger and rail move together. RTL is out of scope per the criteria (the sign flips, but the app ships LTR only).

## The five logic questions

1. **Silent failure:** the closest candidate is Tailwind silently dropping an invalid arbitrary value — `min-w-[min(400px,calc(100vw-6rem))]` would vanish and the column would collapse to flex minimum with no error. It follows the exact repo convention proven in production (`max-h-[min(780px,calc(100vh-1rem))]`, `notification-center.component.ts:33`), and the new spec pins the class string. No silent failure introduced.
2. **Unexpected user action:** opening the workspace sidebar or the Git dock below ~496px still overflows the row and clips the Git tab — the floor cannot compensate for `shrink-0` panels it does not subtract. Pre-existing, 32px better than before, and outside the 400px default state the fix targets. Second: app chrome (top bar, side tabs, canvas footer) stays pointer-reachable while the `aria-modal` compact sheet is open — defect 2.
3. **Wrong answer from input data:** a stale wide `dock.width()` after a window shrink caps at `max-w-full` (board width) and the overlay then covers the left session rail too — recoverable through the overlay's own Close/Compact controls, and strictly no worse than the old `100vw` cap covering the entire window.
4. **Dependency failure:** `FloatingUIService.position` rejecting leaves the rail menu `visibility: hidden` while `aria-expanded` is true (retry once, then give up, `floating-ui.service.ts:192-208`). Pre-existing mechanism, untouched by this diff.
5. **Missing from requirements:** M3 (disabled Hand off shows no reason) from visual-review-rev2 is not addressed by this diff and is outside this round's acceptance criteria — flagged back to the coordinator, not counted against this diff.

## Defects

1. **(minor)** The floor reserves 6rem but the two tabs are 4rem, and the changed comment says "leaving room for both sidebar tabs". `electron-shell.component.ts:398-405` vs `sidebar-tab.component.ts:63-64` (`w-8` default, no `size` input passed at `electron-shell.component.ts:390,451`). Failure scenario: at a 464-496px window with the workspace sidebar open, the chat column is 32px narrower than the space actually available, shrinking the transcript/composer for no benefit; any future reader "correcting" 6rem→4rem from the comment alone would introduce a worse clip when panels are open. Suggested fix: either keep 6rem and correct the comment to "both sidebar tabs (4rem) plus a 2rem buffer for an open panel", or reserve `calc(100vw-6rem)` knowingly and leave a test pinning the constant. The adjacent stale comment `electron-layout.service.ts:54` ("below its 400px CSS min-width") should be updated in the same pass.
2. **(minor)** The `aria-modal` compact sheet no longer isolates anything outside the board. With `fixed inset-0` the sheet blocked the whole window; with `absolute inset-0` inside the board layout, the app top bar, the Workspaces/Git tabs and the canvas footer (a sibling of `.session-viewport`, `orchestra-canvas.component.ts:83-104`) stay pointer-reachable while `[role="dialog"][aria-modal="true"]` (`canvas-inspector-dock.component.ts:241-245`) tells assistive tech the rest is inert. Failure scenario: a sighted pointer user opens a modal detail sheet, clicks Settings in the top bar mid-modal, and lands on a standalone route with the sheet state silently retained (the Tab trap still cycles inside the sheet, so keyboard users are unaffected; Escape still closes). Suggested fix: state this as intended board-scoped modality in the comment at `canvas-inspector-dock.component.ts:239`, or mark the app chrome `inert` while `compactSheetOpen()` — but note the visual review explicitly wanted the top bar usable, so the comment is likely enough.

## Decisions

- **6rem is accepted as a deliberate buffer, not re-litigated as a blocking constant** (defect 1 records the mismatch). Options: exact 4rem vs 6rem with comment; evidence: `w-8` tabs, `flex-1` fill making closed-panel behavior identical, and the 32px-over-reserve reducing overflow when a panel is open. Reversible by a one-line class change.
- **The compact sheet's board-scoped modality is treated as intended** (defect 2, comment-only fix recommended): the B1 fix the visual review itself offered ("offset the sheet below the nav… or lift it above the nav") is satisfied more strongly by board containment, and the review demanded the top bar stay clickable.
- **Judged the e2e failure fixed-by-plausibility, not by evidence**: the geometric cause (title row at window y≈8 under the top bar, proven by `elementFromPoint` in visual-review-rev2) is removed by the containing-block change; the CI run is the confirming step.
- The `calc()`-without-spaces arbitrary value was checked against the repo's own working convention (`canvas-rail-card.component.ts:346`, `notification-center.component.ts:33`) rather than assumed.
