# Code logic review — TASK_2026_707 PR 2 backend (usage analytics aggregate + RPC)

Independent family: ptah-cli (Ollama Cloud). Implementer families: codex (batches A, A2), antigravity (batch B).
Scope reviewed: `libs/shared/src/lib/types/rpc/rpc-analytics.types.ts` + `rpc.types.ts` registration, `libs/backend/agent-sdk/src/lib/session-stats/**` (public dated scan), `libs/backend/usage-analytics/**` (all sources, pricing, summary, DI), `libs/backend/rpc-handlers` analytics handler + registration + host manifest, three host DI roots, `tsconfig.base.json`.

## Verdict

**APPROVE WITH FIXES — score 6/10**

Tally: 0 blocking, 5 major, 4 moderate, 9 minor. The core is sound: UTC bucketing, the exclusive end, Claude message-id dedup across parent/subagent ledgers, cost provenance rules (reported never summed, unknown is null + `unpriced`, never 0), Grok tick conversion, workspace confinement before any filesystem access, and per-file cache identity are all implemented correctly and the suite passes independently (I ran it: 5 suites, 10 tests). The score sits in the "real gaps" band because dedup is not a stable session/message identity for Codex and Grok, one token normalization is an unverified external assumption that can double count, a budget timeout destroys the whole response instead of degrading to partial, and the project's guard-spec rule for new services/RPC methods was knowingly skipped. Nothing here corrupts data on the normal path or breaks any host at runtime today, so nothing is blocking.

## Verified correct (with evidence)

1. **Range math and UTC bucketing.** `usage-summary.service.ts:32-34` computes UTC-midnight `since`/`until` with an exclusive end; `file-facts.ts:51` filters `>= since && < until`; `usage-summary.service.ts:51` derives the day from `toISOString()`. Codex enumerates day folders with `getUTCFullYear/Month/Date` (`codex.source.ts:22-23`). The agent-sdk spec pins the exclusive boundary (`session-stats-reader.service.spec.ts:468-488`).
2. **Claude dedup including subagent transcripts.** `scanDatedUsage` (`session-stats-reader.service.ts` diff, new lines ~115-185) yields key `sessionId:messageId` (`record.messageId ? ...`), so a record duplicated between the parent ledger and an owned subagent ledger collapses in the summary `seen` set (`usage-summary.service.ts:46-48`). Copied transcript files cannot re-enter: the UUID filename filter (`UUID_REGEX.test(name.replace(/\.jsonl$/, ''))`) rejects renamed copies, and the scan is scoped to the workspace's own sessions directory. The ledger change that carries `messageId` is additive (`session-usage-ledger.ts:219-242`).
3. **Cost provenance.** `usage-pricing.service.ts:12-13` returns a provider-reported cost alone; each contribution takes exactly one branch, so reported and model-priced costs are never summed. Missing pricing or missing cache rates → `{ costUsd: null, costSource: 'unpriced' }` (`usage-pricing.service.ts:29-33`); `calculateMessageCost` returns null, never 0, when unpriced (`pricing.utils.ts:404-421`), and the fact schema enforces `costUsd === null ⇔ costSource === 'unpriced'` (`rpc-analytics.types.ts:26-28`). Grok ticks divide by 1e10 per the xAI doc (`grok.source.ts:8-9`).
4. **Grok per-model over turn totals.** `grok.source.ts:52-58` reads only `modelUsage` and marks a `turn_completed` without it partial instead of adding the aggregate — no double count between turn totals and model rows.
5. **Codex per-event deltas.** `codex.source.ts:54-59` uses `last_token_usage` (never `total_token_usage`), subtracts `cached_input_tokens` from input, and rejects `cached > input` as malformed.
6. **Workspace confinement before filesystem access.** The handler resolves and authorizes the workspace before `summarize` runs (`analytics-rpc.handlers.ts:70-82`); sources touch only their own home directories; `sourceId` values are fixed labels and logs carry fixed messages or `error.name` only (`usage-summary.service.ts:69`, `analytics-rpc.handlers.ts:75-76`). Params are strict-parsed and the invalid-params error names only fields (`analytics-rpc.handlers.ts:58-67`).
7. **Cache identity and bounds.** File key is `path\0size\0mtimeMs` (`file-facts.ts:21`) so appends reparse; 4000 entries / 100k facts FIFO eviction (`file-facts.ts:29-34`); 64 MiB file and 1 MiB line caps fail safe (`file-facts.ts:20`, `file-facts.ts:44-48`); Codex/Grok cap at 10,000 files, OpenCode at 100,000 rows with an overflow probe (`opencode.source.ts:34-36`). Two simultaneous calls only duplicate parse work; the maps are safe in a single thread.
8. **Failure isolation in the sources.** Missing stores → `unavailable` with fixed reasons (`codex.source.ts:18`, `grok.source.ts:21`, `opencode.source.ts:22`); malformed lines increment counts instead of throwing; `better-sqlite3` is lazy-required inside a try (`opencode.source.ts:29-31`), opened `readonly` + `fileMustExist` and closed in `finally` (`opencode.source.ts:31,58`), so a host whose ABI cannot load it degrades to `unavailable` rather than crashing — and the module is already a root dependency (`package.json:150`) used by cron-scheduler/lane-outcomes stores in the same hosts.
9. **RPC registration.** `rpc.types.ts` gains the registry entry and the runtime method entry; the runtime allowlist prefix already existed; the manifest entry has `requires: []` so every host serves the method and the surface specs derive it automatically; registration order is safe in all three hosts (`registerUsageAnalytics` after auth providers in `apps/ptah-electron/src/di/phase-2-libraries.ts`, `apps/ptah-extension-vscode/src/di/phase-2-libraries.ts`, `libs/backend/cli-engine/src/lib/container.ts`; tsyringe resolution is lazy, so the later `registerSdkServices` still lands before the handler is resolved).

## Defects

### Major

1. **Dedup is not a stable session/message identity for Codex and Grok — moved or resumed sessions double count.** Codex keys facts `file:lineIndex` (`codex.source.ts:59`); Grok keys `file:promptId:model` (`grok.source.ts:61`). A rollout file copied or resumed under a new path replays the same requests with new keys, so every replayed `token_count` and `turn_completed` is counted again. The plan requires "dedup moved copies by stable session/message identity" (`implementation-plan.md:111`), and the research file notes the comparison product deduplicates across moved session copies (`provider-usage-sources.md:364-366`). Fix: derive the key from stable content identity — Codex: rollout session id (from `session_meta`) + the response item id or a hash of (timestamp, model, usage quadruple); Grok: session id (directory name) + `prompt_id` + model, dropping the file path from the key.
2. **OpenCode input tokens are not normalized to uncached — possible systematic double count, and the assumption is unverified.** `opencode.source.ts:50` sets `inputUncachedTokens: value.tokens.input` while Codex subtracts cached from input (`codex.source.ts:59`). If OpenCode's stored `input` includes cache-read tokens (as Ollama's does, `provider-usage-sources.md:131`), then `input + cacheRead` double counts every cached token in "Processed". The research file has no OpenCode section, so this is an external assumption no fixture validates; the asymmetry between the two sources shows it was not settled. Fix: capture a real `opencode.db` fixture and either subtract `tokens.cache.read` from `tokens.input` (matching Codex) or document the verified disjoint semantics; also verify `time.created` is epoch ms (the row schema accepts seconds too, `opencode.source.ts:9`).
3. **The 30 s budget timeout fails the whole RPC instead of returning partial, and the Claude scan that can hit it is uncapped.** On abort mid-scan the service rethrows (`usage-summary.service.ts:68`), the handler maps every non-user error to `PERSISTENCE_UNAVAILABLE` (`analytics-rpc.handlers.ts:94-102`), and all accumulated facts are discarded. `ClaudeLedgerSource` already catches the abort and returns partial contributions (`claude-ledger.source.ts:26-28`), but the next `throwIfAborted()` at `usage-summary.service.ts:40` throws them away. The plan requires "report `partial` on timeout rather than fake completeness" (`implementation-plan.md:111`). `scanDatedUsage` enumerates every transcript record with no file or record cap (unlike Codex/Grok's 10,000-file and OpenCode's 100,000-row caps), and `claude-ledger.source.ts:10` accumulates all contributions in memory, so a large store makes the budget reachable and the dashboard then shows a hard error, not partial data. Fix: on `AbortError` inside the source loop, stop the loop and return the summary with the remaining sources marked `unavailable` reason `scan budget exceeded`; give the Claude source the same file bound as the other sources.
4. **`better-sqlite3` is missing from the library's build externals.** `libs/backend/usage-analytics/project.json` external list has only `vscode, tsyringe, eventemitter3, rxjs, @anthropic-ai/claude-agent-sdk`, while `libs/backend/cron-scheduler/project.json:21` lists `better-sqlite3` (and `sqlite-vec`) for the same situation. The lib's own `build` target would try to bundle the native module and fail or ship a broken bundle. Fix: add `"better-sqlite3"` to `external`.
5. **Guard specs were not updated; no spec in any host resolves the new handler or the service token.** Confirmed: zero occurrences of `Analytics` in any `container.smoke.spec.ts`, `expected-resolvable.ts`, `rpc-surface.spec.ts` or `surface-composition.spec.ts`. The surface specs derive from the manifest, so the method surface is covered, but the DI seam is not: `EXPECTED_RESOLVABLE` is an explicit list of handler classes resolved against a production-shaped container (`apps/ptah-electron/src/di/expected-resolvable.ts:13-28`, `container.smoke.spec.ts:261-264`), and optional tokens are resolved port-style (`container.smoke.spec.ts:99`). A host that forgets `registerUsageAnalytics` makes `AnalyticsRpcHandlers` throw at resolution (its constructor injects `USAGE_ANALYTICS_TOKENS.USAGE_ANALYTICS_SERVICE`), and today no test would notice. The project rule quoted in the review brief makes these updates required, not follow-up. Fix: add `AnalyticsRpcHandlers` to `EXPECTED_RESOLVABLE` in each host, and resolve `USAGE_ANALYTICS_TOKENS.USAGE_ANALYTICS_SERVICE` in each `container.smoke.spec.ts` the way `SKILL_TELEMETRY_SEAM` is resolved — that is the assertion that proves the libraries-phase registration ran.

### Moderate

6. **Unknown-workspace CLI facts are included under a workspace filter.** `workspaceMatches` returns `true` when the recorded root is missing (`file-facts.ts:56`), so Codex facts without cwd (`codex.source.ts:33-34`), Grok directories whose name fails `decodeURIComponent` (`grok.source.ts:25-27`), and OpenCode rows with a null session directory (`opencode.source.ts:45-46`) all enter the requested workspace's totals, only flagged partial. The dashboard then attributes another workspace's spend to the displayed workspace. Fix: when a workspace filter is active, exclude facts with a missing root (keep the partial flag) or aggregate them under a distinct `unknown-workspace` sourceId so totals stay honest. Related: Codex pins `cwd` from `session_meta` only (`codex.source.ts:52`), so a mid-session directory change keeps the old root.
7. **Unreadable Grok session files vanish silently.** The per-session catch is empty (`grok.source.ts:37`): a corrupt or permission-denied `updates.jsonl` adds no malformed count and no partial flag, so a store full of broken sessions still reports `complete` — contradicting batch A2's claim that all sources surface errors as counts. Fix: count skipped files as malformed or set partial in that catch.
8. **No summary-level memoization; the 90-day warm target is unmeasured and the plan's persisted rollup was dropped.** Batch A2 removed the 30-second snapshot; every request re-prices and re-groups every in-range contribution, and `scanDatedUsage` iterates every ledger record even when no file changed (the ledger cache avoids parsing only). The plan's warm ≤2 s / cold ≤10 s fixture was never run, and the planned persisted daily rollup (file identity + byte offsets, `implementation-plan.md:111`) is not implemented. Fix (minimum): a short-TTL summary memo keyed by range + workspace + per-source file identities; schedule the persisted rollup before calling warm performance done.
9. **Contract gap — cache savings cannot be computed by the frontend.** `UsageFact` (`rpc-analytics.types.ts:19-28`) carries `cacheReadTokens` and `costUsd` but no savings field, and the plan requires savings ("cached-input tokens priced at the full uncached input rate minus their actual cache-read cost", `implementation-plan.md:109`). Recommendation — add exactly one additive field: `cacheSavingsUsd: number | null` on `UsageFactSchema` and the summary row builder. Compute it in `UsagePricingService.price()` where pricing and tokens are both in hand: `cacheReadTokens * (pricing.inputCostPerToken - pricing.cacheReadCostPerToken)`, returning `null` when `costSource === 'unpriced'` or the input rate is missing; `pricesCacheTokens` (`pricing.utils.ts:427-436`) already guarantees the cache-read rate exists whenever `cacheReadTokens > 0`, so every model-priced fact is computable. Sum it in the group loop exactly like `costUsd` (`usage-summary.service.ts:61`). Do not add a cache-write savings field — cache writes cost more than input, not less.

### Minor

10. **OpenCode `cost > 0` is labeled `provider-reported`, contradicting the plan.** `implementation-plan.md:107` says OpenCode local cost is "a reported local estimate, labeled model-priced unless provider billing evidence exists". The implementation (`opencode.source.ts:50` → `usage-pricing.service.ts:12-13`) matches the review brief's stated expectation instead. OpenCode's `cost` is OpenCode's own priced estimate, not provider-billed spend; either relabel it model-priced or record the deviation as a settled decision.
11. **The bundled fallback drops the provider qualifier.** For Codex/Grok facts the OpenRouter lookup is qualified (`codex/gpt-5` — never a real slug, so the catalog always misses) but the bundled lookup uses the bare model id (`usage-pricing.service.ts:22`), against the plan's "keep the provider qualifier in the key to avoid cross-provider collisions" (`implementation-plan.md:109`). Fix: qualify the bundled lookup, or map provider → OpenRouter vendor prefix (codex → openai, grok → xai) before both lookups.
12. **`MAX_FACTS` overflow leaves inconsistent state.** The throw at `usage-summary.service.ts:65` is caught by the source loop: up to 100k partially accumulated facts stay in the response, an extra `sourceId: 'unknown'` unavailable status is appended while the real source status (pushed at :43) still says complete. Fix: on overflow mark the offending source partial and stop, or drop that source's groups.
13. **Claude records without a message id can double count across parent/member ledgers.** The fallback key is `sessionId:ledgerName:index` (scanDatedUsage), so a duplicated null-id record in parent and subagent files enters twice. Older transcripts only; acceptable if noted.
14. **Codex schema failures skip silently.** A `token_count` whose payload fails `payloadSchema` or `usage` parsing `continue`s without `malformed++` (`codex.source.ts:51,56`) — an undercount invisible in status. Count them.
15. **Readonly WAL edge.** A readonly connection to a WAL database with no existing `-shm` can fail to open; the catch returns `unavailable` (`opencode.source.ts:56-57`), so OpenCode reads can silently report unavailable while OpenCode is not running. Worth a reason string that names the WAL case.
16. **OpenCode cache eviction wipes everything.** `if (this.cache.size >= 12) this.cache.clear()` (`opencode.source.ts:53`) discards all entries instead of the oldest; bounded but crude.
17. **`pricing.asOf` is the generation time, not the catalog as-of** (`usage-summary.service.ts:79`) — the plan wants the price-catalog version/timestamp. Semantic nit.
18. **Source failures are logged as `sourceId: 'unknown'`.** The per-source catch (`usage-summary.service.ts:70`) loses which source failed (only `error.name` is logged); the frontend cannot point the user at the broken source. Carry the source id into the pushed status.
19. **Ollama Cloud and Antigravity are hard `unavailable`** (`cli-session.source.ts`), although the plan required an Ollama `/api/usage` source covering 7/30-day windows with a top-ten + remainder split (`implementation-plan.md:107`). Disclosed by both batches and outside this review's source list, but it is a plan requirement not met — schedule it; do not let the dashboard imply Ollama has no usage.

## The five logic questions

1. **Silent failure:** unreadable Grok sessions and schema-failed Codex events disappear without any status signal (defects 7, 14); a failed source in the summary is reported as `unknown` (defect 18); a `better-sqlite3` load failure correctly degrades to `unavailable`.
2. **Unexpected user action:** switching to the 90-day range on a large store can trip the 30-second budget and yield a hard `PERSISTENCE_UNAVAILABLE` instead of partial data (defect 3); filtering by a workspace shows other workspaces' CLI spend when cwd metadata is missing (defect 6).
3. **Wrong answer, not error:** moved/resumed Codex rollouts and copied Grok sessions double count (defect 1); OpenCode totals double count cache reads if the stored input is inclusive (defect 2); an unqualified bundled lookup can price the wrong vendor's same-named model (defect 11).
4. **Dependency failure:** OpenRouter fetch failure falls back to the bundled card correctly; a sqlite open/WAL failure degrades to `unavailable` with a generic reason (defect 15); an abort mid-operation destroys the response instead of degrading (defect 3).
5. **Missing versus requirements:** cache savings on the wire (defect 9), the Ollama 7/30-day API source (defect 19), the persisted daily rollup and measured performance fixture (defect 8), and the guard-spec updates the project rule requires (defect 5).

## Decisions

- Treated the OpenCode `tokens.input` cache semantics as an unverified external assumption rather than a proven bug, because the research file has no OpenCode section; the fix is a real-database fixture, and the finding stays major because the two CLI sources contradict each other on the same normalization.

- Kept the review brief's cost-provenance expectation (`OpenCode cost>0 → provider-reported`) as the accepted behaviour and recorded the plan-text conflict as a minor deviation to settle in documentation (defect 10).
