## Notes

### Five logic questions

1. **Silent failure:** #101 currently turns a rejected dynamic import into intentionally empty chips and summaries (`batches.md:1573-1577`). Without rejection-cache policy, that success-looking empty state can persist after a recoverable loader failure.
2. **Unexpected user action:** A user who closes the dock before the first display in the live turn is correctly held back by #99 once transcript wiring supplies the live turn (`display-dock.state.ts:152-163,230-234`; `batches.md:1567-1569`). A user closing Displays while agents run now also holds Agents closed; that is an intentional, acceptable consequence of one dock (`display-dock.state.ts:160,255-263`).
3. **Wrong input data:** A stale callback from a prior transcript instance can build a valid-looking summary map for superseded turn inputs unless #101 adds a lifecycle/current-input guard; the existing per-tab map does not identify transcript generation (`display-dock.state.ts:104-114,236-252`).
4. **Dependency failure, timeout, or bad shape:** The only stated dynamic-import failure handling is “no chip and no summaries” (`batches.md:1573-1577`). The ruling must prescribe bounded retry/reset behavior; no network or timeout path may publish a partial map.
5. **Missing requirement:** Cache scope and invalidation are unspecified. A shared cached module namespace is safe, but per-tab summary data must remain in `DisplayDockState`'s tab-keyed state; late imports must not write after destroy/remount (`display-dock.state.ts:104-114,236-252`).

## Decisions

- Open point: choose and document the retry boundary for a failed Electron lazy import (recommended: clear the rejected loader promise and retry only on a subsequent eligible summary publication, avoiding repeated retries in one reactive tick).
- Open point: require a destruction/generation guard before an async loader completion publishes summaries, including the remount case.
