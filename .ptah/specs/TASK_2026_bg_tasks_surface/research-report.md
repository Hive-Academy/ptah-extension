# Research Report - TASK_2026_bg_tasks_surface

## Summary

- Background Bash reaches the SDK transformer as `local_bash`, but the transformer returns no event (`libs/backend/agent-sdk/src/lib/message-transform/system-message.transformer.ts:176-198`).
- Background Task subagents and CLI lanes have complete code paths to existing Electron agent surfaces (`libs/frontend/chat/src/lib/services/session-agents/session-agent-roster.service.ts:69-100`).
- Monitor has a static inline card, not a live task-status view (`libs/frontend/chat/src/lib/components/organisms/execution/monitor-card.component.ts:26-87`).
- Generic SDK tasks have no live non-agent store or roster input. The SDK snapshot message is also dropped (`libs/backend/agent-sdk/src/lib/sdk-message-transformer.ts:427-431`).

## Root causes

1. **The backend deliberately excludes background Bash from the live agent pipeline.** `isAgentTaskType` returns false for `local_bash` (`libs/shared/src/lib/type-guards/guards/exec.ts:329-350`). The task-start handler marks the task and returns an empty event list (`libs/backend/agent-sdk/src/lib/message-transform/system-message.transformer.ts:176-198`). Later progress and update handlers also discard it (`libs/backend/agent-sdk/src/lib/message-transform/system-message.transformer.ts:324-394`). The terminal path settles the ordinary tool result instead of creating a live background entry (`libs/backend/agent-sdk/src/lib/message-transform/system-message.transformer.ts:658-698`).

2. **Ptah does not consume the SDK's generic live-task snapshot.** The installed SDK defines `background_tasks_changed` as replacement state for the complete live background-task set (`node_modules/@anthropic-ai/claude-agent-sdk/sdk.d.ts:3495-3515`). The SDK also says to exclude ambient tasks from activity indicators (`node_modules/@anthropic-ai/claude-agent-sdk/sdk.d.ts:5648-5756`). Ptah has guards and dispatch for the four lifecycle messages, but no snapshot branch; unknown messages are dropped (`libs/backend/agent-sdk/src/lib/sdk-message-transformer.ts:391-431`, `libs/backend/agent-sdk/src/lib/types/sdk-types/claude-sdk.types.ts:416-440`).

3. **The Electron roster models agents, not generic background work.** Its only work inputs are subagents, CLI agents, and background agents (`libs/frontend/chat/src/lib/services/session-agents/session-agent-roster.service.ts:79-87`). The roster builder creates only orchestrator, subagent, CLI, and background-agent rows (`libs/frontend/chat/src/lib/services/session-agents/session-agent-roster.ts:87-212`). `pendingBackgroundTasks` is stored after a turn but is documented as later Phase 3 UI state (`libs/frontend/chat-state/src/lib/tab-manager.service.ts:1884-1905`, `libs/frontend/chat-types/src/lib/chat-types.ts:772-776`). Therefore, a Bash or Monitor task without an agent record has no row to render.

4. **The existing Monitor component is not a live task surface.** `ExecutionNodeComponent` mounts the card inside the execution tree (`libs/frontend/chat/src/lib/components/organisms/execution/execution-node.component.ts:276-298`, `libs/frontend/chat/src/lib/components/organisms/execution/execution-node.component.ts:735-743`). `MonitorCardComponent` reads only tool input and presents static command metadata (`libs/frontend/chat/src/lib/components/organisms/execution/monitor-card.component.ts:10-19`, `libs/frontend/chat/src/lib/components/organisms/execution/monitor-card.component.ts:26-87`). It cannot show SDK task progress or completion.

5. **A shared RPC or Electron mount failure does not explain all four kinds.** SDK subagents and CLI lanes both reach the same existing roster. Canvas mounts `CanvasLaneTabsComponent` (`libs/frontend/canvas/src/lib/canvas-rail/canvas-focus-area.component.ts:51-58`), and the inspector renders all session agents with a running count (`libs/frontend/chat/src/lib/components/organisms/session-inspector/inspector-agents-section.component.ts:60-70`, `libs/frontend/chat/src/lib/components/organisms/session-inspector/inspector-agents-section.component.ts:82-124`). The legacy agent panel is disabled when the Electron dock is enabled (`libs/frontend/chat/src/lib/components/templates/chat-view.component.html:296-333`, `libs/frontend/chat/src/lib/components/templates/chat-view.component.ts:428-435`), so it is not the primary Electron surface.

## Recommended fix

Use the SDK snapshot as the generic task source, and reuse the existing Electron agent surfaces.

1. Add a `background_tasks_changed` transform branch. Emit one flat snapshot event with session ID and the replacement task list. Filter ambient tasks as the SDK contract requires (`node_modules/@anthropic-ai/claude-agent-sdk/sdk.d.ts:3495-3515`, `libs/backend/agent-sdk/src/lib/sdk-message-transformer.ts:391-431`).
2. Store the snapshot by session with replace semantics. Keep task kind, description, status, and task ID. Do not convert shell or monitor work into false subagent identities.
3. Add those generic task rows to `SessionAgentRosterService`. Render them through the existing `CanvasLaneTabsComponent` and `InspectorAgentsSectionComponent` mount points (`libs/frontend/chat/src/lib/services/session-agents/session-agent-roster.service.ts:69-100`, `libs/frontend/canvas/src/lib/canvas-rail/canvas-focus-area.component.ts:39-68`).
4. Keep the existing SDK-subagent and CLI-lane paths unchanged. Their event, store, and render chains are complete in the inspected code.

This is the smallest single fix that covers Bash, Monitor, and other SDK task kinds. A Bash-only change would leave the generic task gap and would not use the SDK's intended level signal.

## Decisions

- **Decision:** trace the installed SDK, not an assumed newer contract. **Evidence:** the installed package is `@anthropic-ai/claude-agent-sdk` 0.3.278 with Claude Code 2.1.278 (`node_modules/@anthropic-ai/claude-agent-sdk/package.json:3`, `node_modules/@anthropic-ai/claude-agent-sdk/package.json:83`). **Reversible:** yes.
- **Decision:** treat Canvas lane tabs, the session inspector, and Command Center as the Electron surfaces. **Evidence:** Electron enables the dock, while the legacy panel is limited to `!dockEnabled` (`libs/frontend/chat/src/lib/components/templates/chat-view.component.ts:428-435`, `libs/frontend/chat/src/lib/components/templates/chat-view.component.html:296-333`). **Reversible:** yes.
- **Decision:** prefer the generic snapshot over a Bash-only exception. **Evidence:** the snapshot covers the full live set and has replace semantics, while the current transformer drops it (`node_modules/@anthropic-ai/claude-agent-sdk/sdk.d.ts:3495-3515`, `libs/backend/agent-sdk/src/lib/sdk-message-transformer.ts:427-431`). **Reversible:** yes.
- **Verified:** the cited source paths and component mounts above were inspected directly. **Inferred:** the user-visible absence follows when no live record reaches those components; this investigation did not reproduce the runtime symptom.

## Unknowns

- No runtime trace established which SDK task type each Monitor variant emits. The exact effect of `skip_transcript`, `ambient`, and missing `tool_use_id` therefore remains conditional on the runtime message.
- No runtime trace established why a specific background subagent or CLI lane was absent if that occurred. Exact session ownership can filter otherwise valid records (`libs/frontend/chat/src/lib/services/session-agents/owned-by-session.ts:1-8`).
- Snapshot delivery frequency and event ordering relative to per-task lifecycle messages were not measured.
- Builds, tests, verification, and runtime reproduction were intentionally not run under the task constraints.
