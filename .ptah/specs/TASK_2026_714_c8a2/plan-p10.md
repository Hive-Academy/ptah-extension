## Risks

1. **Hard runtime refusal:** codex-runtime.ts:56-65 currently rejects nonempty lane suppressions. Native selection before 10b.0a/b would fail every normal lane. The 10b prerequisite and start-frame proof are mandatory.
2. **False parity from test doubles:** 10a profile/events tests demonstrate projection, not App Server execution. 10d.P needs host composition and coordinator-run live evidence where unit fixtures cannot establish binary, MCP or report behavior; the requested stop before paid/live execution is a real gate.
3. **Resume identity:** the runtime requires full CodexThreadIdentity and fingerprint (codex-runtime.ts:29-55), while the lane request carries a session id. A missing identity must fail visibly, not start a new thread.
4. **Policy bleed:** shared runtime contexts can coexist; home, cwd, MCP, instructions and approval/sandbox must stay context-scoped. A two-home test is insufficient for same-home isolation (parity-inventory.md:12).
5. **Host composition gap:** Electron already has runtime composition, while CLI engine and VS Code currently only register the SDK and CLI services (container.ts:701,768; phase-2-libraries.ts:197,261). Removal B cannot precede host bindings.
6. **Packaged dependency:** deleting root/agent-sdk/app SDK metadata early may break the native binary resolver at agent-sdk/src/lib/detector/codex-native-binary-path.ts:145 and packaging externals. This belongs to P15 audit.
7. **Cost and timing:** context startup, model/list and retry may launch processes but should not trigger a paid model turn. Live/paid proof remains coordinator-owned under batches.md:3646.
