# Codex native usage, pricing, and plan limits: source audit

Scope: Electron native chat first, then native CLI lanes. This is a code and spec audit, not an executed test or a paid App Server observation. The native chat translator, turn stream, and Electron scope are the relevant implementation boundaries (`libs/backend/codex-runtime/src/lib/codex-event-translator.ts:215`, `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-turn-stream.ts:221`, `apps/ptah-electron/src/di/codex-runtime-composition.ts:219`). Runtime behavior beyond the cited implementation and specs is **UNCONFIRMED**.

## 1. Claude baseline

**Price source and arithmetic.** `findModelPricing` uses a runtime rate map, with a small bundled table and a null result for an unknown model; the comments identify OpenRouter catalog hydration and explicitly omit subscription-covered Codex IDs from that table (`libs/shared/src/lib/utils/pricing.utils.ts:43-59`, `libs/shared/src/lib/utils/pricing.utils.ts:64-109`). `calculateMessageCost` sums input, output, cache-read, and cache-creation rates, returning null for an unknown rate (`libs/shared/src/lib/utils/pricing.utils.ts:404-420`). The Claude result transformer prefers the SDK's reported per-model `costUSD` when available; otherwise it asks the pricing provider and applies that four-class calculation (`libs/backend/agent-sdk/src/lib/helpers/stream-transformer.ts:858-895`). It uses SDK `total_cost_usd` for a reported cumulative run cost, or sums priced model rows, leaving it null when any row is unpriced (`libs/backend/agent-sdk/src/lib/helpers/stream-transformer.ts:938-954`). Live provisional cost uses the same calculator (`libs/backend/agent-sdk/src/lib/helpers/live-session-stats-publisher.ts:551`).

**Turn versus session.** The SDK result's `usage` is per turn, while `modelUsage` is cumulative for its query, including subagents; the transformer replaces the run's value in `SessionStatsOwnerService`, rather than adding every cumulative result (`libs/backend/agent-sdk/src/lib/helpers/stream-transformer.ts:956-980`, `libs/backend/agent-sdk/src/lib/helpers/stream-transformer.ts:989-1003`). The owner calculates an accepted turn's cost as a delta, rejects duplicates/nonmonotonic results, and publishes a lifetime snapshot; unknown or decreasing cost stays null (`libs/backend/agent-sdk/src/lib/session-stats/session-stats-owner.service.ts:557-607`, `libs/backend/agent-sdk/src/lib/session-stats/session-stats-owner.service.ts:918-951`). The transformer sends `turnCost`, four token classes, duration, per-model context/cost, and optional authoritative `sessionStats` through `onResultStats` (`libs/backend/agent-sdk/src/lib/helpers/stream-transformer.ts:1060-1079`). The host callback broadcasts `MESSAGE_TYPES.SESSION_STATS` with those fields, including the optional snapshot (`libs/backend/cli-agent-runtime/src/lib/wiring/sdk-callbacks.ts:432-453`). The renderer routes that message to `ChatStore`; `SessionStatsAggregatorService` installs the snapshot in each tab and derives live model context separately (`libs/frontend/chat/src/lib/services/chat-message-handler.service.ts:185-189`, `libs/frontend/chat/src/lib/services/chat-message-handler.service.ts:787-816`, `libs/frontend/chat/src/lib/services/chat-store/session-stats-aggregator.service.ts:118-174`). The session stats source passes the snapshot to the shared UI; its header reads cost and token count only from the backend snapshot, and context from live model stats (`libs/frontend/chat/src/lib/services/session-stats/session-stats-source.ts:230-245`, `libs/frontend/chat-ui/src/lib/molecules/session/session-stats-summary.component.ts:95-107`, `libs/frontend/chat-ui/src/lib/molecules/session/session-stats-summary.component.ts:221-240`). Context uses the last request's input/cache context reading and provider window evidence, not cumulative session tokens (`libs/backend/agent-sdk/src/lib/helpers/stream-transformer.ts:165-172`, `libs/frontend/chat/src/lib/services/chat-store/session-stats-aggregator.service.spec.ts:476-516`).

**Reload and metadata.** `SessionStatsOwnerService.prepareRun` reloads transcript prefix and saved cost state; the reader scans Claude JSONL sessions and subagent files and prices their usage, with `totalCost: null` when pricing coverage is partial (`libs/backend/agent-sdk/src/lib/session-stats/session-stats-owner.service.ts:452-470`, `libs/backend/agent-sdk/src/lib/session-stats/session-stats-reader.service.ts:155-195`, `libs/backend/agent-sdk/src/lib/session-stats/session-usage-aggregator.ts:250-305`). `session:stats-batch` serves the same transcript projection for dashboard/reload reads (`libs/backend/rpc-handlers/src/lib/handlers/session-rpc.handlers.ts:1253-1270`, `libs/frontend/dashboard/src/lib/models/session-analytics.models.ts:15`). The metadata type does declare `totalCost` and `totalTokens`, but inspected creation paths initialize them to zero and the Codex update preserves existing values; the chat history reader instead reads `stats?.totalCost` and token counts from a stats snapshot (`libs/backend/agent-sdk/src/lib/session-metadata-store.ts:307-318`, `libs/backend/agent-sdk/src/lib/session-metadata-store.ts:1166-1173`, `libs/backend/agent-sdk/src/lib/session-metadata-store.ts:2123-2124`, `libs/backend/agent-sdk/src/lib/session-history-reader.service.ts:440-441`). **Finding:** transcript/saved-cost reconstruction, not those metadata counters, is the evidenced Claude reload path; whether any other writer updates the metadata counters is **UNCONFIRMED** after searching source assignments (`libs/backend/agent-sdk/src/lib/session-metadata-store.ts:1172-1173`, `libs/backend/agent-sdk/src/lib/session-stats/session-stats-reader.service.ts:155-195`).

**Plan limits are distinct from dollar cost.** Claude stream `rate_limit_event`, assistant rate-limit errors, and API retries are mapped to plan-limit evidence and notified through a callback registry (`libs/backend/agent-sdk/src/lib/helpers/plan-limits/claude-rate-limit.mapper.ts:5-18`, `libs/backend/agent-sdk/src/lib/helpers/stream-transformer.ts:737-755`, `libs/backend/agent-sdk/src/lib/helpers/plan-limits/session-plan-limit-callback-registry.ts:2-23`). An open native Claude session can also read its `/usage` table through `ClaudePlanUsageReader` (`libs/backend/auth-providers/src/lib/quota/readers/claude-plan-usage.reader.ts:2-7`, `libs/backend/auth-providers/src/lib/quota/readers/claude-plan-usage.reader.ts:164-228`). `provider:getPlanLimits` returns the owner's snapshot; `PlanLimitsStore.load()` calls it and also accepts `PLAN_LIMITS_CHANGED` pushes; `session-stats-source` attaches the resulting owner view to the shared header's Plan limits section (`libs/backend/rpc-handlers/src/lib/handlers/provider-rpc.handlers.ts:253-267`, `libs/frontend/core/src/lib/services/plan-limits.store.ts:2-23`, `libs/frontend/core/src/lib/services/plan-limits.store.ts:175-221`, `libs/frontend/chat/src/lib/services/session-stats/session-stats-source.ts:178-245`, `libs/frontend/chat-ui/src/lib/molecules/session/session-stats-summary.component.html:403-415`).

## 2. Codex today: end-to-end and accounting edge cases

**Native data path.** `thread/tokenUsage/updated` has `last`, `total`, and an optional model window; the schema's usage buckets are input, cached input, output, reasoning output, total, and optional cache write (`libs/backend/codex-runtime/src/lib/codex-protocol-methods.ts:389-395`, `libs/backend/codex-runtime/src/lib/codex-protocol-schemas.ts:649-655`). `CodexEventTranslator` stores a thread baseline at `turn/started`, derives the first baseline as `total - last` if necessary, updates the thread total, and emits the whole-turn delta, the last request total for context, and only a positive model context window (`libs/backend/codex-runtime/src/lib/codex-event-translator.ts:114-125`, `libs/backend/codex-runtime/src/lib/codex-event-translator.ts:215-239`). It passes the latest usage to terminal events and clears per-turn state (`libs/backend/codex-runtime/src/lib/codex-event-translator.ts:251-276`). `CodexChatEvents` maps input to `max(0, input-cached)`, cache read to cached input, cache creation to cache-write input, and output to output; it emits `message_delta.tokenUsage` and terminal `message_complete.tokenUsage` (`libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-events.ts:11-21`, `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-events.ts:274-285`, `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-events.ts:325-335`). The turn result callback emits `deps.stats` only when input and output exist: `turnCost:null`, `costUSD:null`, tokens, duration, model row, optional context capacity and `lastTurnContextTokens` (`libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-turn-stream.ts:205-253`). That follows the same `SESSION_STATS` broadcast, renderer handler, aggregator, source, and shared component as Claude (`libs/backend/cli-agent-runtime/src/lib/wiring/sdk-callbacks.ts:432-453`, `libs/frontend/chat/src/lib/services/chat-message-handler.service.ts:185-189`, `libs/frontend/chat/src/lib/services/chat-store/session-stats-aggregator.service.ts:118-174`, `libs/frontend/chat/src/lib/services/session-stats/session-stats-source.ts:230-245`).

**Why cost is missing.** The Codex provider entry says its subscription covers usage and declares zero static model rates, but the shared pricing table deliberately does not seed subscription Codex IDs; its pricing utility says subscription turns can be valued at published rates and only labeled as covered (`libs/shared/src/lib/providers/entries/codex-provider-entry.ts:13-37`, `libs/shared/src/lib/providers/entries/codex-provider-entry.ts:78-93`, `libs/shared/src/lib/utils/pricing.utils.ts:43-59`, `libs/shared/src/lib/utils/pricing.utils.ts:185-198`). The native result code explicitly chooses `null` and says Codex reports no pricing, without invoking the available rate lookup or calculator (`libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-turn-stream.ts:221-240`, `libs/shared/src/lib/utils/pricing.utils.ts:404-420`). This is an **intentional implementation choice and a product/accounting gap**, not evidence that the App Server billed zero; the provider-entry zero fields are discovery placeholders rather than the native turn price (`libs/shared/src/lib/providers/entries/codex-provider-entry.ts:30-37`, `libs/shared/src/lib/providers/entries/codex-provider-entry.spec.ts:86-90`). The repository's pricing comment and subscription test expect a published-rate consumption figure, so the native chat path conflicts with that shared pricing intent (`libs/shared/src/lib/utils/pricing.utils.ts:193-196`, `libs/shared/src/lib/utils/pricing.utils.spec.ts:712-729`, `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-turn-stream.ts:221-240`). The main header renders **“cost unavailable”**, not `$0.00`, when its authoritative snapshot is null; compact/inspector views use an em dash for null (`libs/frontend/chat-ui/src/lib/molecules/session/session-stats-summary.component.html:82-104`, `libs/frontend/chat-ui/src/lib/atoms/cost-badge.component.ts:19-24`, `libs/frontend/chat-ui/src/lib/atoms/cost-badge.component.ts:35-50`, `libs/frontend/chat-ui/src/lib/molecules/session/session-stats-format.ts:6-14`). For Codex, the native callback contains **no `sessionStats` field**, so the aggregator keeps a prior snapshot if one exists and the header lacks a newly calculated lifetime total; the per-turn footer receives null (`libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-turn-stream.ts:221-253`, `libs/backend/cli-agent-runtime/src/lib/wiring/sdk-callbacks.ts:447-452`, `libs/frontend/chat/src/lib/services/chat-store/session-stats-aggregator.service.spec.ts:592-603`, `libs/frontend/chat/src/lib/services/chat-store/session-stats-aggregator.service.spec.ts:760`). The first-load state follows those shared template rules; whether any other runtime path supplies an initial Codex snapshot is **UNCONFIRMED** (`libs/frontend/chat-ui/src/lib/molecules/session/session-stats-summary.component.ts:95-107`, `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-turn-stream.ts:221-253`).

**Accounting edge cases.** `total` is cumulative across a thread; repeated notifications in a turn replace its delta, so summing them would double-count, while the current translator does not sum them (`libs/backend/codex-runtime/src/lib/codex-event-translator.ts:220-239`, `.ptah/specs/TASK_2026_714_c8a2/decisions.md:155-157`). Cached input is subtracted once from input and carried as cache read; reasoning output is not an extra UI bucket and remains within output/total under the pinned upstream semantics, as documented in the decision record and asserted by a synthetic projection spec (`libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-events.ts:11-21`, `.ptah/specs/TASK_2026_714_c8a2/decisions.md:198`, `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-events.spec.ts:599`). **UNCONFIRMED:** whether cache-write tokens are already included in input; the decision explicitly requires a spike before pricing from them (`.ptah/specs/TASK_2026_714_c8a2/decisions.md:200`). A new translator instance has no loaded thread total, so its first usage event uses `total - last`; if a resumed turn has multiple model requests before that first event or misses a notification, earlier requests in that turn can be omitted—this is a code-path inference, **UNCONFIRMED live** (`libs/backend/codex-runtime/src/lib/codex-event-translator.ts:89-91`, `libs/backend/codex-runtime/src/lib/codex-event-translator.ts:222-230`, `.ptah/specs/TASK_2026_714_c8a2/decisions.md:197`). Compaction events do not reset the thread total baseline in the translator; therefore the last request's `totalTokens` is the context numerator, not lifetime usage, and negative deltas remain a risk if the native counter resets—**UNCONFIRMED live** (`libs/backend/codex-runtime/src/lib/codex-event-translator.ts:33-44`, `libs/backend/codex-runtime/src/lib/codex-event-translator.ts:220-231`, `libs/backend/codex-runtime/src/lib/codex-event-translator.spec.ts:769`). Failed/interrupted terminals retain already observed usage, while a terminal with no usage produces no stats callback; failed turns show a sanitized generic notice rather than provider diagnostic detail (`libs/backend/codex-runtime/src/lib/codex-event-translator.ts:251-265`, `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-events.ts:298-325`, `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-turn-stream.ts:207-212`). Child-thread usage is not included by the parent translator's per-thread map, and a session-level aggregate across native child threads is absent from the Codex result payload; whether the upstream parent `total` already folds child usage is **UNCONFIRMED** (`libs/backend/codex-runtime/src/lib/codex-event-translator.ts:89-91`, `libs/backend/codex-runtime/src/lib/codex-event-translator.ts:220-230`, `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-turn-stream.ts:221-253`).

**Persistence answer.** No `SessionStatsOwnerService.replaceRun` equivalent appears in the native Codex result callback; it emits only a per-turn stats object (`libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-turn-stream.ts:205-253`, `libs/backend/agent-sdk/src/lib/helpers/stream-transformer.ts:983-1003`). `SessionMetadataStore.updateCodexExecution` preserves existing `totalCost` and `totalTokens` or initializes them to zero, and the inspected native turn stream does not write them (`libs/backend/agent-sdk/src/lib/session-metadata-store.ts:1166-1173`, `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-turn-stream.ts:205-253`). The stats-batch reader scans Claude JSONL sessions, not Codex thread history; a Codex lifetime total after reload is therefore not demonstrated by these paths (**UNCONFIRMED** if another path supplies it) (`libs/backend/agent-sdk/src/lib/session-stats/session-stats-reader.service.ts:155-195`, `libs/backend/rpc-handlers/src/lib/handlers/session-rpc.handlers.ts:1253-1270`).

## 3. Authentication and price source

`CodexHomeAuthService.getAccountUsageEligibility()` returns `unsupported-auth` for absent auth, an `openai_api_key`/`OPENAI_API_KEY` field, or `auth_mode:'ApiKey'`; it returns `unsupported-config` for an overridden API base/OAuth endpoint; an access token with those exclusions is `supported` (`libs/backend/auth-providers/src/lib/providers/codex/codex-home-auth.service.ts:276-286`, `libs/backend/auth-providers/src/lib/providers/codex/codex-home-auth.service.ts:357-358`). API-key mode targets the API endpoint, while OAuth uses a configured or ChatGPT backend endpoint (`libs/backend/auth-providers/src/lib/providers/codex/codex-home-auth.service.ts:412-431`). This eligibility gates **plan-usage reads**, not Codex chat pricing: `CodexAccountUsageClient` checks it before spawning a usage child, whereas the native turn callback always emits null cost (`libs/backend/codex-runtime/src/lib/codex-account-usage-client.ts:249-273`, `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-turn-stream.ts:221-240`). A session-level billing/auth mode from resolved provider profiles is **UNCONFIRMED** in the Codex stats payload: the chat profile resolves provider/home, but the result callback has no auth-mode or pricing-source argument (`libs/backend/rpc-handlers/src/lib/chat/codex-host/codex-chat-host-ports.ts:256-426`, `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-turn-stream.ts:205-253`).

The repo has old bundled OpenAI rates such as `gpt-4o`, and a runtime OpenRouter rate map, but no bundled `gpt-5*`/`gpt-6*` Codex API price in `DEFAULT_MODEL_PRICING`; a spec deliberately refuses to price `gpt-5.3-codex` from a `gpt-5` row (`libs/shared/src/lib/utils/pricing.utils.ts:43-109`, `libs/shared/src/lib/utils/pricing.utils.spec.ts:202`). The Codex static provider list has zero price placeholders and `pricingModel:'subscription'`, so it must not be used as an API invoice rate (`libs/shared/src/lib/providers/entries/codex-provider-entry.ts:13-37`, `libs/shared/src/lib/providers/entries/codex-provider-entry.ts:78-93`). A defensible API-key estimate needs exact model ID, input/output/cache-read/cache-write rates, rate effective date/source, bucket semantics, and explicit unknown/partial coverage; the shared calculator already has the four classes but currently treats missing cache rates as zero, which would understate a partially priced turn (`libs/shared/src/lib/utils/pricing.utils.ts:18-41`, `libs/shared/src/lib/utils/pricing.utils.ts:404-432`, `.ptah/specs/TASK_2026_714_c8a2/decisions.md:200`). The pinned App Server schemas expose token and rate-limit fields, including credits/reset-credit/upsell data, but no explicit price, charged dollars, or account balance cost in these relevant messages; any newer unpinned protocol behavior is **UNCONFIRMED** (`libs/backend/codex-runtime/src/lib/codex-protocol-methods.ts:208-217`, `libs/backend/codex-runtime/src/lib/codex-protocol-methods.ts:389-400`, `libs/backend/codex-runtime/src/lib/codex-protocol-schemas.ts:649-686`).

## 4. Plan usage and limits

`CodexAccountUsageClient` has 30-second hit and miss TTLs, caches/coalesces per normalized `CODEX_HOME`, and verifies the spawned child reports that same home before `account/rateLimits/read`; it closes the child before publishing the result and closes again idempotently in `finally` (`libs/backend/codex-runtime/src/lib/codex-account-usage-client.ts:20-24`, `libs/backend/codex-runtime/src/lib/codex-account-usage-client.ts:146-192`, `libs/backend/codex-runtime/src/lib/codex-account-usage-client.ts:273-325`). A notification received by **that short-lived read child** validates and invalidates its cache, but the live chat translator explicitly ignores `account/rateLimits/updated`; source search found no live-chat-to-ledger consumer (**UNCONFIRMED** for external integrations) (`libs/backend/codex-runtime/src/lib/codex-account-usage-client.ts:273-285`, `libs/backend/codex-runtime/src/lib/codex-event-translator.ts:127-135`). The default-home `CodexAccountUsageService` still uses its own gated read/process path, while an explicit home delegates to the native client; it keeps separate cache/in-flight logic (`libs/backend/auth-providers/src/lib/providers/codex/codex-account-usage.service.ts:133-143`, `libs/backend/auth-providers/src/lib/providers/codex/codex-account-usage.service.ts:186-241`). `ProviderOwnerResolver` establishes the Codex owner by reading usage once; `ProviderRpcHandlers` reads the owner snapshot, preserves legacy Codex fields from cached account usage, and exposes `provider:getPlanLimits` for all owners (`libs/backend/auth-providers/src/lib/quota/provider-owner.resolver.ts:596-639`, `libs/backend/rpc-handlers/src/lib/handlers/provider-rpc.handlers.ts:192-267`). Electron creates per-session native scopes and disposes both runtime and usage client; the CLI lane scope similarly closes both (`apps/ptah-electron/src/di/codex-runtime-composition.ts:219-276`, `libs/backend/cli-engine/src/lib/codex-lane-runtime-composition.ts:204-223`).

**Field loss.** The response schema has default limits, `rateLimitsByLimitId`, `rateLimitResetCredits`, and `rateLimitUpsell`; each limit has primary/secondary windows, plan type, reached type, spend control, individual limit, and credits (`libs/backend/codex-runtime/src/lib/codex-protocol-methods.ts:208-217`, `libs/backend/codex-runtime/src/lib/codex-protocol-schemas.ts:657-686`). The native client selects only the `'codex'` bucket if present, else default; its DTO retains primary/secondary, `rateLimitReachedType`, and `planType`, dropping the other bucket IDs, credits, individual limit, spend-control flag, reset credits, and upsell (`libs/backend/codex-runtime/src/lib/codex-account-usage-client.ts:71-96`). The quota reader converts each window's used percent, reset and duration, preserves primary/secondary position, and marks exhaustion only when a reached type is present and a window is at least 100%; it does not surface credits or an overall account-spend state (`libs/backend/auth-providers/src/lib/quota/readers/codex-plan-usage.reader.ts:67-120`). The webview's `PlanLimitsStore` pulls `provider:getPlanLimits` and accepts ledger pushes, and the shared session UI displays Plan limits from that store (`libs/frontend/core/src/lib/services/plan-limits.store.ts:175-221`, `libs/frontend/chat/src/lib/services/session-stats/session-stats-source.ts:178-245`, `libs/frontend/chat-ui/src/lib/molecules/session/session-stats-summary.component.html:403-415`). `ptah_agent_list` formats its own Plan limits table and limit-state column from lane limit results; it is another presentation of the ledger, not evidence that the dropped credit fields reach it (`libs/backend/vscode-lm-tools/src/lib/code-execution/mcp-core/agent-limit.formatter.ts:2-6`, `libs/backend/vscode-lm-tools/src/lib/code-execution/mcp-core/mcp-response-formatter.ts:1788-1839`).

**Mid-turn exhaustion.** The pinned protocol has a structured `usageLimitExceeded` failure for an image-generation item, and `rateLimitReachedType` for account readings; the chat translator maps generic `error` to a sanitized turn error and failed terminal to failure, while `CodexChatEvents` presents “Codex reported a runtime error.” (`libs/backend/codex-runtime/src/lib/codex-protocol-schemas.ts:390-408`, `libs/backend/codex-runtime/src/lib/codex-event-translator.ts:241-265`, `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-events.ts:9`, `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-events.ts:295-325`). The lane event projector uses that same generic wording; a separate text classifier recognizes Codex “usage limit” wording, but a structured native mid-turn limit-to-ledger mapping is **NOT TESTED** in the inspected native suites (`libs/backend/cli-agent-runtime/src/lib/cli-agents/cli-adapters/codex/codex-lane-events.ts:148-174`, `libs/backend/cli-agent-runtime/src/lib/cli-agents/limits/lane-limit-classifier.ts:4-16`, `libs/backend/codex-runtime/src/lib/codex-event-translator.spec.ts:421-421`).

**Process cost/stability.** Cache coalescing means concurrent same-home reads share a child, while two homes may read concurrently; a refresh after TTL or explicit refresh starts a fresh child, making repeated cold reads a process-start cost (**latency magnitude UNCONFIRMED**) (`libs/backend/codex-runtime/src/lib/codex-account-usage-client.ts:146-192`, `libs/backend/codex-runtime/src/lib/codex-account-usage-client.ts:262-270`, `libs/backend/codex-runtime/src/lib/codex-account-usage-client.spec.ts:262-292`). ## 7. Target design and implementation batches

**Contract.** Keep the existing Claude-shaped `ResultStatsPayload`/`SessionStatsEntry` and shared header/plan-limit components; do accounting and rate-limit adaptation behind the native backend boundary. The UI already treats `sessionStats` as authoritative and null cost as unknown, so a Codex-specific frontend branch would bypass that contract (`libs/backend/cli-agent-runtime/src/lib/wiring/sdk-callbacks.ts:432-453`, `libs/frontend/chat-ui/src/lib/molecules/session/session-stats-summary.component.ts:95-107`, `libs/frontend/chat-ui/src/lib/atoms/cost-badge.component.ts:19-24`). Use two separately labeled concepts: **actual API charge** only if an authoritative provider field exists, and **estimated token value** from an exact, versioned rate card; the current protocol has no charge field and the static subscription placeholders are zero (`libs/backend/codex-runtime/src/lib/codex-protocol-methods.ts:389-400`, `libs/shared/src/lib/providers/entries/codex-provider-entry.ts:13-37`).

1. **Usage foundation:** Add a native per-session usage owner at `codex-event-translator.ts` / `codex-chat-turn-stream.ts` that accepts cumulative thread totals, deduplicates notifications by thread/turn, persists normalized turn snapshots with session identity, and emits an authoritative `sessionStats` in the existing callback. Rehydrate it on resume from native thread history or a compact Ptah accounting sidecar; specify child-thread and compaction rules before coding. Add translator, turn-lifecycle, metadata/history, and renderer-aggregator specs; gate with a focused changed-project check when tests are permitted. Motivation: the current callback has no snapshot and metadata counters are not written (`libs/backend/codex-runtime/src/lib/codex-event-translator.ts:215-239`, `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-turn-stream.ts:221-253`, `libs/backend/agent-sdk/src/lib/session-metadata-store.ts:1166-1173`).
2. **Pricing:** Carry the resolved Codex auth/billing mode into the backend stats owner; select exact model prices with source/version/effective date, require every used token class to be priced, and publish an `estimated` cost source for API-key mode only if product chooses it. Preserve unknown cost when the exact rate or cache semantics are missing; do not reuse `CODEX_PROVIDER_ENTRY` zeros. Add exact-model/cache/unknown-rate and API-key-versus-plan specs in `pricing.utils.spec.ts` and `codex-chat-turn-lifecycle.spec.ts`; gate with focused checks when permitted. Motivation: auth eligibility is separate from stats and the rate calculator can silently treat missing cache rates as zero (`libs/backend/auth-providers/src/lib/providers/codex/codex-home-auth.service.ts:276-286`, `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-turn-stream.ts:221-240`, `libs/shared/src/lib/utils/pricing.utils.ts:404-432`).
3. **Live limits and richer fields:** Route validated `account/rateLimits/updated` from the long-lived chat context to the quota owner/cache, with identity/home checks and a ledger push; retain per-limit buckets, credits, individual limit, reached cause, and reset/upsell data in a typed backend DTO. Extend the existing plan-limit snapshot contract if needed, then reuse `PlanLimitsStore`/shared tiles and `ptah_agent_list` formatter. Add native notification, account-client, quota-reader, RPC, store, and tool-format specs; gate with focused checks when permitted. Motivation: chat currently ignores notifications and `usageResult` discards fields (`libs/backend/codex-runtime/src/lib/codex-event-translator.ts:127-135`, `libs/backend/codex-runtime/src/lib/codex-account-usage-client.ts:71-96`, `libs/frontend/core/src/lib/services/plan-limits.store.ts:175-221`).
4. **Limit failure and process stability:** Map structured limit/reached evidence to a safe user-facing reset/cause and ledger exhaustion without forwarding raw provider diagnostics; ensure the default and explicit home readers share the same cache/process policy, then measure cold refresh and Windows cleanup on Electron. Add failed-turn, concurrent refresh, abort, and packaged Electron scope specs; gate with focused checks and a separately authorized minimal live observation. Motivation: chat currently uses a generic notice and default versus explicit home have different readers (`libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-events.ts:295-325`, `libs/backend/auth-providers/src/lib/providers/codex/codex-account-usage.service.ts:186-241`, `apps/ptah-electron/src/di/codex-runtime-composition.ts:219-276`).

**Product decisions needed before implementation:** Should subscription sessions show a published-rate *token value*, an explicit “covered by plan” value, or cost unavailable? Should API-key estimates be displayed in the Cost chip or a separate estimated-spend label, and which price source/update cadence is trusted? Should a session total include native child-thread usage and pre-compaction usage, and should interrupted/failed charged usage count? Should credits/individual limits appear in the existing Plan limits section and `ptah_agent_list`, and how should multiple `limitId` buckets be ordered? These choices are open because the repo's subscription pricing intent differs from the native null-cost callback, child accounting is not in the result payload, and richer limit fields are parsed but dropped (`libs/shared/src/lib/utils/pricing.utils.ts:185-198`, `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-turn-stream.ts:221-253`, `libs/backend/codex-runtime/src/lib/codex-protocol-methods.ts:208-217`, `libs/backend/codex-runtime/src/lib/codex-account-usage-client.ts:71-96`).
