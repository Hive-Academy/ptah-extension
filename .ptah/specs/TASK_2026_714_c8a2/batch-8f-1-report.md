## Decisions

1. **Development root discovery.** Decision: walk upward from appPath to the nearest existing node_modules, with an injectable directory predicate. Options: hard-code three parents from dist/apps/ptah-electron, or walk ancestors. Evidence: D1's development app lives under dist/apps/ptah-electron, while the worktree node_modules is a junction; ancestor discovery also handles source-root launches without assuming a fixed output depth. Packaged roots bypass discovery and remain strict. Reversible: yes, isolated root helper and its bootstrap call.
2. **Canonical identity.** Decision: canonicalise both root and executable and return the canonical executable path. Options: lexical containment, or canonical containment while retaining a lexical binary identity. Evidence: the worktree junction resolves to the main checkout, and a package symlink can otherwise escape lexical containment. Reversible: yes, isolated executable helper; callers must keep the binary identity consistent.
3. **Settings boundary.** Decision: move the reader to rpc-handlers and inject both resolver and store from activation. Options: widen TC-18 allow-list, encode token strings in DI, or use permitted activation and rpc-handlers layers. Evidence: the original composition also resolved SETTINGS_STORE, so moving only the reader/resolver would still violate TC-18. Reversible: yes; no schema or persistence migration.
4. **Asynchronous verification seam.** Decision: await verification inside the profile port and cache inspection promises process-wide by canonical file identity. Options: synchronous per-open work, eager boot verification, or the awaited profile seam. Evidence: adapter open awaits profile before its synchronous createScope call. The exported inspection helper accepts an async version-reader seam for focused specs; production uses bounded promisified execFile. Reversible: yes, Electron composition only.
5. **Shutdown budget and persistence.** Decision: retain scope close before record/lookup/map teardown, use the neighbouring 2-second budget convention, and retain the final flush after the bounded drain. Options: unbounded close, early identity disposal, or bounded close before final persistence. Evidence: markInactive needs the live lookup and stages writes; the existing final flush occurs after disposeAfterPersistence. Reversible: yes, budget constant and ordering are local. A timed-out close may finish too late for its final write; the app still exits and the remaining teardown runs.
6. **Live settings precedence.** Decision: do not parse unused saved fallbacks when live session values exist. Options: validate every stored fallback first, or validate only effective values. Evidence: session values must win; an irrelevant malformed saved effort/permission should not prevent controls for a valid live session. Reversible: yes, factory-only behavior.
