## Verdict

REVISE — 7/10. The consumer, MCP routing, payload, timeout, and normal settlement paths match the batch contract, but lifecycle publication can prevent a gateway prompt from being denied.

## Findings

1. **Serious — `libs/backend/rpc-handlers/src/lib/chat/codex-host/codex-chat-host-ports.ts:290-302,581-600`.** `promptLifecycle.publish` runs without isolation and before `settle`. If a publisher throws on the timeout's `resolved` event, the timer callback exits before `declineApproval`, so the native approval remains pending instead of failing closed. A throwing `requested` publisher also interrupts `present` before timer creation; its subsequent `dismiss` can throw on `resolved`, leaving the wire entry behind. A synchronous publisher that answers reentrantly can emit two resolutions or answer before the timeout decline. Claude's `SdkPermissionHandler.emitLifecycle` catches listener errors (`sdk-permission-handler.ts:233-244`). Isolate publication and remove/clear the pending entry before invoking an external publisher; keep native decline guaranteed even if publication fails. Add fake-timer coverage for a throwing and reentrant publisher.

2. **Moderate — `libs/backend/rpc-handlers/src/lib/chat/codex-host/codex-chat-host-ports.ts:140-143`.** The full system-abort message is copied from `SdkPermissionHandler.requestUserPermission` (`libs/backend/agent-sdk/src/lib/sdk-permission-handler.ts:1083-1098`), and the spec copies it again at `codex-chat-host-ports.spec.ts:1134-1136`. Claude currently exports no builder or constant for this text. If Claude's wording changes, a gateway timeout sends a different instruction to the model while these self-contained specs still pass. Extract and export a small `buildSystemAbortPermissionMessage(toolName, reason)` from the Claude branch through `@ptah-extension/agent-sdk`, then use it here and in the spec.

3. **Minor — `libs/backend/rpc-handlers/src/lib/chat/codex-host/codex-chat-host-ports.spec.ts:1255-1349`.** The fake-timer cases cover direct answer, dismiss, cancel, delivery failure, replacement, timeout, and missing publisher, and restore real timers. They do not exercise adapter session end/dispose or process exit with a prompt pending. The current adapter/sink teardown appears to call `cancelPrompt` and `dismiss` (`codex-chat-adapter.ts:628-639`, `codex-chat-approval-sink.ts:195-225,337-342`), but a broken teardown hook could leave the 60-second timer alive and emit a late denial. Add a teardown integration case that advances fake timers after disposal and checks there is no second response or lifecycle event.
