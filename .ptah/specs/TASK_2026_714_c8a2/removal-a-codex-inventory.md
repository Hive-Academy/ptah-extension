These are Codex-specific branches inside shared services, not grounds to delete the services.
3. `CodexTranslationProxy` subclasses the shared `TranslationProxyBase`, supplies Codex OAuth headers, Responses endpoint and model mapping, then translates Anthropic requests/streaming replies (`libs/backend/auth-providers/src/lib/providers/codex/codex-translation-proxy.ts:18,30-48,77-95,114-150`). Keep the separately registered Codex home/auth/account-usage services (`providers/register-providers.ts:70-124`).
4. The SDK adapter passes the provider profile to that executor (`libs/backend/agent-sdk/src/lib/sdk-agent-adapter.ts:1008,1073`). Remove only Codex-specific accommodations, retaining the Claude SDK for its other routes.
5. Host composition registers provider and SDK services in Electron (`apps/ptah-electron/src/di/phase-2-libraries.ts:209,222`), VS Code (`apps/ptah-extension-vscode/src/di/phase-2-libraries.ts:190,199`) and CLI engine (`libs/backend/cli-engine/src/lib/container.ts:695,702`). ## 2. App Server route and Electron admission

The active-provider/profile check can produce native Codex (`libs/backend/auth-providers/src/lib/auth/workspace-provider-profile-resolver.ts:205-266`). `RoutingAgentAdapter` chooses native only for a Codex session with native host capability, otherwise it chooses the legacy adapter (`libs/backend/agent-sdk/src/lib/codex-app-server/routing-agent-adapter.ts:87-117`); DI creates that router and native adapter when ports exist (`libs/backend/agent-sdk/src/lib/di/register.ts:994-1005,1050-1100`). Packaged Electron is blocked twice today: `createElectronCodexRouting` derives `nativeCodex` only from the shared chat gate or an unpackaged dev override (`apps/ptah-electron/src/di/codex-runtime-composition.ts:74-88`; `libs/backend/codex-runtime/src/lib/codex-dev-route.ts:14-27`), and `CodexChatAdapter.openContext` calls `resolveGatedCodexRuntime(..., 'chat', ...)` (`codex-chat-adapter.ts:350-359`). The shared gate returns `enabled: false` even on reviewed win32/x64 (`libs/backend/codex-runtime/src/lib/codex-parity-gate.ts:193-226`; `libs/backend/codex-runtime/src/lib/di/registration.ts:109-136`). D29's Electron-local lane rule admits packaged win32/x64 (`apps/ptah-electron/src/di/codex-lane-composition.ts:50-57,247-264`) and leaves the shared gate closed; chat has no equivalent yet.

Smallest proposed Electron-only path: add an Electron-local chat admission using the same packaged win32/x64 rule, set `nativeCodex` from it while leaving `nativeCodexGateway` as it is, and supply the chat adapter a host-owned runtime-resolution port that enforces that admission before resolving the session-scoped raw runtime. Preserve the existing verified-bundle/root/hash checks (`apps/ptah-electron/src/di/codex-runtime-composition.ts:126-195,224-258,380-410`). The optional port can live in `CodexChatAdapterPorts` (`libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-adapter.ts:71-90`) with the current gated resolver as default, so VS Code, CLI and TUI retain the same type/route. As the old Codex proxy is removed, their Codex chat attempt must fail explicitly rather than fall back through Claude SDK (`routing-agent-adapter.ts:87-117`; `workspace-provider-profile-resolver.ts:268-300`). Do not widen packaged admission for any other host or platform (`decisions.md:248-249`).

MCP is part of the native path, not a removal target: the Codex TOML facet writes Ptah MCP servers (`libs/backend/harness-sync/src/lib/targets/mcp/codex-toml-mcp-facet.ts:104-115,213,310`); chat host ports merge Ptah and user MCP (`libs/backend/rpc-handlers/src/lib/chat/codex-host/codex-chat-host-ports.ts:318-400`); runtime config handles per-server secrets (`libs/backend/codex-runtime/src/lib/codex-mcp-config.ts:153-169`).
