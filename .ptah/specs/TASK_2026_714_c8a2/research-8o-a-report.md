# Codex 0.165.0 Manual mode: PowerShell read approvals

## Summary

Keep D14 (`untrusted` plus workspace-write) so writes and file edits require approval before execution.
Codex 0.165.0 has no per-thread safe-read switch; its native project rules can allow particular commands, but trust and sandbox implications make them a poor Ptah default.
Have Ptah answer command approval requests automatically only for a tightly reviewed read-only PowerShell command set; send every other command and every file edit to the user.

## Q1 — What `untrusted` allows

In this release, protocol `untrusted` becomes Rust `AskForApproval::UnlessTrusted`. For a command with no matching exec-policy rule, that policy requests approval **for every command**; the source says so explicitly. A matching `allow` rule skips the request; `prompt` requests it; `forbidden` rejects it. The dangerous-command matcher can force a prompt or prohibition, but is not a read-command allowlist. Evidence: [`exec_policy.rs` L342–445, L741–824](https://github.com/openai/codex/blob/rust-v0.165.0/codex-rs/core/src/exec_policy.rs#L741-L824), [`command_safety/mod.rs` L1–8](https://github.com/openai/codex/blob/rust-v0.165.0/codex-rs/shell-command/src/command_safety/mod.rs#L1-L8). The Windows tests specifically expect direct `Get-Content Cargo.toml` under `UnlessTrusted` to prompt, and an explicit `echo` allow rule to skip approval: [`exec_policy_windows_tests.rs` L25–79](https://github.com/openai/codex/blob/rust-v0.165.0/codex-rs/core/src/exec_policy_windows_tests.rs#L25-L79).

There is **no Windows or PowerShell known-safe cmdlet list** in this tag. The shell safety module exposes dangerous-command detection, including PowerShell-specific dangerous patterns, but no positive safe-command matcher or special treatment for `Get-Content`: [`is_dangerous_command.rs` L5–21, L75–92](https://github.com/openai/codex/blob/rust-v0.165.0/codex-rs/shell-command/src/command_safety/is_dangerous_command.rs#L5-L21), [`windows_dangerous_commands.rs` L6–73](https://github.com/openai/codex/blob/rust-v0.165.0/codex-rs/shell-command/src/command_safety/windows_dangerous_commands.rs#L6-L73). Thus `Get-Content README.md` prompts because it is unmatched, regardless of whether the file exists. The observed prompt for `Get-Content missing.txt` is consistent with policy evaluation before the command runs. The `rg --files ~/.codex/skills | rg ...` command is likewise unmatched by default.

Codex recognizes a `powershell`/`pwsh` executable with `-Command` or `-c` (and common `-NoLogo`/`-NoProfile` flags), parses the command text in-process, and checks extracted command words against policy. It first unwraps `bash -lc` where applicable. If PowerShell extraction/parsing fails, policy checks the original command vector instead. `-EncodedCommand` and `-File` are not lowered by this extractor. Evidence: [`powershell.rs` L8–81](https://github.com/openai/codex/blob/rust-v0.165.0/codex-rs/shell-command/src/powershell.rs#L8-L81), [`exec_policy.rs` L841–878](https://github.com/openai/codex/blob/rust-v0.165.0/codex-rs/core/src/exec_policy.rs#L841-L878), [Windows wrapper tests L47–62](https://github.com/openai/codex/blob/rust-v0.165.0/codex-rs/core/src/exec_policy_windows_tests.rs#L47-L62). Exec-policy rules are the positive allow mechanism; the engine loads `*.rules` from the `rules` directory of enabled configuration layers: [`exec_policy.rs` L634–685](https://github.com/openai/codex/blob/rust-v0.165.0/codex-rs/core/src/exec_policy.rs#L634-L685).

The native project-rule route has two material caveats. Project rules are loaded only when that configuration layer is trusted; the loader explicitly gates project-local exec policies on project trust. Trusting the project can enable other project configuration, and App Server can persist a project trust decision to Codex home during thread start when its conditions hold: [`loader/mod.rs` L1065–1109](https://github.com/openai/codex/blob/rust-v0.165.0/codex-rs/config/src/loader/mod.rs#L1065-L1109), [`thread_processor.rs` L1331–1393](https://github.com/openai/codex/blob/rust-v0.165.0/codex-rs/app-server/src/request_processors/thread_processor.rs#L1331-L1393). Also, an explicit rule `allow` may imply sandbox bypass when its entire parsed command matches, subject to the effective permission profile; it is not merely “do not show a prompt”: [`exec_policy.rs` L424–438](https://github.com/openai/codex/blob/rust-v0.165.0/codex-rs/core/src/exec_policy.rs#L424-L438), [`sandboxing.rs` L232–261](https://github.com/openai/codex/blob/rust-v0.165.0/codex-rs/core/src/tools/sandboxing.rs#L232-L261). `CODEX_HOME` could point a whole process at separately provisioned rules, but that changes its configuration/auth home and is not a self-contained per-thread rule override; default rules location is derived from Codex home: [`exec_policy.rs` L834–835](https://github.com/openai/codex/blob/rust-v0.165.0/codex-rs/core/src/exec_policy.rs#L834-L835).

## Q3 — Minimal Ptah build options

**Recommendation: add a narrow host-side approval decision before displaying `item/commandExecution/requestApproval`.** Ptah already distinguishes command approvals from file-change approvals and can answer a request with a decision: [`codex-approval-bridge.ts` L24–30, L457–482](../../../libs/backend/codex-runtime/src/lib/codex-approval-bridge.ts). The host currently presents the command request to the user: [`codex-chat-host-ports.ts` L437–479](../../../libs/backend/rpc-handlers/src/lib/chat/codex-host/codex-chat-host-ports.ts). In Manual mode, auto-accept only an explicitly reviewed, parsed set of read operations and safe argument forms; require interactive approval for every unknown command and every file edit. Use a one-request accept, not session-wide approval or a rule amendment. Log the classified command and decision.

The security cost is that Ptah becomes responsible for PowerShell parsing, aliases, argument flags, pipelines, redirection, command substitution, and path scope. “Read-only” can still expose secrets, and tools such as `rg` can acquire execution behavior through flags or configuration. An unsafe classifier could allow a write without the D14 prompt; a conservative classifier merely causes more prompts. Check the approval request's effective sandbox/permissions before auto-accepting. A smaller alternative is to add a trusted project `.codex/rules` file with exact narrow rules, but it depends on project trust, can broaden sandbox trust, and has user-home persistence risk. A dedicated Ptah read-only tool path avoids command parsing for supported reads but does not remove shell approval prompts for model-chosen shell calls. No native, self-contained per-thread switch in 0.165.0 meets both D14 and automatic PowerShell reads.

## Skill lookups

Ptah's injected UI hint explicitly says to load `ptah-surface-authoring`: [`ptah-ui-hint.ts` L7](../../../libs/backend/agent-sdk/src/lib/prompt-harness/ptah-ui-hint.ts). The Codex host adds that hint to `developerPrompt` when the UI fence and coding MCP profile are enabled: [`codex-chat-host-ports.ts` L388–424](../../../libs/backend/rpc-handlers/src/lib/chat/codex-host/codex-chat-host-ports.ts); the runtime sends the prompt at thread start and on the first turn: [`codex-runtime.ts` L351–378, L584–595](../../../libs/backend/codex-runtime/src/lib/codex-runtime.ts). The supplied project guidance also tells the agent to use skills. Those instructions explain the extra skill lookup. The exact choice to search `~/.codex/skills` rather than Ptah's packaged skill location was the model's behavior; the trace does not prove it was required by Codex's own skill discovery.

## Decisions

- Retain D14: `untrusted` approval plus workspace-write sandbox in Ptah Manual mode.
- Do not use `on-request` plus workspace-write for Manual: it can run writes without prior approval.
- Recommend a conservative Ptah command-approval bridge for reviewed reads; keep all file-change approvals interactive.
- Treat project exec-policy rules as an opt-in native workaround, not the default product solution.

## Unknowns

- This was source/binary read-only research. No live App Server run tested a per-thread `projects.<cwd>.trust_level` override or a project rule under this exact Ptah profile.
- The exact PowerShell commands and argument forms that Ptah should auto-allow need a separate threat review and implementation design. No classifier or source code was changed here.
