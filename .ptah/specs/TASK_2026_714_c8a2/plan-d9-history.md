# D9 — Native Codex chat history after reload

**Scope and acceptance.** Electron native chat must reopen a saved thread and reconstruct its complete ordered conversation, including user, assistant, reasoning, tools, and child-thread activity, through the *existing* Claude UI event contract. The Codex rollout remains the source of truth; Ptah persists only metadata keyed by thread id. Do not add a Ptah JSONL transcript, frontend Codex branch, proxy, MCP stripping, `thread/revert`, rewind, or rollback. D31 requires this before Removal A (`decisions.md:248-250`; `batches.md:2646-2651,3728-3765`).

## Current path and failure

- The webview calls `session:load`, then `chat:resume` with a tail `historyPage`; older pages use `chat:history-page` (`libs/frontend/chat/src/lib/services/chat-store/session-loader.service.ts:934-957,1005-1027`; `libs/backend/rpc-handlers/src/lib/handlers/chat-rpc.handlers.ts:284-327`). `session:load` validates metadata and deliberately returns `messages: []`, `agentSessions: []` (`libs/backend/rpc-handlers/src/lib/handlers/session-rpc.handlers.ts:718-767`).
- `chat:resume` calls `ChatHistoryReadService.readForResume`, which resolves the session folder and calls `SessionHistoryReaderService.readSessionHistory`; `chat:history-page` calls `readSessionEvents` and `selectHistoryPage` (`libs/backend/rpc-handlers/src/lib/chat/session/chat-session.service.ts:1772-1812`; `libs/backend/rpc-handlers/src/lib/chat/session/chat-history-read.service.ts:63-103`). The reader opens Claude `projects/<sessionId>.jsonl`, replays main and agent messages, and returns `{events: FlatStreamEventUnion[], stats: SessionStatsEntry|null, staleSnapshot?, blockOwners?, syntheticToolResults?}` (`libs/backend/agent-sdk/src/lib/session-history-reader.service.ts:346-365,597-652`). The RPC reply uses `ChatResumeResult` with `success`, `events`, `stats`, `resumableSubagents`, `cliSessions`, and optional whole-turn `historyPage.olderCursor`; a page returns `{events, olderCursor, resumableSubagents}` (`libs/backend/rpc-handlers/src/lib/chat/session/chat-session.service.ts:1935-1965`; `libs/shared/src/lib/types/rpc/rpc-chat.types.ts:348-386,454-469`). Events are the existing `FlatStreamEventUnion` sequence, notably `message_start` with role, `text_delta`, `thinking_delta`, `tool_start`, `tool_result`, `message_delta` usage, `message_complete` (`libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-events.ts:133-141,155-165,225-281,324-335`).
- D10 option A makes `session:validate` return `{exists:true}` for metadata with `codexExecution.runtime === 'codex-app-server'` and a valid `codexThread`, without looking for a Claude JSONL (`libs/backend/rpc-handlers/src/lib/handlers/session-rpc.handlers.ts:1074-1099`). `chat:resume` nevertheless still uses the Claude reader. Missing Claude JSONL yields `events: []`, `stats: null`, then normally a successful empty `chat:resume` reply (`libs/backend/agent-sdk/src/lib/session-history-reader.service.ts:393-412,615-623`; `libs/backend/rpc-handlers/src/lib/chat/session/chat-session.service.ts:1940-1965`). An unrelated gate, parse, or activation failure may instead surface an error; a live reload result is **UNCONFIRMED**. `chat:history-page` likewise reads the Claude path (`chat-history-read.service.ts:83-103`).

## Pinned App Server contract and replay gap

- The manifest admits `thread/read` (`libs/backend/codex-runtime/src/lib/protocol/codex-app-server-protocol.manifest.json:107`), but production request schemas lack it (`libs/backend/codex-runtime/src/lib/codex-protocol-methods.ts:54-108`). Pinned schema: `thread/read` request `{threadId: string, includeTurns?: boolean}`; response `{thread: Thread}` (`protocol/codex-app-server-protocol.schema.json:879-900,23754-23782`). `Thread.turns` is populated for `thread/read` **only when `includeTurns: true`**; each `Turn.items` holds `ThreadItem` and `itemsView` reports completeness (`:21397-21403,26078-26096`). `thread/read` itself has no pagination cursor. Its schema warns full hydration is deprecated for paginated threads; `thread/turns/list` and `thread/items/list` expose cursor/limit/direction and `nextCursor` (`:23757-23759,23277-23355,25644-25722`). Read `thread.historyMode`/`itemsView`; follow every cursor until complete, fail on malformed/stalled cursors, then order turns and items chronologically. Do not present a partial page as full history.
- A `Thread` has `sessionId` and nullable `parentThreadId`, but `thread/read` has no embedded children (`:21300-21306,21366-21376,23771-23782`). Discover child threads through paged `thread/list` under the same `CODEX_HOME`, filter by matching `sessionId` and parent chain, then read each child; `thread/list` has `nextCursor` (`:23371-23519`). Whether the pinned binary returns every child and enough ordering detail is **UNCONFIRMED**; prove it before claiming child-card parity. The task's spike JSON files contain only “schema present; behavior unverified” for `thread/read` (for example `spike-run-7a.json:165`); no captured response fixture was found. Build a minimal redacted fixture by hand from the pinned schema for specs, label its live shape **UNCONFIRMED**, and replace or supplement it after an authorized live capture. AS7-2 likewise marks replay unverified (`batches.md:1323-1324`).
- `CodexEventTranslator` consumes live notifications, not `thread/read` snapshots (`libs/backend/codex-runtime/src/lib/codex-event-translator.ts:104-115,187-213`). It already translates completed assistant text, reasoning/plan, command, file-change, MCP, dynamic and collaboration tool items (`:325-513`), but drops `userMessage` (`:327-328`); tools need synthetic start *and* completion; usage arrives only via `thread/tokenUsage/updated` (`:215-239`). The live chat mapper publishes final text/reasoning through callbacks and emits an assistant `message_start` on first projected event (`libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-events.ts:99-141,168-232`). The live turn stream creates the user event separately (`codex-chat-turn-stream.ts:257-299`). Therefore snapshot replay needs a deterministic backend projector for user content, final assistant/reasoning blocks, tool pairs and child agent cards. Preserve stable message/tool ids and timestamps from the snapshot where available. The read schema does not prove historical token usage; emit usage/stats only when App Server actually supplies it, otherwise the contract's `stats: null`, never invented numbers. Child-card and usage live parity remain **UNCONFIRMED** until fixture/live evidence.

## Runtime, routing, and errors

Use the persisted `codexThread` identity and session metadata to reconstruct the *session's* profile and `normalizedHome`, rather than focused provider state. Electron's `createElectronCodexScopeFactory` makes a child DI container and owns runtime disposal (`apps/ptah-electron/src/di/codex-runtime-composition.ts:224-276`); the process starts with `CODEX_HOME: profile.normalizedHome` (`libs/backend/codex-runtime/src/lib/codex-app-server-process.ts:170-192`). For a closed chat session, verify the pinned binary, create an ephemeral session scope, open/resume that thread without starting a turn, issue `thread/read` and any required paged reads, then close context/scope in `finally` (`libs/backend/codex-runtime/src/lib/codex-context.ts:220-265`; `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-adapter.ts:283-299,360-364`). An already open context may serve the read if its identity/home match. Keep configured MCP intact. A missing rollout, unknown thread, mismatched identity/home, invalid page, or unavailable binary must become an explicit failed `chat:resume` / `chat:history-page` response or RPC error visible through the existing UI error path; never convert it to empty history. A genuinely empty existing thread may return `events: []`.
