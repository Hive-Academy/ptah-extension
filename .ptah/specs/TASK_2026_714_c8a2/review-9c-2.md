## Findings

1. **Medium — chat sinks no longer use the Windows system root.** `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-adapter.ts:481` passes `{ systemRoot: undefined, autoAcceptReadOnly: consumer === 'chat' }`. `libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-approval-sink.ts:104-106` treats a present `systemRoot` key as an override, including `undefined`. The previous constructor parameter default applied when the adapter passed positional `undefined`, so the sink used `process.env['SystemRoot'] ?? process.env['windir']`. Style finding 5 said that `undefined` means that default. `classifyReadOnlyCommand` (`codex-read-only-command.ts:32-40`) trusts `System32\WindowsPowerShell\v1.0\powershell.exe` only when `systemRoot` is set, and the sink reads it only for chat auto-accept (`codex-chat-approval-sink.ts:139-140`). Chat read-only auto-accept of that executable now fails closed and shows a card. **Fix:** omit `systemRoot` at the adapter call, and in the constructor use `options.systemRoot ?? process.env['SystemRoot'] ?? process.env['windir']` so omission and `undefined` both keep the old default. Drop the `hasOwnProperty` branch.

2. **Low — `publishPromptLifecycle` still does not document listener failure.** `libs/backend/agent-sdk/src/lib/sdk-permission-handler.ts:229-233` states the host-bridge purpose, the four outcomes, and that callers settle once with no dedupe. Style finding 4 also required listener-error behavior. `emitLifecycle` at `sdk-permission-handler.ts:237-247` logs a throw and continues; `onPromptLifecycle` at `:217-221` already says that. **Fix:** add one sentence to the `publishPromptLifecycle` comment: a throwing listener is logged and does not block publication or the caller.
