## Capability gaps (not removals, and not parity)

These Claude or proxy behaviors have no demonstrated Codex App Server equivalent in this worktree. They stay on the Claude path. Codex must not report them as working.

An explicit unsupported error or a recorded gap is safety behavior only. It is not acceptance that the capability was removed, and it cannot by itself satisfy a parity requirement or complete the stage that owns the capability. For each necessary capability below, rollout of the affected stage stays blocked until a native equivalent is verified or the user explicitly approves the reduced capability. This inventory does not approve any reduction. No automatic translation-proxy fallback is added. A retained path is allowed only when it preserves the capability and does not misrepresent the runtime. The legacy lane adapter remaining callable in stage 1 is that kind of path for lanes. It is not a chat-turn proxy fallback.

- Subagent start, background-agent list, and interrupted-subagent injection. Lane config currently sets `agents.enabled=false` (`codex-lane-config.builder.ts:103`), which is the opposite of chat subagents and must not be copied onto chat as a hidden substitute. The Codex chat stage that owns this control stays blocked until an equivalent is verified or the user approves the reduction.
- `canUseTool` prompt semantics for `AskUserQuestion` and `ExitPlanMode` (`sdk-query-options-builder.ts:772-777`). Until research maps each one, the system shall not silently grant a broader approval than the selected level. A missing mapping fails visibly, does not claim the prompt was honored, and does not ban a later valid mapping. It also does not complete the affected stage.
- Partial message deltas (`includePartialMessages`). Final text is still required. Not reporting partials as available is safety behavior, not proof that streaming parity is met.
- Proxy transcript behaviors that are already gaps: reasoning carry-over, `cache_creation`, and `prompt_cache_key` (workspace memory `codex-responses-proxy`). Native execution shall not claim to have fixed those unless the runtime reports the corresponding fields. Honesty about the fields is not an approval to drop a field the user still requires once research shows the runtime can send it.
- Lane mid-turn steer and run-scoped interrupt (`codex-cli.adapter.ts:354-360`). Today's lanes advertise this limit. Keeping the limit visible on the legacy path is not a decision to add steer, and it is not proof that a future shared lane may drop a steer or interrupt the user requested. This task still does not add steer (out of scope in `task-description.md`).

The account App Server client is not evidence for any row above. It only implements `initialize` and `account/read`. Unsupported errors from that client are not proof of chat parity.

## Proposed Removals

None. No capability in the table is authorized for removal. No gap in the list above is an approved reduction.

Stage 3 may propose deletion of the Codex translation proxy and of per-turn `@openai/codex-sdk` exec only after a caller audit shows no remaining production caller, and only with a separate user approval. Until that approval, both stay.
