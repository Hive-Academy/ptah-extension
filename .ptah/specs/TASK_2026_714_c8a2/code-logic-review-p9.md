## Findings

1. **Serious — Native terminal failure looks like a completed gateway turn.** In libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-events.ts:264-294, a failed terminal calls the webview error callback and yields a message_complete event with stopReason failed; it does not throw. The callback targets the webview at libs/backend/rpc-handlers/src/lib/chat/codex-host/codex-chat-event-callbacks.ts:72-78,164. The gateway pump at libs/backend/gateway-chat-bridge/src/lib/gateway-chat-bridge.ts:1090-1115 counts that event but only handles text_delta, so a failed turn with partial output is sealed as a normal reply and recorded done at :737-748. A gateway user receives partial or empty output with no failure reply. Make the gateway consumer treat failed/interrupted terminal status as a turn failure, discard partial text as appropriate, and send its normal error reply; add a native failed-terminal integration case.

2. **Serious — A corrected native final text is lost on the gateway.** In libs/backend/agent-sdk/src/lib/codex-app-server/codex-chat-events.ts:143-168, textFinal with text that does not start with the streamed prefix sends the authoritative text only through callbacks.content and emits no text_delta. That callback publishes to webview delivery at libs/backend/rpc-handlers/src/lib/chat/codex-host/codex-chat-event-callbacks.ts:80-93. The gateway consumes only text_delta at libs/backend/gateway-chat-bridge/src/lib/gateway-chat-bridge.ts:1100-1102, so the chat platform receives the obsolete streamed prefix, even though the webview would show the corrected final. Carry complete-source replacement through the gateway stream contract or give the bridge a backend projection that reconciles each native text item before sealing. Cover divergent textFinal, including a shorter final answer.

3. **Serious — Missing runtime metadata can silently replace a bound native session.** resolveSessionRuntimeIdentity returns undefined for an absent binding at libs/backend/agent-sdk/src/lib/codex-app-server/session-runtime-identity.ts:30-39. The gateway then synthesizes a Claude identity for any valid bound id with no metadata at libs/backend/gateway-chat-bridge/src/lib/gateway-chat-bridge.ts:1035-1044. If a previously bound native session's metadata row is absent when the next gateway turn begins, the bridge prepares a Claude profile and routes resume to the legacy adapter (libs/backend/agent-sdk/src/lib/codex-app-server/routing-agent-adapter.ts:218-226); a failed resume starts a new session at libs/backend/gateway-chat-bridge/src/lib/gateway-chat-bridge.ts:947-966 and :1133-1156. This violates the stated bound-session rule and can switch provider and context without a user command. Fail closed when a nonempty binding has unknown provenance, or distinguish verified legacy Claude bindings from missing metadata before allowing any fallback. Keep the binding and require explicit /new.

4. **Medium — A rejected approval reply is published as allowed and loses its deny timer.** libs/backend/rpc-handlers/src/lib/chat/codex-host/codex-chat-host-ports.ts:663-672 removes the pending prompt before calling the approval router. When deps.approvals.respond returns false or throws at :684-720 (for example, a stale owner or invalid response), the code still publishes the UI-derived outcome at :721-727 and returns true. For an allow response, the gateway lifecycle reports allowed although the native sink did not accept it; takePrompt also cleared the 60-second timer at :308-315, so this prompt has no gateway deny-window settlement. Keep the pending entry until native acceptance is confirmed, or explicitly deliver a native decline and publish denied/aborted on rejection. Test false and throwing router responses for an unroutable gateway prompt.
