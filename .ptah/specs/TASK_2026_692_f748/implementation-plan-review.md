# Implementation plan review — TASK_2026_692_f748

**Verdict:** REVISE

The plan identifies the right integration points and covers most acceptance criteria, but its admission and attempt-lifetime rules still permit a second compaction or a lost manual request. Decision 9 is binding: AC 3.7 skips only Codex-proxy sessions and ignores E2. The plan's provisional D1 must be made final before handoff.

## Findings

1. **Serious — Manual admission can pass before the idle claim and execute after it.** Plan §§7 and 11 (`implementation-plan.md:355-361,519-535`) put the claim inside the pump's synchronous enqueue section, but the router calls `requestManualCompact` before asynchronous provider resolution. The current route awaits `resolveEnhancedPromptsContent` and then `resolveProviderProfileForWorkspace` before calling `executeSlashCommand` (`libs/backend/rpc-handlers/src/lib/chat/session/chat-slash-command-router.service.ts:122-137`). A manual request can receive `send`, yield during either await, and then an idle timer can claim and enqueue `/compact`. The resumed manual route still ends and relaunches the query (`libs/backend/agent-sdk/src/lib/helpers/session-lifecycle-manager.ts:730-748`). The router's one-time check cannot satisfy AC 2.5's exactly-one-compaction guarantee. Serialize manual admission with the claim through its actual send/transition, or recheck and reserve admission after the last await; test this ordering and the inverse ordering, including notice attribution. Existing coordinator dedupe cannot help before PreCompact (`libs/backend/agent-sdk/src/lib/helpers/compaction/compaction-coordinator.ts:166-179,243-252`).

2. **Serious — The plan releases a successful claim before the required PostCompact boundary.** Plan §4 says `turn-ended` in `boundary` completes the attempt and releases the claim (`implementation-plan.md:267-276`); the integration summary repeats boundary-then-turn-end as a release path (`:609-611`). The binding requirement holds the manual coalescing claim from enqueue until PostCompact or failure (`task-description.md:186-197`; `decisions.md:11`). `compact_boundary` and `result` are ordinary stream messages processed by the tap (`libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-query-executor.service.ts:247-267`), while PostCompact is a separate hook that later rekeys and emits completion (`libs/backend/agent-sdk/src/lib/helpers/compaction-hook-handler.ts:518-565`). A boundary and result before the PostCompact hook would clear the claim, letting a manual command relaunch the query before the matched compaction's hook completes. Keep the claim through matched PostCompact; use a bounded failure path when PostCompact is absent. Add a virtual-clock test with boundary, result, manual admission, then PostCompact.

3. **Serious — The RxJS trigger and feedback contract is underspecified and can miss or repeat a fire.** Plan §7 describes `state$` as `scan(reduceIdleSession)` producing `{state,effects}`, then defines `fire$ = state$ on attempt-due` (`implementation-plan.md:338-359`). The reducer explicitly leaves the Pending attempt in place for `attempt-due` until a separate `fire-started` signal (`:267-269`). No field in the stated `state$` output identifies which signal produced that state, so the proposed `fire$` cannot distinguish a due event from any later event that leaves the attempt Pending. `distinctUntilChanged(attemptId)` in `due$` also does not itself express cancellation on every signal (`:345-350`). Carry the input signal or a one-shot due effect through the scan, make the pending timer switch on every relevant state transition, and prove one fire when due, input/cancel, and feedback occur in the same virtual-time frame. The pump's send includes an asynchronous message construction before the final admission check (`libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-stream-pump.service.ts:219-247`), so this must also be tested with a pending promise and session release.

4. **Moderate — Completion and notice identity still depend on unverified hook ordering.** Plan A3 checks only boundary-before-result (`implementation-plan.md:117-119`), while its reducer handles PostCompact as completion only after `boundary` (`:267-276`). The hook can rekey and emit its PostCompact completion independently of the stream (`libs/backend/agent-sdk/src/lib/helpers/compaction-hook-handler.ts:529-565`); the tap sees boundary on the stream (`libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-query-executor.service.ts:247-257`). Define both PostCompact-before-boundary and boundary-before-PostCompact transitions, including which event owns the notice and when the claim clears. Test both and a PostCompact without boundary. A2 is correctly treated as an external CLI behavior requiring a live scratch-session probe before the sending batch is accepted; the existing pump only proves it queues a user message with an origin, not that the CLI executes `/compact` as a command (`libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-stream-pump.service.ts:234-247`).

## Coverage and evidence

- **Silent failure:** A2 could enqueue `/compact` as ordinary prompt text; the planned live probe gates acceptance, but its failure must stop rollout. A failed context read returns no arming value rather than a false positive (`libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-query-executor.service.ts:431-450`); the plan tests stale and missing readings.
- **User action:** A manual `/compact` during the router's awaited work can race the idle claim (Finding 1); a manual request between result and PostCompact can evade coalescing (Finding 2).
- **Wrong-answer input:** The TTL classifier correctly requires a one-hour write with zero five-minute writes. The parser exposes write TTL split, not read TTL (`libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:210-236`), and the plan does not infer read TTL. Late turn readings are keyed by turn ID.
- **Dependency failure:** Send refusal after the pump's second idle check yields no enqueue (`libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-stream-pump.service.ts:241-247`); the plan maps it to INFO. Promise cancellation and post-claim release still need the test in Finding 3. Failed/malformed SDK usage is classified `not-1h`; timeout and process sleep/wake have explicit fire-gate checks.
- **Unspecified requirement:** A2 and A3 are not guaranteed by repository code. The plan contains A2 with a live-probe gate and A3 with a generic-marker fallback, but must define both hook orderings (Finding 4). Decision 9 resolves D1; remove its provisional status.

AC 1.1-1.5 map to tracker/reducer specs; AC 2.1-2.9 to pump, coordinator, router and service specs; AC 3.1-3.9 to the fire-gate spec; AC 4.1-4.7 to reducer/service and lifecycle specs; AC 5.1-5.5 to settings/provider/export specs; AC 6.1-6.4 to transformer and frontend marker-chain specs; AC 7.1-7.2 to package metadata and scoped lint. The planned AC 2.7 test covers manual-after-claim, but omits manual-before-claim and boundary-result-before-PostCompact. The 1,000-session virtual-time test addresses group/timer cleanup; the design's `groupBy` duration and `finalize` are plausible for close, but need an explicit test that late feedback cannot recreate a group after release. The unref scheduler and injected clock have direct test seams. No builds, tests, or git operations were run for this document review.

The cited coordinator, pump, tap, hook, router, usage parser, settings, notice, and DI surfaces were spot-checked. The handoff's parallel groups use disjoint files after their stated prerequisites (`implementation-plan.md:637-649`), and the host-neutral `agent-sdk` design uses tsyringe tokens, an injected Logger, strict types and no host imports; proposed new files are bounded. Findings 1-3 distinguish REVISE from a moderate-only approval.

## Round 2

### Round 1 findings

1. **R1, Serious — Resolved.** The router now plans an authoritative, synchronous `admitManualCompact` after its last provider-resolution await and before `executeSlashCommand`, with a reservation held through the call (`implementation-plan.md:608-625`). The current await gap and subsequent call are at `libs/backend/rpc-handlers/src/lib/chat/session/chat-slash-command-router.service.ts:122-137`; the pump's final idle check and queue push are synchronous today (`libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-stream-pump.service.ts:241-247`). The plan tests manual-first and idle-first ordering (`implementation-plan.md:184-188,476-480,634-638`).
2. **R2, Serious — Resolved for boundary-first completion.** Boundary followed by result now enters `boundary-ended` and retains the claim until matched PostCompact or the bounded 30-second grace deadline (`implementation-plan.md:310-316`). The stream tap processes boundary and result separately (`libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-query-executor.service.ts:247-267`), and PostCompact emits from the hook (`libs/backend/agent-sdk/src/lib/helpers/compaction-hook-handler.ts:518-565`). A missing hook releases with `postcompact-timeout`; a hook arriving after that deadline cannot match the closed attempt under the plan's attempt-identity rule (`implementation-plan.md:208-211,316,323-324`). This bounded failure path is reviewable, but the new PostCompact-first issue below remains.
3. **R3, Serious — Resolved.** `attempt-due` now moves Pending to `sending` and emits the only fire effect in the same reduction; every reduction recalculates a single timer, and all producers, timers and feedback use a FIFO drain (`implementation-plan.md:278-289,301-304,397-421`). The send's callback checks group and attempt liveness after the pump's asynchronous message construction and immediately before queue insertion (`implementation-plan.md:426-439`; `libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-stream-pump.service.ts:234-247`). Same-frame and pending-promise cases are specified (`implementation-plan.md:483-487`).
4. **R4, Moderate — Resolved as an ordering contract.** The reducer now defines boundary-first, PostCompact-first and PostCompact-without-boundary transitions, including notice ownership (`implementation-plan.md:310-329`); the notice key follows the boundary frame's `session_id` (`implementation-plan.md:325-329,649-653`). The hook rekeys and emits independently of stream processing (`libs/backend/agent-sdk/src/lib/helpers/compaction-hook-handler.ts:529-565`; `libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-query-executor.service.ts:247-267`). Both orders and the missing-boundary case have planned tests (`implementation-plan.md:339-344,480-483`).

### New finding

1. **Serious — PostCompact-first release leaves manual admission silently deduping a completed compaction.** Revision 2 releases the idle claim on `post-compact` while the attempt waits in `postcompacted` for a later boundary or result (`implementation-plan.md:317-322`). But the hook's PostCompact path only rebinds the coordinator record and emits completion (`libs/backend/agent-sdk/src/lib/helpers/compaction-hook-handler.ts:529-565`); `CompactionCoordinator.onPostCompact` does not leave TRIGGERED/COMPACTING (`libs/backend/agent-sdk/src/lib/helpers/compaction/compaction-coordinator.ts:230-240`). Its `requestManualCompact` still returns `deduped` for those states (`:243-252`), and `onTurnEnd` cannot clear them without a boundary because it accepts only COOLDOWN/BACKOFF (`:211-222`). The router's planned fast path returns success without sending for `deduped` (`implementation-plan.md:615-620`). Thus a user manual `/compact` after the matched PostCompact but before a boundary is silently dropped, possibly until the dwell timeout if no boundary arrives. This contradicts the required admission after claim release (`task-description.md:193-203`). Define a coordinator transition or admission rule for PostCompact-first completion, and test manual admission between PostCompact and boundary and after PostCompact with no boundary.

### Failure-mode coverage and limits

- **Silent failure / user action:** The new finding gives a success-looking result for a manual command that was never sent. The manual-before-idle race from Round 1 has a synchronous reservation (`implementation-plan.md:617-625`).
- **Wrong-answer input:** The one-hour classifier requires a positive one-hour cache write and zero five-minute writes; absent or read-only usage is `not-1h` (`implementation-plan.md:242-250`; `libs/backend/agent-sdk/src/lib/helpers/compaction/subagent-budget-monitor.ts:210-236`).
- **Dependency failure:** A missing PostCompact after boundary/result releases the claim after 30 seconds with `postcompact-timeout` (`implementation-plan.md:312-316`); a late hook is not a match for the closed attempt. A send promise settling after session release is vetoed at the pump callback (`implementation-plan.md:426-439`).
- **Unspecified requirement:** The CLI's treatment of a streamed coordinator-origin `/compact` remains an external assumption. The plan gates acceptance on a live scratch-session probe and stops rollout if it fails (`implementation-plan.md:119-124,752-755`).

This is a document and source-logic review. No build, test, diagnostics run, or git operation was performed. The score is in the 5–6 band: the four prior gaps have concrete remedies, but the new PostCompact-first path can lose a user command; that separates it from a sound 7–8 plan. The design is not foundationally wrong, so it does not warrant 3–4.

### New finding

Preserve the completion mark across TRIGGERED→COMPACTING, or define an equivalent rule that guarantees admission after PostCompact. Add a test for PostCompact → delayed compacting status → manual admission, including the router result.

### Failure-mode questions and limits

- **User action:** manual `/compact` after PostCompact and a delayed compacting status is dropped; before PostCompact, the held claim still coalesces it (implementation-plan.md:171-176,331-347).
