## Authoring rubric — numbered checklist (keep/cut rules) applicable to any skill or subagent prompt

1. **Zero Model Education (Cut)**: Delete explanations of concepts pre-trained models already master (e.g. SOLID, DRY, AST vs regex, Three.js light types, async/await). State *what* to do, never *how the concept works*.
2. **Zero Historical Narrative (Cut)**: Delete all bug post-mortems, commit dates, PR rationale, and previous implementation history (e.g., `(TASK_2026_182 repaired 2026-08-09)`). The model needs the invariant rule today, not the story of how it broke yesterday.
3. **One Schema + Table, Never N Code Blocks (Cut)**: If an example repeats with minor parameter tweaks (e.g. 8 CLI delegation calls differing only in task prompt), write the invocation schema **once** and provide a compact Markdown table of variable values.
4. **No Pedagogical "Good vs Bad" Blocks (Cut)**: Abstract contrasts ("Bad: do not be vague; Good: be specific") waste tokens. State the constraint imperatively: `Prompt must cite absolute file path, output format, and acceptance criteria.`
5. **No Slogans or Trailing Cheerleading (Cut)**: Strip "Pro Tips", "Remember: Quality First", and cheerleading conclusions. Every line must be an operational instruction, input, boundary, or output contract.
6. **Strict Progressive Disclosure (Keep)**: `SKILL.md` must be a lean routing table (under 150 lines, <7 KB) containing only: triggers, execution flow map, and a table linking to topic references. Never duplicate reference content in `SKILL.md`.
7. **Strict Role-Gated Capabilities (Keep)**: Only inject capabilities an agent is authorized to execute. Pure reporters and reviewers must never receive code replacement shims or task ID allocation instructions.
8. **Explicit Input/Output Contracts (Keep)**: Always specify exact absolute paths for input files, explicit deliverable paths, structured return schemas (markdown or JSON), and a closed enum of valid statuses.
9. **Bounded Convergence Rules (Keep)**: Always specify hard termination bounds on loops (e.g. `max 3 concurrent`, `cap at 2 revise rounds`, `timeout 8s`). Never describe open-ended iteration.
10. **Discover, Never Hardcode (Keep)**: Never hardcode vendor rosters, tool names, or library versions. Direct the agent to discover capabilities from tools (`ptah_agent_list`) or dependency manifests.

## Tradeoffs / risks

1. **Subagent Adherence on Compact Schemas**: Compressing full markdown output templates into concise schema tables risks minor format deviations with lighter models (e.g. Claude Haiku, GPT-4o-mini). *Mitigation*: Retain explicit header strings (`## Tasks completed`, `## Verdict`) in return contracts while stripping verbose field descriptions.
2. **Tool-Call Overhead Under Progressive Disclosure**: Stripping `orchestration/SKILL.md` down to a routing stub requires the orchestrator to execute an extra `view_file` call to load `checkpoints.md` or `strategies.md`. *Mitigation*: The 18 KB saving on *every* invocation easily repays the cost of a targeted reference read only when needed.
3. **Build & Manifest Synchronization**: Pruning the 11 orphan `.ts` components (98.8 KB) from `ptah-angular` will break CI workflows running `manifest:check` unless accompanied by `npm run manifest:generate` and manifest denylist updates in [`generate-content-manifest.js`](D:/projects/ptah-extension/scripts/generate-content-manifest.js#L33).
4. **Downstream Mirror Propagation**: Existing user installations (`~/.ptah/plugins` and `~/.ptah/user`) fast-forward on `contentHash` changes via `UserLayerMirrorService`. If references are renamed rather than edited in-place, stale local files could persist on client machines.
