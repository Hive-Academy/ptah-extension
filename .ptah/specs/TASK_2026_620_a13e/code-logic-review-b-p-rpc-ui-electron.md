# Code logic review — B-P RPC, Thoth UI, Electron

## Verdict: REVISE

Score: **6/10** — the contract, RPC gates, switch write paths, rollback handling, and Windows/macOS tray refresh path are substantively implemented, but one supported-host failure leaves the always-on tray displaying stale pause state after an external change. This is above the 5-band because the primary in-process paths and targeted tests cover the intended transitions; it cannot reach the 7-band until the tray's cross-process freshness contract works on Linux as well as the other supported Electron hosts.

## Findings

1. **Serious — P5: external pause changes remain stale in the Linux tray.**
   [apps/ptah-electron/src/services/tray/tray.service.ts:46-53](apps/ptah-electron/src/services/tray/tray.service.ts:46) documents that another process's edit produces no configuration event and explicitly says Linux AppIndicator produces no tray events. The only external-refresh listeners are `mouse-enter`, `click`, and `right-click` at [tray.service.ts:320-327](apps/ptah-electron/src/services/tray/tray.service.ts:320); the configuration subscription at [tray.service.ts:305-318](apps/ptah-electron/src/services/tray/tray.service.ts:305) covers only in-process writes. Therefore a Linux user who pauses/resumes through Thoth, another Ptah process, or `~/.ptah/settings.json` can open the tray and see the prior checkbox and tooltip indefinitely. Clicking that stale checkbox can then persist the opposite of the user-intended state. This violates the binding “refreshed when the setting changes elsewhere” decision. Add a Linux-capable refresh mechanism (for example, provider/file-change notification or bounded refresh while the tray is live) and exercise the no-tray-event path.

No additional logic finding was established. The changed RPC and UI paths were inspected in full together with their surrounding registration and caller paths. In particular, `memory:runNow` validates parameters and rejects pause at [memory-rpc.handlers.ts:648-678](libs/backend/rpc-handlers/src/lib/handlers/memory-rpc.handlers.ts:648); memory switch updates write only supplied trigger keys plus the independent master at [memory-rpc.handlers.ts:750-785](libs/backend/rpc-handlers/src/lib/handlers/memory-rpc.handlers.ts:750); the shared `PAUSED` union is present at [rpc-error-codes.types.ts:7-34](libs/shared/src/lib/types/rpc/rpc-error-codes.types.ts:7); and the five named skills manual-model-work routes use the pause assertion (for example [skills-synthesis-rpc.handlers.ts:728-733](libs/backend/rpc-handlers/src/lib/handlers/skills-synthesis-rpc.handlers.ts:728), [846](libs/backend/rpc-handlers/src/lib/handlers/skills-synthesis-rpc.handlers.ts:846), [1106](libs/backend/rpc-handlers/src/lib/handlers/skills-synthesis-rpc.handlers.ts:1106), and [1151-1158](libs/backend/rpc-handlers/src/lib/handlers/skills-synthesis-rpc.handlers.ts:1151)).

## Five logic questions

1. **Silent failure / success-looking result:** The Linux tray can silently retain a success-looking but obsolete checkbox and tooltip after an external setting write; there is no notification or error surface for the stale state ([tray.service.ts:46-53](apps/ptah-electron/src/services/tray/tray.service.ts:46), [320-327](apps/ptah-electron/src/services/tray/tray.service.ts:320)).
2. **Unexpected user action:** On Linux, pause or resume from Thoth/a second process, then use the tray. The menu can describe the old state and the next click reverses the user’s intended master setting (same evidence as finding 1).
3. **Wrong input data:** A changed `memory.enabled` or `skillSynthesis.enabled` value in the shared settings file is correct input but produces the wrong tray presentation on the eventless Linux path. Memory’s `{ triggers: {}, enabled }` payload itself does not overwrite other trigger keys ([memory-diagnostics-state.service.ts:120-145](libs/frontend/memory-curator-ui/src/lib/services/memory-diagnostics-state.service.ts:120), [memory-rpc.handlers.ts:763-785](libs/backend/rpc-handlers/src/lib/handlers/memory-rpc.handlers.ts:763)).
4. **Dependency failure / malformed response:** The UI switch disables until it has a Boolean value, rolls back after a failed write, and re-reads the host ([memory-diagnostics-state.service.ts:99-145](libs/frontend/memory-curator-ui/src/lib/services/memory-diagnostics-state.service.ts:99)); the tray catches persistence/read failures and preserves the prior menu ([tray.service.ts:271-292](apps/ptah-electron/src/services/tray/tray.service.ts:271), [364-402](apps/ptah-electron/src/services/tray/tray.service.ts:364)). Those paths are appropriately non-silent, aside from the eventless stale-state case above.
5. **Missing requirement:** The plan specified menu-open refresh but did not require an eventless-Linux equivalent. The implementation’s own platform note demonstrates that menu-open refresh is unavailable there, leaving cross-process consistency unspecified and unfulfilled ([tray.service.ts:46-53](apps/ptah-electron/src/services/tray/tray.service.ts:46)).
