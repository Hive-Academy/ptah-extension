## How descriptions are consumed

| Consumer | File | Reads | Budget / truncation |
| --- | --- | --- | --- |
| Agent SDK session (skill listing) | plugins passed to the SDK; harness-sync copies skills byte-for-byte into the Claude target | whole frontmatter via the SDK binary | None in Ptah. The skill spec caps a description at 1,024 characters |
| Plugin skill prompt injection | `libs/backend/agent-sdk/src/lib/helpers/plugin-skill-discovery.ts` (`parseFrontmatter`, `formatSkillsForPrompt`) | **first line only** (`^description:\s*(.+)$`), strips one outer quote character | None. Injected in full into setup-wizard, enhanced-prompts and multi-phase analysis system prompts. A `>-` block scalar would inject the literal `>-` |
| Rival CLI harness copies | `libs/backend/harness-sync/src/lib/targets/skill-transform.ts` (`sanitizeYamlDescriptions`) | single line; wraps an unquoted value containing `: ` in double quotes for strict YAML parsers | None |
| Harness builder skill catalog | `libs/backend/rpc-handlers/src/lib/harness/selection/skill-catalog.ts` | inline or block scalar | Truncated to 500 characters with `…` (UI card) |
| Command autocomplete | `libs/backend/workspace-intelligence/src/autocomplete/command-discovery.service.ts` | tolerant parser, folded continuation lines | None |
| skills.sh directory enricher | `libs/backend/cli-agent-runtime/src/lib/skills-directory/skills-sh-description.enricher.ts` | external skills.sh entries, not shipped skills | 500 characters |
| Skill synthesis | `libs/backend/skill-synthesis` | its own DB rows, not shipped SKILL.md files | curator prompt slices to 120 characters |

Findings:

- Ptah never budgets the SDK-facing description. Every character loads into every
  session, which is why the pass matters.
- `plugin-skill-discovery.ts` is the binding constraint on format: descriptions
  must stay single-line scalars. The guard enforces it.
- No shipped description exceeded the catalog's 500-character cut after the pass
  (before: 14 did, so harness-builder cards showed cut-off text).
- Specs and docs: no spec pins shipped description text.
  `command-discovery-frontmatter.spec.ts` carries its own abridged fixture of the
  old angular-3d text to test parser tolerance of an unquoted colon; it reads no
  real file and stays valid. `apps/ptah-docs/.../popular-skills.md` paraphrases
  skills in its own words and quotes no description. Nothing needed updating.
- `.claude/skills/` in the repo is a stale, drifted mirror (several SKILL.md files
  already differ from the plugin sources). It is not shipped and was not edited.

## Guard

`libs/backend/vscode-lm-tools/src/lib/code-execution/skill-description-shape.spec.ts`,
next to `lane-rule-single-home.spec.ts` and `vendor-roster-drift.spec.ts`. It
fails on a missing or empty description, a block scalar, more than 400
characters, a `(n)` numbered list, or more than four double-quoted phrases.

Proof it fails: tribunal was temporarily given a `(1)`, five quoted phrases and
446 characters (3 of 6 tests failed, each naming the file); then composition-patterns
was emptied and video-showcase made a `>-` block scalar (5 of 6 failed). Both
files were restored and the manifest check passed again.
