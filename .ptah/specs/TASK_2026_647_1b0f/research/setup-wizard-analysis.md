# Setup Wizard versus chat: architecture analysis

Evidence below is repository source at the stated lines. **Proposed** describes a change, not present behavior. Line estimates are conditional deletion opportunities, not a promise that an entire file is unused.

## A

**Present path.** `WizardViewComponent` chooses welcome → scan → analysis results → agent selection → generation → enhance → completion from its step signal (`libs/frontend/setup-wizard/src/lib/components/wizard-view.component.ts:110-132`). `WizardAnalysisRunner` first calls `wizard:get-resumable-run`; if no unfinished analysis exists it calls `wizard:deep-analyze`, then `wizard:recommend-agents`, stores the result and advances to analysis (`libs/frontend/setup-wizard/src/lib/services/wizard-analysis-runner.service.ts:176-213,245-279`). `wizard:deep-analyze` validates params and workspace access, requires the MCP server, calls `MultiPhaseAnalysisService.analyzeWorkspace`, then reads completed phase files into the response and seeds memory best effort (`libs/backend/rpc-handlers/src/lib/handlers/setup-rpc.handlers.ts:272-389`). The analysis service executes four phase prompts with `InternalQueryService.execute` and consumes its own SDK stream; this is **not** `chat:start` (`libs/backend/agent-generation/src/lib/services/wizard/multi-phase-analysis.service.ts:590-673`; `libs/backend/rpc-handlers/src/lib/handlers/chat-rpc.handlers.ts:236-248`).

Agent selection calls `wizard:submit-selection`; its handler authorizes `analysisDir`, creates or resumes a generation checkpoint, then launches `AgentGenerationOrchestratorService` under `GenerationRunSupervisor` (`libs/backend/rpc-handlers/src/lib/handlers/wizard-generation-rpc.handlers.ts:217-295,869-892`). Generation's content pass also uses `InternalQueryService.execute`, with its own SDK stream processor (`libs/backend/agent-generation/src/lib/services/content-generation.service.ts:395-417,591-664`). On generation completion the frontend advances to enhance (`libs/frontend/setup-wizard/src/lib/services/setup-wizard/wizard-phase-generation.ts:88-113`). `PromptEnhancementComponent` auto calls `enhancedPrompts:runWizard` using the analysis directory; the backend `EnhancedPromptsService` builds input and makes another internal SDK call (`libs/frontend/setup-wizard/src/lib/components/prompt-enhancement.component.ts:270-307`; `libs/backend/rpc-handlers/src/lib/handlers/enhanced-prompts-rpc.handlers.ts:210-243,342-348`; `libs/backend/agent-generation/src/lib/services/enhanced-prompts/enhanced-prompts.service.ts:376-502,804-825`).

**Streaming.** Analysis converts SDK events to `setup-wizard:analysis-stream` and broadcasts phase progress (`libs/backend/agent-generation/src/lib/services/wizard/multi-phase-analysis.service.ts:852-882,896-1007`). Generation broadcasts `setup-wizard:generation-stream` and `setup-wizard:generation-progress`; prompt enhancement broadcasts `setup-wizard:enhance-stream` (`libs/backend/rpc-handlers/src/lib/handlers/wizard-generation-rpc.handlers.ts:924-951`; `libs/backend/rpc-handlers/src/lib/handlers/enhanced-prompts-rpc.handlers.ts:663-680`). A wizard dispatcher routes these plus `scan-progress`, completion and error events into wizard signals (`libs/frontend/setup-wizard/src/lib/services/setup-wizard/wizard-message-dispatcher.ts:26-46,59-90`). `scan-progress` has a receiver, but no producer was found in the inspected wizard backend paths; the active runner directly starts `deepAnalyze` (`libs/frontend/setup-wizard/src/lib/services/setup-wizard/wizard-message-dispatcher.ts:38-46`; `libs/frontend/setup-wizard/src/lib/services/wizard-analysis-runner.service.ts:245-269`). The transcript already imports the **shared** `ExecutionNodeComponent` and `ExecutionTreeBuilderService`, but builds a separate tree from wizard phase events; `ToolOutputFormatterService` is exported and tested yet has no production import in the wizard tree (`libs/frontend/setup-wizard/src/lib/components/analysis-transcript.component.ts:17-35,113-157`; `libs/frontend/setup-wizard/src/index.ts:3`; `libs/frontend/setup-wizard/src/lib/services/tool-output-formatter.service.ts:16-73`).

Normal chat calls `chat:start`/`chat:continue`; `ChatSessionService` starts an SDK chat session and hands its stream to `ChatStreamBroadcaster`, while `chat:resume` reads history (`libs/frontend/chat/src/lib/services/message-sender.service.ts:356-440,668-702`; `libs/backend/rpc-handlers/src/lib/handlers/chat-rpc.handlers.ts:236-268`; `libs/backend/rpc-handlers/src/lib/chat/session/chat-session.service.ts:738-768,945-949`). Its presentation store merges finalized and streaming messages into execution trees that `MessageBubbleComponent` renders (`libs/frontend/chat/src/lib/services/stream-presentation-store.service.ts:160-220,238-283`; `libs/frontend/chat/src/lib/components/organisms/message-bubble.component.ts:61-72`). `WorkflowSessionClaimService` is only an in-memory correlation-to-surface claim map, not a wizard persistence layer (`libs/frontend/chat-routing/src/lib/workflow-session-claim.service.ts:5-28`).

## B

**Existing durable analysis.** The four ordered outputs are `project-profile`, `architecture-assessment`, `quality-audit`, and `elevation-plan` at `01`–`04` markdown files (`libs/backend/agent-generation/src/lib/types/multi-phase.types.ts:126-147`). `AnalysisStorageService` owns `<workspace>/.ptah/analysis/<slug>/manifest.json`, phase files and a neighboring `generation-manifest.json`; manifest reads are Zod validated (`libs/backend/agent-generation/src/lib/services/analysis-storage.service.ts:2-12,68-89`). `AnalysisRunCheckpoint` persists version 3, model, lifecycle, per-phase file/status/duration and timestamps before work; resume skips completed phases, converts an active phase to pending on pause, and records failed or completed outcomes (`libs/backend/agent-generation/src/lib/services/wizard/analysis-run-checkpoint.ts:48-120,127-217`; `libs/backend/agent-generation/src/lib/types/multi-phase.types.ts:22-91`). Resume with a missing, malformed, completed, old-version or different-model manifest starts fresh (`libs/backend/agent-generation/src/lib/services/wizard/analysis-run-checkpoint.ts:48-76`). Each phase has an abort controller and timeout; prior phase text is restored after abort/failure if missing, although a process crash during stale-file removal can lose that partial diagnostic text (`libs/backend/agent-generation/src/lib/services/wizard/multi-phase-analysis.service.ts:241-275,294-335,630-685`). `wizard:cancel-analysis` aborts the active analysis; cancellation leaves a paused manifest (`libs/backend/rpc-handlers/src/lib/handlers/setup-rpc.handlers.ts:691-712`; `libs/backend/agent-generation/src/lib/services/wizard/multi-phase-analysis.service.ts:401-409`). The frontend discovers an unfinished run and offers explicit resume/fresh choices; it also adopts a completed analysis while recovering generation (`libs/frontend/setup-wizard/src/lib/services/wizard-analysis-runner.service.ts:99-146,176-213`).

**Existing durable generation and prompt state.** The generation checkpoint stores selected agents, output paths, outcome statuses, analysis directory and lifecycle; resume retries pending/running/failed items while keeping settled ones, and refuses paths outside the workspace (`libs/backend/agent-generation/src/lib/types/generation-checkpoint.types.ts:15-29`; `libs/backend/rpc-handlers/src/lib/handlers/wizard-generation-checkpoint.service.ts:126-168,212-277`). It records each terminal agent outcome and stops further work if checkpoint update fails (`libs/backend/rpc-handlers/src/lib/handlers/wizard-generation-checkpoint.service.ts:286-314`). `GenerationRunSupervisor` owns one abort controller, a ten-minute watchdog, outcome shaping, and one completion broadcast; `wizard:cancel` pauses but keeps the checkpoint, and `wizard:retry-item` retries one agent (`libs/backend/rpc-handlers/src/lib/handlers/wizard-generation-run.supervisor.ts:172-212,243-298`; `libs/backend/rpc-handlers/src/lib/handlers/wizard-generation-rpc.handlers.ts:613-703`). Enhanced prompt state is workspace-keyed in extension `globalState`, with generated content, enabled flag and cache metadata; a trace is written to disk before the state is saved, and failure to write prevents state update (`libs/backend/agent-generation/src/lib/services/enhanced-prompts/enhanced-prompts-state-store.ts:2-80`; `libs/backend/agent-generation/src/lib/services/enhanced-prompts/enhanced-prompts.service.ts:536-572`). UI step, selection and live stream arrays are Angular signals, so only the backend artifacts and prompt global state are durable across panel destruction (`libs/frontend/setup-wizard/src/lib/services/setup-wizard-state.service.ts:97-110,121-181,432-458`).

## C

**Overlap.** The wizard reimplements SDK stream conversion and broadcast in `MultiPhaseAnalysisService`, generation content handling and wizard RPC callbacks, plus a frontend dispatcher and wizard-specific live arrays; chat already has session start/continue/resume, a stream broadcaster and merged streaming/finalized execution messages (`libs/backend/agent-generation/src/lib/services/wizard/multi-phase-analysis.service.ts:649-673,896-1007`; `libs/backend/agent-generation/src/lib/services/content-generation.service.ts:591-664`; `libs/frontend/setup-wizard/src/lib/services/setup-wizard/wizard-message-dispatcher.ts:26-90`; `libs/frontend/setup-wizard/src/lib/services/setup-wizard-state.service.ts:121-145`; `libs/backend/rpc-handlers/src/lib/chat/session/chat-session.service.ts:738-768,945-949`; `libs/frontend/chat/src/lib/services/stream-presentation-store.service.ts:160-220`). The wizard transcript already reuses chat's node renderer, so this is primarily duplicate event routing/state and layout, not an entirely separate renderer (`libs/frontend/setup-wizard/src/lib/components/analysis-transcript.component.ts:17-35,113-157`).

**Conditional deletion estimate.** If every AI turn uses chat, roughly 500–700 of 1,033 lines in `multi-phase-analysis.service.ts` (execution, stream conversion and broadcast) can go, but checkpoint/result validation remains; roughly 80–160 of 1,205+ lines in `content-generation.service.ts` (stream translation, not content safety/writing); 198/198 transcript lines; 338/338 formatter lines if no other production consumer; 80–123/123 dispatcher lines; 120–220/680 wizard coordinator lines; and 100–170/295 analysis runner lines. These ranges are estimates from the relevant code regions and file lengths, and must be confirmed by references after migration (`libs/backend/agent-generation/src/lib/services/wizard/multi-phase-analysis.service.ts:579-1007`; `libs/backend/agent-generation/src/lib/services/content-generation.service.ts:591-764`; `libs/frontend/setup-wizard/src/lib/components/analysis-transcript.component.ts:1-198`; `libs/frontend/setup-wizard/src/lib/services/tool-output-formatter.service.ts:1-338`; `libs/frontend/setup-wizard/src/lib/services/setup-wizard/wizard-message-dispatcher.ts:1-123`; `libs/frontend/setup-wizard/src/lib/services/setup-wizard-state.service.ts:97-181,318-336,642-680`; `libs/frontend/setup-wizard/src/lib/services/wizard-analysis-runner.service.ts:99-295`). Do not count checkpoint, safety validation, file writing or propagation as chat duplication (`libs/backend/rpc-handlers/src/lib/handlers/wizard-generation-checkpoint.service.ts:286-340`; `libs/backend/agent-generation/src/lib/services/orchestrator.service.ts:929-1012`; `libs/backend/rpc-handlers/src/lib/handlers/wizard-generation-rpc.handlers.ts:978-1030`).

## D

The split is **partly present at the RPC boundary**: `wizard:deep-analyze`, `wizard:submit-selection`, and `enhancedPrompts:runWizard` are separate methods (`libs/backend/rpc-handlers/src/lib/handlers/setup-rpc.handlers.ts:272-276`; `libs/backend/rpc-handlers/src/lib/handlers/wizard-generation-rpc.handlers.ts:204-217`; `libs/backend/rpc-handlers/src/lib/handlers/enhanced-prompts-rpc.handlers.ts:198-213`). Their **workflow coupling** is the step transition from generation to enhance, and the enhance component's refusal to run without an analysis result (`libs/frontend/setup-wizard/src/lib/services/setup-wizard/wizard-phase-generation.ts:88-113`; `libs/frontend/setup-wizard/src/lib/components/prompt-enhancement.component.ts:270-307`). Backend generation accepts both `analysisDir` and optional precomputed analysis, while its content generator reads analysis phase files when the directory exists; enhance enriches from the same files and its `regenerate` currently fails without a latest analysis (`libs/backend/rpc-handlers/src/lib/handlers/wizard-generation-rpc.handlers.ts:251-276,869-892`; `libs/backend/agent-generation/src/lib/services/content-generation.service.ts:573-587,1054-1096`; `libs/backend/agent-generation/src/lib/services/enhanced-prompts/enhanced-prompts.service.ts:639-674,982-1080`).

**Proposed independent steps.** Provide explicit “Generate agents” and “Generate project guidance” actions. Each takes an authorized workspace and a chosen **completed** analysis slug (or an explicit “analyze now” precondition), reads validated phase files from `.ptah/analysis/<slug>`, and persists its own run/output status. Use a seed prompt/skill in a normal `chat:start` session for each step, then `chat:continue` for user steering. The prompt names phase files and the target output contract; the agent can read those files with workspace-relative paths, as existing phase prompts already require (`libs/backend/agent-generation/src/lib/services/wizard/multi-phase-analysis.service.ts:600-609`; `libs/backend/agent-generation/src/lib/services/wizard/multi-phase-prompts.ts:120-129,179-201`). Keep a narrow finalization boundary for generated agent validation, writes, sync and prompt trace/state; direct chat tool writes alone do not provide those existing guarantees (`libs/backend/agent-generation/src/lib/services/orchestrator.service.ts:929-1012`; `libs/backend/rpc-handlers/src/lib/handlers/wizard-generation-rpc.handlers.ts:978-1030`; `libs/backend/agent-generation/src/lib/services/enhanced-prompts/enhanced-prompts.service.ts:536-572`). Preserve output directory authorization and workspace binding (`libs/backend/rpc-handlers/src/lib/handlers/wizard-generation-rpc.handlers.ts:897-911`; `libs/backend/rpc-handlers/src/lib/handlers/enhanced-prompts-rpc.handlers.ts:223-243`).

## E

**Choose the existing analysis artifact plus manifest under `.ptah/analysis`**, with a chat session ID recorded per phase. It already has phase files, Zod-validated versioned manifest, per-step status, model and duration, and resume semantics (`libs/backend/agent-generation/src/lib/services/analysis-storage.service.ts:2-12,68-89`; `libs/backend/agent-generation/src/lib/types/multi-phase.types.ts:22-91`; `libs/backend/agent-generation/src/lib/services/wizard/analysis-run-checkpoint.ts:48-76,127-217`). Proposed manifest additions: `sessionId`, attempt number, input file fingerprints and output verification status per phase; migration must version the manifest rather than reinterpret version 3 (`libs/backend/agent-generation/src/lib/types/multi-phase.types.ts:46-91`). Start each phase as a chat session with its current seed prompt, write/verify the phase file, then mark complete; resume restores the manifest, skips verified outputs and resumes or restarts only the active phase, using normal chat history and `chat:resume` for the transcript (`libs/backend/agent-generation/src/lib/services/wizard/multi-phase-prompts.ts:38-41,120-129,214-221,338-350`; `libs/backend/rpc-handlers/src/lib/handlers/chat-rpc.handlers.ts:264-268`; `libs/backend/rpc-handlers/src/lib/chat/session/chat-session.service.ts:945-949`). On failure/cancel, mark paused or failed and preserve partial files; a file alone must not imply completion (`libs/backend/agent-generation/src/lib/services/wizard/analysis-run-checkpoint.ts:149-196`; `libs/backend/agent-generation/src/lib/services/wizard/multi-phase-analysis.service.ts:294-335`). This provides cross-turn/reopen state while chat carries the conversational stream.

**Other choices.** `.ptah/specs` is task management with `task.md` carriers and an index, so using it for one workspace analysis would introduce task lifecycle semantics into an existing analysis storage domain (`libs/backend/task-specs/src/lib/task-scanner.service.ts:84-85`; `libs/backend/task-specs/src/lib/task-index.service.ts:9-17`; `libs/backend/agent-generation/src/lib/services/analysis-storage.service.ts:2-12`). A chat session whose agent writes files still needs authoritative validation, step status and retry decisions; the existing checkpoint already provides them (`libs/backend/agent-generation/src/lib/services/wizard/analysis-run-checkpoint.ts:141-217`; `libs/backend/agent-generation/src/lib/services/wizard/multi-phase-analysis.service.ts:440-548`). Thus chat is the execution/transcript layer; the artifact manifest is the step ledger.

## F

Keep agent catalog/recommendation and selection controls, preview and per-agent outcomes, saved-analysis results/dashboard, prompt summary/enablement, completion and consent-driven propagation as workflow additions around chat (`libs/backend/rpc-handlers/src/lib/handlers/setup-rpc.handlers.ts:470-560,751-865`; `libs/frontend/setup-wizard/src/lib/components/agent-selection.component.ts:1004-1148`; `libs/frontend/setup-wizard/src/lib/components/analysis-results.component.ts:1-100`; `libs/frontend/setup-wizard/src/lib/components/analysis-stats-dashboard.component.ts:1-80`; `libs/frontend/setup-wizard/src/lib/components/prompt-enhancement.component.ts:125-151`; `libs/frontend/setup-wizard/src/lib/components/completion.component.ts:1-100`; `libs/backend/rpc-handlers/src/lib/handlers/wizard-generation-rpc.handlers.ts:978-1030`). Keep concise phase progress/status cards sourced from the manifest, rather than a separate SDK transcript (`libs/frontend/setup-wizard/src/lib/components/scan-progress.component.ts:405-464`; `libs/frontend/setup-wizard/src/lib/components/generation-progress.component.ts:348-386`; `libs/backend/agent-generation/src/lib/services/wizard/analysis-run-checkpoint.ts:127-217`).

## Decisions

1. Preserve the analysis artifact/manifest as the authoritative step ledger and add a chat session reference per phase; use `chat:start`, `chat:continue`, `chat:resume` for conversation and stream (`libs/backend/agent-generation/src/lib/services/analysis-storage.service.ts:2-12`; `libs/backend/rpc-handlers/src/lib/handlers/chat-rpc.handlers.ts:236-268`). Reject chat history alone because it does not record verified phase-file status (`libs/backend/agent-generation/src/lib/services/wizard/analysis-run-checkpoint.ts:141-217`).
2. Expose agent generation and project guidance as independent actions tied to a selected completed analysis, while preserving their separate checkpoint/trace and safe finalization until replacements are verified (`libs/backend/rpc-handlers/src/lib/handlers/wizard-generation-rpc.handlers.ts:217-295`; `libs/backend/agent-generation/src/lib/services/enhanced-prompts/enhanced-prompts.service.ts:536-572`). Reject placing these outputs back inside the four-phase analysis run because they already have separate RPCs and distinct persistence (`libs/backend/rpc-handlers/src/lib/handlers/setup-rpc.handlers.ts:272-276`; `libs/backend/rpc-handlers/src/lib/handlers/enhanced-prompts-rpc.handlers.ts:210-213`).
3. Replace wizard live transcript transport with normal chat messages; keep result, selection, checkpoint summary and completion UI (`libs/frontend/chat/src/lib/services/stream-presentation-store.service.ts:160-220`; `libs/frontend/setup-wizard/src/lib/components/wizard-view.component.ts:110-132`).

## Open questions

1. Should independent generation allow **no analysis** as the current agent orchestrator can self-analyze, or require a chosen completed artifact? Current submit accepts `analysisDir` and optional `analysisData`; prompt regeneration currently requires an existing analysis (`libs/backend/rpc-handlers/src/lib/handlers/wizard-generation-rpc.handlers.ts:251-276`; `libs/backend/agent-generation/src/lib/services/enhanced-prompts/enhanced-prompts.service.ts:639-674`). Recommended: explicit optional analysis for agents, required completed artifact for project guidance.
2. Should a phase resume the same SDK session after crash, or start a new chat attempt with the same phase file as context? Existing checkpoint restarts unfinished phases and only skips completed ones; chat supports session resume (`libs/backend/agent-generation/src/lib/services/wizard/analysis-run-checkpoint.ts:127-196`; `libs/backend/rpc-handlers/src/lib/chat/session/chat-session.service.ts:945-949`). Recommended: resume for interactive continuation, new attempt when file validation fails.
3. The wizard `ToolOutputFormatterService` has only its export and tests in the inspected wizard tree; confirm monorepo import references before deletion (`libs/frontend/setup-wizard/src/index.ts:3`; `libs/frontend/setup-wizard/src/lib/services/tool-output-formatter.service.ts:16-73`).
