## Findings

- F1 (product, boot window): after the window opens, `session:list` answers `organizationAvailable: false` for 5-45 s on every boot I observed (availableAfterMs 5374-44818 across 15 boots; RPC ready at about 0.3 s). Any capture or `session:delete` cascade in that window is dropped (`[SessionOrganization] removeSession dropped ...: store not open`), which is the plan's boot-window row, but for delete it leaves rows that nothing removes later, contradicting AC6 "delete removes all rows" in that window. Rows stay hidden (R-TL12), so no user-visible effect, but the DB keeps stale rows. Also one `[ERROR] [SessionOrganization] session:list could not read organization` line (reported to Sentry) appeared during boot in run 1. Needs a decision: retry the cascade once the store opens, or accept and document. Also check that the sidebar refreshes when availability flips true (not tested; the UI was not driven).
- F2 (environment): `platform-core` `file-settings-manager.bench.spec.ts` fails on this machine (not caused by this branch).
- F3 (environment): other agents rebuilt `dist\apps\ptah-electron` while my smoke ran, breaking smoke run 4; running Electron smoke needs an exclusive `dist`.
