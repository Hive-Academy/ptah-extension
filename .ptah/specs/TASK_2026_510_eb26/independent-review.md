# Independent Review — PR 550 (`codex/fix-electron-builder-windows-packaging`)

## Verdict

None found.

## Checks performed

1. **`ROOT` resolution.** Computed with Node directly: old `path.resolve('apps/ptah-electron/scripts', '../../..')` and new `path.resolve('apps/ptah-electron/scripts/lib', '../../../..')` both resolve to `D:\projects\ptah-extension` (`apps/ptah-electron/scripts/lib/native-addon.js:9`). Verified by execution, not just by inspection.

2. **Unified ABI validation.** Built the truth table over `expectedAbi` x `requireAbi` for `probeAddonWithElectron` in `apps/ptah-electron/scripts/lib/native-addon.js:140-147`. With `requireAbi:false` (the option `rebuild-native.js:136` passes), null/undefined `expectedAbi` does not throw and a mismatch does throw — matching the old `rebuild-native.js` behavior (`!= null` gate only). With `requireAbi` defaulting to `true` (the option `verify-packed-native.js`'s wrapper leaves unset), null/undefined `expectedAbi` always throws and a mismatch throws — matching the old `verify-packed-native.js` behavior (`== null` gate). The matching-ABI cell does not throw under either mode, matching both old callers. All eight cells check out.

3. **Exported API.** `rebuild-native.js:184-191` still exports `getPrebuildTarget`, `getElectronRebuildEnv`, `resolveBetterSqliteRuntimeAddon`, `promoteRebuiltAddon`, `probeAddonWithElectron`, `main` — identical set to HEAD. `verify-packed-native.js:324-330` still exports `getPrebuildTarget`, `resolveBetterSqliteRuntimeAddon`, `findPackedFiles`, `probeAddonWithElectron`, `main` — identical set to HEAD. `better-sqlite3-packaging.spec.ts:125` calls `rebuild.probeAddonWithElectron(addon, electronVersion, 149)` with three arguments; the wrapper at `rebuild-native.js:130-143` keeps that exact three-argument signature and forwards to the shared four/five-argument function internally, so the spec's call still works. `packedVerifier.findPackedFiles` and `packedVerifier.resolveBetterSqliteRuntimeAddon` (spec lines 82-111) are unchanged pass-throughs.

4. **`getElectronVersion` behavior change.** The shared version (`native-addon.js:32-37`) throws `'electron not installed in node_modules'` when the package.json is missing; the old `verify-packed-native.js` copy did not have an explicit check but called `fs.readFileSync` directly, which throws an `ENOENT` error on a missing file regardless. Both versions throw synchronously before `main()` can proceed, and both propagate to the same `handleFailure` → `process.exit(1)` path in `verify-packed-native.js:315-322`. This is a message-text change only; it does not alter the pass/fail outcome of the verifier on any input.

5. **`validatePackedAddon`.** Confirmed at `verify-packed-native.js:191-234`: failure strings for the hash-mismatch case (line 208-211) and the Electron-probe-failure case (line 223-226) are character-for-character identical to the pre-refactor inline strings. The success log text at line 228-232 is identical to the old inline `console.log`. Ordering is preserved: the hash check (`hash !== rootHash`) is evaluated and returned on before the Electron probe is ever invoked, exactly as the old `if (hashMatch) { ... probe ... } else { push failure }` did — a hash mismatch still short-circuits and never calls `probeAddonWithElectron`.

6. **Logging.** The shared `probeAddonWithElectron` in `native-addon.js:93-149` contains no `console.log` call. The `[verify] better-sqlite3 loaded under Electron ...` line lives only in the `rebuild-native.js:130-143` wrapper (line 138-141) and is called once, from `main()` (`rebuild-native.js:155`), so it still prints exactly once per rebuild run with the same text. The `verify-packed-native.js:69-81` wrapper does not print that line, matching the old `verify-packed-native.js`'s own `probeAddonWithElectron`, which also never printed it.

7. **Unused or missing requires.** `rebuild-native.js:30-32` (`node:child_process`, `path`, `fs`) are all used (`execFileSync` in `electronRebuildFromSource`; `fs.existsSync`/`fs.copyFileSync` in `promoteRebuiltAddon`; `path.join`/`path.relative` throughout). `verify-packed-native.js:35-38` (`fs`, `os`, `path`, `crypto`) are all used (`fs.existsSync`/`readFileSync` in `main`/`sha256`, `os.tmpdir` in `verifyPackedParcelWatcher`, `crypto` in `sha256`). Neither file leaves a dangling `require('url')`/`pathToFileURL` — that moved into `native-addon.js` along with `getElectronAbi`, which is the only place that still needs it.

8. **`// NOSONAR` and the `path.isAbsolute` guard.** At `native-addon.js:100-107`, `electronExecutable` comes from `require(path.join(ROOT, 'node_modules', 'electron'))`, whose documented export is always the absolute path to the Electron binary — so the guard is real code that runs on every call but, given that contract, cannot fire on a correctly installed `electron` package. It does not risk breaking a working build under any normal state; it would only ever trip if the `electron` npm package's export contract itself changed, which is an environment failure the build should refuse anyway.

9. **`postinstall` safety.** `native-addon.js` requires only `node:fs`, `node:path`, `node:url`, `node:child_process` (lines 3-6) and performs no I/O at module-load time — `ROOT` is a pure `path.resolve` and `ELECTRON_ABI_FALLBACK` is a static object literal; every `fs`/`child_process` call is inside a function body, called later. `rebuild-native.js:33-40` requires this module unconditionally at top level, outside the `main().catch(handleFailure)` try boundary — same structural position as the old top-level `require('child_process')`/`require('fs')`/`require('url')` calls it replaced. Since the new require touches only Node built-ins and no filesystem or child-process calls at load time, it cannot throw during `npm install`, so the `IS_POSTINSTALL` non-fatal path is preserved.

10. **Did the duplication actually go away?** `apps/ptah-electron/scripts/verify-packed-onnx.js` and `apps/ptah-electron/scripts/verify-packed-wasm.js` do not contain copies of `getElectronVersion`, `getElectronAbi`, `getPrebuildTarget`, `resolveBetterSqliteRuntimeAddon`, or `probeAddonWithElectron`. `verify-packed-onnx.js` defines its own unrelated `findPackedManifests`; `verify-packed-wasm.js` defines its own `findAsars`, `normalize`, `verifyAsar` and imports `@electron/asar`. Neither script requires `./lib/native-addon`. No new duplicated block was found against the shared module.
