## Open items

1. **Batch 18 `agent apply`: Blocking, A1.** Single-template apply is not a safe implicit replacement decision. Its `.ptah/agents` target differs from wizard output, but that does not remove the data-loss behavior. The finding is explicitly an existing-path scope observation; the smallest preservation fix is default create-only plus kept output, not a new interactive replacement flow.

2. **Pack completion `changed`: Moderate, A3.** Fetch-cache state and write state are independent. Derive the flag from terminal per-file outcomes; do not change the backend cache flag's meaning to compensate.

3. **Batch 12 outcome decisions:**
   - **After-write origin hook limited to the harness root: acceptable; no separate defect severity.** The handler attaches it only at the harness root (`libs/backend/rpc-handlers/src/lib/handlers/wizard-generation-rpc.handlers.ts:1680`), hashes the written file (`:1161`), and the orchestrator invokes it only for written outcomes (`libs/backend/agent-generation/src/lib/services/orchestrator.service.ts:943`). It is appropriate not to mark opened-folder output as a Library source. Hook errors are logged and do not reverse a successful write (`orchestrator.service.ts:974`). Recommendation: retain this placement; include origin fidelity in the A2 concurrency verification because the hash is read after writing, rather than carried from the exact committed bytes.
   - **Persisted `mode` guards instead of `{decision; baseline}`: acceptable; no separate defect severity.** `libs/backend/agent-generation/src/lib/types/generation-checkpoint.types.ts:213` discriminates modes and requires a baseline for replace-allowed at `:220`; `:286` validates the persisted record. The handler restores guards from the manifest at `libs/backend/rpc-handlers/src/lib/handlers/wizard-generation-rpc.handlers.ts:1677`. Recommendation: retain the representation and regression coverage for rejected baseline-less replace guards and legacy create-only defaults. A field-name deviation alone is not a logic defect.
   - **Retry kept = success; changed-since-preview = unsuccessful with explanation: acceptable; no separate defect severity.** `libs/backend/rpc-handlers/src/lib/handlers/wizard-generation-rpc.handlers.ts:1530` returns the stale-decision error, while `:1548` permits kept as a settled outcome. Keep intentionally makes no write, so successful settlement is coherent. Recommendation: preserve that distinction and expose the settled per-file outcome wherever callers need to distinguish successful retention from successful generation. Do not silently upgrade either outcome to written.

4. **D30: Blocking, A4, not merely Serious.** The decisive case is suppressed refresh failure behind successful file completion, matching the role's Blocking definition of silent failure that misleads a user. Missing grade alone would warrant a lower severity. The smallest complete backend fix must address all three stages: collect/persist facts, build live result facts, and build replay result facts. Merely moving `result` outside `if (request.tabBinding)` leaves the bound-only handler gates intact and does not fix the behavior.

## Five logic questions

1. **How does failure look successful?** A4 loses failed Library-refresh facts on the ordinary wizard path; A3 reports change after an all-kept install. Evidence: handler `:1012`, supervisor `:328`, CLI agent `:207`, with full paths in the findings.
2. **What user action is unexpected?** Reapplying a template overwrites local edits (A1); concurrent pack/wizard writes can defeat create-only (A2).
3. **What input produces a wrong answer rather than an error?** A nonempty `files` array containing only kept outcomes combined with `fromCache:false` produces `changed:true` (A3). A kept retry's success is intentional, not a wrong answer (open item 3).
4. **What if a dependency fails or returns malformed data?** A non-ENOENT target read error is kept by the wizard writer (`libs/backend/agent-generation/src/lib/services/file-writer.service.ts:175`), but apply catches every destination error as absence (A1). Refresh failure can be hidden (A4). Malformed external-manifest behavior and exhaustive RPC-boundary validation remain unverified in this bounded review; no clean verdict is asserted for them.
5. **What is missing from the requirements?** The exact concurrency guarantee between the two write implementations, other hosts, and external editors needs definition. The pack queue is local to its service (`libs/backend/platform-core/src/agent-pack-download.service.ts:279`); it cannot establish a repository-wide atomic replacement contract. A2 identifies a concrete default-create violation independent of that broader decision.
