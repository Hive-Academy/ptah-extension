# Research Report - TASK_2026_UI_DEFECTS

## Question

- Decision this supports: which trustworthy usage source each of OpenCode, Grok/xAI, and Antigravity should surface in Ptah's plan-limits UI.
- Question: can the installed CLIs, local state, local Antigravity server, or documented provider APIs yield percent/window/reset, or at least token/cost usage or a credit balance?
- Bounds: no credentials, email addresses, API keys, refresh tokens, token/cost values, or request bodies were printed. No login/logout/configuration changes were made. A direct paid xAI API request was not manufactured merely to inspect headers.

## Answer

There are usable sources, but they mean different things. Antigravity is the only one here with a live, per-model plan-style reading: its running local language server exposes `remainingFraction` and `resetTime`; Ptah already contains a guarded provisional reader for it. OpenCode v2.0.12 has a supported local `stats --json --cost` command, and Grok Build 1.0.46 has `grok usage <session-id>`; both yield historical local token/cost accounting, not an account-plan percentage, reset window, or credit balance. xAI's documented Management API can read API-team prepaid balance, but that is distinct from the locally authenticated Grok Build account and requires suitable Management-API authorization/team scope.

## Disagreements

- “No official usage API” is too broad for OpenCode: it is true for provider-account plan/balance telemetry, but false for the supported local `opencode stats --json --cost` token/cost history. The UI wording must preserve that distinction.
- Zen documentation says users can set monthly limits and hold credits; the issue tracker says no programmatic balance read exists. Documentation governs: treat monthly limit as configuration and wallet balance as console-only until an official read endpoint appears.
- xAI documents API-team credit balance and RPS/TPM rate limits, while the Grok Build CLI's observed 402 concerns Grok Build balance. They are separate products/credential domains; do not infer one from the other.
- Antigravity is observable through a real local RPC, but the vendor has not published it as a stable public contract. Ptah's source and independent monitors agree on shape/discovery, so it is useful with explicit unofficial provenance, not an API guarantee.

## Local consequences

- `libs/backend/auth-providers/src/lib/quota/readers/antigravity-plan-usage.reader.ts`: keep this as the Antigravity source of truth; it already maps remaining fraction to percent and `resetTime` to `resetsAt`.
- `libs/backend/auth-providers/src/lib/quota/readers/antigravity-ls.provisional.ts`: preserve the provisional boundary; never log CSRF/port command-line values.
- `libs/backend/auth-providers/src/lib/quota/readers/`: OpenCode and Grok need separate **local usage** readers if implemented; neither should implement `PlanLimitWindow.used.kind = 'percent'` from cost alone.
- `.ptah/specs/TASK_2026_UI_DEFECTS/usage-limits-systematic-report.md`: update its OpenCode conclusion from “No usage source” to “no provider-plan source; local token/cost source available.” Its Antigravity service-unavailable result remains accurate for this machine's current no-server state.

## Unknowns

- Whether this installed OpenCode version's cost aggregate double-counts forked or child sessions. Smallest experiment: create a disposable local session and a fork, then compare `opencode stats --json --cost` to an independently summed, read-only DB fixture; do not use production billing data.
- Whether a Grok session ID can be selected safely and stably from the local session index without exposing titles/prompt content. Smallest experiment: use a synthetic session fixture and invoke `grok usage` with its known ID, recording schema only.
- Whether the stored Grok OAuth principal is authorized for xAI Management billing. The local OAuth credential was not printed or exchanged. Smallest experiment: an opt-in user-authorized Management API credential with a test team, requesting only the documented prepaid-balance endpoint and recording field names/status, not values.
- Which response rate-limit headers xAI returns for an actual authorized API request. Official docs establish RPS/TPM/429 but not header contract. Smallest experiment: opt-in zero/low-cost test request through a header-redacting proxy, capturing only header names and status.
- Whether the installed Antigravity IDE version starts its language server when opened and whether its present protocol reply matches the existing schema. Smallest experiment: user starts the IDE normally; run the existing reader once, retain only field names/status, and never persist CSRF tokens.
