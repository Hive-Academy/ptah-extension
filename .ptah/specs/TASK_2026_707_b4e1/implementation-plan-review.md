Verdict: REVISE

1. **Blocking — transition clearing is deferred and can be missed.** `implementation-plan.md:20-22,36-40` puts `update()` only in the draw callback, but `command-scene-renderer.ts:110-139,168-179` can receive multiple `setSnapshot`/`setVoice` transitions before the next frame, or while hidden. A live → idle → live transition can therefore retain old ripples and `lastEmit`; reduced motion can similarly retain state until a draw. **Plan change:** clear the emitter synchronously in both setters when voice state changes or reduced motion becomes true, while keeping expiration and emission in `update()`. Specify that a hidden transition clears immediately; the first visible frame redraws the canvas.

2. **Blocking — listening cadence contradicts itself.** `implementation-plan.md:9,20-22,43-45` describes listening as rising-edge emission, but the shared rule emits repeatedly while the level stays above 0.18; its gap-shrink test also needs repeated emissions. **Plan change:** state explicitly that both listening and speaking emit on an eligible rising edge and then at their state-specific gap while held above threshold. State whether a new rising edge before the minimum gap is suppressed; use one consistent rule. Recommended: suppress it.

3. **Should-fix — initial and resumed emission timing is unspecified.** `implementation-plan.md:11,20-22,27-29` gives no initial value for `lastEmit` or first thinking breath. `command-scene-renderer.ts:168-179,312-326,622-624` resumes with a new rAF timestamp after a potentially long pause; `setSnapshot` itself has no timestamp (`command-scene-renderer.ts:110-133`). **Plan change:** initialize/reset `lastEmit` to negative infinity, emit one thinking breath on its first painted frame, prune expired ripples by age, and emit at most once per `update()` call (no catch-up loop). Use only the supplied rAF timestamp for born/elapsed/gap calculations. This prevents a resume burst; the first resumed frame may emit one ripple if the level is held high.

4. **Should-fix — strength and level normalization need an exact rule.** `implementation-plan.md:15-18,27-29,48-49` promises strength in 0..1 and non-finite levels as zero but does not say how finite values outside 0..1 are handled. `command-scene-status.ts:140-146,162` already clamps level for the ring. **Plan change:** normalize the selected input/output level with `Number.isFinite(level) ? Math.max(0, Math.min(1, level)) : 0` before threshold, gap, and strength calculations; test negative and above-one values as well as NaN/Infinity.

5. **Should-fix — draw position is valid but visibility requires a check.** `command-scene-renderer.ts:409-421,479-525` has a root-glow pass before the later halo/sprite pass, so the proposed insertion point exists. The sprite is blitted over a square extending to `2.2 * node.radius` from its center (`command-scene-renderer.ts:510-525`); a new ripple starts at `radius + 18` (`implementation-plan.md:15-17`). For the spec root radius 30 (`command-scene-renderer.spec.ts:27-31`), that starts at 48 inside the sprite's 66-pixel half-width. Actual coverage depends on sprite alpha, which these files do not establish. **Plan change:** retain the requested order, but make the Electron dark/light check verify visible inner and outer arcs; if the sprite obscures the inner arc, move only ripple drawing after the sprite and before the root rim/voice ring, or adjust its start radius. Record the chosen placement in the plan.

6. **Note — frame-cap claim is qualified by reduced motion.** `command-scene-renderer.ts:213-225,312-326,622-624` shows live voice states bypass the 33 ms cap while `active` is true. Under reduced motion, `active` is false, so a paint occurs only after invalidation (`command-scene-renderer.ts:110-139,176-179`), as expected when ripples are disabled. Hidden mode cancels the frame and forces one on resume (`command-scene-renderer.ts:168-179`). **Plan change:** qualify the sentence at `implementation-plan.md:41` and `context.md:33-37` as “live voice states paint every frame when reduced motion is off”; no frame-cap change is needed. A stale last canvas frame can remain while hidden, but the resume paint clears it (`command-scene-renderer.ts:335-338`).

7. **Note — references and existing assertions.** The removal range `command-scene-status.ts:161-179` is exact; `drawVoiceRing` keeps its static ring at `command-scene-status.ts:119-160`. `command-scene-renderer.ts:195-211` contains `destroy()`, and the root draw calls are at `:409-421` and `:479-559`. The renderer is 625 lines, rather than the 624 stated in `context.md:38`. Existing tests assert frame scheduling (`command-scene-renderer.spec.ts:149-176,424-434`), reduced-motion ring/halo (`:543-564,747-760`), and general arc/ink behavior (`:627-652`), but none asserts the removed speaking loop's two time-looped arcs. **Plan change:** correct the line count and keep the planned new renderer-level ripple test; no existing assertion needs deletion for the loop removal.

## Decisions

- The rAF timestamp is the correct time base: the renderer passes it to existing animation code (`command-scene-renderer.ts:343,461,558`) and uses `performance.now()` only for render-cost measurement (`:327,618`). No clock conversion is needed.
- The at-most-four rule at `implementation-plan.md:17-18` is implementable: prune expired entries first, append at most one new ripple per update, then drop the oldest if length exceeds four. This also makes long hidden pauses harmless.
- Keep ripple inks from the current `snapshot.inks` as R7 requires (`context.md:40-42`); captured ink on birth gives each ripple stable color during its 1400 ms life. A later theme change may briefly show old-color ripples unless the emitter is cleared on theme change; clear it in `setSnapshot` when `theme` changes.
