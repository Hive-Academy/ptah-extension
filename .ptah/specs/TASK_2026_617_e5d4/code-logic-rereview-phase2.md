## New findings from the fix round

- N1 (Minor) `grok-cli.adapter.ts` row regex `^(?:[*\->•]\s*)?(\S+)`: under `Available models:` any indented line now yields its first
  token if it looks like an id, so an indented footer such as `  Run grok models --help` would add a bogus model `Run` to the
  picker. Real output has only been observed with one row. Fix: after the first token require either end of line, ` (`, or
  whitespace plus `-`/`:`/`—`, or stop the list at the first blank line after at least one row.
- N2 (Minor) `settings.fixtures.ts` `CLI_MODELS_FIXTURE` (`:528-539`) has no `grok` key although `AgentListCliModelsResult.grok` is required,
  so the Grok row's model popover in the e2e/QA harness shows an empty list. Add `grok: [{ id: 'grok-4.7', name: 'Grok 4.7' }]`. The fixture is untyped, so
  the compiler does not catch it.
- N3 (Minor, accepted) The effort is now forwarded raw from `options.reasoningEffort`; correctness depends on the single caller
  (`agent-process-manager`) passing the already-mapped value. Any other caller passing e.g. `minimal` gets an info, not a
  failure, so the failure mode is benign.
- N4 (Minor, accepted) Pi's `--list-models` probe now swallows a synchronous `spawnCli` refusal (it used to propagate); this is
  consistent with "never throws" and with Pi's caller treating `undefined` as an empty list.

## `cli-stdout-probe.ts`

Behaviour is identical to the two inlined copies, plus: synchronous start refusal is caught and logged; `error` is logged. Logged
fields are `command` and `error.message` only. Timer is cleared on close and error; on timeout the child is killed and the
promise resolves, and a later `close` resolves a settled promise harmlessly (timer already fired, `clearTimeout` of a fired timer
is a no-op). Module placement beside `cli-adapter.utils.ts` is justified by the spec mocking story and works.
