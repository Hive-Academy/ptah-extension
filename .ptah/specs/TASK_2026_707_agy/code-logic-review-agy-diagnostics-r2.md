## New defects

**N1 — Low — ERROR-step suppression is asymmetric with the ERROR-step buffer.** `antigravity-cli.adapter.ts:743` buffers a step when `step.state === 'ERROR' || step.status === 'ERROR'`, but `adapter:1124` suppresses segments only when `step.state === 'ERROR'`. A step carrying `status: 'ERROR'` without `state: 'ERROR'` would be captured as error evidence and still emit the phantom `tool-call` D8 targeted. No observed `agy` emission puts a `status` field on steps (schema notes `adapter:19-26`; every fixture in the spec uses `state`), so this is latent, not live. Fix: accept `|| step.status === 'ERROR'` at `adapter:1124` and add one absence assertion for the ERROR step already written at `spec:982-989`.

**N2 — Low — a crash with a nonzero exit and no result event still double-reports the bare exit code.** `antigravity-cli.adapter.ts:928-930` (close detail "Antigravity CLI process exited with code N") and `:936-939` (generic "Antigravity CLI exited with code N") both fire when `exitCode !== 0 && !failedResult && !aborted` — two near-identical error segments for one crash. The D7 fix removed the duplicate only for the failed-result case. `spec:1123-1139` tolerates it (`errors.length >= 1`). The generic segment is now fully subsumed by the close detail (every input satisfying `:935` also satisfies `:927`); remove it or gate it to fire only where the detail did not.

## Five logic questions

1. **How does this fail silently?** The remaining silent-loss spots are the declared D6 remainders: captured AGY_ERROR lines truncated at 1 KiB (`diagnostics:30`) — the full redacted line still reaches the transcript — and errorSteps payloads bounded in count but not size (`adapter:744-746`), practically capped by the 1 MiB line buffer (`adapter:833-843`). N1 is a silent contradiction on an unobserved field (buffered as error evidence, emitted as a tool-call).
2. **What user action produces unexpected behaviour?** Continuation after a failed turn is now refused (`adapter:856-858`, `spec:967`) — intended, and it is what makes the per-turn reset sound. Abort during a failed turn still settles 1 (abort → close with signal → `adapter:920` maps signal to 1; the already-settled turn is unaffected; `spec:1148-1158` covers abort).
3. **What input data produces a wrong answer rather than an error?** Both round-1 wrong-answer inputs are closed: `error: null` no longer flips SUCCESS to exit 1 (`spec:1037`), and a trailing malformed result no longer resolves 0 (`spec:1119`). The ERROR-then-SUCCESS same-turn anomaly now yields `done` 1 with no stale log (`spec:1049-1053`).
4. **What happens when a dependency fails, times out, or returns a wrong shape?** Child `'error'` → turn 1 + adapter error segment + `done` 1 (`adapter:950-958`, unchanged); a throwing logger can no longer hang the turn (D10); a never-exiting child after a failed result no longer hangs the consumer (D3) but defers close-time evidence and the MCP restore indefinitely (self-healing, `adapter:662-664`); any `error` JSON shape is accepted (D1).
5. **What is missing that the requirements never mentioned?** No ERROR-state handling for non-tool steps (an ERROR `agent_response` still emits its text delta — reasonable, it is model output); ordinary non-AGY_ERROR stderr remains unredacted in the passthrough (frozen by round-1 verify item 6); no test asserts the absence of the phantom tool-call (N1).

## Failure modes (remaining)

1. Child never exits after a failed result → close detail, logger diagnostics and the MCP entry restore wait for exit/abort; the turn itself settles 1 (bounded, abortable).
2. AGY_ERROR line > 8 KiB before its newline → only the head is captured (`adapter:893`), then truncated to 1 KiB (`diagnostics:30`); the tail is absent from the log but present in the transcript.
3. Hypothetical `status: 'ERROR'` step → phantom tool-call despite the buffer (N1).
4. Crash with nonzero exit and no result event → two near-duplicate exit-code error segments (N2).
5. `logger.warn` throwing at `adapter:943` skips the failure log at `:946` (post-resolve; no hang).
6. Five large ERROR-step payloads retained in memory until close (declared D6 remainder; practically bounded by the 1 MiB line cap).

## Decisions

- **D6 remainder judged acceptable to defer.** Options: fix now (size-cap errorSteps payloads, raise the captured-line cap) vs defer. Evidence: the payload path is practically bounded by the 1 MiB line buffer for chunked delivery; the 1 KiB truncation loses log evidence that the transcript still carries in full; the fix report declares both out of scope with rationale (`batch-agy-diagnostics-fix1.md:38`) and round 1 rated D6 Low. Deferral is reversible and should be tracked as future work.
- **D8's suppression accepted on code trace, with a recommended one-line hardening (N1).** The code path is trivial and the fixture at `spec:982-989` exercises it without asserting the absence; adding the `status` symmetry plus one absence assertion closes both holes. Not blocking.
- **N2 not blocking:** cosmetic segment duplication in the crash-without-result path; the generic segment is fully subsumed by the close detail and can be removed in a follow-up.
- **`closeAfterSettledTurn` continuation race ruled pre-existing and out of scope** — the git diff shows it as unchanged HEAD context; this fix neither introduced nor worsened it.
- **`Logger.warn` verified by reading `logger.ts:145`** in lieu of the post-fix scoped typecheck, which the fix report states was unavailable after a service timeout; the rest of the new code introduces no untypechecked constructs (all imports resolve, `formatAgyFailure`'s parameter type accepts the zod-inferred `AgyResult`).
- **No verification commands run** per the task instruction; the implementer's 56/56 jest tail and round-1's orchestrator typecheck (pre-fix code only) were taken as given evidence.
- **Native read/grep used instead of ptah exploration tools** — not in this lane's exposed catalog; same environment as round 1.
