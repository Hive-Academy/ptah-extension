## Findings

1. **Moderate (test gap):** The dispatcher specs mock `proposeConfig` to reject with `Object.assign(new Error, {name})`. They never run the real `HarnessConfigUpdatesError` or `HarnessProposalNoSessionError` classes (non-exported, in the builder) through the dispatcher. If a class `name` is renamed, both sides drift silently. The builder spec checks only `/no SDK session/`, not `.name`. Minimal fix: add one builder-spec assertion on `error.name === 'HarnessConfigUpdatesError'` and `'HarnessProposalNoSessionError'`. Alternatively, export shared name constants.
2. **Minor:** The `ZodError` branch assumes the name. A thrown zod 4 error may have a different `name` (for example `$ZodError`). That error is the store's invalid session id error, which the code assumes arrives as `ZodError`. I did not verify this against the store. If the name differs, the error falls into the generic message, which is safe and still leak-free, but less informative. Minimal fix: also match `'$ZodError'`, or confirm against the store's thrown type with a spec.
3. **Minor:** The "proposal store unavailable" error (`ptah-api-builder.service.ts:880`) is a plain `Error` with no code. The dispatcher turns it into the generic "Retry if the session and storage are available." The specific text is lost, and nothing is leaked. The behaviour is acceptable.
4. **Minor (test):** No dispatcher spec covers the `HARNESS_PROPOSAL_NO_WORKSPACE` code branch, the fs `code` branch or the Zod branch. Only 3 of 7 branches are tested.
5. **Minor (out of scope):** The `getLaneLimits` change in `ptah-api-builder.service.ts` is a formatting-only reflow. The webview handler ignores `sessionId`, so a proposal for session A applies to whichever harness workflow is open. Filtering by session id is for a later batch and is not required here.
6. **Minor:** `broadcast?.` is used where `broadcast` is a required dep, which is harmless. A missing webview manager only debug-logs, but the proposal is already persisted, so no data is lost.

No Critical or Serious defects found. No TODOs or stubs in the diff.
