## New findings

1. **Moderate — freshness `warn` loses the cause it was added to expose.** `analysis-freshness.service.ts:81-87` passes `{ error, analysisRoot }` as the context object. `Logger.formatLogArg` (`libs/backend/vscode-core/src/logging/logger.ts:19-37`) special-cases a top-level `Error` only; a nested `Error` goes through `JSON.stringify` and serialises to `{}`. So the log still reads "Could not determine analysis freshness" with no message or stack, which was the original S2 complaint. Sibling usage: `analysis-storage.service.ts:761` passes `error instanceof Error ? error.message : String(error)`; `analysis-run-checkpoint.ts:66-69` passes the `Error` as the second argument. Fix: use one of those shapes (`error instanceof Error ? error : new Error(String(error))` as the second argument, with the root in the message, or `error.message` in the context).
2. **Minor — hard-coded `'.ptah/analysis'` fallback** at `analysis-freshness.service.ts:88` while the same method already computed `analysisRoot` through `storage.getAnalysisDir`. Derive it with `relativeDir(analysisRoot)` so the path cannot drift from the storage layout.
3. **Minor — `RunDirVariant` is spelled out again.** `analysis-run-checkpoint.ts:78` declares `'primary' | 'legacy-fallback'` inline although `RunDirVariant` is exported from `analysis-storage.service.ts:50` for exactly this. Import the type.
4. **Minor — the generic hashing helpers live in a file named `analysis-fingerprint.ts`.** `sha256Hex` and `hashFileOrNull` (`:94-111`) are not fingerprint concerns; callers import them under a name that suggests otherwise (`multi-phase-analysis.service.ts` imports only the two hash helpers). Cost is discoverability only; a rename to `analysis-hash.ts` (the name suggested in the original review) would read better. Not blocking.
5. **Minor — duplicated message literal.** `'Phase finished without an SDK session id'` appears in `completeOrFailPhase` and in the final-failure branch of `multi-phase-analysis.service.ts` (the hunk at `outcome.resultReceived && outcome.sessionId === null`). Two copies can drift; hoist to a module constant. (The `try` in `completeOrFailPhase` also wraps `markCompleted` persistence, so a persist failure becomes a `markFailed` attempt; behaviour question for code-logic-reviewer, not raised here.)

Known Minor items not re-raised: unreachable `primary && !primaryResumable && fallbackResumable` branch, doubled resumable test, `ensureSlugDir` with no production caller. M5 out of scope (FU-12).
