## New finding

1. **Blocking — a whitespace-only edit during the begin RPC can be erased.** `session-budget-actions.service.ts:351-353` trims the queued content before sending it. On a captured response, :368-372 trims the current content again and clears the entire queue when those trimmed values match. **Scenario:** the queued text is `A`; the user clicks Continue, then changes it to `A  ` (two Markdown hard-break spaces) before the RPC resolves. The backend owns `A` and returns `draftCaptured: true` (`session-handover-coordinator.service.ts:263,424-431`); both frontend comparisons equal `A`, so it clears the newly edited `A  `. The successor receives only `A` (`session-handover-coordinator.service.ts:568-580`). The current race spec edits to a different trimmed value and therefore misses this case (`session-budget-actions.service.spec.ts:363-374`). **Fix:** save the original raw `queuedContent` alongside the trimmed RPC value; clear only when the current raw content is exactly the original raw content. Add a pending-RPC test where only whitespace changes. Keep the operation-carried flag tied to `draftCaptured`, since it describes the captured earlier text.
