## Verdict

**REVISE — 5/10.** The plan identifies the budget automation and provides a workable wait with an explicit exit, but two user-visible paths still violate the intended control over handover and queued text. This is below a sound 7–8 because both occur on ordinary actions; it is above 3–4 because the main budget paths, contracts, and scoped verification are mapped.

## Findings

1. **Blocking — An agent can still initiate a handover without a user action.** D22 requires every handover to be user-authorized (`decisions.md:299-311`). The plan explicitly retains the agent's successor call and makes `begin()` set `userConfirmed` for that caller (`implementation-plan-v2-user-authorized.md:16-18, 49-53, 402-406`). The tool calls `handoverCoordinator.begin(activeId, 'successor', ...)` directly (`libs/backend/cli-agent-runtime/src/lib/session-children/session-spawner.service.ts:289-310`). Tool permission does not constitute the user's handover click. A model-initiated tool call can therefore start or queue a rotation, contradicting D22 even after every `budget-auto` path is deleted. Refuse successor mode until a distinct user authorization exists, or route it through an explicit user confirmation. Add the CLI runtime source and a refusal spec to the affected files and checks.

2. **Serious — Cancel can send a composer draft instead of restoring it as a draft.** The plan moves `queuedInput` from the composer into `op.inputs`, clears the composer on accepted begin, and promises that Cancel restores it (`implementation-plan-v2-user-authorized.md:119, 174-176, 190-202, 260-264, 280-281`). The current source is `tab.queuedContent` (`libs/frontend/chat/src/lib/services/session-budget-actions.service.ts:228-245`). Coordinator `restore()` calls `runtime.restoreInputs` (`libs/backend/agent-sdk/src/lib/helpers/session-handoff/session-handover-coordinator.service.ts:759-774`), whose implementation prepends inputs to the source message queue and wakes an idle pump (`libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-registry.service.ts:560-573`). Thus Cancel during a wait can turn unsent composer text into a message that runs on the source. Define separate restoration for captured composer text back to the composer, or explicitly obtain user agreement that Cancel will queue it for sending. Cover Cancel before and after the turn ends, including the blocking limit.

3. **Moderate — The live display can clear on an ignored estimate unless the return contract is specified.** F1 clears `liveBudgetStage` whenever a live payload lacks the optional field (`implementation-plan-v2-user-authorized.md:270-280`), while B3 says `observeLive` returns a stage from the live figure (`:236-247`). Today `observeLive` ignores older revisions and incompatible measures without clearing the retained live figure (`libs/backend/agent-sdk/src/lib/helpers/session-budget/session-budget.service.ts:285-310`). Specify that these early returns emit the retained valid stage, or that the adapter omits an update which the frontend does not interpret as a clear. Otherwise the banner can disappear or flicker even though the budget service still considers the earlier estimate active. Clear explicitly at the terminal/result and when settings disable the budget.

The automatic-path inventory matches the searched production entry points: terminal and result arming (`session-lifecycle-manager.ts:520-548`, `sdk-agent-adapter.ts:1823-1834`), the single budget notice post (`session-budget.service.ts:1162-1165`), and the two `begin` callers (`session-handover-rpc.handlers.ts:92-104`, `session-spawner.service.ts:301-306`). P1–P8 remove the budget starts and notice; P9 is a parked blocking-limit operation. The wait has Cancel and Continue now anyway (`implementation-plan-v2-user-authorized.md:119-132`), and Stop is explicitly addressed (`:177-179, 207-209`). A lane that finishes without another terminal may leave counts stale, but the explicit exit prevents a trap (`:410-413`). The changed contracts and producer/consumer paths are named (`:249-291, 294-303`); batch file ownership is disjoint (`:363-377`); proposed Jest and Nx commands are project scoped and capped (`:378-393`). No checks were run, as requested.

## Lane-introduced constraints

- **Wrap-up only during an active turn, with an existing budget entry and stage at handoff or limit** (`implementation-plan-v2-user-authorized.md:140-149`): reasonable because a notice posted while idle would land on an unrelated turn, but D22 did not specify this refusal. Keep the button disabled while idle and show the returned reason.
- **One wrap-up request per stage rank per turn** (`:147-149`): reasonable duplicate protection; D22 did not set a frequency limit. The UI and backend must agree on the reset point.
- **Lane-provider errors count as zero lanes** (`:151-157, 213-215`): this is inherited behavior but weakens the user's requested wait when lane status is unavailable. Report the unknown count and require Continue now anyway, or justify this explicit exception in the product copy.
- **No timer or automatic wait escalation** (`:154-157, 410-413`): consistent with D22's removal of the 15-minute escalation, provided the two exit buttons remain available.
- **Composer sends during a wait go to the source** (`:412-413`): a product behavior added by the plan. The proposed banner copy makes it visible; it needs a focused interaction check.

## Q1 recommendation

Refuse `ptah_session_start` successor mode unless the user has explicitly authorized that specific handover. For this addendum, a clear refusal in `SessionSpawnerService.startSuccessor` plus a focused spec is the smallest implementation. An agent tool call under general tool permissions is not the D22 user click. Keep non-successor child-session modes untouched.

## Decisions

- **REVISE** before Gate 2: resolve Findings 1 and 2, and make the live-stage return/clear semantics explicit.
- Retain the plan's budget-auto removals, blocking-limit park, visible work wait, Stop handling, and project-scoped verification after those changes.
