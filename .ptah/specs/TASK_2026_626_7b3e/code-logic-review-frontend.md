# Frontend code logic review — TASK_2026_626_7b3e

## Verdict: NEEDS_FIXES

**Score: 7/10.** The main live path is wired and its ordering and side-effect guards are explicit, but a real multi-tab background-workspace path misses updates. This is a sound implementation with a bounded routing gap (7–8), rather than a 5–6 implementation with failures on the ordinary single-tab path. No source was edited. Jest, Nx, and builds were not run as requested; the batch reports describe their own verification, but are not independent execution evidence for this review.

## Findings

1. **Moderate — live updates reach only one background tab for a session.** `SessionStatsAggregatorService.tabsForSession` first uses the active-workspace plural lookup and, when empty, wraps a *singular* cross-workspace lookup in a one-element array (`libs/frontend/chat/src/lib/services/chat-store/session-stats-aggregator.service.ts:243-248`). The underlying partition lookup uses `tabSet.tabs.find(...)`, so it returns only the first matching background tab (`libs/frontend/chat-state/src/lib/tab-workspace-partition.service.ts:294-300`). The active-workspace path intentionally supports multiple bound tabs (`libs/frontend/chat-state/src/lib/tab-manager.service.ts:575-580`), and the live handler updates only returned tabs (`libs/frontend/chat/src/lib/services/chat-store/session-stats-aggregator.service.ts:222-230`). If two tabs for the same session are in a background workspace, only one receives the provisional estimate or authoritative settle; the other can retain stale figures or an estimate marker after Stop. **Required fix:** resolve every matching background tab for the session, and cover a two-tab background workspace where both tabs receive a live estimate and settle. The existing authoritative `session:stats` path shares this helper (`session-stats-aggregator.service.ts:129`), so fix its routing with the same change.

## Five logic questions

1. **Silent success:** the live handler returns normally after updating only the first background tab (`session-stats-aggregator.service.ts:222-230,243-248`); the missing tab has no warning or error. This is finding 1.
2. **User action:** opening the same session in multiple tabs, then switching workspaces during a turn, can leave one tab's stats or estimate marker stale (`tab-manager.service.ts:575-580`; `tab-workspace-partition.service.ts:294-300`). This is finding 1.
3. **Wrong-answer input:** a lower-revision live estimate after an authoritative snapshot is rejected by `SessionStatsRevisionFloor.admit` (`libs/frontend/chat-state/src/lib/session-stats-snapshot.ts:81-88`) before either the snapshot or context is patched (`libs/frontend/chat-state/src/lib/tab-manager.service.ts:2283-2297`). An equal-revision authoritative live snapshot with stray context does not change the context because the parser strips it and the tab manager also gates context on `provisional === true` (`libs/shared/src/lib/types/messages/session-stats-live.ts:92-104`; `tab-manager.service.ts:2288-2296`). I found no wrong numeric answer on this path within the declared revision contract.
4. **Failed or malformed dependency:** malformed live envelopes are rejected with one warning by the message handler (`libs/frontend/chat/src/lib/services/chat-message-handler.service.ts:719-730`); malformed deep snapshots are rejected with one warning by the aggregator (`session-stats-aggregator.service.ts:303-319`). An unknown session with no tab or surface is dropped without a throw (`session-stats-aggregator.service.ts:222-226`). A background lookup that returns just one of several tabs is the unreported dependency-shape failure in finding 1.
5. **Missing requirement:** the plan covers a single background tab but does not specify multi-tab background routing (`.ptah/specs/TASK_2026_626_7b3e/implementation-plan.md:873-961`); the active plural lookup shows that multiple tabs are a supported state (`tab-manager.service.ts:575-580`). This is finding 1.
