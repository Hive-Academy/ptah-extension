## Architecture decision

- **Chosen:** `sessions.sqlite` owns an append/upsert usage ledger of accepted turn/model contributions plus a materialized `session_stats` row. The same backend repository executes indexed SQL aggregation for the existing `analytics:spendSummary` response and session detail reads. Write each accepted turn incrementally in one transaction and finalize asynchronously on true end. Restart reconciliation processes unfinished rows.
- **Rationale:** the current stats owner already distinguishes cumulative results from turn deltas, and `sessions.sqlite` is registered early in Electron and CLI. Close-only writes lose all data on a crash; storing only a session aggregate loses per-day/model facts. A separate analytics DB introduces unnecessary cross-database joins and migration work.
- **Rejected:** JSONL as primary source (reported cost is often absent and load is slow); Angular aggregation (duplicates backend logic); one write per streamed token/frame (high write volume and repeated cumulative counters); universal immediate provider support (some adapters have no reliable per-turn usage).
- **Assumptions:** sessions may continue after a Stop; verify in lifecycle tests. Current branch lacks a VS Code host root; support is contingent on locating and wiring its composition root in the target branch. External Codex/OpenCode/Grok source files may not correspond to Ptah sessions; preserve their existing source adapters until parity is measured.
- **Effect on existing code:** replace the dashboard JSONL scan and fact aggregation path; keep JSONL reader for history/backfill and retain live chat display. Preserve old RPC during rollout, redirecting to the ledger.

## Component specifications

### 1. Session usage schema and repository

- **Purpose:** durable, queryable source of truth for captured usage.
- **Contract:** `session_stats(session_id PK, host, workspace_key, provider_id, started_at_ms, last_usage_at_ms, finalized_at_ms NULL, status, input_tokens, output_tokens, cache_read_tokens, cache_write_tokens, known_cost_micro_usd, has_unpriced, source, pricing_version NULL, revision, updated_at_ms)`; `session_usage_turns(session_id, producer, run_id, turn_id, model_id, event_key, occurred_at_ms, counters, known_cost_micro_usd NULL, cost_authority, source, pricing_version NULL, PRIMARY KEY(session_id,producer,event_key,model_id))`. Optional nullable `parent_session_id`/`subagent_id` when identity exists. Use integer micro-USD to avoid floating accumulation, safe integer checks, and an explicit unknown flag; `source` is `live|jsonl-backfill|estimated`, independently of `cost_authority` (`provider-reported|model-priced|unpriced`). Do not sum `estimated` into billed cost when a live row exists. Index `(workspace_key,occurred_at_ms,provider_id,model_id)` and `(session_id,occurred_at_ms)`; referential link to sessions only if existing session creation order can guarantee it, otherwise reconcile orphan usage.

### 3. Finalizer and one-time backfill

- **Purpose:** seal completed sessions and recover historical/incomplete records.
- **Contract:** true session end queues a database-backed `finalize_pending` state; startup scans unfinished rows and sessions whose last activity exceeds a documented idle threshold. Background worker is bounded/concurrency-limited, idempotent, and cancels/clears pending finalization on resumed activity. Finalization verifies stored revision, marks finalized only after reconciliation; no blanket closing on Stop or compaction. Backfill walks existing sessions in pages after `SessionStoreGate.whenReady()`, reads JSONL through `SessionStatsReaderService` once per session, writes `jsonl-backfill` rows only where no live event key exists, records cursor/receipt and source quality, and never replaces higher-quality live values. Missing JSONL yields partial/unknown, not zero. Re-run safely after interruption; cap time and memory per pass.

## Integration architecture

- **Flow:** provider result/usage checkpoint → normalize and validate → idempotent transaction in session usage turns → update session_stats → true-end pending finalization → bounded worker seals/reconciles → SQL grouped summary → existing RPC → dashboard presentation.
- **Persistence:** `sessions.sqlite` owns lifetime; receipt/cursor makes backfill resumable. Keep provider-reported dollars and rate-card estimates distinct, with pricing version/as-of and no retrospective repricing of live costs. A nullable cost plus `has_unpriced` preserves lower-bound semantics.
- **Trust:** Zod at provider, IPC/RPC and repository boundaries; authorize workspace before SQL; parameterized statements only. No paths or secrets in logs.
- **Failure/rollback:** retain existing JSONL reader during rollout, but never silently overwrite live rows. SQLite migration failure leaves prior schema untouched; old builds remain able to open their prior `sessions.sqlite` only where the existing migration downgrade rule permits, so release rollback needs DB backup/forward migration plan.
- **Observability:** injected Logger records failed writes/backfill counts and source-quality counts without transcript content; expose partial source status through current summary contract.

## Architecture-level quality requirements

- **Functional:** accepted live usage survives restart; duplicate and reordered events do not inflate totals; exact reported dollars win over estimates; partial/unpriced values remain visible; one-time backfill never erases live data.
- **Performance:** dashboard summary performs indexed SQLite queries only; no JSONL scan on normal load. Backfill uses bounded pages; streaming performs at most one transaction per accepted turn/checkpoint, not per token.
- **Security:** workspace isolation enforced before query; static parameterized SQL; no untrusted raw errors in UI.
- **Maintainability:** preserve public index imports and acyclic Nx graph; host-neutral contracts only; no new host imports into libs; small repository/worker/normalizer units.
- **Testability:** migration/restart, dedup/revision, SQL correctness, lifecycle, RPC authorization and frontend rendering fixtures.
