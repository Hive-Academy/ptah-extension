## New defects

1. **Moderate — a SecretStorage read failure prevents the CLI default even when its login is usable.** `createAuthCredentialProbe` awaits SecretStorage before checking either the environment key or the connected login (`libs/backend/auth-providers/src/lib/auth/active-provider-resolver.ts:41-49`); a rejection exits `resolveActiveAuthWithDefault` before it can select a method (`active-provider-resolver.ts:116-125`). `AuthSecretsService.getCredential` propagates its storage read rejection (`libs/backend/vscode-core/src/services/auth-secrets.service.ts:171-180`). With no configured method, a connected CLI login and unavailable SecretStorage, adapter initialization now fails (`libs/backend/agent-sdk/src/lib/sdk-agent-adapter.ts:678-679,783-797`), although the CLI strategy itself only needs a CLI health check (`libs/backend/auth-providers/src/lib/auth/strategies/cli.strategy.ts:41-79`). Existing probe specs cover successful reads (`active-provider-resolver.spec.ts:156-176`), not a rejected one.
2. **Moderate — a notification exception turns committed recovery into a failed list/admission.** `reclaimAbandonedOperations` commits first, then invokes listener callbacks without isolation (`libs/backend/auth-providers/src/lib/accounts/provider-account.store.ts:708-711`). The new actions-service subscription calls `emit`, which invokes every external listener without a catch (`provider-account-actions.service.ts:225-228,686-697`). For example, the RPC listener reaches workspace enumeration and notification outside its snapshot-read catch (`libs/backend/rpc-handlers/src/lib/handlers/provider-account-rpc.handlers.ts:601-619`). If either dependency throws, a plain `list()` fails after the profile was already restored (`provider-account.service.ts:257-259`); admission calls through the same reclaim method can fail after this committed side effect (`provider-account.store.ts:424-429,519-522`). The new listener spec checks successful callbacks and unsubscribe (`provider-account.store.spec.ts:984-1005`), not a throwing callback.

## Five logic questions

1. **Silent failure:** a failed or unfinished console PID persistence leaves a null child PID that later looks reclaimable after host death (defect 1).
2. **User action:** reopening the account list now restores a crashed pending profile (defect 6 closed), but a failing state-change listener can make that read appear to fail after the restore (new defect 2).
3. **Wrong answer from input:** missing or unknown auth method with a connected login now selects CLI in both initialization and workspace resolution; explicit API key and stored/environment key stay on API key (defect 2 closed).
4. **Dependency failure/timeout:** SecretStorage rejection aborts default selection (new defect 1); an in-flight named admission is drained unless Electron's two-second quit deadline expires (defect 3, bounded behavior).
5. **Missing requirement:** the crash proof for a console whose PID was never durably recorded still needs an unresolved persisted state or an equivalent guard; a best-effort kill cannot prove the child gone across host death (defect 1).
