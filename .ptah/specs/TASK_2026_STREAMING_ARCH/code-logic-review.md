# Code Logic Review - Phase 6 zoneless audit

Verdict: **APPROVED** (with one evidence caveat and two documentation nits; no runtime defect found)

Scope: all 19 audit rows opened at the cited files; targeted grep of `libs/frontend/**` component/directive/service files for `runOutsideAngular`, `NgZone`, `setTimeout(`, `setInterval(`, `requestAnimationFrame(`, `ResizeObserver`, `MutationObserver`, `addEventListener(`. About 45 hits examined in code (the grep output was truncated by the tool, so not every hit was opened). Read-only; nothing run.

## Defects (plain field + async callback + template read)

None found. Defect count: 0.

Every examined async callback either writes a signal (`.set`/`.update`), emits an `output()` (the parent template listener marks its view dirty), or touches only DOM and private non-template fields. Template-visible state in all sampled components is `signal`/`computed`/`input`.

## Findings that are not defects (caveats)

1. `libs/frontend/core/src/lib/services/message-router.service.ts:217-224,242` - the audit row says "Safe" for the non-signal path, but that path uses `ngZone.run(...)`. Under zoneless, `NgZone.run` does not notify the scheduler. Safety therefore depends entirely on every handler for non-stream messages writing signals. The report asserts this but does not enumerate the 31 handler files (grep `handledMessageTypes =`). I spot-checked the services that appeared in my sampling (`plan-limits.store`, `back-office-activity.service`, `boot-status.service`, `editor-launcher.service`) and they use signals. Residual risk: not exhaustive. Minimal fix if a handler is found: write a signal, or `inject(ChangeDetectorRef).markForCheck()` for plain fields.
2. `libs/frontend/chat-ui/src/lib/atoms/streaming-quotes.component.ts:98-146` - the template is bypassed (`textContent` written directly from an outside-zone interval). Correct under zoneless because it never depends on CD. Fragile only if someone later adds a template binding for this text.
3. Doc nit: audit rows for `compact-session-activity.component.ts` and `tab-manager.service.ts` cite no line for the verdict reason ("async activity handling"), so they are hard to re-verify. They are correct: `compact-session-activity.component.ts:924,888,961` writes signals or a private field (`isUserScrolledUp`, never read by the template); `tab-manager.service.ts:2618-2638` timer calls `_doSaveTabState` (persistence, no template field).
