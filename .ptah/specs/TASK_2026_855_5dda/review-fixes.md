# Review fixes — TASK_2026_855_5dda

Findings from `code-logic-review.md` and `code-style-review.md`, and what was done with each.

| Finding | Outcome |
| --- | --- |
| Logic S1: silent fallback to the main tree when a session row is missing | Fixed. `SessionWorktreeLookup.worktreeFor()` stays the single integration point and now returns `{ known, worktreePath }`: a loaded row (with or without a worktree) or a tab with no backend session is `known`, and a session id without a loaded row is `known: false`. `GitSessionScopeCandidate.organizationResolved` carries it to git-ui. `GitDockScopeStore` then produces a scope with `unresolved: true` and `root: null`. That scope does not retarget the services, sends no lease, and closes the new `GitDockMutationGate`. `SourceControlService` (stage/unstage/discard/commit/abort/continue) and `ReviewDiffService.applyHunks` refuse while the gate is closed, without an RPC. The scope header shows "worktree not loaded · read-only". Read-only callers (board card, inspector) use `.worktreePath`. |
| Logic S2: a refused root reads "No workspace folder open" | Fixed. New code `GIT_ROOT_UNAVAILABLE` in `rpc-error-codes.types.ts`. `GitRootResolver.resolve()` throws `RpcUserError('This worktree is no longer available.', 'GIT_ROOT_UNAVAILABLE')` for a refused named root. "No workspace folder open" now means only that no folder is open. The message is `GIT_ROOT_UNAVAILABLE_MESSAGE` in shared `git-operation.constants.ts`. `rpcCall` forwards only the message, so the webview matches it the way `isRpcTimeout` matches its prefix. `GitStatusService` maps it to the new status reason `root-unavailable` ("this worktree is no longer available"). `git:watchRoots` catches the code and reports the root as `rejected`. |
| Logic M1: per-call probe cost | Fixed (this revises D17 for reads only). Read-only methods (`READ_ONLY_GIT_METHODS` allowlist) share the worktree probe while it is in flight and keep a confirmation for 1.5 s (`READ_PROBE_TTL_MS`). A refusal is never cached. Any method not on the list counts as a write and re-validates on every call. |
| Logic M2: lease ranking flaps on renewal | Fixed. Each lease takes a rank from a sequence when it is created or its root set changes. A renewal with the same roots keeps its rank. `desiredRoots` sorts by rank, not by `renewedAt`. `makeRoomForLease` and expiry still use `renewedAt`. |
| Logic M3: `send` ignores rejected/evicted | Rejected roots fixed. The lease client remembers the roots the backend rejected and leaves them out of the 60 s renewals. If none are left, the lease is released. The next `update()` from the dock asks for every root again. Evicted roots are not shown in the header: it would need a new signal from the lease client to the scope store and the header, which is not a small change. Skipped. |
| Logic minor: `outcomeFor` info log on every renewal | Fixed: now `debug`. |
| Logic: lease capacity drop, TOCTOU | Accepted as the review recommended. No change. |
| Style: divergent normalizers | Fixed by the change with the smallest blast radius. `libs/frontend/chat/src/lib/services/workspace-root.ts` (3 consumers) now delegates to the shared `normalizeWorkspaceRoot` (48 consumers, unchanged). Chat therefore now folds case on POSIX paths too, like the dock and the watcher pool. Covered in `session-working-root.spec.ts` and `workspace-root.spec.ts`; the second checks that the chat and shared helpers give the same results. |
| Style: five-service list duplicated | Fixed. `GitDockScopeStore.removeWorkspace(path)` now tears the folder down in each of its services, then runs its own pin and session-root cleanup. The coordinator holds only the store (same dynamic import of `@ptah-extension/git-ui/services`, no static edge). |
| Style: `instanceof` handshake hides a non-pool binding | Fixed: `boot-heavy-services.ts` now logs a warning when the registry is registered but is not a `GitRootWatcherPool`. |
| Style: unrelated reformat in `platform-core/src/di/tokens.ts` | Reverted to main's one-line `HOST_ATTENTION_NOTIFICATIONS`. |
