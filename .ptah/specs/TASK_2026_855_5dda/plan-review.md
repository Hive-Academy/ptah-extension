# Plan review

**Verdict: REJECT** — the scope subscription and watcher lifetime need correction before implementation.

1. **Blocker — tab changes may never retarget the dock.** The plan puts input reads inside `reconcile()` but calls it `untracked()` from the effect (`implementation-plan.md:475-491`). Angular cannot subscribe to signals read only inside `untracked`; the existing coordinator changes roots explicitly after its generation guard (`libs/frontend/chat/src/lib/services/workspace-coordinator.service.ts:196-205`). **Change:** read `activeSession`, `openSessions`, folders, and worktree state in the tracked effect body, pass their snapshots into `reconcile`, and test an active-tab-only switch with no workspace switch.

2. **Major — leases and watchers are not actually bounded by lifetime.** The pool stores every `leaseId`, expires entries only on a later `setLease`, and has no timer (`implementation-plan.md:340-349,393-405`). A closed renderer can leave up to four watchers running indefinitely; repeated renderer instances can grow the lease map without bound. **Change:** schedule expiry at the nearest deadline (or use one bounded sweep timer), stop and delete expired leases, cap lease count, and test expiry without a subsequent RPC. Also reconcile skipped primary roots whenever the primary watcher changes (`implementation-plan.md:344-346,360,384-385`), or they can remain unwatched until renewal.

3. **Major — the proposed worktree list can authorize the wrong session after a fast switch.** `WorktreeService` has one global `_worktrees` signal and `loadWorktrees()` publishes whichever response finishes last (`libs/frontend/git-ui/src/lib/services/worktree.service.ts:49-58,81-99`); it sends the current dock root (`:230-237`). The plan adds one global `loaded` flag and uses that list for every session (`implementation-plan.md:475-482,512-513`). **Change:** key worktree lists and loaded state by open folder or repository, capture and guard the requested root/generation on response, and do not use a prior folder's list to accept a candidate. Include A→B→A out-of-order RPC tests. `GitStatusService` already demonstrates a generation and root guard (`git-status.service.ts:495-527`).

4. **Major — write authorization needs a live root check.** The plan widens all mutating `git:*` calls to a registered worktree and adds a 5-second *positive* authorization cache (`implementation-plan.md:209-238,706-717,740-747`). Current `findRegisteredWorktree` verifies list membership, directory existence, and matching common dir per request (`libs/backend/rpc-handlers/src/lib/handlers/git-workspace-root.ts:54-99`); current writes only accept a registered folder (`git-rpc.handlers.ts:290-315`). A removed or replaced worktree can remain authorized during the cache window. **Change:** revalidate list membership and canonical filesystem identity for every mutation, or cache reads only and invalidate on worktree/folder changes. Test removal or replacement between two writes. Keep the existing `isInsideRoot` protection for direct file reads (`libs/backend/vscode-core/src/services/git-info.service.ts:207-228,2653-2664`); `validatePaths` alone only rejects `..` segments (`:2830-2858`).

5. **Major — the Electron DI smoke guard is incorrectly optional.** The plan says registration alone is probably enough and makes `expected-resolvable.ts` / `container.smoke.spec.ts` conditional (`implementation-plan.md:87-90,419-420`). The smoke test resolves only the explicit `EXPECTED_RESOLVABLE` list (`apps/ptah-electron/src/di/container.smoke.spec.ts:351-361`); the new handler will not be tested unless added to it (`apps/ptah-electron/src/di/expected-resolvable.ts:15-27`). **Change:** require both files to cover `GitWatchRpcHandlers` and its new port, plus the Electron `rpc-surface.spec.ts` assertion (`apps/ptah-electron/src/di/rpc-surface.spec.ts:31-39,74-79`). Retain the planned VS Code and CLI absent-method/capability updates (`implementation-plan.md:309-319`) and scoped host typechecks (`:789-791`).

6. **Minor — reduce duplicated root policy state.** The frontend resolver accepts any candidate while `registeredWorktrees === null` (`implementation-plan.md:131-158`), and the dock separately keeps a loaded signal and worktree list (`:475-482`), while the backend remains the authority. This allows a header to label an unverified root as editable. **Change:** represent that state as pending/unavailable until the backend confirms it, or remove the frontend registration check and display backend refusal explicitly. Avoid promising `no allocation beyond the result` (`:163`) while returning a `rejected` array.

The proposed dependency direction is compatible with the current Nx tags: chat and git-ui are `scope:webview,type:feature`, core is `scope:webview,type:core`, shared is `scope:shared,type:util` (`libs/frontend/{chat,git-ui,core}/project.json:7`; `libs/shared/project.json:6`; `eslint.config.mjs:293-306,415-438`). No new module-boundary cycle is evident from the named imports. Review was static; no checks were run and no source files were changed.
