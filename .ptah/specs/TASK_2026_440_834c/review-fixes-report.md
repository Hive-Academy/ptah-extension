## Comment 1: Correct the EXDEV explanation in backup residual documentation

### Verdict

### Code Verification
Checked `libs/backend/persistence-sqlite/src/lib/integrity/integrity-worker-protocol.ts` (`performBackup` at lines 638–645 and publication at line 709) and `libs/backend/persistence-sqlite/src/lib/backup.service.ts` (`takeBackup` at lines 400–407).
`stagingPath` is generated by the host as `${destPath}.${crypto.randomBytes(4).toString('hex')}.tmp` in the destination directory, and `integrity-worker-protocol.ts` strictly verifies that `path.dirname(request.stagingPath) === path.dirname(request.destPath)`. Atomic publication is `linkSync(stagingPath, destPath)` within that same directory. The source database `dbPath` is copied page-by-page via `source.backup(stagingPath)` (SQLite Online Backup API), which functions seamlessly across distinct filesystem volumes. Therefore, a separate source-database volume has zero bearing on `linkSync(stagingPath, destPath)`, and staging and destination can never be on different volumes.
