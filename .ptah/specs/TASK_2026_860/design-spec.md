# TASK_2026_860 — Sessions rail, agent dock, inspector and pulse

## Design source

Use the current Angular webview visual language, specifically `apps/ptah-extension-webview/tailwind.config.js` themes `anubis` and `anubis-light`, `libs/frontend/chat-ui/src/lib/molecules/compact-session/compact-rail-card.component.ts`, and the current canvas dock and inspector templates. The `docs/design-system/panel-theme-spec.md` describes the landing page's operator themes and does not replace these webview tokens. No new color tokens or literal colors are required in implementation. The prototype embeds the existing theme values so it opens offline.

Use `bg-base-100` for the rail, `bg-base-200` for cards and menus, `bg-surface-1` for the dock, `border-base-content/10` or `border-surface-border` for separators, `text-base-content` for primary copy and `text-base-content-muted` for secondary copy. State colors are the existing `text-state-run`, `text-state-need`, `text-state-err`, `text-state-idle`, `text-state-done` utilities, with corresponding `--state-ink-*` values already defined for both themes. Selection uses the card's existing primary tinted fill and frame. Buttons use `btn btn-ghost btn-xs`; destructive Stop adds `text-state-err` and an error tinted hover surface using the existing `error` token. Do not rely on color alone: every state has visible text.

## Sessions rail

### Structure and dimensions

- Expanded width follows the existing bands: 304px (`lg`/`xl`), 288px (`md`), 272px (`sm`). Collapsed width remains 56px. The surface fills available height, with the session list as the sole vertical scroll area and the two existing footer actions pinned below it.
- Header retains the 72px height, `px-2 py-1`, `Sessions` at `text-sm font-semibold`, `runningCount / MAX_RUNNING_SESSIONS running` at `text-xs text-base-content-muted`, density toggle, then collapse control. Below the title use the existing 28px status summary strip (`h-7`, `gap-1`, horizontal scroll with hidden scrollbar and right fade). Its heading is visually hidden: “Jump to session status.”
- The summary has five separate, text labeled buttons in this order: **Needs input 1**, **Error 1**, **Running 2**, **Done 4**, **Idle 1** for the example. Show only nonzero actions. Each uses `btn btn-ghost btn-xs`, a state colored dot, text and tabular count. Accessible name: “1 needs input, jump to the next session” etc. All five remain in tab order even if horizontal scrolling is needed; focus scrolls the focused button into view. The unexplained bare digit strip disappears. Counts update live without changing button identity.
- List uses three ordered section headings: **Running**; **Waiting / Needs input / Error / Idle**; **Finished**. The middle title may wrap to two lines at 272px; use `text-xs font-semibold` and `text-base-content-muted` count aligned right. Header row `min-h-7 px-2`, section gap `mt-2` except the first, and card stack `gap-1.5 px-2 pb-2`. Empty sections are omitted. Counts are aggregate card counts, not a replacement for status jump actions.
- `Running` contains `running`; the middle group contains `needs`, `error`, `idle`, in existing stored tile order; `Finished` contains `done`. Keep stored tile order within each group; regrouping does not mutate it. Cards are 176px comfortable or 96px dense (`COMPACT_RAIL_CARD_HEIGHT`); retain `rounded-lg border border-base-content/10 bg-base-200`, 4px left state stripe, 14px left and 10px right inner padding. Dense removes the preview/lane detail already hidden by the existing card; status dot and label stay on the title line in both densities. Card spacing and group heading positions are the same in both modes.
- Status presentation: Running = `text-state-run` dot with shared 1.4s pulse and “Running”; Needs input = `text-state-need` static dot and “Needs input”; Error = `text-state-err` static dot and “Error”; Idle = `text-state-idle` static dot and “Idle”; Done = `text-state-done` static dot and “Done”. Dot 8px, label `text-xs`, text in `text-base-content` if colored text alone falls below body contrast. Maintain the current 4px stripe. The card select button's accessible name includes session title and full status, including when collapsed; the 56px rail shows a state dot and title tooltip/accessible name, never an unlabeled color mark.
- The Finished section is collapsible while the rail is expanded. **Decision: initial state collapsed only when it has more than three cards; otherwise expanded.** The example's four finished cards begin collapsed in the expanded rail. In that expanded rail, the header always shows its count and a `ChevronRight`/`ChevronDown` icon with `aria-expanded`; click, Enter and Space toggle it. User choice persists while the rail remains mounted; count changes do not override a user toggle. On a fresh mount apply the threshold again. When the rail collapses to 56px, force the Finished cards visible as labeled dots even if the expanded rail's Finished group was collapsed; do not change the stored expanded-rail preference. Restore that preference when the rail expands. A focused card moved into a collapsed Finished group moves keyboard focus to the Finished heading; selecting or jumping to a finished session expands the group before focusing the card. In the collapsed rail, keep focus on the same card because every Finished card remains visible.
- Rail ArrowUp/ArrowDown/Home/End follows displayed card order; preserve focus on the same session ID after a status move where possible, otherwise focus the next visible card or previous card, then group header if none. Card selection remains explicit; focus movement alone does not select. Move Up/Down acts only among visible siblings in the same group; at group boundaries the menu item is disabled with “First/last in group” reason. Preserve existing card menu actions and the New session / Previous sessions footer.

### Empty and collapsed cases

With zero sessions show “No sessions yet” in the list, keep New session and Previous sessions, and show no empty group headings or jump buttons. With only finished sessions show the Finished heading and count in the expanded rail. In the collapsed 56px rail hide summary and headings visually, force Finished cards visible, and keep each dot's full-card selection button keyboard focusable with accessible name “<title>, <status>” and a visible focus outline. The `aside` accessible label remains “Sessions”; the collapse button is “Expand rail.”

## Agent dock

- Use existing `bg-surface-1 border-b border-surface-border px-2 pt-1 pb-0.5`, 28px (`h-7`) chips and `gap-0.5`. Named chip max 140px, selected pill max 180px, avatar 24px; keep the selected pill's existing secondary border. The selected pill counts as one chip. **Maximum five rendered agent chips on every width and every render path**; narrower widths may show fewer. Reserve room for the overflow trigger when hidden agents exist. Unknown/non-finite width or missing `ResizeObserver` uses the safe one-chip layout plus overflow until measured.
- Rendered order, left to right: selected agent first **only if selected and not running**; then all visible running agents; then waiting, failed, queued, done and stopped agents in that order. Preserve roster order within each status, even when kinds differ. A selected running agent sits in the running sequence. The selected non-running pill is the sole exception to running-first order. Selection is maintained across resize/status changes. If width cannot fit the selected pill and trigger, put the selected agent in overflow; never exceed five chips or clip the trigger.
- Overflow trigger is a 28px high ghost rounded button reading `+N` (N = number hidden) with `aria-label="N more agents"`, `aria-haspopup="menu"`, `aria-expanded`. The open dropdown uses `bg-base-200 border border-base-content/10 rounded-lg`, minimum 224px width, `p-1`, and one 32px minimum row per hidden agent. Each row: 24px existing agent avatar, truncated name, explicit status in state ink, tabular duration in muted text. Hidden agent appears exactly once, including finished agents. Row's accessible name contains name, status and duration. Selected hidden agent has a secondary left inset marker and `aria-checked=true`. Selecting a row closes the menu, sets `aria-expanded="false"`, selects the lane, then returns focus to the overflow trigger after re-render; selection must not reopen the menu. Escape closes the menu, sets `aria-expanded="false"`, and returns focus to its trigger without changing selection.
- ArrowLeft/ArrowRight/Home/End traverse rendered tabs in visual order; focus alone does not select. While focus is inside the dock, freeze the current visible chip membership and order through live status updates, subject to the five-chip cap and available width. If a focused tab is hidden by a width update, move focus deliberately to overflow without changing selected lane. The freeze releases as soon as focus leaves the dock subtree, which includes the overflow trigger and menu. Re-plan the visible chips then using the current width, five-chip cap and running-first order (with the selected-agent exception); selection stays unchanged. Hover/focus detail cards and the transcript/composer area below the dock stay as today.

## Expanded inspector header

- Scope is the expanded/sheet header only; compact inspector rail remains compact. Keep `border-b border-surface-border py-2 pl-3 pr-2` and the title (`text-sm font-medium line-clamp-2`), status, workflow and branch (`text-xs text-base-content-muted`). Header actions sit in one right aligned `flex shrink-0 items-center gap-1` row. Order: **Rename**, **Organize**, conditional **Stop**, then existing panel toggle. Every icon button is `btn btn-ghost btn-xs btn-square size-7`, icon `size-4`, with `title`, tooltip and matching `aria-label`; use Lucide `Pencil`, `FolderOpen`, `Square`, `Ellipsis`, and existing `PanelRightClose`. Stop gets `text-state-err` and `hover:bg-error/10`; tooltip “Stop session”. The toggle retains “Compact session details” or “Close session details” according to presentation.
- Rename appears only for a persisted session ID; Organize only when organizer is available **and** the session is persisted; Stop only while this inspector session is running. A draft never exposes Rename or Organize. Button actions target the inspector session and its tab, not the currently active global tab. Stop captures both IDs before any agent query, retains the existing confirmation, and carries the captured target through confirmation, abort and failure fallback. Cancel sends no abort.
- At **header content width below 320px**, replace all available Rename/Organize/Stop icons with one `Ellipsis` ghost button, `aria-label="More session actions"`, immediately left of the panel toggle. Its menu lists the same available actions in the same order, with explicit labels and a red tinted Stop row; panel toggle stays visible. Use container width, not viewport width. The title gets the remaining width and may wrap to two lines; controls do not overlap it. On action selection or Escape, close this menu, set the trigger's `aria-expanded="false"`, and return focus to the “More session actions” trigger. In wider headers the menu disappears and icons return. All action targets have focus-visible outlines and keyboard activation.

Core and ring use `currentColor` or existing state ink. No full rotation remains in these loading visuals. ## Theme and accessibility checks

For dark `anubis`, base surfaces are `#131317`, `#1a1a20`, `#242430`, primary copy `#e8e6e1`; state ink values are the existing `--state-ink-*` tokens. For light `anubis-light`, use the theme's warm OKLCH bases and its stronger state ink overrides; the primary selection frame uses `primary-content` on the light theme, as the current card does. Use `text-base-content-muted` for readable secondary copy in both themes. Do not use low-opacity text as a substitute. All interactive elements have a 2px `focus-visible` outline and 2px offset; dark uses `oklch(var(--s))`. For light panels, copy the existing `apps/ptah-extension-webview/src/styles.css:1042-1056` override: `:where([data-theme='anubis-light']) :is(button, input, select, textarea, a):focus-visible` uses `outline-color: var(--ptah-gold-strong)`. This existing token measures at least 5.24:1 against the theme's cream panels, above the 3:1 non-text minimum. Group counts and status labels remain text, not color-only indicators. Status dots and the pulse are decorative (`aria-hidden=true`) beside real text.

## Revision 1

1. **Collapsed rail:** The 56px rail always renders every Finished card as a focusable, named dot. The expanded rail keeps the more-than-three initial collapse rule and restores the user's Finished expansion choice when expanded again.
2. **Menus:** Dock overflow and inspector “More session actions” close on selection and Escape, set `aria-expanded="false"`, and return focus to their trigger. A hidden-agent selection keeps the dock menu closed after its chip list re-renders.
3. **Light focus:** The prototype and implementation use the webview's existing `--ptah-gold-strong` focus outline override on `anubis-light` panels, with 2px width and offset.
4. **Dock freeze:** Freeze ends when focus leaves the dock subtree. The dock then re-plans the visible chips for current width, five-chip cap and running-first order, retaining the selected agent.
