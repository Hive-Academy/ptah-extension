## Constraints the new layout must keep

1. No layout shift on focus: a focus change moves content between slots, never slot geometry
   (AC 1.4 intent; task-description.md:107; risk row :311). Row 43 keeps this; only the "tile keeps
   its own Gridstack cell" reading changes.
2. At most one live transcript in the canvas (plus one open lane view): D1 (implementation-plan.md:23-41),
   AC 4.5 (task-description.md:157).
3. Automatic card never overwrites `TabState.viewMode` (AC 1.5); the user toggle still works on the
   focused session (AC 1.6); the budget stays one value, `CANVAS_LIVE_BUDGET` (AC 1.7).
4. 1-2 sessions behave as today; existing canvas/chat/chat-ui spec expectations pass unedited
   (NFR "Compatibility", task-description.md:204-205). This conflicts with any rail at 2 tiles.
5. BL: no detached `ptah-canvas-tile` / `gridstack-item` / `chat-msg-slot` after a tile closes
   (plan-part-4.md:247-260); every per-tile timer, listener and injector has a release path
   (tile `ngOnDestroy` :662-665, detail transcript `onCleanup` :67, queue listeners F7).
6. One `buildTree` per published tab snapshot in a mounted live view (decisions rows 16, 33).
7. Drafts survive every slot swap (F5; `ComposerDraftStore` keyed by tab id).
8. Hidden workspaces stay mounted, paused and deregistered (rows 17-18; commit 571227a8a isolation
   cited at tile :565-571); `RETAINED_WORKSPACE_CAP = 4`.
9. Running cap counts every canvas session in all workspaces (decisions rows 18-19); the guard is
   provided wherever a composer mounts (row 30).
10. Persisted record stays forward-safe: a newer `version` makes older builds read-only
    (persistence :184-189); hydration never writes before load (spec "never writes before hydration").
11. The queue never reorders cards (AC 6.7); no automatic reordering by attention (task-description.md:75).
12. Card update rate ≤ 2/s from stream data (NFR, task-description.md:202-203); urgent states skip the sample.
13. Accessibility: cards, lane rows, tabs, queue items keyboard-reachable; `role="tablist"`; queue
    popover has an accessible name (task-description.md:206-208).
