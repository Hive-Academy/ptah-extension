## Data flow: new session and restored dock

Rail footer emits `newSession` to `CanvasRailBoard`, then to `OrchestraCanvas.openNewSessionPopover`. The dock popover checks `canStartRunningSession()` and `canAddTile()`, obtains the optional name, calls `addTile(name || defaultSessionName())`, focuses the result and closes. Empty names retain first-prompt auto-rename because they keep the default name. Rail footer and zero-tile empty board anchor the same popover. Preserve `geometryBaseline` reset, focus and scroll anchor from `canvas-rail-board.component.ts:321-329` after successful add. Check `canAddTile()` and null `addTile`. Focus after named popover is new behavior. A cap or hard-bound failure leaves no tile and announces the existing reason.

The focused tab id enters the stable Rail lane host, then the child `SESSION_CONTEXT` signal. ChatView resolves that tab's display feed and `DisplayDockState` key. The feed registers Turn summary and `ptah-ui` display surfaces, the chip's Open in panel selects the same per-tab state, and `ptah-display-dock` renders Displays/Agents, toggle, pin, close and width. In the Rail host, the Agents tab receives only agents whose `parentSessionId` equals the focused session id. The separate session details column remains independently toggleable. A failed lazy dock load uses the existing eager Agents fallback; keep the chip status contract. No batch owns its source. No batch may set `HIDE_AGENT_SIDEBAR: true` on a host that shows a transcript. The dock remains protected in both Rail and single chat view (decision 77).

## Data flow: sub-agent tile and full lane

The main transcript's `ExecutionNode` receives `agentTileMode=true`. An `agent` node becomes one compact tile using its existing node id, name/kind/status and `children` tool count. Use `SubagentRecord` by `parentToolUseId` for last activity and ownership; use existing stats aggregation for duration. The tile shows a pending permission badge/action derived from descendant tool permissions. Its click emits the existing `SESSION_CARD_ACTIONS` lane action. The full lane resolves the agent node from the focused tab's live execution tree, using `ExecutionTreeBuilderService.buildTree(state, 'tab-' + tabId)` as the transcript does (`chat-transcript.component.ts:389-410`), and renders `<ptah-execution-node [node]="agentNode">` with tile mode off through the exported `ptah-execution-node` (`chat/src/lib/components/index.ts:145`). ## Item 10: switching design and budget

Baseline: 10/10 focus swaps had a >50 ms long task. Median main-thread task time was 422 ms, maximum 514 ms; longest long task median 124 ms, maximum 289 ms. A median 7,657 and maximum 16,921 elements were added per swap; CLS was 0 and one live view remained (`switch-baseline.md:18-43`). The direct cause to remove is the focus area's keyed `@for` destroying the lane host and transcript on every id change.

Choose **one stable ChatView plus a capped retained transcript LRU**. Keep the orchestrator lane/ChatView mounted while switching focused tabs; bind a reactive tab id instead of a keyed host. Add a host opt-in token in `session-context.token.ts` so only the Rail focus host activates retention in tile mode. Extend `TranscriptRetentionService` for that host so up to four recent transcripts stay mounted; the Rail opt-in token supplies cap 4, separate from the shared default. In Rail mode the effect follows `SESSION_CONTEXT`, not global `activeTabId`. Inactive transcripts use the existing frozen `vm` and do not subscribe to live presentation work. Evict on LRU overflow, close and workspace removal; clear tree cache only when no other surface retains that tab, and release listeners. The main panel remains mounted in canvas mode (`app-shell.component.html:795-829`). Raise cap only with measured heap MB and element count. A non-orchestrator lane may cover the ChatView, but must not instantiate another one. Keep the composer and per-tab draft state across focus swaps.

Reject destroy/create: it caused the measured DOM churn. Reject `content-visibility:auto` alone: it cannot avoid rebuilding 5k-17k elements. Reject opacity alone: it masks the delay but does not reduce it. Add a 180 ms opacity/transform transition to the stable content layer, with `prefers-reduced-motion` disabling it. Animate compositor properties only; do not animate width, height or position. A cold ninth tab can still need a first render; measure that separately and schedule expensive markdown only if the measured cold case exceeds 50 ms. Do not add a per-card timer/observer.

Expected warm acceptance: no long task >50 ms, CLS 0, focused card in view, F5 draft restore, one live ChatView, zero detached nodes. Fewer than 100 added elements and no newly created transcript subtrees are diagnostics only. The first cold visit is recorded separately and must be reported if it misses the 50 ms target. Re-run `.ptah/tmp/final-run/s-switch.mjs` with `TAG=after-r9`, 10 swaps and the same four sessions; compare median/max Task, Script, Style, Layout, longest long task, element additions and CLS. Verify `s-draft3.mjs` and `s-heap.mjs`; both `s-heap` and `s-switch` report JS heap MB, document element count before/after, and retained transcript count versus cap 4; do not treat a pretty fade as a performance pass.

## Failure cases and migration

- A closed tab or removed workspace evicts its transcript and dock state and cannot retain a stale lane action. A reset/clear keeps the tab identity and empty draft semantics.
- A mismatched or unknown sub-agent owner never appears on another card or Agents view and cannot be opened into that session. The tolerant main-panel monitor remains a recovery surface for unattributed agents.
- A pending permission that changes id before click uses the existing stale-action path; the tile and full view do not respond to an old request.
- A dock lazy-load failure shows the existing Agents fallback and an error status. A display fence without a registered display reports unavailable only when its surface truly cannot be opened.
- Read v3 Grid as Rail in memory, preserving tile ids/order, `railCollapsed`, `railDensity` and `railScrollTop`. Read v2 as Rail defaults. On write, keep the strict v3 tile shape with existing/default width and row-break values; normalize only board mode. No geometry-dropping rewrite. Maintain the newer-version read-only guard. Test v3 Grid, v2, v1, malformed, newer read-only and write-then-read round-trip; no silent loss of sessions.
