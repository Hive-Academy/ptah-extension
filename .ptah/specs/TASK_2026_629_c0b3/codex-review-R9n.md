# R9n code logic review

Review family: codex (implementer: Claude)

Score: **6/10**. Verdict: **REVISE**. Two Serious findings. The live node, permission, provider, and display paths have focused evidence, placing this above the 3–4 band; two reachable user flows still lose work or strand the view, keeping it below 7–8.

## Findings

1. **Serious — Escape discards an agent message draft.** `single-chat-subagent-view.component.ts:35-38,135-140` handles every unhandled bubbling Escape by emitting Back, which destroys this view (`chat-transcript.component.html:169-180`). The nested “Message this agent” textarea sends keydown to a handler that only handles Ctrl/Cmd+Enter (`inline-agent-bubble.component.ts:382-395,1061-1066`); its draft is component-local (`inline-agent-bubble.component.ts:1035,1056-1058`). A user typing a message there and pressing Escape loses that text. Fix in this batch’s view: when Escape originates in an input, textarea, or editable descendant, leave the view open (or define an explicit first-Escape input dismissal that retains the draft). Add a real nested-input keyboard case. The current Escape spec dispatches only on the host (`single-chat-subagent-view.component.spec.ts:187-210`).

2. **Serious — a disappeared agent leaves an inert transcript behind an unavailable overlay.** `chat-transcript.component.ts:691-709` converts a missing live node into `{ node: null }` while retaining `openSubagentId`; `chat-transcript.component.html:12,169-180` therefore keeps the scroller inert and the overlay open. The overlay offers only a Back button and an unavailable message (`single-chat-subagent-view.component.ts:48-55,79-95`). Switching or replacing the active session’s tree while an agent is open can strand the user in a dead view until manual Back. The spec explicitly pins this behavior (`chat-transcript.component.spec.ts:1333-1345`) rather than closing it. Clear the open id and restore the transcript/focus when a previously resolved node disappears; retain the unavailable announcement if needed. Distinguish a temporary inactive freeze from an active tree where the id is truly absent.

## Five logic questions

1. **Silent success:** A stale or `cli:` lane is announced and not opened (`chat-transcript.component.ts:742-748`), and a stale permission badge rechecks its id (`subagent-tile.component.ts:104-106`); neither claims success. The silent loss is the agent message draft on Escape (finding 1).
2. **Unexpected user action:** Escape in the nested agent textarea closes the overlay (finding 1). Back after a normal tile open restores the saved scroll and focus (`chat-transcript.component.ts:722-739`; `chat-transcript.component.spec.ts:1246-1298`).
3. **Wrong-answer input:** A lane key for another or absent agent is rejected by searching this transcript’s current view model (`chat-transcript.component.ts:742-769`), avoiding a wrong-session result. Duplicate tool-call ids within one tab would select the newest match (`chat-transcript.component.ts:765-770`); uniqueness is assumed and was not established by these tests.
4. **Dependency failure or malformed shape:** If the agent node vanishes after opening, the user gets the dead overlay in finding 2. The permission path passes lookup and responses through `ChatStore` (`single-chat-subagent-view.component.ts:120-133`); its focused spec uses an execution-node stub (`single-chat-subagent-view.component.spec.ts:159-174`), so it does not itself exercise a real card or a failed response.
5. **Missing requirement:** The contract specifies preserving the main composer draft (`batches-rail-r9.md:191-199`) but does not state what Escape should do to a nested agent message draft; finding 1 makes that omission user-visible. The prompt’s no-stale-view requirement also needs the automatic close in finding 2.

## Decisions

- **Tile mode scope:** The one opt-in is the message bubble in `chat-transcript.component.html:47-54`; `ChatView` mounts that transcript at `chat-view.component.html:79-92`. Thus single chat, Tribunal conductor (`conductor-tile.component.ts:142,215-225`), and current Rail (`canvas-detail-transcript.component.ts:34-58`) all inherit it. This is consistent with “only the main transcript” as a component/entry-path rule, though it is wider than “single chat only.” Tribunal has no parent lane handler and opens in place. Current Rail also opens in place until R9f; this is a temporary integration state. R9f expressly owns the Rail `SESSION_CARD_ACTIONS` provider, its lane selection, and removing `HIDE_AGENT_SIDEBAR: true` (`batches-rail-r9.md:346-359`). The current Rail host still supplies that hide token (`canvas-detail-transcript.component.ts:56`), so decision 77’s dock parity is pending R9f rather than demonstrated here. Tribunal likewise supplies the hide token (`conductor-tile.component.ts:218-222`); that existing host should be reconciled with decision 77 before calling all transcript hosts compliant.
- **Provider containment:** The transcript factory returns the parent handler through `skipSelf` when one exists (`chat-transcript.component.ts:229-239`), covered by a Rail-shaped test (`chat-transcript.component.spec.ts:1360-1374`). The compact card and transcript are siblings in alternate branches of `ChatView` (`chat-view.component.html:4-15,79-92`), so the card cannot inherit the transcript element provider. A sibling probe checks null actions/context and tolerant mode (`chat-transcript.component.spec.ts:1059-1084,1347-1358`); this does not mount the real card, but the actual card’s strict switch is the same token check (`compact-session-card.component.ts:181-184,229-232`).
- **Permission gate:** A real tile badge opens the agent containing the pending tool (`chat-transcript.component.spec.ts:1376-1409`), and the full view forwards permission lookup/response (`single-chat-subagent-view.component.ts:79-86,120-133`; `single-chat-subagent-view.component.spec.ts:159-174`). A stale id does nothing in the existing tile test (`subagent-tile.component.spec.ts:101-108`). The full-view spec stubs `ExecutionNode`, so a real permission-card interaction remains an integration check for Mode 2/R9f.
- **Live and display behavior:** Rebuilt agent nodes reach the same open view (`chat-transcript.component.spec.ts:1270-1285`); normal Back restores scroll, opener focus, and the sibling composer value (`chat-transcript.component.spec.ts:1246-1298`). The fenced `ptah-ui display stats` test confirms same-id update while the view is open (`chat-transcript.display.spec.ts:801-885`), though it tests `DisplayDockState` rather than a rendered chart/table. No R9n source sets `HIDE_AGENT_SIDEBAR` (`chat-transcript.component.ts:229-239`).
