## Findings

1. **Minor — keyboard interaction coverage is indirect.** `libs/frontend/canvas/src/lib/canvas-rail/canvas-rail-card.component.spec.ts:184-190` checks the host role and the existence of `.rc-select`, but does not activate that button with Enter or Space or assert that its bubbled click calls `focusTile` only once. The collapsed test at `canvas-rail-card.component.spec.ts:192-211` covers a pointer click only. If a later change handles the button's keydown as well as its native click, a keyboard user could select twice without these new cases failing. Add browser-level Enter/Space activation checks for the select and collapsed buttons, plus one nested action click that must not select the card. Current code does not show the double handling: `canvas-rail-card.component.ts:166-174` handles Enter only when the host itself is the event target, and `canvas-card-click.ts:2-3,15-22` excludes inner buttons from host clicks.

## Decisions

- **`listitem` versus `button`: keep `listitem`.** `canvas-rail-card.component.ts:29-31,42-52` makes the native `li` a list item in the Rail list. Its selectable control is the `.rc-select` native button (`compact-rail-card.component.ts:182-190`), and collapsed mode uses a native button (`canvas-rail-card.component.ts:94-102`). A button role on the whole host would encompass the lane and request buttons (`compact-rail-card.component.ts:228-332`) as nested interactive controls. The current host is not in the tab order; native button activation supplies Enter and Space for keyboard selection. The host's Enter handler is only a programmatic-focus fallback (`canvas-rail-card.component.ts:169-174`). The focus helper excludes the hidden collapsed subtree (`canvas-rail-keyboard.ts:11-15`), and focus styling covers both visible controls (`canvas-rail-card.component.ts:71-74`; `compact-rail-card.component.ts:137-140`). Impact: list semantics and keyboard selection coexist without nested button semantics.
- **Interaction and geometry:** the host pointer class is at `canvas-rail-card.component.ts:50`; Tailwind preflight gives native buttons a pointer cursor (`node_modules/tailwindcss/lib/css/preflight.css:343-345`). Hover selectors cover the card, actions, and lane rows (`compact-rail-card.component.ts:145-156`) and the collapsed control (`canvas-rail-card.component.ts:75-78`). They change paint properties only. The 176/96 card height binding remains `compact-rail-card.component.ts:44,384-386`; the 70 px lane block remains `compact-rail-card.component.ts:80,303-337`. `rc-lane-overflow` remains at `compact-rail-card.component.ts:125-128,309`. No reorder logic appears in the four-file diff. Impact: R9c does not alter the Rail layout or introduce item 13 behavior.
- **Theme behavior:** hover colors use `--rail-state-ink`, `currentColor`, and `--bc` (`compact-rail-card.component.ts:145-156`; `canvas-rail-card.component.ts:76-78`). No new fixed color is introduced. The new specs inspect CSS source and cannot measure computed dark/light contrast (`compact-rail-card.component.spec.ts:139-174`; `canvas-rail-card.component.spec.ts:192-208`); the plan assigns computed contrast and screenshots to its later visual probe (`implementation-plan-rail-r9.md:122,127`). Impact: source logic is sound, while real theme appearance remains unverified here.

## Five logic questions

1. **Silent success:** no new async or error-swallowing path was added. Selection calls `focusTile` and emits a request (`canvas-rail-card.component.ts:153-156`); R9c only changes CSS and host semantics. No R9c-specific silent failure is demonstrated.
2. **Unexpected user action:** an inner button click is filtered by `isIgnoredCardClick` before the host selects (`canvas-rail-card.component.ts:166-168`; `canvas-card-click.ts:2-3,15-22`). Native button Enter/Space activation reaches that same path. The missing integration test is finding 1.
3. **Wrong input data:** R9c introduces no data transformation. State-specific hover ink is selected by `data-state` (`canvas-rail-card.component.ts:44,56-70`; `compact-rail-card.component.ts:47,62-76`); no input shape that yields a wrong answer was found in the changed logic.
4. **Dependency failure or timeout:** the changes do not add a dependency call. The existing `focusTile` call has no result contract (`canvas-rail-card.component.ts:153-156`), so its preexisting failure behavior is outside this batch. Scoped diagnostics timed out and were not treated as a pass.
5. **Unstated requirement:** real computed hover contrast in both themes is not established by the source-level tests (`compact-rail-card.component.spec.ts:139-174`). The plan explicitly schedules that visual check later (`implementation-plan-rail-r9.md:122,127`), so this review does not treat it as an R9c implementation defect.

Score rationale: 8/10 reflects a sound, narrow change with native keyboard controls and preserved geometry, plus one meaningful interaction-test gap and unmeasured visual contrast. A 9 would require direct keyboard and theme evidence; a 7 would require a demonstrated behavioral defect, which this review did not find.
