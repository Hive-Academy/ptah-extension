# Bundle defer code-logic review

**Score: 6/10. Verdict: REVISE.** The isolated component imports and template-only uses make lazy chunks likely, and the edited unit specs render the loaded state. The lost focus action and the unguarded e2e geometry read require another pass. A production build was prohibited, so the size saving and emitted chunks remain unmeasured.

## Findings

1. **Serious — Rail “lanes” action can lose focus permanently.** `libs/frontend/canvas/src/lib/canvas-rail/canvas-rail-board.component.ts:853-863`; `libs/frontend/canvas/src/lib/canvas-rail/canvas-focus-area.component.ts:58-70`. Clicking the Rail lanes action before the idle block completes focuses the tile and then runs one `afterNextRender` query for a selected tab. The placeholder contains no tab, so the optional `focus()` does nothing. Loading the tabs later never retries; keyboard focus remains on the Rail control instead of the requested lane. This is most likely on first entry, a busy renderer, or a slow chunk request. **Fix:** retain a pending lane-focus request and fulfill it after the tab appears, with a cancellation check when focus changes; alternatively provide a nondeferred, focusable lane target.

2. **Moderate — A stale lane remains selected in state until the lazy child starts, and the live panel has a dangling accessible name meanwhile.** `libs/frontend/canvas/src/lib/canvas-rail/canvas-focus-area.component.ts:58-83`; `libs/frontend/canvas/src/lib/canvas-detail/canvas-lane-tabs.component.ts:164-177`; `libs/frontend/canvas/src/lib/canvas-detail/canvas-lane-view.component.ts:60-68,226-236`. If an agent lane disappears while its key is selected, the eager lane view displays the Orchestrator transcript through `selectedKind()`, but `CanvasDetailService` retains the stale key until the tabs component's effect emits the reset after idle loading. Its `role="tabpanel"` also points `aria-labelledby` at a tab that does not exist throughout every placeholder window, including the ordinary Orchestrator case. A screen reader can encounter an unnamed panel and state can be read stale during that interval. **Fix:** normalize vanished lane keys in the eager focus area or detail service, and give the panel a stable accessible name while tabs are absent; keep the tab relationship once loaded.

3. **Moderate — The existing split e2e assertion races the deferred tabs.** `apps/ptah-electron-e2e/src/specs/canvas/canvas.spec.ts:149-154`; `libs/frontend/canvas/src/lib/canvas-rail/canvas-focus-area.component.ts:58-70`. The test waits for the eager Details button and then calls `laneTabs.boundingBox()` directly. That call can return `null` before the idle block renders, causing a false failure even though the component loads later. Waiting for the header does not establish that the deferred host exists. **Fix:** await `expect(laneTabs).toBeVisible()` before reading its box. The reported e2e safety claim does not cover this selector.

4. **Minor — The dock placeholder does not always reserve the queue's width.** `libs/frontend/canvas/src/lib/orchestra-canvas.component.ts:112-120`; `libs/frontend/canvas/src/lib/canvas-needs-you-queue.component.ts:47-56`. The placeholder always measures the “All clear” label, while the loaded trigger reads “N need you” when requests exist. In that common state, the control grows at idle and shifts neighboring dock controls despite the stated footprint guarantee. **Fix:** reserve a width covering the count label, or keep dock placement stable with a fixed-width wrapper.

## Five logic questions

1. **Silent failure:** the optional focus call in finding 1 succeeds as a no-op when the tab is absent; there is no retry or visible error.
2. **User action:** opening a Rail card's lanes action during initial idle loading leaves focus on the old control; a pending request also makes the dock grow when it loads.
3. **Wrong answer from input data:** a selected lane that has disappeared leaves a stale key while the visible panel falls back to Orchestrator (finding 2).
4. **Dependency failure or delay:** if the lazy chunk is delayed, the focus action and accessible-name gap persist; if loading fails, Angular has no `@error` fallback in these blocks, so the queue, tabs, or details content remains unavailable behind its placeholder. The existing tests force `DeferBlockState.Complete` and do not exercise loading failure.
5. **Requirement gap:** the task did not specify how keyboard focus and tabpanel naming should work before an idle-loaded tab strip exists, nor a wait condition for e2e selectors of deferred components.

## Decisions

- **Decision:** treat the missing lane-focus retry as a serious regression. **Options:** accept the idle window, use an earlier trigger, or preserve the focus request. **Evidence:** the Rail callback queries once and the placeholder has no tab. **Reversible:** yes.
- **Decision:** request an e2e wait at the deferred selector. **Options:** rely on elapsed time after the header appears, or await the tab itself. **Evidence:** the selector's `boundingBox()` is read without an existence assertion. **Reversible:** yes.
