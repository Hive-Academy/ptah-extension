# Rail implementation plan — revision 1 re-review

Scope: revision 1 of `implementation-plan-rail.md`, the five findings in `implementation-plan-rail-review.md`, and the cited pre-Rail code. No Rail source exists yet. This was a read-only review; no build or test was run.

## Previous findings

1. **CLOSED — question Answer action (formerly Serious).** The plan now gives questions `AskUserQuestionRequest.id`, guards `answerQuestion(shownId)` against the current callout, and routes the accepted action to the Orchestrator lane (`implementation-plan-rail.md:382-383,402-410`). The view has an Answer button in both densities with the shown id (`:565-572`), and tests cover replacement, keyboard use and the wrapper route (`:612-615,703-705`). This restores the existing Answer affordance (`libs/frontend/chat/src/lib/components/molecules/compact-session/compact-session-card.component.ts:100-105`) while keeping the Grid branch unchanged (`implementation-plan-rail.md:409-410`).

2. **CLOSED — StopFailure error identity (formerly Serious).** The revised id uses a per-tab `terminalFailureSeq`; the counter is calculated inside both tab writers when a new reason is stamped (`implementation-plan-rail.md:384-390,468-493`). The active writer already performs one update and a no-op comparison before publishing (`libs/frontend/chat-state/src/lib/tab-manager.service.ts:1340-1345,1358-1375`); the background writer has the equivalent spread (`libs/frontend/chat-state/src/lib/tab-workspace-partition.service.ts:372-400`). `StopFailure` calls `setLastTerminalReason` (`libs/frontend/chat/src/lib/services/chat-store/turn-end-handler.service.ts:212-245`), which reaches the active writer or its background fallback (`tab-manager.service.ts:2223-2226,1383-1384`). A repeated terminal `turn_state` with the same reason does not advance the proposed helper, even where the existing terminal-heal rule accepts the record (`tab-manager.service.ts:1471-1480,1660-1687`); two failures separated by `markTabStreaming` do advance because it clears the reason (`:2817-2819`). The plan tests both sequences and the background path (`implementation-plan-rail.md:505-512`). The existing restore projection spreads unknown fields and the persistence projection spreads the tab, so the proposed field is retained (`libs/frontend/chat-state/src/lib/tab-persistence.ts:109-124,266-275`).

3. **CLOSED — lane comparator (formerly Moderate).** The equality rule now compares all six current row fields plus `moreCount`, `total`, and every status count (`implementation-plan-rail.md:372-378`); those are the fields exposed by `CompactLaneRow` and `CompactLaneSummary` (`libs/frontend/chat-ui/src/lib/molecules/compact-session/compact-lane.types.ts:11-29`). The test list includes `startedAt` and `kind` changes and an unrelated-session event (`implementation-plan-rail.md:447-450`). This removes the stale-duration case in the prior review.

4. **CLOSED — dense lane access (formerly Moderate).** The dense button explicitly uses `lanes.total`, appears at one or more lanes, and has a zero-lane state (`implementation-plan-rail.md:560-564`); `total` is separate from `moreCount` in the current summary (`libs/frontend/chat-ui/src/lib/molecules/compact-session/compact-lane.types.ts:23-29`). The new route forwards `moreLanes` through the wrapper to the board's lane-tab focus, retaining the per-tab lane choice (`implementation-plan-rail.md:672-677,838-840`). The view, wrapper and board cases cover one/four/zero lanes and destination (`:609-611,706-707,871`).

5. **CLOSED — shared density geometry (formerly Moderate).** The plan defines one exported 176/96 pair and names the card host, list item, guard and scroll anchor as its readers (`implementation-plan-rail.md:549-558,670-671,794-805`). The board owns and resets the baseline on density, collapse, add and close; it does not reset on focus or width (`:806-815`). The tests cover both densities followed by state and stream updates, a deliberately wrong height, anchor scroll, and the pure geometry helper (`:863-874`). This adds a check beyond the existing counter-only metrics (`libs/frontend/canvas/src/lib/canvas-render-metrics.service.ts:19-31`); the Electron no-shift probe remains in the plan (`implementation-plan-rail.md:1252-1256`).

2. **Unexpected user action:** Answer on a question and dense `+N` now have explicit routes and tests (`implementation-plan-rail.md:402-410,560-564,703-707`; current Answer route `compact-session-card.component.ts:100-105`).
3. **Wrong answer from valid data:** a changed lane `startedAt` or `kind` can no longer be suppressed by the specified comparator (`implementation-plan-rail.md:372-378,448-450`; `compact-lane.types.ts:11-20`).
4. **Dependency failure or wrong shape:** the new pure counter rides the existing active/background updates, and R0 checks are scoped to frontend projects (`implementation-plan-rail.md:487-503,1230-1233`; `tab-manager.service.ts:1334-1384`; `tab-workspace-partition.service.ts:372-400`). This remains a plan claim until implementation and tests run.
5. **Missing requirements case:** the revision adds the previously absent geometry baseline and one-to-three-lane dense route (`implementation-plan-rail.md:560-564,806-815`; `compact-lane.types.ts:23-29`). No further concrete omitted case was established in the changed seams.
