Orchestra Canvas — mission-control prototypes

Three layouts for many sessions with many agents. All pages share one simulated event store: about 100 stream events per second over 6–9 sessions, with permission requests and failures. The HUD at the bottom left shows the DOM node count, stream events/s, UI patches/s and the number of live transcripts.

A · Recommended

Mission board

Cards never move. Click a card and its detail opens directly below its row, with one tab for the orchestrator and one for each sub-agent, CLI lane and background task. Click a lane row on a card to open that lane's output. Use the Fidelity switch to compare with today's "all live" canvas.

 B

Focus + rail

The layout from the reference image. A left rail groups sessions by attention, the centre shows one live chat, and the inspector is on the right. Ctrl+K switcher, Alt+↑/↓ to move between sessions.

 C

Zoomed-out overview

No transcripts at all. One row per session with agent lanes, todos, context, cost and inline Allow/Deny. For 9+ sessions, and as the zoom-out level of A.

What to try

  • In A, set Fidelity to "All live (today)" and watch the DOM nodes and UI patches/s in the HUD. Then switch back.
  • Wait for a permission request. Approve it from the card, the attention menu or the overview row, without opening the transcript.
  • In A, click a CLI lane row (›_) on a card: the detail opens on that lane's output. Use ←/→ to move the detail to the next session.
  • In C, click a row: it opens the same session in B.

Limits of these prototypes

  • The data is simulated in the page. The real summary must be a computed selector over the existing chat store.
  • The live transcript adds one node for each stream event, as an approximation of incremental markdown rendering. It does not include markdown parsing, so real costs are higher.
  • Gridstack drag and resize are not modelled. The CSS grid only shows the spans.
