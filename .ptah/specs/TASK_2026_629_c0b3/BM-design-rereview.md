# BM design rereview — TASK_2026_629_c0b3

**Verdict: REVISE.** Six prior findings are resolved; finding 2 is partial. The reset behavior and a release/retrack race need design changes. This is a document and source review; no verification commands were run.

## Prior findings

1. **RESOLVED — subagent TodoWrite.** Design §2a:36,44 excludes `parentToolUseId` both when recording the marker and when resolving it; BM1 tests interleaved parent/subagent events (§4:101–104). The parent field exists on flat events (`libs/shared/src/lib/types/execution/stream.ts:83–86`). Impact: a nested tool no longer replaces the session count.
2. **PARTIAL — capped or lost latest input.** Design §2a:35–45 retains the latest tool ID through FIFO eviction, returns unknown when its input cannot be parsed, and BM1 includes cap eviction (§4:101–106). However `compaction_complete` installs `createEmptyStreamingState()` (`libs/frontend/chat-streaming/src/lib/accumulator-core.service.ts:571–579`; `streaming-handler.service.ts:469–473`), which clears the proposed marker while leaving `tab.messages` in place. If a live TodoWrite occurred after the last finalized TodoWrite, the selector's no-marker branch (§2a:45) can report that older finalized list as current. **Change:** carry a conservative latest-input/unknown marker across compaction until the turn is finalized, or explicitly return unknown after this reset; test a live TodoWrite, compaction, and an older finalized list. Impact: the card otherwise shows a stale but plausible done/total.
3. **RESOLVED — malformed todo items.** Design §2a:42 validates each status and both text fields before counting, and BM1 covers malformed and partial inputs (§4:105–108). The existing guard only checks the array (`libs/shared/src/lib/type-guards/guards/exec.ts:239–247`). Impact: invalid entries now produce unknown rather than a wrong count.
4. **RESOLVED — unspecified streaming refresh source.** Design §2b:54–61 removes polling and maps turn events from tracked tab IDs to current session IDs. BM2 covers draft ID assignment and shared roots (§4:123–127). `TabState` holds the session ID (`libs/frontend/chat-types/src/lib/chat-types.ts:538–563`). Impact: a draft tab can trigger its turn-end read after acquiring an SDK ID.
5. **RESOLVED — polling and unbounded git reads.** Design §2b:58–62 permits only first-track, turn-end/fail and push refreshes, with two global reads in flight; BM2 tests nine distinct roots (§4:123). Backend work remains material: status, two numstat diffs and capped untracked reads (`libs/backend/vscode-core/src/services/git-info.service.ts:264–267,999–1037`). Impact: simultaneous tiles no longer launch nine backend reads together.
6. **RESOLVED — stale counts after failure.** Design §2b:63–68 replaces known counts with unknown on unavailable status, RPC failure or timeout; BM2 tests failure and recovery (§4:122). The RPC explicitly distinguishes unavailable status from a clean file list (`libs/shared/src/lib/types/rpc/rpc-git.types.ts:122–147`). Impact: failed refreshes do not display old counts as current.
7. **RESOLVED — missing card placeholders.** Design §2c:73–79 fixes todo, context and git slots with an em dash, and BM1 covers none/unknown layout (§4:110). The current metrics zone is persistent (`libs/frontend/chat-ui/src/lib/molecules/compact-session/compact-session-activity.component.ts:787–802`). Impact: absent metrics retain their positions.

## Marker and reset audit

`setStreamingEventCapped` is the production writer of `events`; it has an in-place replacement branch and a FIFO eviction branch (`libs/frontend/chat-types/src/lib/chat-types.ts:246–289`). The proposed marker update must run before both branches, including same-ID `tool_start` replacement. The normal batching and background paths spread the state, preserving an added scalar field (`libs/frontend/chat-streaming/src/lib/batched-update.service.ts:191`; `libs/frontend/chat/src/lib/services/chat-store/chat-lifecycle.service.ts:234–236`). `createEmptyStreamingState` resets it (`chat-types.ts:168–183`). Turn finalization installs messages before dropping streaming state in a microtask (`libs/frontend/chat-state/src/lib/tab-manager.service.ts:1968–2001`); the selector's marker-first rule prevents an older finalized list during that interval. `deepCopyStreamingState` enumerates fields without the new marker (`libs/frontend/chat-streaming/src/lib/message-finalization.service.ts:309–330`), but its copies feed the tree/history builders, not the metric selector, so this is not an observed 628-era regression. BM1 covers initial set, subagent exclusion, eviction and partial input (§4:96–109); it does not cover compaction or same-ID replacement. Add both marker lifecycle cases to its tests.

## New issue

8. **Moderate — release/retrack can accept an old read.** Design §2b:54 says an emptied root drops its generation and an in-flight result is discarded. If the same root is tracked again before that result settles, a newly created entry can reuse the old generation, so a generation-only guard may publish the old response over the new entry. BM2 tests release and discard but not rapid release/retrack (§4:126). **Change:** require the completion guard to compare the captured root-entry identity or a generation that is never reused, and test release, retrack, then old response completion. Impact: a reopened tile can show stale git counts.

No new boundary or batch-order defect was found: BM1 exports presentational types/selector, BM2 consumes them in chat and registers the handler, BM3 consumes chat in canvas (§4:94–137). The file sets are disjoint and the stated estimates are below 40 calls per batch. The existing `git:info` result and worktree resolution support the no-new-RPC decision (§1:S9–S11; `libs/backend/rpc-handlers/src/lib/handlers/git-rpc.handlers.ts:203–221,318–348`).
