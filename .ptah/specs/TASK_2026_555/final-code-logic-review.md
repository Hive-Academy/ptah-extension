## Five logic questions

1. **Silent failure.** Writes that report success from the host's own result: covered (mcp-port, localhost, namespaces, agent-behaviour, drawer, Cursor popover all read `result.data.success === true` or read back). The reverse (reports failure when it succeeded) exists in M-3. Cursor stream status text bypasses redaction (M-2). `auth:checkConnection` never rejects on a probe throw and records `failed/unclassified` (correct, `connection-check.ts:114-123`).
2. **Unexpected user action.** Replace key while a check runs, then re-check (M-1). Delete a custom connection while stale route says it is not the driver (M-5). Press Undo after a drawer write on the same field (m-1). Esc on a modal: `cancel` closes the native dialog itself; every parent flips `isOpen`, so no desync today, but a parent that ignored `closed` would get a closed dialog with `isOpen` still true (`native-modal.component.ts:176`). Not hit.
3. **Wrong answer from input data.** `agy models` output with a status/error line (M-4). A saved pre-52.2 `id<TAB>name` model is normalised by `agyModelId` on spawn but will not match any listed id in the picker (cosmetic).
4. **Dependency failure.** Provider probe throws: fixed record. Key store read throws: fixed error, but whole list lost (M-6). Disk full on settings write: `SettingsPersistError` with code only, rollback only while the key's generation owns it (correct, apart from m-6). `agent:setConfig` is multi-field and non-atomic: a mid-way failure leaves earlier fields written and the client reports a failure for the whole call; the post-save refresh (always run, `providers-commit.service.ts` `run`) then shows the truth. Acceptable.
5. **Missing, never stated.** Backend guard for removing the active custom provider (M-5). A cooldown or rate limit on `auth:checkConnection` (each click is one billable inference request; only double-click is coalesced). Log/Sentry hygiene parity with the auth handlers (S-1). `@error` for the deferred wizard (m-2).

## Verification of the specific focus items

- **D15 ("Saved" only after the write's own result).** `SettingsSaveFeedbackService.save` returns `saved` only when `write()` resolved true and the commit it produced is `saved` (`:100-113`); refused/failed/threw never show success; `saveGeneric` requires `result.ok`; `runDrawerWrite` copies `commit()` only after its own write resolved. `ProvidersCommitService.run` never lets read-back promote a rejected write (`settle`). `config:model-switch`, `config:effort-set`, `memory:setTriggers`, `skillSynthesis:setLanes` ignore inner success but all carry a read-back, so they are covered. Failed write reverts: mcp-port, localhost, namespaces, prompt mode, Ultracode (now read back) all restore the previous value and alert.
- **Host error text.** `requireRpcData` replaces every failure with a fixed message; `settle` drops thrown errors (`void error`). Visible strings come from fixed constants or `commit.message` (built from fixed copy). `output-style` banners map codes to fixed sentences; the invalid-style notice shows the parser's own message about the user's file (not host/secret text). `auth:copilotLogin`, `auth:setApiKey`, `auth:deleteStoredKey`, tier writes, `agent:setConfig`, `ptahCli:*` results are now fixed text.
- **Races.** Concurrent saves: `saving()` merges `commit().status` and `genericSaving`; `ProvidersCommitService.run` sets `saving` synchronously before its first await, so no check-then-act gap. `ConnectionCheckRecorder` ticket/tombstone ordering is correct for recording (M-1 is about the returned value). `settings.json` rollback ownership by generation + reload epoch is correct (m-6 aside). Undo is kept while another save runs and dismissed only when the Undo write starts (`:128-141`).
- **Secrets.** `maskKeyHint` is read-path only, never throws, returns nothing for keys under 12 chars. `getAuthStatus` caches `apiKeyHint`; every key mutation path (`setApiKey`, `saveSettings`, `deleteStoredKey`) calls `invalidateAuthStatusCache`, so a stale hint is not served. `ptahCli:testConnection` keeps the registry's own already-sanitised `error`. Cursor: key literal redaction in rejection, log and cancel paths; gaps in M-2. Frontend: typed Cursor key lives only in the popover signal, cleared on save success and destroy. Logs: S-1.
- **`auth:checkConnection` / `ConnectionCheckRecorder`.** Strict schema, trimmed id, unknown id -> `RpcUserError`, uncheckable -> fixed refusal; failed probe is a record, not an error; `detail` is dropped; `latencyMs` is rounded and clamped; failed records carry null latency. Registered once via `registerSharedRpcHandlers` (singleton) and that function runs in all three hosts (`phase-3-handlers.ts:92`, `phase-4-handlers.ts:104`, `container.ts:829`); `AuthRpcHandlers` and `ProviderRpcHandlers` both inject the same instance. Map is bounded by provider ids.
- **Antigravity.** `agyModelId` splits on tab, so an old saved `id<TAB>name` spawns with the id only; empty model adds no `--model`; args are passed as an argv array. Parser risk in M-4.
- **`agent-spawn-environment` config reads.** Switching to `getConfiguration('ptah', 'agentOrchestration.<key>')` matches how `agent:setConfig` writes (`setAgentCfg`), fixing a read of the wrong section; correct on all three hosts' workspace providers.
- **`[ptahBusyDisabled]`.** Capture-phase listeners on the control run before its own template handlers; `stopImmediatePropagation` also stops child targets (icon inside a button); `aria-disabled` + `readonly` set; no listener leak (`DestroyRef`). Residual: m-4.
- **Merge.** `register-shared-rpc-handlers.ts` keeps both sides, no duplicate registration. `providers-settings.component.ts` takes the branch's component and applies main's `@defer (when wizardOpen(); prefetch on idle)` inside `@if (wizardOpen())`; main's only other change to that file was the reformat plus this defer (checked with `git log` from the merge base). No `viewChild`/synchronous wizard access. `loadCustomProviders` moved out of the settings try in both bootstraps (exported, same shape in Electron and VS Code; CLI path fixed separately via `PLATFORM_TOKENS.WORKSPACE_PROVIDER` in `with-engine.ts`).
- **Incomplete/stubbed.** None found: no placeholder returns, TODOs or fabricated data in the product code read. Test harness fixtures are test-only.
