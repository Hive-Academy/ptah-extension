## Current defects and scope

- Backend delivery still gates live chunks on `visibleTabIds` (`libs/backend/rpc-handlers/src/lib/chat/streaming/chat-stream-delivery-coordinator.service.ts:164-180`). The claimed builder correlation ID is absent from the viewport set. A normal, visible tab will enter that set through the shared embed and stream normally after 649 migrates the builder.
- Snapshot resync still writes straight to the chat store (`CH/services/chat-message-handler.service.ts:563-589`), whereas live chunks check the claim (`:514-529`). The 649 builder will use a real tab without a claim, so snapshot and live paths will refer to the same tab. 648 does not patch snapshot routing for remaining claimed surfaces.
- Apply still drops the successful response (`HB/components/harness-builder-view.component.ts:849-853`). The add-on migration in 649 must show success and written files.

None in 648. Later removal of duplicated builder composer, transcript or claim/rehydrate code must follow successful parity checks in 649. `WorkflowSessionClaimService` and `StreamingSurfaceRegistry` remain for Tribunal and Apps.
