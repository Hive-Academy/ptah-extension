## Deleted files

All three are one-shot AI-migration instructions that `nx migrate` generated for Nx 23.2.1 (commit 8d3e01581). The repo is now on Nx 24.0.0 (`package.json`), the migrations were applied, and nothing references the files.

- `convert-to-flat-config.md` (291 lines): root `eslint.config.mjs` exists and no `.eslintrc*` remains.
- `migrate-ban-types-rule.md`: no `ban-types` reference remains in any config.
- `verify-typecheck.md`: tells the reader to run `nx run-many -t typecheck`, which this repo's rules forbid. The migration is done.

`tools/ai-migrations/` is now empty (git sees only the three deletions).

## Decisions

- Nx boilerplate READMEs ("This library was generated with Nx") were rewritten to one purpose line, a verify command and, where useful, a consumer list. Options: delete them, or keep them. Chose a short rewrite because the lasting facts (purpose, import alias, tags, historical-name caveat for `vscode-core` and `vscode-lm-tools`) are not obvious from the directory name. Reversible.
- Used `npm run verify -- -p <short-name>`. Checked that `nx show project chat` resolves the unscoped name of a scoped project.
- `scripts/brand-icons/rejection-report.md` and the mcp-bench `planted-negatives.v1` fixtures were left alone: both are generated or consumed by code and are not documentation.
- `tools/process-sampler/src/sampler.js` still classifies a `ptah`/`ptah-cli` entry with `worker`/`interact` as `ptah-worker`. The remote worker binary in this repo is `ptah-worker` (`libs/backend/worker-host/src/lib/dispatch.ts:33`), whose basename does not match that rule. This is a source issue, outside scope. Follow-up: update the classifier and the README row together.
- Out of scope but noticed: `libs/frontend/dashboard/src/index.ts` still exports `BuildersCardComponent` (the Builders portal was removed); `libs/frontend/webview-e2e-harness/src/lib/scenarios/vscode-shell/` still tests a VS Code host shell; `libs/backend/vscode-core/src/api-wrappers/*` still imports `vscode`.
