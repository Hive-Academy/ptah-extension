## Open questions and unmet requirements

- **Live enablement gate remains open:** `getBotIdentity` reads the login and OAuth scope header, but fine-grained GitHub write permissions are not verified before live enablement. `setBotToken` stores the token without checking those permissions. The orchestrator should keep publication paused until a permission-verification contract is agreed and implemented. Options: a non-mutating GitHub permission check with documented fine-grained semantics (recommended), or explicit operator verification in the canary gate. This is a security and outward-facing decision reserved for the spawner.
- Electron secret storage falls back to plaintext on Linux without a keyring. The focused fake contract proves the encrypted path, not Ubuntu keyring availability. A security decision is needed before using a live bot credential there.
- The direct CLI Jest command could not run because `libs/backend/cli-engine/jest.config.ts` does not exist. The orchestrator must run its scoped project verification.
- Actual Electron screenshots and canary dry-run were outside this lane's allowed commands.
