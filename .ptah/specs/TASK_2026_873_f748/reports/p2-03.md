## Decisions

- Exact failure mode plus affected behavior reuses identity; any other existing candidate on the path is uncertain. Alternative: title/line matching. Evidence: FR-8 and P2-01 identity contract. Reversible.
- Keep SQLite intent rows immutable per head, and let the P2-02 adapter reconcile unknown outcomes through bot-owned markers. Alternative: blind POST retry. Evidence: adapter's marker reads and AC-11.3. Reversible.
- Import GitHub port directly from the public alias because Nx tags permit feature -> data-access and the contract already exists. Alternative: duplicate review-core port. Evidence: current project tags and boundary rules. Reversible.
- Consume `ContextStageResult.incrementalScope` directly at the stage-to-publication call. On follow-up heads, require a new identity on a changed or dependent path for inline publication, use `recheckFailureIds` to accept a verifier-confirmed fixed prior failure, and edit the walkthrough on every head. Alternative: infer incremental state from the current diff alone. Evidence: P2-04 carries durable previous head and open failure IDs (`context/incremental-scope.service.ts:13-37`). Reversible.

## Open questions and limits

- This batch cannot edit the forbidden DI/index/orchestrator files; live wiring remains for P2-06. No live GitHub write was performed.
- Per-PR serialization is process-local. The SQLite intent is durable and marker reconciliation covers restart, but concurrent separate processes sharing the same database need a lease or a single active host guarantee.
- Addressed follow-ups consume verifier `disproved` results only when they identify an exact prior identity in `recheckFailureIds` and explicitly say the failure is fixed or resolved. A prior failure absent from lens/verifier output cannot be marked addressed. Reopened exact identity is recorded, but a separate reopened GitHub follow-up is not yet created.
- Suppression evidence for candidates without a completed verifier output remains in the preview, because they have no stable verifier candidate ID to use as an identity-match key.
- No skill-loading tool was exposed to this CLI lane; repository guidance was used.
