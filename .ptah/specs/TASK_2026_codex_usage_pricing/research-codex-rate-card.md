# Codex API rate card research

Retrieved **2026-11-02**. USD per **1 million text tokens**. This is a rate card for the *published OpenAI API value* of native Codex usage, not a claim that a ChatGPT subscription is charged these amounts. The table uses **Standard, short-context** prices. “Cache write” is its own input-side token class with a separate published price; it must not also be charged at the ordinary input rate. The pricing page additionally distinguishes 30-minute and 12-hour cache writes for some models. [OpenAI API pricing](https://platform.openai.com/docs/pricing).

## Scope and model discovery

- Ptah pins **Codex CLI / App Server 0.165.0** (`libs/backend/codex-runtime/src/lib/protocol/codex-app-server-protocol.manifest.json`, `pinnedVersion`, generated 2026-10-28). The manifest lists `model/list`.
- Ptah's static fallback has seven IDs, in this order: `gpt-6.1-sol`, `gpt-6-astra`, `gpt-6-sol`, `gpt-6-luna`, `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna` (`libs/shared/src/lib/providers/entries/codex-provider-entry.ts:45-58`). Its tier defaults are opus → `gpt-6.1-sol`, sonnet → `gpt-6-sol`, haiku → `gpt-6-luna` (same file, lines 64-68). The source says these IDs followed `visibility: "list"` in a live `codex debug models` catalog on **2026-10-07**; it also says the old `gpt-5.x-codex` IDs failed for ChatGPT-account Codex. These are a *dated fallback*, not a guarantee of today's account-specific live catalog.
- The actual native picker uses paginated App Server `model/list`, up to 100 pages, returning each model's `id`, `model`, display name, default flag and reasoning efforts (`libs/backend/codex-runtime/src/lib/codex-context.ts:852-879`). The pinned schema's `ModelListResponse` has `data` and `nextCursor` (`.../protocol/codex-app-server-protocol.schema.json:15933-15955`); `Model` also contains `defaultServiceTier` and `serviceTiers` (`:15740-15834`). Tests use synthetic model-list pages, not a captured complete live response. A model returned to a different account or on a later date can therefore fall outside these seven IDs.

## Unpriced models

**None of the seven dated static fallback IDs is wholly unpriced**: each has an official API model page with input, cached-input and output rates and an exact cache-write price or formula. This finding does **not** price every possible live `model/list` ID. Treat a live ID absent from an exact OpenAI model/pricing page as **unavailable**, including any ChatGPT-only or Codex-only ID. Do not borrow the price of a similarly named model or of a `-codex` variant. `gpt-7-nova` in `workspace-provider-profile-resolver.spec.ts:1353` is a synthetic future-model test fixture, not evidence that OpenAI offers or prices it.

The historical `gpt-5.3-codex` has its **own** published Standard API rate ($1.75 input, $0.175 cached input, $14 output) on the [official pricing page](https://platform.openai.com/docs/pricing), but is **not** in the seven-ID current static fallback. Its [model page](https://platform.openai.com/docs/models/gpt-5.3-codex) does not publish a separate cache-write price. If a real native session uses this ID and has cache-write tokens, U2 requires **unavailable** for that session; do not import a GPT-5.3 base-model write price.

## Tier and protocol notes

- **Long context:** The [GPT-6.1 Sol](https://platform.openai.com/docs/models/gpt-6.1-sol), [Astra](https://platform.openai.com/docs/models/gpt-6-astra), [GPT-6 Sol](https://platform.openai.com/docs/models/gpt-6-sol), and [Luna](https://platform.openai.com/docs/models/gpt-6-luna) pages state that API requests with **more than 272K input tokens** cost **2× input and cache rates and 1.5× output for the full request**. The three [GPT-5.6 Sol](https://platform.openai.com/docs/models/gpt-5.6-sol), [Terra](https://platform.openai.com/docs/models/gpt-5.6-terra), and [Luna](https://platform.openai.com/docs/models/gpt-5.6-luna) pages likewise state 2× input and 1.5× output above 272K; their language is less explicit about cached reads, so do not silently apply a cached-token multiplier without confirming the applicable price. The [pricing page](https://platform.openai.com/docs/pricing) exposes separate short/long rate tables. For example, `gpt-6.1-sol` Standard long-context rates are **$4 input / $0.20 cached input / $5 30m write / $10 12h write / $15 output**. The GPT-6.1 Sol model page says subscription usage in Codex/ChatGPT Work has **no long-context surcharge**; that statement is about subscription usage, not API-key billing.
- **Processing speed:** The [pricing page](https://platform.openai.com/docs/pricing) has separate **Standard, Flex/Batch, Fast, Ultrafast** tables. Its current GPT-6 flagship rows show Flex/Batch at **0.5×** and Fast at **2×** Standard; Ultrafast is **6×** for the listed `gpt-6-astra` and `gpt-6.1-sol` rows. [GPT-6 Sol](https://platform.openai.com/docs/models/gpt-6-sol) and [Luna](https://platform.openai.com/docs/models/gpt-6-luna) individually document the 0.5× Flex/Batch and 2× Fast rates. Do not assume every model supports every tier. The pricing page states a **10% regional-processing uplift** for eligible models released on/after 2026-03-05 and the FedRAMP uplift noted above.
- **Cache duration:** The [current pricing table](https://platform.openai.com/docs/pricing) has distinct **30m** and **12h** write columns. The pinned `TokenUsageBreakdown` reports `cacheWriteInputTokens` (default 0), `cachedInputTokens`, `inputTokens`, `outputTokens`, and `reasoningOutputTokens` (`.../codex-app-server-protocol.schema.json:25935-25970`), but **does not report write retention duration**. A 12h write cannot be priced using a 30m rate. For `gpt-6-sol`, `gpt-5.6-terra`, and `gpt-5.6-luna`, the cited current pages have no exact 12h-write number.
- **App Server service tier:** The pinned `Model` schema advertises `defaultServiceTier` and `serviceTiers` (`:15775-15834`), and `ModelServiceTier` has `id`, `name`, `description` (`:16058-16077`). `ThreadStartParams` and `TurnStartParams` accept `serviceTier`; `TurnStartParams.serviceTierForTurn` explicitly overrides only the new turn, while null/omitted inherits the thread tier (`:25224`, `:26458-26470`). `ThreadStartResponse`, `ThreadResumeResponse`, `ThreadSettings`, and `ThreadForkResponse` expose a nullable `serviceTier` (`:25312`, `:24589`, `:25027`, `:22020`). **Neither `ThreadTokenUsageUpdatedNotification` (`:25623-25642`) nor `Turn` / `TurnCompletedNotification` (`:26049-26139`) carries the actual billed service tier for each usage increment.** The schema therefore exposes configured/requested tier state, but does not prove which tier every request *used*, especially across overrides or routing changes. `ModelReroutedNotification` separately reports from/to model (`:15984-16011`), which also matters to per-model attribution.

## Decisions

1. **U1:** For ChatGPT-plan native Codex sessions, calculate the published API-rate **value** only when every used token class has a defensible exact price, and label it **“covered by subscription.”** This is a comparison value, not an out-of-pocket charge. The GPT-6.1 Sol docs explicitly waive the long-context surcharge for subscription usage.
2. **U2:** For API-key sessions, use the exact model ID and the applicable rate for each of four disjoint classes: uncached input, cached input/read, cache creation/write, output. `reasoningOutputTokens` is a subset of output and must **not** be added a second time. The calculation is `(uncached × input + read × cached + write × write + output × output) / 1,000,000`, with context/tier/retention adjustments only when known. The 1.25× write figures above are exact arithmetic from OpenAI's published formula, not an inferred neighboring-model price.
3. Show **“unavailable”** when **any used class** has no exact published rate for the actual model and pricing conditions. A zero-token class needs no rate. In particular, no pricing substitution between `gpt-6-sol` and `gpt-6.1-sol`, between base and `-codex` IDs, or between 30m and 12h writes.
4. Treat model, service tier, long-context status and cache-write retention as part of the rate key. A thread's configured tier alone is insufficient evidence of actual per-request tier in this pinned protocol; any Standard estimate made from configuration should be labeled as a **Standard-rate estimate**, not an exact invoice. Where the tier or retention is unknown and could change a used class's rate, apply U2's **unavailable** rule rather than present a falsely exact amount.

## Open questions

- What does a **current, account-specific** `model/list` response contain beyond the 2026-10-07 fallback snapshot? This read-only study did not call an authenticated App Server or paid model endpoint.
- Can the native Codex response or another permitted local source supply **actual billed service tier**, **cache-write retention duration**, and **per-request** long-context status? The pinned usage notification lacks the first two, and its token usage is not itself an invoice.
- Does OpenAI publish an exact **12h cache-write rate** for `gpt-6-sol`, `gpt-5.6-terra`, or `gpt-5.6-luna`, and explicit cached-read long-context treatment for the latter two? The cited current pages do not resolve these cases.
- Recheck `gpt-5.6-sol`'s promotional rates after **2026-11-21**, and refresh the whole rate card when the API pricing page changes.
