## 2. Target behavior and design

### Lifetime usage and reload

Add a host-neutral `CodexSessionUsageOwner` under `libs/backend/agent-sdk/src/lib/codex-app-server/`, with one instance per Ptah session. Its input is validated native usage evidence: session ID, native thread ID, turn ID, parent thread ID when present, model ID, cumulative `total`, `last`, timestamp and terminal state. Keep a map of **absolute cumulative counters per thread** and an accepted `(thread, turn)` checkpoint. A repeated or stale notification replaces neither checkpoint nor total; a higher cumulative update contributes only its positive delta. Persist normalized checkpoints, not raw notifications. A counter reset starts a new epoch only with explicit native reset/thread evidence; otherwise mark coverage partial and keep the last safe total. Preserve four disjoint classes: uncached input, output, cache read and cache creation. Reasoning output stays inside output; do not add it again.

On resume, load the saved per-thread checkpoint **before** consuming the first new notification. Native history can backfill a missing checkpoint only when its thread/turn identity and counter semantics are verified; otherwise retain an explicit partial-coverage state instead of treating `total - last` as a complete lifetime. Record a compact, versioned accounting checkpoint in session metadata using the existing metadata writer and rehydrate it through the existing history/reload route. Persist the last accepted counters and session aggregate atomically with session identity. Reconcile history and checkpoint by stable event identity and monotonic counter, never by summing both. The same snapshot must serve live `sessionStats`, history reload and `session:stats-batch`.

Aggregate every native child thread linked to the root Ptah session. Prefer a native parent/child identity; if it is absent, retain child usage separately with `coverage: partial` until attribution is known. Do not count a child twice if native parent `total` already includes it: compare upstream semantics in the separately authorized live observation and encode the inclusion rule in a fixture. Compaction does not reset lifetime usage; only context display uses the last request/window. Commit any observed positive usage from failed and interrupted turns and publish its snapshot even when terminal state is failure. A terminal without a usage event contributes unknown usage, not invented zero. The native owner should be the authoritative source of `SessionStatsEntry`; `codex-chat-turn-stream.ts` emits it in the existing stats callback, with per-turn `turnCost` and the current model context row.

### Pricing and cost presentation

Resolve billing mode once from the selected session's native execution/auth profile, including explicit home, before the turn. Use a typed `subscription | api-key | unknown` value; do not infer it from quota eligibility or focused UI provider. Keep MCP configuration in the execution profile and never strip it. For each used model, call the existing `findModelPricing` and `calculateMessageCost`, with exact model identity and a recorded catalog source/version/effective date. Accept only an exact ID or an explicitly documented equivalent variant; do not silently fall back to a different model family. Require input/output rates and every **used** cache class to be priced (`pricesCacheTokens`); verify the native cache-write inclusion semantics before converting cache-write counters into disjoint input/cache-creation tokens. An unknown model, missing rate, ambiguous cache semantics, or unpriced used class yields `totalCost: null`, `pricingCoverage: partial|none`, and no misleading numeric total. Keep `knownCost` only as the already labeled subtotal. Reprice persisted token records deliberately when a catalog version changes; never add differently priced cumulative totals.

For U1, subscription gets published-rate token value with `subscriptionCovered: true`, visibly labeled **covered by subscription**, never an actual charge. For U2, API-key gets a final **estimate** in the existing cost chip, not an invoice. No authoritative charge field exists in the inspected native protocol, so the plan never calls it an actual charge. Unknown billing mode stays unavailable. The `CODEX_PROVIDER_ENTRY` zero placeholders are excluded.

The present contract cannot express these final labels. Add optional provider-neutral `costBasis?: 'reported' | 'estimated' | 'covered-by-subscription'` to `ResultStatsPayload` and `SessionStatsEntry` (and the relevant message schema), preserving old producers. `provisional` remains exclusively the live in-turn estimate marker. Pass `costBasis` through the existing stats callback and shared renderer aggregator. The shared `session-stats-summary` cost chip and `cost-badge` show “estimated” or “covered by subscription” beside/inside the existing chip and in its tooltip. Null cost always shows unavailable regardless of basis. No Codex condition or separate Codex UI branch. Inspect all shared cost presentations, including compact/inspector/history, for consistent labels; use one shared formatting helper where needed.

### Plan limits and process policy

Route validated `account/rateLimits/updated` from the long-lived native chat context into the same home/account quota owner/cache used by `provider:getPlanLimits`, after checking native context, resolved home and owner identity. Ignore mismatched or stale notifications. Invalidate or update the relevant per-home cache and push a newer ledger/snapshot revision through the existing broadcaster so `PlanLimitsStore` sees the same data as a subsequent pull. Preserve `rateLimitsByLimitId` plus default limits, primary/secondary windows, reached type, spend-control flag, `individualLimit`, credits, reset credits and upsell in a typed backend DTO. Sanitize display fields; do not expose identifiers, credentials or raw provider diagnostics.

**Default display/order:** show the active `codex` bucket first when present, then other limit IDs in stable lexical order, with primary before secondary within each bucket. Show credits and individual allowance in the existing Plan limits section and `ptah_agent_list` via provider-neutral optional fields/tiles; show reset and reached cause when supplied. Unavailable values stay absent. If credits are `unlimited`, render that state, not a numeric balance. Use a stable bucket-qualified window key to avoid collisions. When a structured limit-reached error arrives mid-turn, project its safe reached type, affected bucket/window and reset time into the existing plan-limit ledger and an actionable, sanitized transcript notice. Preserve any already observed usage and publish its stats. Keep generic notice when structured evidence is absent.

Use **one** `CodexAccountUsageClient` cache/coalescing/process policy for both default and explicit homes. Resolve and normalize the default home before calling it; retain the existing auth and home gates, 30-second hit/miss TTL, abort behavior, native binary verification and `finally` close. Share ownership at the right composition scope so a chat notification can update the same cache seen by RPC without leaking across homes. Electron remains the first host; CLI lanes reuse the host-neutral owner, while VS Code/TUI compile with optional fields.

## 4. Separately authorized live/paid confirmation

Request explicit authorization **after** implementation and scoped tests, with a cap of four paid turns and a chosen account/home. Capture only redacted native event metadata: `(thread, turn, parent)` IDs as stable hashes, `last` and `total` four-class counters, model/window, terminal status, compaction/child relationship, rate-limit bucket/reset/reached type, cached versus new child-process timing, final chip label and metadata snapshot before/after reload. Sequence: fresh turn containing two model requests; one child/compaction turn if possible; close/reopen and one resumed turn; one interrupted or failed turn. Stop at four turns. Compare parent/child inclusion and cache-write semantics before trusting priced totals. Exercise a rate-limit notification only if one naturally occurs; do not deliberately exhaust quota. Measure cold refresh and Windows child cleanup in Electron. No live request or app launch is authorized by this plan.

## 5. Open questions that affect scope

None required to start implementation. The default for credits, individual allowance and bucket ordering is specified above. The only possible scope change is if the pinned native protocol lacks reliable parent/child identity or cache-write semantics: keep those totals explicitly partial/unavailable, document the limitation, and use the separately authorized observation to decide whether a protocol upgrade is necessary.
