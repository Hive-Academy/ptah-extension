## Findings

1. **Serious — `libs/backend/lane-routing/src/lib/decision-model/system-one.live.spec.ts:114-127,153-163,199-207`; `libs/backend/lane-routing/src/lib/routing-constants.ts:116-120`.** The ID-form test makes two successful `SystemOneClient.decide` calls before the latency test. Consequently `durations[0]` is the first *timed fixture*, not a cold inference. Calling its 438 ms value `coldMs` in the comment and `test-report.md:20,27,34` can silently keep the remote timeout at 3000 when a genuinely cold request would trigger the plan's higher-timeout formula. **Fix:** measure the first inference before any successful model call in a fresh session, then record a genuine cold sample and reapply `implementation-plan.md:624-628`; update the comment and report with that result. The current p95 and 1876/2562 ms arithmetic are correct for their recorded values, but the 2562 ms figure is not a verified cold margin.

2. **Moderate — `libs/backend/lane-routing/src/lib/decision-model/system-one.live.spec.ts:129-150`; `libs/backend/lane-routing/src/lib/decision-model/decision-model.probe.ts:103-136`; `.ptah/specs/TASK_2026_684_a11d/test-report.md:39,43`.** A2 requires the keyed empty-body route to answer 400/422 and the control path to answer 404 (`batches.md:84-86`). Thus 7/7 passing does not prove A2, and “Task 21.3 conditional fixes: not needed” is premature for its A2 branch. **Fix:** capture and assert both actual HTTP statuses in the live probe case, report them, then retain probe-based endpoint status or apply the planned key-presence branch according to the result.

## Contract trace and five logic questions

- **Rule and budget:** `routing-constants.ts:109-138` sets local and remote to 3000 ms, margin to 250 ms, and the computed two-request plus gather budget to 8500 ms. For recorded p95 1124 and alleged cold 438, both are below 3000; the margins are 1876 and 2562 ms. `decision-model.target.ts:169-173,261-275` assigns the remote value to remote targets; `pipeline/model-refine.ts:93-109` passes `target.timeoutMs` into `SystemOneClient`. `failure-class/decision-model-failure-classifier.ts:230-232` allows target timeout plus 250 ms (3250 here). `pipeline/model-call.ts:252-253` has a separate 3250 ms structured-call deadline, while `pipeline/model-call.ts:67-96` has no such shorter outer deadline for System One. No examined remote caller deadline is below 3250 ms. The 8500 ms overall constant is a computed budget, not evidence of an enforced wall-clock deadline at callers.
- **A1/A3/A4:** `system-one.live.spec.ts:114-127` exercises the suffixed ID and the supplied output reports both forms true. `:222-231` checks unknown-model `provider-error` with `notFound: true`. `:153-210` makes successful fixture calls through `SystemOneClient`, whose `system-one.client.ts:187-203` parses `SystemOneResultSchema`; the answer object is strict at `system-one.schema.ts:72-80`. These support A1, A3, and A4 for the tested model and responses.
- **1. Silent failure:** `system-one.live.spec.ts:199-207` prints a success-looking `coldMs` even though earlier calls warmed the model; `test-report.md:27` uses it for calibration.
- **2. User action:** selecting the direct Ollama Cloud model after an idle cold start may hit the 3000 ms timeout despite the live report's claimed cold margin (`decision-model.target.ts:176-203,261-275`). Actual cold latency remains unmeasured.
- **3. Wrong-answer input:** a probe route returning 2xx (or a mismatched 404/405 pair) produces `ready` at `decision-model.probe.ts:107-136`, so the report can mark A2 true without its required 400/422 and control 404 statuses.
- **4. Dependency failure:** a failed control request with a route-specific response also produces `ready` at `decision-model.probe.ts:117-124`; the live test's `ready` assertion cannot distinguish this from the intended result.
- **5. Missing requirement:** Batch 21 defines cold as an input to calibration (`implementation-plan.md:623-628`) but the test does not guarantee a pre-inference sample; A2 likewise lacks direct raw-status assertions (`batches.md:84-86`, `system-one.live.spec.ts:129-150`).
