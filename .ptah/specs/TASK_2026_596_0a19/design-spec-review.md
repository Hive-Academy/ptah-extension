## New blocking findings

N1. **Provider equality is being presented as established account identity (Req 4.1-4.3; AC 7.1, 8.2; O1).** HTML line 391 maps every claude-prefixed provider key to claude, every codex-prefixed key to codex, and similarly for other vendors. sameOwner at line 392 compares those family labels and checks only the lane's ownerUnknown flag; it neither establishes account identity on both sides nor includes the resolved Codex account/CODEX_HOME identity. subgroups at line 419 uses the same family key. The new shared-account display therefore asserts “Same account as this session” without evidence sufficient under Req 4.

The explicit unknown-owner fixture is handled safely, but absence of ownerUnknown is not proof of a shared account. Different vendors are an easy different-owner example; they do not test the required same-provider/different-account case. Spec line 139's “a Claude lane in a Claude session” example reinforces the unsafe shortcut without an explicit identity precondition.

**Required correction:** use explicit established quota-owner identities in the fixture and design contract: provider plus resolved account identity, including Codex's resolved account context. Share only when both identities are known and equal. Group by that identity plus model scope, and keep independently unknown owners from supplying each other's evidence. Add same-provider/account-A versus account-B, unknown session owner, and sign-out/account-change examples. Provider names alone must never establish ownership. For a design prototype, explicit mock owner IDs are sufficient; implementing authentication/account discovery is not required here.

N2. **The new same-owner shortcut can point at a plan tile that does not exist (Req 4.5; AC 7.1, 8.2).** HTML lines 465-467 suppress every window's detail whenever sameOwner succeeds, showing only state chips and “see plan tiles.” But planTiles at lines 539-544 filters the session's windows using S.scope. For a Sonnet session with an Opus lane on the very same confirmed account, the session's plan tiles omit Weekly · Opus while the lane's chips include it. The reset, usage and provenance for that allowance are then available nowhere in this grid. The shown Opus-session/Sonnet-lane example only exercises the safe direction and misses this loss.

**Required correction:** deduplicate by allowance coverage as well as owner identity. Only point to plan tiles for windows that are actually rendered there with the same owner/window/model scope. Keep full lane detail for missing model-specific windows, or explicitly render additional lane-only plan tiles with their scope labelled and without making them apply to the session. Add the reverse fixture: Sonnet main session, Opus lane, Opus-only exhaustion. The O1 instruction to avoid repetition cannot remove unique information.

No other new blocking defect was identified in the reviewed Revision 5 changes. The requested tile structure, visible provenance, expired-evidence rendering, stale presentation, textual subtotal separation and compact initial view should be retained.
