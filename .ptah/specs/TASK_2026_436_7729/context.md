## Design direction (architect to decide and verify)

1. **One neutral Ptah instructions body, generated per workspace.** Source = `PTAH_CORE` made
   CLI-neutral + the workspace enhanced prompt. Claude/VS Code-isms in core (webview framing
   :28-35, Task-tool hierarchy :117-144, worktree/teammate rules :133-135, orchestration mandate
   :190-240, `subagent_type` table :224-232, VS Code-only `ptah_lsp_*` :65-68) must be transformed or
   split into a Claude-only section. Extend `transform-rules.ts` (`CLI_TOOL_MAPPINGS` has no opencode/pi).
   Dynamic blocks (memory, symbols, first-query recall) stay session-only — never written to files.
2. **Spawned lanes — native channel, not the task message.** Codex: `developer_instructions` =
   user's own value (read from `CODEX_HOME`/`~/.codex/config.toml`) + Ptah body + role. Others: the
   strongest channel each CLI offers (opencode inline config, agy stdin when over argv budget, etc.);
   fall back to the task preamble. Report the channel as 433 does for roles. Fix the ptah-cli
   duplicate-guidance bug.
3. **User-launched CLIs — new `instructions` harness facet.** Write a fenced, manifest-owned Ptah
   section (begin/end markers, like the `.gitignore` `# ptah:harness:begin/end` block,
   `harness-sync/CLAUDE.md:805-850`) into each CLI's instruction file, preserving all user content
   outside the block. One writer for shared files (`AGENTS.md` is read by several CLIs; codex and agy
   already co-own `.agents/`). Keyed per workspace (TASK_2026_365). Files are normally committed — do
   not add them to the gitignore block. This repo itself commits `AGENTS.md` and
   `.github/copilot-instructions.md` — the dogfood case.
4. **Size budgets.** Core ~18KB + enhanced ~8KB + role ≤64KiB. Argv lanes hit 32,767 (8,191 via
   `.cmd`); codex `developer_instructions` is argv too; `AGENTS.md` hits codex
   `project_doc_max_bytes`. Decide per CLI: file vs argv vs stdin, and what to trim first. Use the
   433 command-line guard; never truncate silently.
5. **Settings/consent.** Writing into user-committed instruction files needs an explicit setting
   (default on or off is a product decision) and a visible harness health row.
