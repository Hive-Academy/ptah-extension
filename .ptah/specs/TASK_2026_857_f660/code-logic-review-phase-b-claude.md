## Findings

1. **Serious — off→on without an intervening admission leaves old results live.** `host-routing.coordinator.ts:174-178,248-265,379-389,480-487`. An assessment or pre-flight starts; the user switches routing off and back on before settlement, with no turn admitted while off. Only `disableReset` increments the epoch, and it runs only when the coordinator observes off. The old result passes both epoch and enable checks and can mutate cache or queue a reminder. Gate 2 tests force a disabled admission (`host-routing.coordinator.spec.ts:663-666,689-691`) and miss this. **Smallest fix:** observe setting transitions and reset affected tabs when off is selected, independent of admissions/settles; test both old assessment and old pre-flight with no intervening admission.
2. **Serious — disabling does not block a reminder already queued for the next hook.** `host-routing.coordinator.ts:415-422,480-492`; `user-prompt-submit-hook-handler.ts:90-109`. Pre-flight queues `Routing:`, then routing is switched off before the next `UserPromptSubmit`. Without a coordinator read first, `take()` injects it despite the disabled setting. This can happen with an already queued prompt, or when the hook runs before post-dispatch admission observes off. **Smallest fix:** invalidate routing entries at the setting transition and guard consumption against the current setting, preserving unrelated hook context.
3. **Serious — a fast assessment can inject its reminder into its own turn.** `chat-session.service.ts:1259-1268`; `host-routing.coordinator.ts:197-211,319-327,415-422`; `session-stream-pump.service.ts:276-289`. `sendMessageToSession` resolves after enqueue, not after `UserPromptSubmit`. If a follow-up is held behind an in-flight turn, its assessment can finish and put a reminder before the SDK reaches that follow-up's hook. The hook then takes the reminder for the same follow-up, contrary to NEXT-turn delivery; it can also replace an older reminder the follow-up should have received. **Smallest fix:** tag a reminder with its producing turn sequence/ID and let the hook consume only entries from earlier turns; test a held follow-up and fast pre-flight.
4. **Moderate, defer — setting read failure has no diagnostic.** `host-routing.coordinator.ts:174,261,387`; `host-routing-setting.ts:12-21`. A throwing configuration read returns `false` internally, so routing stops without a logged stage failure. Chat remains usable. **Smallest fix:** log a safe error class in the setting service or return a tagged failure the coordinator logs, without setting values.
5. **Moderate, defer — closed tabs retain routing state until LRU eviction.** `host-routing.coordinator.ts:124-127,233-237,507-529,613-620`. Closing a tab does not prune its scope text, alias or queued reminder; a long-running Electron process keeps up to 200 stale states and aliases. If a tab ID is reused, a new chat can inherit the old revision/window. **Smallest fix:** subscribe to tab/session close, remove state and aliases, discard its reminder; retain the cap as a backstop.

## Five logic questions

1. **Silent failure:** a configuration read failure looks like user-disabled routing and is not logged (`host-routing-setting.ts:12-21`; finding 4).
2. **Unexpected user action:** a quick off→on toggle allows old results (`host-routing.coordinator.ts:379-422`; finding 1); remaining off can still allow a queued reminder (`user-prompt-submit-hook-handler.ts:90-109`; finding 2).
3. **Wrong answer from input/timing:** a follow-up sent mid-turn can receive its own routing result because enqueue and hook execution are separate (`session-stream-pump.service.ts:276-289`; finding 3).
4. **Dependency failure:** scope/decide/listing rejection leaves chat unaffected and logs a safe class (`host-routing.coordinator.ts:197-213,395-425,444-459`); setting failure lacks logging. A queue throw after `routedRevision` is set leaves the revision marked routed without a reminder (`:415-425`), a low-probability missing-reminder case for transactional ordering when fixing the queue path.
5. **Unspecified lifecycle:** no tab-close contract releases scope state or aliases (`host-routing.coordinator.ts:233-237,507-529`; finding 5).
