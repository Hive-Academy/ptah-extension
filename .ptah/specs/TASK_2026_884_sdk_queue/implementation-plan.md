## Decisions

- **Default delivery:** every provider queues a mid-turn follow-up as a separate next turn for its captured session. The renderer sends it immediately with a client UUID. The backend releases it on turn settlement, independent of selected/hidden tab and window focus.
- **Claude owner:** extend Ptah's existing per-session SessionRecord.messageQueue and SessionStreamPump. The supplied findings prove SDK priority later produces FIFO, but public Query has no cancellation and interrupt leaves SDK-queued messages runnable. Keep the item out of the SDK until Ptah claims it. Preserve Stop and withdrawal.
- **Codex owner:** extend CodexChatPeerQueue's session-object FIFO for user follow-ups. Do not use busy turn/start; live findings show it joins the running turn. Keep peer require-idle behavior. Expose Send now only for Codex via turn/steer with expectedTurnId. A changed turn leaves the item queued; successful steer marks it sent to the active turn. Stop after steer may lose its text; never automatically requeue.
- **End/restart:** Stop withdraws queued items before interrupting, returns only confirmed withdrawn text to the same tab's composer. Session end fails remaining items and never redirects them. Persist accepted pending items in a minimal session-scoped backend recovery record before acknowledgement. After process restart, expose them as failed/recoverable drafts, never auto-run them in a resumed session. This prevents acknowledged text from disappearing when tab-persistence restores without queuedContent.

## Contracts and ownership

Batch 1 defines these exact public types in libs/shared/src/lib/types/rpc/rpc-chat.types.ts and registers them in RpcMethodMap in libs/shared/src/lib/types/rpc.types.ts:

- ChatContinueParams: add queueIntent?: 'next-turn' and require clientMessageId when queueIntent is present. Existing idle callers keep their contract.
- ChatContinueResult: add queueState?: 'queued' | 'admitted' and queuedMessageId?: string; success with queued means accepted, not delivered.
- ChatQueuedListParams/Result, ChatQueuedWithdrawParams/Result, ChatQueuedEditParams/Result, ChatQueuedSteerParams/Result: all carry sessionId and tabId; mutations also carry clientMessageId. List returns ordered items and revision. Withdraw/edit only work before claim. Steer requires the expected active turn and returns TURN_CHANGED without removing the item on mismatch.
- ChatQueuedMessageStateEvent: {sessionId, tabId, clientMessageId, state: 'queued' | 'delivered' | 'withdrawn' | 'failed' | 'steered', reason?, revision}. Publish this event independently of CHAT_CHUNK viewport suppression. Hidden statusOnly terminal copies update status only; they never release the queue.

The RPC names are chat:queued-list, chat:queued-withdraw, chat:queued-edit and chat:queued-steer. chat:continue accepts queueIntent. Validate UUID, text, attachments, ownership and method params with Zod at the handler. chat: is already in ALLOWED_METHOD_PREFIXES; update exact method map and surface guards. Duplicate UUID with same session/payload returns the existing receipt; conflicting reuse fails. Each backend entry captures immutable sessionId, tabId, registration token/session object, UUID, text, attachments, options and FIFO position. Before admission, recheck the live registration and provider thread. Never look up the active tab as a fallback. After asynchronous preparation, recheck identity again. Delivery event means the provider accepted the next turn, not that it completed.

The backend queue coordinator belongs to chat-session.service.ts and a small adjacent service behind a chat/tokens.ts Symbol.for token. Claude SessionStreamPump claims one queued entry after SessionRegistry.markTurnEnded wakes it. Codex peer FIFO admits one after idle. Both report queued/delivered/withdrawn/failed by UUID. The coordinator persists a pending recovery record before acknowledging; write failure rejects acceptance. It deletes/updates the record on terminal states and loads remaining records as failed drafts after restart. chat:abort performs withdraw-all and interrupt as one ordered operation, returning confirmed withdrawn items; a raced claimed item is reported as admitted and is not restored as unsent. No per-item timer or observer.

The renderer keeps a session-keyed signal store of backend queue receipts and events. It submits with captured tab/session, reconciles from chat:queued-list on reconnect/restart, and retains failed submissions as editable drafts. It removes queuedContent as source of truth. Composer shows queued items with Edit/Withdraw, plus Codex-only Send now. Stop restores only confirmed withdrawn text in FIFO order. A tab close, reset, or new session in the same tab detaches the old view, never retargets its pending work. Held slash commands remain separate ordered items; a command that ends/replaces its session fails later items into drafts. The CommandCenterSendLockService release path sends a held local draft for its captured session after release; it no longer flushes queuedContent. Budget actions, auto-handoff and setup-wizard stores use the same session-keyed queue state and entry point.
