# Research Report - TASK_2026_418_a91c

## Question

- Decision this supports: how to make post-PR #490 Codex-proxy session statistics truthful without changing the Claude Agent SDK harness or reintroducing PR #490's proxy-usage accounting defect.
- Question: where must cost, scope, context-capacity, and compaction values be normalized so direct Claude, Codex proxy, OpenRouter, resume/restart, duplicate JSONL records, and background subagents remain correctly attributed?
- Bounds: no live provider calls, no Ollama invocation, no product-code edits, no private-log material or unsanitized fixture content, and no claim about provider invoices, subscription allowance, or cache efficiency.

## Answer

Normalize cumulative SDK result telemetry at the backend stream-result boundary, before it becomes `session:stats`; retain a per-query/process generation ledger keyed by resolved SDK session identity plus a locally minted stream/run identity, and emit only the positive delta for that exact ledger. This wins because the current frontend adds every incoming value to replayed totals, while the SDK contract comments define result/model usage as cumulative; a ledger keyed only by session ID would subtract a prior process or resumed stream and make a valid first result disappear. Keep main-session current-context independent from tree/session totals, derive capacity only from the effective provider/model's authoritative response/catalog metadata, and display unknown rather than a guessed window. Compaction must show a reduction only when both measurements are an SDK-native, same-boundary pair with documented comparable semantics; the current `preTokens` live/resume sample and SDK `compact_metadata` result are not proven comparable.

## Disagreements

- Cumulative vs per-turn telemetry: `StreamTransformer` comments call result/model usage cumulative, but `SessionStatsAggregatorService` treats each `SESSION_STATS` payload as additive. The deciding local fact is the frontend addition at `:135-154`; normalize before that call rather than changing PR #490's Responses usage translation.
- Main scope vs tree scope: `LiveUsageTracker` intentionally tracks a single latest-request frame for a compaction/context sample, while `SessionHistoryReaderService.aggregateUsageStats` sums main and subagent histories. Both are valid but must never be labeled or combined as the same “session tokens” quantity.
- Capacity source: OpenRouter publishes model-specific `context_length`; shared helper fallback can use pricing-map entries or Claude regex; Codex proxy has no inspected authoritative context-window metadata. The configured provider route, not a bare model string, decides whether capacity is known.
- Compaction measurement: SDK `compact_metadata` supplies `pre_tokens`/`post_tokens`, while the PreCompact callback supplies a tracker sample. The code does not document that these values are identical measures, so source evidence does not support “shrank.”

## Local consequences

- `libs/backend/agent-sdk/src/lib/helpers/stream-transformer.ts`: introduce the normalization boundary immediately before `onResultStats`. Ledger identity must be `{ resolvedSdkSessionId, streamRunId }`, where `streamRunId` is minted for each query execution and reset on teardown; include model identity inside entries. Do not use a global session-only map.
- `libs/backend/agent-sdk/src/lib/helpers/session-query-executor.service.ts` and query lifecycle caller: own/mint the run identity so restart/resume cannot inherit a predecessor process snapshot. A new run's first valid cumulative result is its baseline delta, not zero.
- `libs/backend/agent-sdk/src/lib/session-history-reader.service.ts`: deduplicate usage-bearing assistant records by stable `message.id`; when absent use JSONL line `uuid` only. Apply separately to main and each agent file so same-looking nested messages do not collapse across agents. Deduplicate before totals/per-model/cost accumulation; leave content replay ownership unchanged.
- `libs/shared/src/lib/utils/subagent-cost.utils.ts` and `libs/frontend/chat-ui/src/lib/molecules/session/session-stats-summary.component.ts`: expose named scopes: main/latest-request context fill, main-session cumulative cost/tokens, and full execution-tree cost/tokens. Never compute current context from tree aggregation or show a tree cost as main-session cost.
- `libs/shared/src/lib/utils/pricing.utils.ts` and `libs/backend/agent-sdk/src/lib/helpers/sdk-query-options-builder.ts`: do not accept a model-only `maxTokens` map as sufficient provenance for Codex. Prefer effective response metadata, then active-provider catalog metadata scoped by provider+model, then first-party SDK authority; otherwise return unknown and omit `CLAUDE_CODE_MAX_CONTEXT_TOKENS`.
- `libs/frontend/chat/src/lib/services/chat-store/session-live-stats.util.ts`: retain PR #490 behavior of preferring `lastTurnContextTokens`; if capacity is unknown or no last-turn sample exists, suppress the fill rather than compute 0% from cumulative totals.
- `libs/frontend/chat-ui/src/lib/molecules/notifications/compaction-marker.component.ts` and `libs/frontend/chat/src/lib/services/chat-store/compaction-lifecycle.service.ts`: replace “shrank A → B” with neutral “Context compacted” unless one explicit SDK-native boundary record includes comparable `pre_tokens` and `post_tokens` plus provenance. ## Unknowns

- Codex authoritative context capacity is unknown from the inspected proxy/auth/model code. Smallest experiment: a sanitized mocked Codex model/response metadata contract test, followed by an authorized live metadata capture that records only model ID, capacity field, provider route, and retrieval timestamp—never credentials or message content.
- Whether every SDK `result.usage` is process-cumulative under every adapter/version is not independently proven beyond source comments. Smallest experiment: a sanitized async SDK fixture emitting two results for one run, then a fresh run/resume with the same SDK session ID; assert output deltas `first cumulative`, `second-minus-first`, and fresh-run baseline behavior.
- Exact SDK `compact_metadata.pre_tokens/post_tokens` semantics relative to live usage are undocumented in inspected code. Smallest experiment: sanitized fixture with one PreCompact callback and one compact-boundary payload whose fields deliberately differ; UI must not render a reduction until explicit common provenance is present.
- Background-subagent event timing versus parent completion is only structurally covered: forwarded subagent text has `parent_tool_use_id`, but historical aggregation loads agent JSONL separately. Smallest experiment: parent plus one nested agent fixture, repeated assistant `message.id` within one file, same `message.id` across distinct files, and late background-agent completion; assert per-file dedupe, preserved tree total, and unchanged parent main-context gauge.
- Direct Claude’s SDK cost is reported as authoritative SDK telemetry, whereas Codex/OpenRouter cost is locally calculated from available pricing. It remains unknown whether a provider route’s rate catalog represents a user invoice or subscription allowance; it must remain labeled reported/estimated telemetry and `null` when no price provenance exists.
