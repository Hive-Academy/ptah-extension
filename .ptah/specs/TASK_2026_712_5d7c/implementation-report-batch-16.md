## Decisions

1. **Stop SDK attachment at the ownership boundary.** Options: add a versioned session-binding mapping migration (recommended next batch/ownership expansion); misuse `run_id` as an SDK alias; create schema opportunistically in the store. Evidence: `libs/backend/persistence-sqlite/src/lib/migrations/0058_provider_accounts.ts:58` defines a run-ID primary key and has no SDK ID column, attachment state or mapping table. Its run lease is also keyed by run ID at line 74. The latter options overload identity or bypass migration ownership. No such schema was created. Reversible once the coordinator assigns migration ownership.
2. **Refuse collisions explicitly.** Options: composite-key all metadata and every consumer; explicit typed refusal. D16 and acceptance expressly allow refusal. Existing repository APIs key all metadata by SDK session ID, so this batch preserves their ambient behavior and rejects a different immutable binding. Reversible with a separately planned key migration.
3. **Use the persisted zero-based registry epoch contract.** Options: reject epoch/revision zero using the shared public binding schema; parse the actual registry contract locally. Evidence: migration 58 defaults both fields to zero (`:19-20`), while `libs/shared/src/lib/types/provider-account.schemas.ts:47` and `:121-123` require positive values. The local strict schema accepts nonnegative safe integers and SHA-256 route fingerprints, matching the authoritative store. This existing public-schema mismatch is reported for its owner; no shared file was edited. Reversible when those contracts are aligned.
4. **Flush named metadata inside the write queue.** Options: rely on ordinary queue-drain coalescing; force the named checkpoint's flush before resolving. Evidence: `settleWrite` intentionally skips flushing while another operation is queued. Named admission needs stronger durability, so only bound writes force a flush. Existing ambient coalescing remains. Reversible.
5. **Preserve omitted linkage on completion, refuse different explicit linkage.** This lets existing completion callers keep their current shape without erasing the binding. A previously persisted ambient entry cannot be silently adopted by a named import. Evidence: D16's same-ID rule and immutable linkage requirement. Reversible only with an explicit migration policy.
