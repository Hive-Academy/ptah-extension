## Architecture decision

**Chosen:** Keep `libs/backend/skill-synthesis` and `libs/frontend/skill-synthesis-ui` as the homes for Library and telemetry. Replace `SkillCandidateStore` with an event/grade store in the same backend library, extend `SpecHarvesterService`, and keep the existing Library and `skillSynthesis:*` RPC namespace for surviving methods. Add a small task-grade projection table, because an invocation event alone cannot represent corrected reviews or distinguish an agent, skill and command grade. Keep 646's lane-outcomes port in the direction it already has: lane-outcomes depends on the port, skill-synthesis implements it.

**Rejected:** A new Library library would move active contracts and multiply DI rewiring without a requirement. Using prompt expansion or tool success as a grade reproduces the false 100%. Keeping `SkillCandidateStore` for its event methods leaves the deleted candidate schema and pipeline coupling alive. Deriving every UI render directly from task files is unbounded I/O and loses review history when task folders are archived.

**Attribution boundary:** `UserPromptExpansionPayload.expansionType` already distinguishes `slash_command` from `mcp_prompt` (`agent-sdk/helpers/user-prompt-expansion-callback-registry.ts:8-16`; hook handler `:55-61`). Encode new slash-command uses with a distinct `skill_invocation_events.source='slash-command'` value; `source='subagent'` maps to Agent and `source='tool-use'` to Skill. Keep old `source='prompt-expansion'` rows and new unresolved `mcp_prompt` uses unclassified unless a command clone identity resolves uniquely; do not retroactively guess their subject kind. This uses the existing `source TEXT` column rather than adding an unreviewed schema field. For skill and command uses lacking `task_id`, read `session_task_links` through `session-organization.store.ts:201-216` (written by `ISessionOrganizationRecorder.linkTask`, `session-organization-recorder.interface.ts:40-47`; migration 0050), matching workspace and a unique primary task link. `agent-sdk/session-metadata-store.ts` is UI metadata, not the task link source. An absent or ambiguous link leaves a use ungraded. Verify any additional shipped clone origins and migrated profile paths before the one-time skill removal or snapshot prune.

### 2. Review-derived success signal

- Extend `SpecHarvesterService` off `SkillCandidateStore` to the event/grade store. `spec-extractor.ts` accepts valid `task.md` carriers only; reads `batches.md` with permanent `tasks.md` fallback, `code-logic-review.md`, `code-style-review.md`, all matching `*-review.md`, `test-report.md`, and validated `judge-round-*.json`. Exclude plan and architecture reviews from executor grades; they grade the planning session only if that session has an exact run/task attribution, otherwise remain findings only. Parse only explicit terminal verdict fields/status sections, normalize agent/skill/command names against Library registry, and retain bounded review findings with path, task, batch and artifact digest. Reject traversal/symlink escapes and malformed or oversized JSON as ungraded with a logged reason, never as success.
- Attribution order: exact `run_id` in 646 lane records or event; then matching task id + session id + workspace, using `session_task_links` (0050) for skill/command events without `task_id`; only then a unique slug/batch within a bounded task window. Do not grade all uses of a slug in a task when multiple runs could match. `skill_invocation_events` (`0037`, `0055`), `skill_session_verdicts` (`0034`), and `lane_outcome_records` (`0054`) provide the existing joins. The existing prompt-expansion payload's `expansionType='slash_command'` is the command-kind source; an unresolved `mcp_prompt` stays use-only. A terminal task status or a tool return code alone is not a grade.
- New `skill_task_grades` table in 0056 stores the only rate-bearing decision per `(task_id, subject_kind, subject_slug, run_id-or-attribution-key)` with verdict, source file/digest, workspace, graded timestamp and bounded findings reference. 0056 backfills only reconciled event rows whose subject kind and task/run provenance are unambiguous (about 81 reconciled rows in the measured profile are candidates); ambiguous or unreconciled events stay use facts, not grades. Re-harvest uses an artifact-digest/version marker and UPSERTs corrections; review changes invalidate prior grade. Conflicting unresolved explicit verdicts produce NULL/no-grade and a diagnostic, with a final explicit review verdict taking precedence over earlier rounds. `cancelled` has no implicit failure or success. One run contributes at most once across event and lane records.
- For an attributable run, precedence is explicit batch verdict > exact lane `final_review` > task-level code review; later corrected evidence at the same rank replaces the prior grade by digest, never adds a second denominator. Skills and commands need an explicit subject-kind event and unique session/task link; aggregate graded runs by subject from `skill_task_grades`, while total uses come from events. Plan-review REVISE never grades an executor.
- `SkillScorecardService` aggregates `wins / graded runs`; if graded count is zero return `null`, display **No grade**. Show use count and graded count alongside the rate. The Library’s Agents, Skills and Commands tabs use the same meaning; agent scorecard and 646 outcome signals remain visible. Review findings linked to the selected slug and grade feed the `SpecFindingsPort` used by manual Enhance draft. A task-level association is evidence about a use, not a causal lift claim.
