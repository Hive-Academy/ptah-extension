## New defects

1. **Blocking — an Ollama agent's usage can be attributed to another key's owner.** `libs/backend/auth-providers/src/lib/quota/provider-owner.resolver.ts:488-505`; `libs/backend/auth-providers/src/lib/quota/plan-credential.source.ts:95-126`; `libs/backend/auth-providers/src/lib/quota/plan-usage.service.ts:257-272,369-374`. Owner resolution and credential resolution read the agent slot separately. If the slot is the sign-in placeholder when the owner is resolved, the target owns the shared provider key; if the agent slot becomes a real key before the credential read, the request uses that real key while the snapshot remains under the shared key's owner. The reverse transition has the same problem. **Fix:** resolve owner and credential from one captured slot value, or verify the credential's derived owner against `target.ownerRef` before using or caching the reading and restart on a mismatch.

2. **Major — an Antigravity account switch can remain unavailable for 60 seconds.** `libs/backend/auth-providers/src/lib/quota/readers/antigravity-oauth-plan-usage.reader.ts:326-348`. A request for owner B while the keyring still holds A records `recentMismatch` for B. If the user then signs into B, subsequent B reads hit the 60-second guard before checking the keyring, returning `service-unavailable` despite valid B credentials. This is an account-change regression from the new mismatch throttle. **Fix:** remove the guard, or invalidate it when account/keyring state changes; never suppress a fresh read for the currently requested owner after a sign-in change.
