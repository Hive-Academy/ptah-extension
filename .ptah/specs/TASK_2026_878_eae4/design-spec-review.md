## Findings

1. **Serious** — prototype/index.html:64,66,1751,1805-1807 use `docs.ptahcode.com`, `github.com/ptahcode/ptah` and a VS Code Marketplace link. The live site uses `https://docs.ptah.live` (libs/web/ui/src/lib/navigation.component.ts:92, footer.component.ts:133) and `https://github.com/Hive-Academy/PtahCode` (parity-inventory.md:19). parity-inventory marks these links `keep`, so the prototype contradicts its own inventory. The marketplace link does not exist anywhere in libs/web or apps/ptah-landing-page/src, and the project is Electron-first. It is a new CTA the owner did not ask for.
2. **Serious** — The prototype footer (index.html ~1774-1808) and nav drop the Discord, Reddit and LinkedIn community links. The inventory (parity-inventory.md:19,51) says they are kept. Either the prototype is wrong or the inventory is. Footer `Terms` (`/terms-and-conditions`) is merged into one "Privacy & Terms" link pointing only to `/privacy` (index.html:1808).
3. **Serious** — parity-inventory.md section numbering does not match design-spec.md §4. The inventory maps to S4 memory, S5 multi-vendor, S6 cost, S7 phone, S8 skills, S9a/S9b providers/CTA (parity-inventory.md:26-47). The spec has S5 decision model, S6 multi-vendor, S7 cost, S8 phone, S9 skills, S10 providers+CTA (design-spec.md:110-121). Row 42 sends the "Security Review" cross-vendor-review fact to "S5 multi-vendor (F01/F02)". In the spec that fact lives in S5 decision-model, but the row says multi-vendor. An implementer cannot trace this reliably. Regenerate the inventory against the final section IDs.
4. **Moderate** — Invented sample telemetry in the spec is not labelled illustrative: corpus `billing-and-auth-invariants`, "18 curated memories · 42 symbol anchors", "Coverage: 96.4% (1,412 / 1,464 files)" (design-spec.md:208-209), judge "Score: 74 → 93" (design-spec.md:366), "2 / 3 active" (design-spec.md:281). None of these numbers is in hidden-features-analysis.md (grep for 96.4 returns nothing). Rule 2 in §3 says every number maps to F##. Require an "Example data" label on these panels, or use real shapes without numbers.
5. **Moderate** — design-spec.md:236 (S6 item 1) says "Switch runtimes mid-session without abandoning your workspace" and the F03 marketing hook in the analysis pairs that with the carry-over. The carry-over mechanism is exactly the part the analysis flags as not confirmed (16 messages / redaction). The spec correctly drops the figure, but the continuity claim itself rests on the same unverified projector (`codex-carry-over-projector.ts`). Soften to "choose Claude or Codex as the main runtime" unless the switch behaviour is confirmed.
6. **Moderate** — design-spec.md:300 subhead "Most agent hosts replay expired prompt caches at full input price or discover a subscription cap mid-refactor" is a categorical competitor claim. The analysis (Competitor exclusivity) says no competitor was audited. It breaks the spec's own §3 rule 4 (design-spec.md:100). Rewrite as a Ptah-only statement.
7. **Moderate** — Light theme. prototype/styles.css:55-66 and the "Light Check" toggle (index.html:26-27) add a `[data-theme="light"]` palette that redefines `--ink-*`. The landing app ships only the `operator` theme (tailwind.config.js:95+). Keep it out of the implementation, or state clearly that it is a reviewer toolbar only. Also `--ink-400:#434b5c` appears in the light block only, and the dark `ink-500 #5b616f` is used decoratively (spec says not for required reading), which is fine.
8. **Moderate** — Accessibility gaps in the spec: no skip-link or focus-order statement for the new anchor-nav; no `tabindex`/skip in prototype. Reduced-motion is covered globally (styles.css:1583-1592) and per section in the spec's motion table (design-spec.md:446-455), but videos in S2 are described "paused with controls" while the hero's pause toggle pattern is not reused or referenced. No WCAG numbers are given for text on `--panel-bg` translucent glass; only `--bcm` has a measured ratio (5.46:1, plausible for #838894 on #08090c). Add measured ratios for text-ink-400 on ink-850.
9. **Minor** — Alt text is present on all 16 prototype images and is descriptive; however three use filenames-as-labels ("01 Orchestration", "02 Council", "03 Command Center", index.html:128-148). The hero band is a static reference only, so it is cosmetic. "02 Council" also names Tribunal while the spec excludes Tribunal below the hero.
10. **Minor** — Token drift: spec §2.3 says the ledger bar copies `.story-outro` with padding `max(1.5rem, calc((100vw - 74rem)/2))`. The real rule is `max(1.125rem, calc((100vw - 64rem)/2))` (hero.component.css:92). Colour/radius/shadow/focus tokens otherwise match.
11. **Minor** — Page-flow detail: executive summary (design-spec.md:8) says chapters `01`…`09`, while the hero's last chapter is `04 / 04`. Numbering a new ledger from `01` right under `04 / 04 · Built to ship.` can read as a reset. Consider continuing from `05`.
12. **Minor** — Implementability: no spec statement on standalone OnPush component names, file layout in libs/web/landing/src/lib/sections, or SSR-safe handling of the GSAP timelines (the spec only says SSR gets a static DOM). Section IDs `#features`, `#the-onboarding-problem`, `#skills-orchestration`, `#providers`, `#cta` are correctly preserved or aliased.
