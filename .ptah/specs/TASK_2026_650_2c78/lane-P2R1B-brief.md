## Defects to fix (all)
1. S2 - orphaned `running` agent checkpoint maps to `starting` forever. wizard-generation-binding.ts:29-43 (consumer wizard-generation-rpc.handlers.ts:241-269). After a host restart there is no controller; lookup returns `starting` with no result indefinitely. Fix: when `manifest.lifecycle === 'running'` (or starting) and there is no active controller in this process and `updatedAt` is older than 30 s (constant), return a terminal `failed` state with an additive optional resumable hint (e.g. `interrupted: true` / `resumable: true` on SetupGenerationResultFacts or the run state - add it to rpc-setup.types.ts as an optional field) and `committedState: 'unknown'`, so the UI can offer Resume. Keep `starting` only inside the 30 s window. Do NOT rewrite the checkpoint during lookup (lookup is read-only).
2. M3 - bound submit swallows the explicit model error. `resolveProviderRoute` throws `RpcUserError(..., 'INVALID_PARAMS')` (wizard-generation-binding.ts:~287-290), called at wizard-generation-rpc.handlers.ts:~437-445 inside the try whose catch (~374-394) replaces every bound error with "Agent generation could not start. Please retry.". Fix: rethrow RpcUserError (or return a safe user-readable error) so the user sees that the model is unavailable.
3. M4 - `isTrusted` (wizard-generation-checkpoint.service.ts:~281-296) checks outputDirectory, analysisDir and manifest.analysisDirectory only. Add the new persisted paths: `source.analysisDir` (when source.kind is verified-analysis), `workspaceRoot` and `tabBinding.workspacePath` - each must be inside / equal to the authorized workspace like the existing checks. An untrusted manifest is ignored as today.
4. M5 - finalize failure skips propagation for tabless runs. wizard-generation-rpc.handlers.ts:~768-778 `afterSettled` awaits `finalize` before propagating written agents. Fix: propagation of written agents runs even when finalize throws (try/finally or propagate first when writtenCount > 0); keep the reported failure (no `done` on finalize failure, per plan).
5. M6 (agent side) - path spelling. Authorization (`authorizeTabWorkspace`, wizard-generation-binding.ts:101-115) is realpath-based and case-insensitive on win32 and RETURNS the canonical host realpath. But the agent side stores/compares the client `tabBinding.workspacePath` string: supervisor `abortBound`, checkpoint `locateBound` (wizard-generation-checkpoint.service.ts:~260-262), `blockedSubmit`. Fix: after authorization, replace the binding's workspacePath with the canonical value returned by `authorizeTabWorkspace` everywhere a binding is stored or compared (submit, cancel, retry, preview, lookup). Old checkpoints with a differently spelled stored path must still match: compare canonically (realpath / win32 case-insensitive) when reading.
6. M8 - agent `analysisData` is parsed before authorization. wizard-generation-rpc.handlers.ts:~293 parses `WizardSubmitSelectionParamsSchema` (incl. ProjectAnalysisResultSchema on client data) before the tab/host check at ~311-340. Fix like the guidance handler (enhanced-prompts-rpc.handlers.ts registerRunWizard): detect the `tabBinding` envelope first, authorize, then parse the bound params WITHOUT analysisData (omit it; bound runs ignore it). Tabless parsing unchanged.
7. Cross-tab resume adoption. wizard-generation-rpc.handlers.ts:~529-542 passes `analysisDir=null` to `locateResumable` for a bound resume, then `prepareResume` overwrites `tabBinding` (wizard-generation-checkpoint.service.ts:~336-343). Tab B can adopt tab A's paused run and tab A loses it. Fix: a bound resume only resumes a checkpoint whose stored tabBinding matches the same tab (canonical compare) OR an old checkpoint with no tabBinding (bind on authorized resume, as B02 allowed); a checkpoint bound to another tab returns `rejection: { reason: 'blocked', ownerTabId }` (same workspace only). Tabless resume unchanged.
8. Provider/model after resume and fallback defaults. wizard-generation-checkpoint.service.ts:~346-358 overwrites provider with the current provider but keeps the old model, without validating the model for the new provider. Fix: on resume, snapshot both provider AND a model validated for that provider (same resolver used for new submits). Also in the lookup/accepted/completeWithoutWork fallbacks (wizard-generation-binding.ts ~236-241, handler ~740-742) do not invent `'anthropic'`/`'sonnet'` for a manifest without a snapshot: use `'unknown'` (type is string) so the UI can hide the line; document this in the report as a note for frontend batch B07.
9. Preview-required rejection. Bound submit without a confirmed bound preview (wizard-generation-rpc.handlers.ts:~446-465, cap 64 at ~900-903) returns only an error string shared by "never previewed" and "targets changed". Fix: add an additive rejection reason `'preview-required'` to SetupGenerationRejection in rpc-setup.types.ts and return it with the existing message. Also: do not consume the confirmed preview if a later launch step fails before the run is accepted.
10. Minor race: retry-item checks `runs.isActive` (~1186) and calls `runs.run` after several awaits; a concurrent submit can make `run()` throw "already active", and submit then returns `accepted` and finalizes `failed` with no terminal push (`launchSubmittedRun` ~637-666). Fix: in that failure path, broadcast the terminal `failed` event to the binding (one push), so the tab is not left waiting. Keep it small.
