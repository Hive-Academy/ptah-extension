## New findings

1. **Moderate — quick popup keys during the fold act on the textarea.** `chat-input.component.ts:393` has no dropdown for up to 240 ms, but `:1832-1852` forwards navigation/Enter only when that dropdown exists. With `showSuggestions()` true, Enter cannot send, yet its default action inserts a newline into the textarea rather than selecting the highlighted slash/@ suggestion; arrows move the caret instead of the list, and Escape cannot close it until it renders. A user who types `/` and presses Enter promptly can end up with `/\n` and a filtered-out command list (`libs/frontend/chat/src/lib/directives/slash-trigger.directive.ts:101-139`, `chat-input.component.ts:1510-1529,1562-1576`). Ordinary typed characters update the trigger query and normally populate the panel after the 50 ms projection debounce; a character typed just before unclip may appear in the list after that debounce. This is a short but real keyboard gap, not a send or data-loss defect. The new specs check panel presence, not these keys.
