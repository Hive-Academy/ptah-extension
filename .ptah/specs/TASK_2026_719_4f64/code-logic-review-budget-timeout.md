### 1. Serious — 120 seconds does not bound the complete chat-start operation

**Evidence:** [executor:1096](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-query-executor.service.ts:1096) starts the 90-second clock only after the handler's preparation. [chat-session:894](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/backend/rpc-handlers/src/lib/chat/session/chat-session.service.ts:894) first awaits MCP overrides; [chat-session:461](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/backend/rpc-handlers/src/lib/chat/session/chat-session.service.ts:461) awaits OAuth overrides, whose [serial loop:54](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/backend/cli-agent-runtime/src/lib/mcp-directory/oauth/mcp-oauth-override-resolver.ts:54) refreshes every configured record. Each request can consume [15 seconds:30](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/backend/cli-agent-runtime/src/lib/mcp-directory/oauth/mcp-oauth-metadata.ts:30).

**Scenario:** six connected MCP servers have expired tokens and slow refresh endpoints. Their serial refresh failures consume roughly 90 seconds, then the observed 35-second named admission completes at roughly 125 seconds. Every individual deadline is respected. At 120 seconds, [renderer:172](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/frontend/core/src/lib/services/claude-rpc.service.ts:172) deletes the pending response without cancelling host work. [message-sender:505](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/frontend/chat/src/lib/services/message-sender.service.ts:505) marks the tab idle/failed, while [chat-session:953](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/backend/rpc-handlers/src/lib/chat/session/chat-session.service.ts:953) can subsequently start broadcasting the admitted session. Retrying can overlap that late run.

**Fix:** start an absolute admission deadline at the handler boundary, propagate its remaining time and cancellation through preparation and SDK admission, and reserve a bounded cleanup/response margin. Expiry must prevent later launch/commit/broadcast. Add a regression covering slow pre-admission OAuth preparation plus an otherwise valid admission. Increasing the renderer constant alone does not establish the claimed invariant.

### 2. Moderate — an expired total budget can still return success

**Evidence:** [executor:722](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-query-executor.service.ts:722) clamps an exhausted budget to zero, then races the pending promise against `setTimeout(0)`. [executor:737](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-query-executor.service.ts:737) checks only disposal/abort; [executor:894](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-query-executor.service.ts:894) likewise does not check elapsed time before admission.

**Scenario:** synchronous work or an event-loop stall crosses the deadline before a resolved/cached step is awaited. An already-fulfilled promise wins against the zero-delay timer; `finally` clears that timer. Further immediately resolved steps can do the same and reach `admitted = true`. Even `wait(Promise.resolve(value))` after the recorded deadline returns a value instead of refusing.

**Fix:** reject and abort synchronously when no budget remains, recheck a monotonic deadline after each awaited result and immediately before admission, and check before starting side effects (prefer a lazy operation callback to an already-started promise). Add expiry-before-entry and expiry-during-synchronous-work cases; the paused-commit test at [accounts spec:601](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-query-executor.accounts.spec.ts:601) does not exercise either.

### 3. Moderate — failed Providers chunk loading has no recoverable UI

**Evidence:** [settings template:164](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/frontend/chat/src/lib/settings/settings.component.html:164) introduces a separate asynchronous dependency for the default Providers tab, but supplies only an empty busy placeholder and no `@error` state.

**Scenario:** a missing/stale chunk or asset-load failure leaves the user unable to reach provider setup, including after the boot auth redirect. There is no accessible explanation or recovery action. The equivalent omission in other tabs does not cover this newly deferred authentication entry point. Angular provides an [error block for deferred dependency failures](https://angular.dev/guide/templates/defer).

**Fix:** add an accessible load-failure message with a working reload/recovery action and verify the deferred error state.
