### M1 — Moderate, new: expiry abandons an already-started promise

**Evidence:** [ex:738](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-query-executor.service.ts:738) accepts a promise, but [ex:741](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-query-executor.service.ts:741) throws before `Promise.race` attaches a rejection handler. At [ex:1123](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-query-executor.service.ts:1123), `getQueryFunction()` has already been called; its load-failure branch rethrows ([loader:89](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/backend/agent-sdk/src/lib/helpers/sdk-module-loader.ts:89)).

**Scenario:** preparation consumes the deadline, then SDK loading returns a rejected promise. The RPC receives the typed timeout refusal, but the SDK promise has no rejection observer and separately produces an unhandled rejection. The same problem applies to eager promise-producing arguments at later waits. This did not happen when every input was attached to the race.

**Fix:** prefer a lazy operation callback, checking expiry before starting work and attaching rejection handling immediately afterward. If keeping the promise API, observe the supplied promise even on the early-expiry branch. Add expired-entry plus rejected-dependency coverage; the new bootstrap-expiry fixture ([spec:623](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-query-executor.accounts.spec.ts:623)) bypasses the executor's module-loader call.

### M2 — Moderate, residual F1: the 30-second margin does not bound preparation or cleanup

**Evidence:** [chat:480](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/backend/rpc-handlers/src/lib/chat/session/chat-session.service.ts:480) still awaits all serial OAuth refreshes ([oauth:54](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/backend/cli-agent-runtime/src/lib/mcp-directory/oauth/mcp-oauth-override-resolver.ts:54)) without a deadline race. The per-request limit is 15 seconds (`libs/backend/cli-agent-runtime/src/lib/mcp-directory/oauth/mcp-oauth-metadata.ts:30`). Cleanup also awaits reservation settlement without a response bound ([ex:986](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-query-executor.service.ts:986)).

**Scenario:** nine refreshes taking roughly 15 seconds each keep the host in preparation beyond the default 120-second renderer timeout. The renderer drops the pending response ([rpc:173](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/frontend/core/src/lib/services/claude-rpc.service.ts:173)); the eventual host refusal is lost. D73 prevents the old late admission in this scenario, so severity is reduced from Serious, but the end-to-end response claim remains false.

**Fix:** bound the named operation's preparation/response lifetime, observe late completion, and prevent the abandoned continuation from launching. This can wrap preparation without rewriting the serial resolver. Separate reservation settlement from the response bound while preserving its ownership guarantees. D73 explicitly defers this residual; it must not be described as fully fixed.

The constants satisfy **90 < 120** ([constants:33](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/shared/src/lib/types/rpc/rpc-chat.types.ts:33), [constants:47](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/shared/src/lib/types/rpc/rpc-chat.types.ts:47)), not an unconditional ordering of actual completion times. The renderer starts its timer before posting ([rpc:173](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/frontend/core/src/lib/services/claude-rpc.service.ts:173), [rpc:219](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/frontend/core/src/lib/services/claude-rpc.service.ts:219)), explicit caller timeouts still win ([rpc:151](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/frontend/core/src/lib/services/claude-rpc.service.ts:151)), and the host uses `Date.now()` ([chat:229](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/backend/rpc-handlers/src/lib/chat/session/chat-session.service.ts:229), [ex:720](D:/projects/ptah-extension/.claude-worktrees/claude-named-accounts/libs/backend/agent-sdk/src/lib/helpers/session-lifecycle/session-query-executor.service.ts:720)), so arbitrary IPC delays or wall-clock adjustments are outside that guarantee.
