# Command Center scene: SVG and DOM design specification

## Authority and scope

This revises the existing canvas scene into an Angular 22 SVG/DOM scene. The supplied `references/reference-exposure-command-center.webp` supplies composition only: source curves, a ticked luminous dial, separated outgoing ribbons and glass cards. Ptah's projection, themes and page controls supply meaning. The [interactive prototype](prototype/index.html) is the visual and behavior review artifact; production implementation waits for Gate 1.7 acceptance. Use the existing technical-content-writer `DESIGN-SYSTEM.md`, `apps/ptah-extension-webview/tailwind.config.js` and `src/styles.css`; do not introduce a new palette or component system.

## Information model and parity contract

`projectOwnedWork` and `CommandWorkNode.id` remain the scene's membership and stable identity. A root session button sits at the dial. The number is **active delegated work**: non-root, non-phase nodes in `running` or `starting`. Counts on the four cards use the same non-root, non-phase set. A tribunal phase is progress of its tribunal, never another delegate. The full existing work list retains every projected node, including phases. Its state-change live region is the only live region; this scene adds no duplicate announcement. Provider marks, nine explicit state labels, accurate ages only when timestamps exist, pending input and command entry remain available. In page chrome, replace “Select a sphere for status” with “Select a work stream for status.”

## One layout model

The page's 336px rail, 16px outer padding and 16px gap are existing page rules (`command-center-page.component.ts`). Breakpoints use **stage container width**, never window width. The stage and page may grow vertically; **the scene itself does not scroll**. Only `.stream-list` and the existing rail list scroll. SVG is decorative and clipped to its scene; DOM text and focus rings are never clipped. The scene row viewport height is an exact integer number of 44px rows plus 5px gaps and **7px top/bottom padding**. The overflow/focus link sits **outside and immediately after** that viewport. All rows up to the 23-node scene cap remain in DOM for scroll and roving focus; only the viewport count below is visible at once. This is a visibility count, not a second placement cap.

## SVG geometry and reference cues

Use one `aria-hidden` SVG spanning `.scene`, viewBox in **CSS pixel coordinates** from its measured `getBoundingClientRect`. In ≥960px layout, each fully visible stream row starts a 1.5px gold curve at its right midpoint and approaches the dial's left edge. In 340–959px layouts, reserve a **24px routing gutter** to the right of the stream list. Each visible row has an endpoint dot just outside its right edge. Its 1.5px curve runs horizontally to the outer gutter, descends there past the list, then bends to a distinct point on the dial's top arc. Curves cannot pass through row text or the overflow link. A 3px endpoint dot at each source reproduces the reference. Nested rows still get a curve, while their indent and parent guide signal ancestry; do not draw a false root relationship for lanes. Use a 96-tick static SVG dial (major every eighth tick), theme gold strokes, plus one static inner luminous radial fill. No SVG filters.

Four **static** gradient ribbons leave four distinct positions on the right arc in wide layout or the bottom arc in vertical layout. Their endpoints are each group's center of the near edge. In stacked layout, top-left/top-right/bottom-left/bottom-right cards start at dial-bottom offsets −0.65r/+0.65r/−0.35r/+0.35r, respectively, where r is dial radius; control points stay directly below each start and directly above its matching card. This keeps left routes left and right routes right, without crossing. Bezier control points are 42px outward in wide layout or 32px vertically in stacked layout. Widths are 16px except waiting at 20px; gradient end opacity is 0.55–0.8. Running uses `--state-ink-running`, waiting `--state-ink-awaiting-input`, finished `--state-ink-completed`; Other uses neutral idle ink with a separate failed/cancelled chip. The ribbon start positions must remain distinct; no shared origin knot. Paths behind cards never intercept pointers. Gold curves are decorative; the dark 2.5:1 curve/stage pair is exempt from non-text information contrast because node identity is conveyed by visible row labels and dots. Status cards use a static translucent `--surface-1` mix, a crisp `--surface-border-strong` border and the theme's box radius, **no `backdrop-filter` or animated blur**.

One `ResizeObserver` watches the scene; `scroll` on `.stream-list` and `focusin` schedule the same remeasurement. Coalesce events to one `requestAnimationFrame`: read scene, dial, visible rows and cards, then write SVG coordinates. Skip rows outside the list viewport. Do not animate geometry or run a continuous canvas-style frame loop. The prototype exposes this when a 24-node list is scrolled. SVG failure leaves rows, cards and rail fully usable.

## Details, focus and semantics

Use the existing `FloatingUIService` behavior, anchored to the active stream or work-list row (`command-overlay.component.ts:152-171`). Plate maximum width **256px** (`w-64` in the current card). First try to the row's right, then left, accepting a side only when the whole plate fits inside the stage and avoids the stream list, dial and all group cards with a 4px clearance. Do not clamp an overlapping candidate into place. At ≥960px if both sides fail, reserve `plate height + 56px` after the scene and put the plate 8px below it, horizontally aligned to the trigger and clamped inside the stage. At 340–959px, reserve the same height between the stream section and dial; put the plate 8px below the section, with its left edge clamped inside the stage. Below 340px, use that same reserved vertical space in the single-column fallback. The stage grows in flow, so the plate covers **no row text, dial or card at any documented width**, including the 340px viewport. Keep a pointer bridge for side placements across the 8px anchor gap; the reserved-space placement is also reachable from the trigger by keyboard and its action. Plate is above decorative paths, no modal focus trap. Show **display name, kind, provider, state and available age**, never raw projection IDs. Closing Escape returns focus to the trigger or its full-list row. The prototype uses equivalent local geometry for its static plate.

The stream column is a labeled list and **one roving-tabindex stop**: exactly one stream button has `tabindex=0`; all siblings `-1`. Up/Down moves and focuses rows, including scrolling them into view. Enter/Space performs click selection. The rail keeps its own existing roving tabindex. Scene focus order in DOM is: active stream row → overflow/focus-work-list link → root button → status groups (noninteractive, zero tab stops) → full work-list active row → command dock controls. When plate actions are shown, Tab can enter them from the trigger; Escape returns to the trigger. Selection and status updates mutate attributes/text on keyed existing row elements (`@for track node.id`); they never rebuild the row subtree. Rebuild only when projection membership changes; if a row disappears while its plate is open, transfer focus to its counterpart in the full list. Hover does not change store selection. No scene live region duplicates work-list announcements.

## Type, tokens, contrast and motion

Use project semantic variables for every picker theme. Offline prototype embeds Anubis literals only. Type ramp: Inter body 13/20, row name 12/18, all secondary labels, ages and units **minimum 11/16**, section label 11/16, count 50/50 wide and 34/34 at the 160px dial. At the 160px dial, hide the inner voice caption because the stage header already states voice; set the root button to 68% of dial diameter and the unit to 92px maximum width. The core text has clearance from the ring. JetBrains Mono is for counts/ages and Cinzel/serif for the brand eyebrow; these follow existing `tailwind.config.js` font families. All rows are 44px high, with a 2px `--ptah-gold-strong` focus outline and 3px offset; the first and last rows keep 7px list padding, more than the 5px outline reach, with no clipping.

WCAG 2.2 AA criteria: text ≥4.5:1 (1.4.3), focus and meaningful non-text boundaries ≥3:1 (1.4.11). Headless Chromium measured the **rendered composites** of stage, translucent row/card fill and text after this revision: dark row sub-label/age `#b8b5b3` on default `#1f1f28` **8.02:1**, on selected/hover `#242430` **7.52:1**; dark failed/cancelled chip `#ff7979` on card composite `#1d181a` **6.90:1**. Light row muted `rgb(116 86 101)` on default `rgb(234 230 226)` **5.19:1**, on selected `rgb(230 226 223)` **5.00:1**; light chip `rgb(180 35 42)` on card `rgb(239 234 231)` **5.47:1**. Existing design-system token pairs remain dark muted on base-100/200/300 6.06/5.66/5.01:1 and light muted 6.03/5.39/5.01:1; dark focus `#f5d97d` against base-200 `#1a1a20` 12.5:1 and light focus `oklch(48% .12 70)` against light base-200 5.61:1. Dark running and failed dots against a row measured 4.25 and 4.15:1, respectively. Alternate picker themes require rendered pair checks; if a focus pair fails, use the existing `--ptah-accent-ink` token documented at ≥4.6:1 in `styles.css`.

Only running arc rotation and voice thinking rotation are continuous motion; both freeze for either store `reducedMotion` **or** `matchMedia('(prefers-reduced-motion: reduce)')`, with either source taking precedence when true. Listening/speaking voice levels still update semantic state and caption under reduced motion but do not scale the ring. No count ticker, path animation, blur animation or per-node particles. Profile on Electron before claiming the target of <16ms interaction at 24 nodes or <32ms at 60.

## Angular handoff and ngxui

Use standalone OnPush Angular components with `input()`/`output()`, signals and keyed `@for`. `CommandSceneComponent` owns aggregation and focus wiring; core owns dial/voice state; streams own capped placement and roving focus; status groups own static cards; connector component owns one SVG and measured anchors; detail plate adapts the existing overlay positioning and actions. The existing work list remains exhaustive. Existing cards, badges, provider marks and typography remain available.

Keep the prior ngxui decision: build locally with SVG/CSS. `@omnedia/ngx-connection-beam` and `ngx-border-beam` package peers specify Angular `^21.0.0` while this project is Angular 22; `ngx-orb` renders WebGL canvas; the number ticker would misrepresent exact counts. No new npm package, GSAP effect or asset is required. This is reversible if peers and behavior are re-evaluated later.
