## Findings

1. **Serious — workspace model saves can silently become machine saves.** `implementation-plan.md:129,139,148` uses the ambient `WorkspaceScopeResolver.write` and a `save` contract without an explicit workspace. Verified anchor: `libs/backend/settings-core/src/scope/workspace-scope-resolver.ts:197-208` writes globally when the active workspace is absent. This violates `task-description.md:66-67` and risks changing other projects. Require workspace saves to capture and validate the request's workspace, refuse a missing workspace, and retain that identity through the settings read/modify/write. Preserve unrelated map entries and serialize competing updates. Add tests for missing workspace (no global write), workspace switch during save, and two concurrent field updates; the proposed two-workspace read test alone is insufficient.

2. **Serious — Restore has no complete success/failure contract after creating the source file.** `implementation-plan.md:66-67,108` returns `restored` after copying into `.claude/agents`, then relies on a separate client reconcile to create the scoped clone. Verified anchor: `libs/backend/harness-sync/src/lib/state/agent-sync-gate.ts:182-191` omits the mirror source when the gate is disabled. Restore can therefore report success without the agent appearing, contrary to `task-description.md:92`; meanwhile `implementation-plan.md:65` removes it from the quarantine list because its source file exists. A failed reconcile has the same misleading outcome, and a retry now conflicts. Define a recoverable source-restored/propagation-pending state, including gate-disabled behavior, and do not silently enable sync consent. Specify partial-copy failure handling so exclusive creation cannot leave an empty/partial source that permanently blocks retry. Test gate disabled, copy failure, reconcile failure, and successful retry while preserving history and conflicting files. Exclusive create and the two-path conflict check are good guards but do not cover these paths.

3. **Serious — automatic whole-workspace reconciliation bypasses the stated edited-file warning.** `implementation-plan.md:106` warns only for agent paths in the loaded health report, yet `:108,149` also reconcile automatically after Restore/model save without that warning. Verified anchor: `libs/backend/rpc-handlers/src/lib/harness/health/harness-health-rpc.service.ts:159-167` invokes full propagation with only an optional target filter, not an agents-only operation. Thus an unrelated edited provider file can be overwritten by any of these actions; edits made after the initial health refresh also escape the warning. C1's snapshot-before-overwrite and refusal on snapshot failure guard recoverability, but not the user's informed choice (`task-description.md:82`). Apply one consistent pre-mutation warning policy to these callers, use fresh affected-path evidence, and disclose the whole-workspace effect. Test cancel/no mutation, edits since tab load, unrelated edited facets, and automatic post-save/post-Restore reconcile. Do not add a new facet API merely to resolve the wording if a clear existing-operation warning suffices.

4. **Serious — model acceptance is inconsistent across UI, save, and emission.** `task-description.md:51-57` expressly accepts a provider-listed value even when it fails the provisional syntax rule. `implementation-plan.md:142,148` instead filters emission by syntax and validates saves using list-independent rules; `confirmUnlisted` has no defined enforcement. A value the UI accepts can be rejected on save or silently omitted from a generated file. Also `:138` treats a mixed fallback/live list as provider-reported, potentially promoting fallback-only entries to Listed-valid. Verified anchor: `libs/shared/src/lib/types/rpc/rpc-agents.types.ts:135-149` marks fallback status per entry. Define a single authoritative classification contract, including listed exceptions, mixed lists, list-unavailable behavior and confirmation enforcement, and ensure accepted values survive emission. Add end-to-end cases for listed-but-syntax-failing, unlisted without confirmation, mixed fallback/live entries, and save failure retaining prior settings. Do not store a value as accepted and silently discard it later.

5. **Serious — the preview can promise paths that generation does not write.** `implementation-plan.md:82` chooses targets by detection/facet support, while `:227` leaves gate handling as an assumption with a conditional-note fallback. That does not meet `task-description.md:103,107`'s concrete file preview. Verified anchor: `libs/backend/harness-sync/src/lib/state/agent-sync-gate.ts:165-175` documents consent gating and why raw state is insufficient. Resolve eligibility using the state that will apply after generation, and explicitly distinguish conditional/unknown destinations from promised writes. `implementation-plan.md:91` tests preview followed only by reconcile, rather than the actual submit-selection/generation path, and allows extra writes with a superset assertion. Require a fixture through the real generation flow, with agent artifact paths matching the definite preview, plus gate-disabled, provider-state-change, preview failure, and cancel/no-write cases. Keep the required warning-and-Generate fallback; do not silently weaken preview accuracy.

6. **Minor — quarantine history identity and malformed-data behavior are underspecified.** `implementation-plan.md:65-66` equates the latest history directory with the quarantine snapshot/date, and defines absent/unparsable marker handling but not a parseable wrong-shaped marker, unsafe stored slug, or absent snapshot. Verified anchor: `libs/backend/agent-generation/src/lib/services/user-layer/user-layer-seed-quarantine.ts:261-312` snapshots into history and records slug arrays plus one completion timestamp, not a snapshot identifier. Specify validated marker fields and safe snapshot selection without treating arbitrary later history as proven quarantine history; disclose an unknown date when it cannot be established. Test wrong-shaped markers, missing/unreadable history and the existing `no-snapshot` outcome, with no source write. No schema or storage migration is required unless existing evidence proves it necessary.

## Decisions for the user

- **Restore destination (scope-changing):** `task-description.md:92` promises restoration into scoped agents; `implementation-plan.md:213` instead promotes quarantined content into the workspace's `.claude/agents` source. This is a defensible way to establish ownership, but changes source files and future propagation and is not settled by `context.md:77`. At the combined gate, choose: **restore as an owned workspace source, clearly disclosed before Restore (Recommended)**; or keep recovery confined to quarantine/scoped storage and do not promise durable ownership until that behavior is designed. Preserve snapshots and refuse all same-slug conflicts either way.
- No additional user decision is needed for the technical defects above. Full-workspace reconciliation is already named by the requirements; make its effects explicit and guarded. Model precedence, shared contracts and implementation mechanics can be resolved by the authors within the agreed scope.
