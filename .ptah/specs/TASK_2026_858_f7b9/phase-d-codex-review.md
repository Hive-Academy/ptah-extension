# Phase D independent code review

Score: **5/10**

Verdict: **CHANGES REQUESTED**

## Findings

1. **High — A turn can finish before it is registered, permanently occupying an active-turn slot.** `libs/backend/worker-host/src/lib/commands/remote-sessions.ts:468-477` calls `driver.end()` only when `driver.driving(sessionId)` is already true. `libs/backend/worker-runtime/src/lib/session-driver.ts:144-152,197-213` does not register a successful `chat:continue` or `chat:start` until after baseline and `worker:turn.begin` append. An end event during the RPC or those appends is ignored for lifecycle purposes, even if captured in the log. The turn remains in `turns`; `maxActiveTurns` can refuse later work indefinitely. The Round 3 report acknowledges this limit; the integration spec emits `session:turnEnded` only after the start response. **Fix:** retain terminal events by tab/session while admission is pending, then end the registered turn in order; cover end events during both start and continue, including slot reuse and a single end/mark record.

2. **High — `session.start` timeout abandons an admitted operation and lock without abort.** `libs/backend/worker-runtime/src/lib/session-driver.ts:197-219` awaits `resolved()` outside the inner cleanup `try`. The 30-second rejection in `libs/backend/worker-host/src/lib/commands/remote-sessions.ts:224-239` therefore reaches only the `finally` that drops the reservation. The backend may already have started the turn and acquired its driver lock; no `turns` or `tabsBySession` entry exists for shutdown or `session.stop`, and a new turn can be admitted beyond `maxActiveTurns`. **Fix:** make resolution failure cancel the started tab through an engine API, or retain its eventual session ID and abort/release it before relinquishing the reservation. Add a spec where `chat:start` succeeds but `session:id-resolved` is absent or late.

3. **High — Failed abort is reported as a successful stop and frees admission.** `libs/backend/worker-runtime/src/lib/session-driver.ts:235-254` deletes the turn before calling `chat:abort` and never checks the RPC result's `ok` flag. `libs/backend/worker-host/src/lib/commands/remote-sessions.ts:397-400` consequently returns `{ stopped: true }` if the RPC returns an error result, while the backend operation and driver lock may still be live. It can also append `worker:turn.interrupted` for a turn that was never interrupted. **Fix:** inspect the abort result and retain the active record on refusal; only mark interrupted and free capacity after confirmed abort or a terminal engine event. Add a failed-abort spec that checks the response, retained capacity, and log.

4. **Medium — A permission request emitted before session resolution cannot be answered.** `libs/backend/worker-host/src/lib/commands/remote-sessions.ts:440-449` calls `pending.add` using only the event's `sessionId` or an already resolved tab. `libs/backend/worker-runtime/src/lib/pending-permissions.ts:35-38` discards requests without either value, while the event itself is queued by tab for later log replay. The client can see the request after resolution but `permission.respond` returns `ALREADY_ANSWERED`. This is acknowledged in the Round 3 report and absent from the permission round-trip spec, which emits a request with a session ID. **Fix:** hold pre-resolution requests by tab and bind them when `session:id-resolved` arrives; test a tab-only request through successful answer and wrong-session refusal.

5. **Medium — Shutdown can miss a start still resolving.** `libs/backend/worker-host/src/lib/commands/serve.ts:403-405` calls `abortTurns()` before stopping the service, but `remote-sessions.ts:493-503` scans only `tabsBySession`. A successful `chat:start` whose `session:id-resolved` has not yet arrived is excluded; its request can remain in flight while the service closes logs and releases currently held locks. The `session.start` handler has no shutdown gate to prevent later registration. **Fix:** stop accepting calls, wait for or cancel pending admissions, abort all admitted starts, and then close logs and release locks. Add a shutdown spec with deliberately delayed resolution.
